## 1. 最终结论

### 1.1 隔离测试可交付

**批准作为隔离环境的受控联调与受控写入验收候选，不批准连接生产数据、真实账号或公网入口。**

下列能力已具备代码级基础，且可由现有二期专项脚本验证：

1. 二期接口统一使用 Bearer 令牌校验账号状态和所属渠道状态，账号或渠道停用时会拒绝请求并撤销当前令牌，见 `backend/server.js:6554`、`backend/server.js:6571`、`backend/server.js:6583`、`backend/server.js:6595`。
2. 数据查询和详情访问按超级管理员、区域管理员、渠道管理员、渠道员工的角色、区域、渠道与本人范围裁决，见 `backend/server.js:6208`、`backend/server.js:6219`、`backend/server.js:6233`。
3. 移动端敏感字段在详情构造阶段按电话、邮箱、统一社会信用代码、地址等规则脱敏，见 `backend/server.js:6628`、`backend/server.js:6656`、`backend/server.js:6674`。
4. 二期写入仍经过服务端功能开关、业务参数、发布契约、幂等键、权限与状态机控制；未发布路径统一拒绝，见 `backend/server.js:6473`、`backend/server.js:7457`、`backend/server.js:8368` 及 `frontend/mobile-v2-api.js:145`。
5. 二期 API 响应已设置无缓存、禁止嵌入、禁止内容嗅探和最小权限策略等头部，见 `backend/server.js:6350`；基础安全脚本对这些 API 头部有断言，见 `scripts/test-mobile-v2-foundation.js:124`。
6. 二期没有附件或文件上传路由。上传中间件仅用于既有导入接口 `POST /api/import/:type/preview` 和 `POST /api/import/:type/execute`，见 `backend/server.js:69`、`backend/server.js:13266`、`backend/server.js:13347`；本期移动端不会新增上传攻击面。

隔离测试必须同时满足：

1. 使用临时数据库、临时审计库、脱敏测试数据和测试账号；不得复用生产库、工作库或真实用户令牌。
2. 仅允许本机或隔离网络访问；不得发布二维码、域名、公网端口或面向真实管理员、渠道伙伴开放入口。
3. 仅由专项脚本临时启动服务；测试结束后确认临时服务、临时数据库、浏览器会话和测试令牌已清理。
4. 写入验收只能按已冻结的服务端功能开关与业务参数执行；调价、取消、退款、附件、外部通知、电子签章和物流接口继续保持关闭。

### 1.2 生产开放不可准入

**不批准生产只读灰度、不批准生产写入灰度、不批准生产正式开放。**

当前存在认证会话、传输与部署隔离、跨域、限流、请求边界、共享进程上传与高风险依赖等阻断项。它们均不能通过隐藏前端入口、仅修改文案或仅依赖测试网络规避，必须完成后端、反向代理、身份源、运维配置和回归验收。

## 3. 生产阻断项

### B-01：生产级独立认证与会话未实现

- **等级：阻断级**
- **证据：**
  - 二期将 Bearer 令牌与用户信息写入可被页面脚本读取的 `sessionStorage`，见 `frontend/mobile-v2-api.js:50`、`frontend/mobile-v2-api.js:63`、`frontend/mobile-v2-api.js:72`。
  - 二期为了兼容测试，直接从一期 `localStorage` 读取令牌，见 `frontend/mobile-v2-api.js:220`、`frontend/mobile-v2-api.js:225`、`frontend/mobile-v2-api.js:229`；页面也明确标记为“兼容测试”，见 `frontend/mobile-v2-app.js:358`、`frontend/mobile-v2-app.js:364`。
  - 当前本地登录按明文密码比较，见 `backend/server.js:3026`；本地登录令牌由时间戳拼接，见 `backend/server.js:3206`、`backend/server.js:3211`，并以原文保存在进程内令牌集合，见 `backend/server.js:3213`。
  - 虽定义了独立会话配置的目标属性，但注释明确当前没有登录、刷新、再次验证接口，见 `backend/server.js:6319`、`backend/server.js:6323`。
- **影响：** 脚本注入、恶意浏览器扩展、共享终端或 HTTP 传输均可能窃取和复用现有 Bearer 令牌；令牌生成、存储、刷新、设备撤销与跨实例一致性不满足生产要求。
- **生产关闭条件：** 独立移动认证必须完成并通过专项验收：管理员接入统一身份认证，渠道账号迁移为安全口令哈希或经确认的统一身份认证；短时访问令牌仅驻留内存；刷新凭证使用 `HttpOnly`、`Secure`、`SameSite=Strict` Cookie；刷新轮换、重复使用检测、设备撤销、账号停用即时失效、再次验证、CSRF 与限流均须落地。生产构建不得读取一期 `localStorage` 令牌。

### B-02：传输加密、同源反向代理与后端网络隔离缺失

- **等级：阻断级**
- **证据：**
  - 二期 API 基址默认拼接当前主机的 `3000` 端口，见 `frontend/mobile-v2-api.js:32`、`frontend/mobile-v2-api.js:36`。
  - 服务端直接调用 `app.listen(PORT)`，未见反向代理、绑定地址或 TLS 服务器配置，见 `backend/server.js:16960`。
  - 本地启动脚本显示并发布 HTTP 地址，前端静态服务绑定 `0.0.0.0`，见 `scripts/start.sh:119`、`scripts/start.sh:128`、`scripts/start.sh:145`、`scripts/start.sh:170`。
  - 现有部署脚本使用 Python HTTP 静态服务、开放端口并显示 HTTP 访问地址，见 `scripts/deploy.sh:90`、`scripts/deploy.sh:120`、`scripts/deploy.sh:153`；部署文档的 Nginx 示例也仅监听 `80` 端口，见 `docs/DEPLOY.md:58`、`docs/DEPLOY.md:60`。
- **影响：** 账号、令牌和业务数据可能被网络窃听或篡改；前端与 V2 API 跨端口部署迫使系统依赖跨域，而后端可被绕过网关直接访问。
- **生产关闭条件：** 使用受管反向代理发布同源 HTTPS；只允许公网 `443`，HTTP 仅做跳转；`/api/mobile/v2/` 代理到仅监听回环或私网的后端；提供证书链、自动续期、端口扫描、代理配置、后端监听地址和实际响应头抓取证据。

### B-03：二期跨域策略未隔离且全局宽松

- **等级：高风险，生产阻断**
- **证据：** 全局无参数调用 `cors()`，所有接口共用该策略，见 `backend/server.js:35`；二期 API 没有专用来源白名单、预检方法或请求头限制。
- **影响：** 当前 Bearer 令牌不会自动附带，因此不能据此认定已经存在跨站直接越权；但任意来源均可获得宽松跨域响应，且二期默认跨端口部署。若后续引入 Cookie 刷新会话、第三方页面误持令牌或错误前端配置，将扩大跨站数据访问和会话攻击面。
- **生产关闭条件：** 二期改为同源访问；网关和应用层均拒绝未知 `Origin`，仅允许正式 H5 域名、必要方法与 `Authorization`、`Content-Type`、`Idempotency-Key` 等必要请求头；不允许通配来源与凭证组合。该变更涉及全局中间件，必须保证一期和电脑端跨域行为回归通过。

### B-04：认证与业务接口缺少限流、正文及请求资源边界

- **等级：高风险，生产阻断**
- **证据：**
  - 全局仅使用未显式配置上限的 JSON 和 URL 编码解析中间件，见 `backend/server.js:35`、`backend/server.js:36`、`backend/server.js:37`。
  - 本地登录路由可以被连续调用，见 `backend/server.js:3436`、`backend/server.js:3511`；源码未发现登录、刷新或 V2 路由的限流中间件。
  - 前端 `15` 秒超时仅中止本地请求，见 `frontend/mobile-v2-api.js:10`、`frontend/mobile-v2-api.js:167`，不构成服务端限流或拒绝服务防护。
- **影响：** 可被口令猜测、资源耗尽、过大请求体和异常查询放大；受控写入的幂等不等于请求频率控制。
- **生产关闭条件：** 在网关与应用层分别设置登录、刷新、再次验证、高风险写入、只读查询的来源与账号双维度限流；明确 V2 的正文、URL、查询参数、并发、响应大小和超时上限；记录拒绝原因并接入告警。限流应使用可信代理源地址，不能直接信任客户端头部。

### B-05：审计来源地址与 HTTPS 判断直接接受转发头

- **等级：高风险，生产阻断**
- **证据：**
  - 审计 IP 直接读取 `X-Forwarded-For` 的首项，见 `backend/server.js:1196`；开放接口也沿用该模式，见 `backend/server.js:13887`。
  - 二期 HTTPS 判断直接读取 `X-Forwarded-Proto`，见 `backend/server.js:6345`。
  - 源码未见按已知代理跳数或网段配置的 `trust proxy`。
- **影响：** 若后端被直接访问或代理不覆盖伪造头，攻击者可伪造审计来源；HSTS 判定也不能作为真实传输安全证据。
- **生产关闭条件：** 后端只接受受信反向代理连接，代理覆盖 `X-Forwarded-For`、`X-Forwarded-Proto` 和 `Host`；按真实拓扑配置受信代理；限流、审计与异常检测使用可信源地址，并以直接访问后端的拒绝测试证明不可伪造。

### B-06：静态移动页面缺少生产可验证的安全响应头

- **等级：高风险，生产阻断**
- **证据：**
  - 安全头仅在 `/api/mobile/v2` 路径被附加，见 `backend/server.js:30`、`backend/server.js:32`、`backend/server.js:6350`。
  - 静态页面本身无内容安全策略元标签，见 `frontend/mobile-v2.html:1` 至 `frontend/mobile-v2.html:17`。
  - 当前静态服务为 Python HTTP 服务，见 `scripts/start.sh:145`；部署文档仅对长期缓存静态资源给出示例，见 `docs/DEPLOY.md:70`。
- **影响：** API 头部不能保护 HTML、脚本、样式和错误页；而当前会话令牌仍可由页面脚本读取，页面侧脚本注入与缓存泄露风险无法被生产策略有效压缩。
- **生产关闭条件：** 由同源 HTTPS 反向代理为 `mobile-v2.html`、脚本、样式及错误页配置并实测 `Cache-Control: no-store`、内容安全策略、`frame-ancestors`、`X-Content-Type-Options`、`Referrer-Policy`、`Permissions-Policy`；策略不得使用未评审的 `unsafe-inline` 或 `unsafe-eval`。不建议仅用页面元标签替代网关响应头。

### B-07：同一后端进程的导入上传链路与高风险依赖未整改

- **等级：高风险，生产阻断**
- **证据：**
  - 全局上传中间件只限制单文件 `10MB`，未见文件类型白名单、内容检测或专用隔离目录策略，见 `backend/server.js:69`、`backend/server.js:70`、`backend/server.js:71`。
  - 上传文件由既有导入路由使用 `XLSX.readFile` 解析，见 `backend/server.js:13266`、`backend/server.js:13291`、`backend/server.js:13347`、`backend/server.js:13372`。
  - `xlsx` 为直接依赖，声明版本为 `^0.18.5`，见 `backend/package.json:14` 至 `backend/package.json:20`；锁文件实际版本为 `0.18.5`。
  - 本次执行 `npm audit --omit=dev --package-lock-only --json --prefix backend`，结果为高风险 `1` 项、中风险 `3` 项：`xlsx` 命中原型污染和正则拒绝服务公告；`express`、`body-parser`、`qs` 命中 `qs` 拒绝服务公告。锁文件中 `express` 为 `4.22.1`、`qs` 受影响范围由审计工具确认。
- **影响：** 虽然移动二期当前无上传接口，但它与导入功能同进程、共用依赖和运行账号。生产开放会同时暴露该进程的上传解析与供应链风险，可能影响移动端可用性、数据完整性和隔离边界。
- **生产关闭条件：** 上传服务与移动 API 至少完成路径、权限、文件类型、内容校验、大小、解析资源和临时文件生命周期整改；优先隔离上传解析进程。升级或替换 `xlsx` 并完成导入兼容回归；更新 Express 依赖链后完成全量回归。未经书面风险接受不得将高风险 `xlsx` 依赖带入生产。
