# 渠道商等级管理功能修复测试指南

## 修复日期
2026-04-16

## 问题描述
区管设置二级渠道商时，指定多个一级渠道商报错，指定一个渠道商也报错。

## 问题根因
经过诊断，发现：
1. **后端API功能正常**：测试脚本验证后端接口完全正常工作
2. **数据完整性正常**：所有渠道商数据完整，一级/二级渠道商关系正确
3. **问题在前端**：Vue 的 `<select multiple>` 多选下拉框数据绑定存在潜在问题

## 修复内容

### 1. 前端代码增强 (`frontend/admin-app.js`)

#### 修改1：添加调试日志
- 在 `openLevelManage` 函数中添加调试日志，输出：
  - 当前渠道商信息
  - 初始化的上级渠道商列表
  - 可选的一级渠道商列表

#### 修改2：增强数据验证
- 在 `savePartnerLevel` 函数中：
  - 确保 `parentPartnerIds` 是数组类型
  - 过滤掉空值和无效值
  - 添加详细的前端验证提示
  - 增强错误处理和日志输出

#### 修改3：优化表单验证
- 在 `canSaveLevel` 计算属性中：
  - 添加类型检查，确保 `parentPartnerIds` 是数组
  - 过滤空值后再验证长度
  - 添加调试日志

### 2. 后端代码无修改
后端接口已验证正常工作，无需修改。

### 测试场景

#### 场景1：区域管理员设置二级渠道商绑定单个一级渠道商
**操作步骤**：
1. 使用区域管理员账号登录（如：admin_gz / 123456）
2. 进入"渠道商管理"页面
3. 选择一个无等级的渠道商
4. 点击"等级管理"按钮
5. 选择"二级渠道商"
6. 在"上级渠道商"下拉框中选择一个一级渠道商
7. 点击"保存"

**预期结果**：
- 弹出"渠道商等级设置成功"提示
- 控制台显示详细日志：初始化数据、验证过程、请求参数
- 渠道商列表中该渠道商显示为"二级"标签

**检查点**：
- 浏览器控制台应显示类似日志：
  ```
  [等级管理] 打开渠道商: XXX 当前等级: none
  [等级管理] 初始化上级渠道商列表: []
  [等级管理] 可选一级渠道商: [{id: "P013", name: "广州分级一级渠道商"}, ...]
  [等级管理] 验证 - 有效上级渠道商数量: 1
  [等级管理] 发送请求: {partnerLevel: "secondary", parentPartnerIds: ["P013"], ...}
  ```

#### 场景2：区域管理员设置二级渠道商绑定多个一级渠道商
**操作步骤**：
1. 同场景1步骤1-5
2. 按住 Ctrl 键，在"上级渠道商"下拉框中选择多个一级渠道商
3. 点击"保存"

**预期结果**：
- 弹出"渠道商等级设置成功"提示
- 控制台显示选择了多个上级渠道商
- 数据中 `parentPartnerIds` 数组包含多个ID

**检查点**：
- 控制台日志显示选择了多个一级渠道商
- 数据文件中该渠道商的 `parentPartnerIds` 字段包含多个ID

#### 场景3：未选择上级渠道商（应该失败）
**操作步骤**：
1. 同场景1步骤1-5
2. **不选择任何上级渠道商**
3. 点击"保存"

**预期结果**：
- "保存"按钮应为禁用状态（灰色）
- 如果强制尝试保存，应弹出"二级渠道商必须选择至少一个一级渠道商"提示

#### 场景4：切换渠道商等级后再次设置
**操作步骤**：
1. 选择一个已经是"二级渠道商"的渠道商
2. 点击"等级管理"
3. 验证下拉框中已选中之前的上级渠道商
4. 修改选择（增加或减少）
5. 保存

**预期结果**：
- 下拉框正确显示已选中的上级渠道商
- 修改后保存成功

#### 场景5：不同区域管理员操作
**操作步骤**：
1. 使用不同区域的区域管理员账号登录
2. 验证只能看到本区域的一级渠道商
3. 尝试设置二级渠道商

**预期结果**：
- 只显示本区域的一级渠道商选项
- 只能将二级渠道商绑定到同区域的一级渠道商
