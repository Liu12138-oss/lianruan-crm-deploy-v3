# V3 生产升级包制作规范

编写日期：2026-07-31  
适用系统：联软 CRM V3  
适用环境：openEuler x86_64 单机 Docker Compose 部署  
适用目录：生产默认安装目录 `/opt/lianruan-crm-v3`  
包格式要求：只使用 ZIP，不使用 TAR、TGZ、7Z、RAR。生产执行只假设有 `bash`、`zip`、`unzip`、`cp`、`mkdir`、`sha256sum`、`docker`、`docker compose`、`curl` 等基础命令。KB 包内 Docker 镜像归档统一使用 `.docker-image` 后缀，通过 `docker load -i` 加载，不使用 `.tar` 文件名。

## 一、核心原则

所有缺陷修复和新功能开发必须基于 V3 版本执行。

禁止把 V2 的升级方式继续用于 V3：

| 禁止行为 | 原因 |
| --- | --- |
| 直接替换 `backend/server.js` | 这是 V2 后端，不是 V3 主线 |
| 直接替换 `frontend/admin-app.js` 或 `frontend/partner-app.js` | 这是 V2 静态前端遗留 |
| 用 `pkill -f node.*server.js` 停服务 | V3 生产由 Docker Compose 管理 |
| 用 `tar.gz` 做生产升级包，或在 KB 包内放 `.tar` 镜像文件名 | 生产欧拉环境按 ZIP 和 unzip 约束处理，镜像归档使用 `.docker-image` 后缀 |
| 不备份直接覆盖生产配置或数据库 | V3 已使用 PostgreSQL，回退成本高 |
| 修改数据库但不提供迁移 SQL 和回退说明 | 会造成版本不可追溯 |

V3 生产升级必须围绕这些资产：

| 类型 | V3 位置 |
| --- | --- |
| 后端镜像 | `lianruan-crm-v3-api:<版本>` |
| 前端镜像 | `lianruan-crm-v3-nginx:<版本>` |
| 任务镜像 | `lianruan-crm-v3-worker:<版本>` |
| 生产编排 | `/opt/lianruan-crm-v3/compose/docker-compose.yml` |
| 生产环境变量 | `/opt/lianruan-crm-v3/config/v3.env` |
| 部署变量 | `/opt/lianruan-crm-v3/config/deploy.env`、`/opt/lianruan-crm-v3/compose/.env` |
| 数据库迁移 | `/opt/lianruan-crm-v3/database/migrations/` |
| 运维脚本 | `/opt/lianruan-crm-v3/scripts/` |
| 健康检查 | `/opt/lianruan-crm-v3/scripts/health-check.sh` |
| 备份脚本 | `/opt/lianruan-crm-v3/scripts/backup.sh` |
| 回退脚本 | `/opt/lianruan-crm-v3/scripts/rollback.sh` |

## 二、升级包类型

### 2.1 完整离线发布包

完整离线发布包用于较大版本升级，包内包含镜像、Compose、配置模板、迁移 SQL、运行时和部署脚本。

制作入口：

```bash
npm ci
npm run verify
deploy/single-server/scripts/download-runtime.sh
V3_IMAGE_TAG=目标版本 deploy/single-server/scripts/build-images.sh
V3_IMAGE_TAG=目标版本 V3_SKIP_PULL=1 deploy/single-server/scripts/save-images.sh
V3_IMAGE_TAG=目标版本 V3_PACKAGE_FORMAT=zip deploy/single-server/scripts/package-offline.sh
```

输出示例：

```text
tmp/phase7-package/lianruan-crm-v3-offline-目标版本.zip
tmp/phase7-package/lianruan-crm-v3-offline-目标版本.zip.sha256
```

完整离线包适用场景：

1. API、Web、Worker 都有较大变化。
2. 需要同步 Dockerfile、Compose、Nginx、运行时。
3. 首次部署或整包重装。
4. 需要给完全离线服务器交付完整资产。

### 2.2 KB 热修复升级包

KB 升级包用于生产缺陷热修复或小范围功能补丁。这里的 KB 指“一个可执行、可复核、可回退、可留痕的知识库式修复包”。每个 KB 对应一个问题或一组强相关问题。

命名规则：

```text
lianruan-crm-v3-kb-YYYYMMDD-编号-简短问题名.zip
lianruan-crm-v3-kb-YYYYMMDD-编号-简短问题名.zip.sha256
```

示例：

```text
lianruan-crm-v3-kb-20260731-001-quote-workload-fix.zip
lianruan-crm-v3-kb-20260731-001-quote-workload-fix.zip.sha256
```

KB 包必须能自动完成：

1. 环境检查。
2. 包完整性校验。
3. 生产 V3 安装目录检查。
4. 升级前自动备份。
5. 按需停止相关服务。
6. 加载新镜像或复制补丁文件。
7. 执行数据库迁移或修复脚本。
8. 启动相关服务。
9. 执行健康检查。
10. 执行业务自检。
11. 生成升级日志。
12. 输出回退方式。

## 三、KB 包目录规范

KB 包解压后必须是单一目录，不允许散落文件。

```text
lianruan-crm-v3-kb-YYYYMMDD-编号-简短问题名/
├── README.md
├── KB说明.md
├── manifest/
│   ├── KB元数据.env
│   ├── 文件清单.tsv
│   └── SHA256SUMS
├── scripts/
│   ├── precheck.sh
│   ├── upgrade.sh
│   ├── verify.sh
│   └── rollback.sh
├── images/
│   ├── lianruan-crm-v3-api-目标版本.docker-image
│   ├── lianruan-crm-v3-nginx-目标版本.docker-image
│   └── lianruan-crm-v3-worker-目标版本.docker-image
├── database/
│   └── migrations/
│       └── YYYYMMDD_KB_编号_说明.sql
├── files/
│   ├── compose/
│   ├── config/
│   ├── scripts/
│   └── patches/
└── tests/
    ├── smoke.sh
    └── 验证清单.md
```

目录说明：

| 目录 | 是否必须 | 说明 |
| --- | --- | --- |
| `README.md` | 必须 | 给运维看的最短执行说明 |
| `KB说明.md` | 必须 | 问题背景、影响范围、修复内容、验证方式、回退方式 |
| `manifest/KB元数据.env` | 必须 | KB 编号、目标版本、最低可升级版本、影响服务 |
| `manifest/SHA256SUMS` | 必须 | 包内文件校验值 |
| `scripts/precheck.sh` | 必须 | 只检查，不改生产 |
| `scripts/upgrade.sh` | 必须 | 自动备份、停启、修复、健康检查 |
| `scripts/verify.sh` | 必须 | 升级后复核 |
| `scripts/rollback.sh` | 必须 | 最小回退动作 |
| `images/` | 按需 | 镜像升级时必须提供 |
| `database/migrations/` | 按需 | 数据库结构或数据修复时必须提供 |
| `files/` | 按需 | 仅限配置、脚本、补丁资源；不要放 V2 文件 |
| `tests/` | 推荐 | 自动冒烟脚本和人工验证清单 |

## 四、KB 元数据规范

`manifest/KB元数据.env` 示例：

```bash
KB_ID=KB-20260731-001
KB_NAME=报价工作量试算修复
TARGET_VERSION=3.0.0-stage9.23.20260731
MIN_VERSION=3.0.0-stage9.20.20260729
PACKAGE_TYPE=hotfix
REQUIRES_DB_MIGRATION=true
REQUIRES_IMAGE_LOAD=true
AFFECTED_SERVICES=api-1,api-2,worker,nginx
DEFAULT_INSTALL_ROOT=/opt/lianruan-crm-v3
BUILD_COMMIT=kb-20260731-001-quote-workload-fix
BUILD_TIME=2026-07-31T00:00:00Z
```

字段要求：

| 字段 | 说明 |
| --- | --- |
| `KB_ID` | 唯一编号，不可复用 |
| `TARGET_VERSION` | 升级后的 V3 版本 |
| `MIN_VERSION` | 允许升级的最低版本 |
| `REQUIRES_DB_MIGRATION` | 是否包含 SQL |
| `REQUIRES_IMAGE_LOAD` | 是否包含镜像 |
| `AFFECTED_SERVICES` | 受影响服务，必须精确 |
| `DEFAULT_INSTALL_ROOT` | 默认安装目录 |
| `BUILD_COMMIT` | 构建标识 |
| `BUILD_TIME` | 构建时间 |

## 五、KB 制作流程

### 5.1 开发前确认

每个 KB 制作前必须确认：

1. 该修复属于 V3 范围。
2. 修复位置在 `apps/`、`packages/`、`database/`、`deploy/single-server/` 或 V3 明确保留的 `apps/web/public/`。
3. 不是修改旧 `backend/`、旧 `frontend/`。
4. 已确认生产当前版本。
5. 已确认是否需要数据库迁移。
6. 已确认是否影响 V2 兼容接口。
7. 已确认回退方式。

### 5.2 代码修复和验证

本地至少执行：

```bash
npm run check
npm test
npm run build
```

涉及数据库、接口、生产包时执行完整门禁：

```bash
npm run verify
```

如果修复旧静态入口，还必须补充：

```bash
node --check apps/web/public/admin-app.js
node --check apps/web/public/partner-app.js
node --check apps/web/public/mobile-app.js
```

按实际修改文件选择执行，不需要无关文件全部检查。

### 5.3 构建镜像

镜像型 KB 必须重新构建受影响镜像。

```bash
V3_IMAGE_TAG=目标版本 deploy/single-server/scripts/build-images.sh
V3_IMAGE_TAG=目标版本 V3_SKIP_PULL=1 deploy/single-server/scripts/save-images.sh
```

如果只修 API，只允许包含 API 镜像；如果只修前端，只允许包含 Nginx Web 镜像；如果 Worker 未变化，不要把 Worker 镜像放入 KB 包。

### 5.4 准备 SQL

数据库迁移命名：

```text
YYYYMMDD_KB_编号_中文说明.sql
```

示例：

```text
20260731_KB_001_修复报价工作量历史映射.sql
```

SQL 要求：

1. 必须可重复执行。
2. 必须写入或兼容 `migration.schema_migrations`。
3. 不能直接删除生产数据。
4. 大批量修复必须分批或说明执行时间。
5. 金额、订单、审批、账号权限修复必须有业务验收样本。

### 5.5 生成 ZIP

制作 KB 包时只使用 ZIP。

```bash
cd tmp/kb-build
zip -qr -X lianruan-crm-v3-kb-YYYYMMDD-编号-简短问题名.zip lianruan-crm-v3-kb-YYYYMMDD-编号-简短问题名
sha256sum lianruan-crm-v3-kb-YYYYMMDD-编号-简短问题名.zip > lianruan-crm-v3-kb-YYYYMMDD-编号-简短问题名.zip.sha256
```

禁止使用：

```text
tar
tar.gz
tgz
*.tar
*.tar.gz
*.tgz
rar
7z
python 解压脚本作为唯一解压方案
```

## 六、生产升级执行规范

### 6.1 上传和解压

生产服务器执行：

```bash
cd /tmp
sha256sum -c lianruan-crm-v3-kb-YYYYMMDD-编号-简短问题名.zip.sha256
unzip -q lianruan-crm-v3-kb-YYYYMMDD-编号-简短问题名.zip
cd lianruan-crm-v3-kb-YYYYMMDD-编号-简短问题名
```

### 6.2 预检查

```bash
sudo bash scripts/precheck.sh /opt/lianruan-crm-v3
```

预检查必须只读，不允许修改生产。

检查项：

1. 当前用户是否 root 或 sudo。
2. 系统是否 openEuler 或 Euler 标识。
3. CPU 架构是否 `x86_64`。
4. 安装目录是否存在。
5. 是否为 V3 安装目录。
6. Docker 和 Docker Compose 是否可用。
7. 目标容器是否存在。
8. 当前版本是否满足 `MIN_VERSION`。
9. 磁盘剩余空间是否足够。
10. 包内文件校验是否通过。

### 6.3 自动升级

```bash
sudo bash scripts/upgrade.sh /opt/lianruan-crm-v3
```

自动升级必须按这个顺序执行：

```mermaid
flowchart LR
  A["预检查"] --> B["生成升级日志目录"]
  B --> C["执行生产备份"]
  C --> D["保存当前版本快照"]
  D --> E["停止受影响服务"]
  E --> F["加载镜像或复制文件"]
  F --> G["同步版本变量"]
  G --> H["执行数据库迁移"]
  H --> I["启动服务"]
  I --> J["健康检查"]
  J --> K["业务冒烟"]
  K --> L["输出升级结果和回退命令"]
```

### 6.4 自动备份要求

KB 升级前必须执行自动备份，但不得默认调用服务器旧 `backup.sh`。如果旧脚本依赖 `tar`、`python`、`jq`、`rsync` 等未承诺命令，升级包会在生产环境失败。

推荐 KB 自带备份逻辑：

```bash
backup_dir="/opt/lianruan-crm-v3/backups/local/时间戳-KB编号-preupgrade"
mkdir -p "${backup_dir}"
cd /opt/lianruan-crm-v3/compose
docker compose exec -T postgres pg_dump -U lianruan_app -d lianruan_crm_v3 > "${backup_dir}/postgres.sql"
cd /opt/lianruan-crm-v3/data
zip -qr -X "${backup_dir}/uploads.zip" uploads
zip -qr -X "${backup_dir}/exports.zip" exports
```

同时 KB 脚本必须额外保存：

```text
/opt/lianruan-crm-v3/releases/升级前版本/
├── compose/docker-compose.yml
├── config/v3.env
├── config/deploy.env
├── config/nginx/default.conf
└── scripts/
```

注意：

1. 使用 KB 自带脚本备份数据库和业务文件，业务目录只使用 ZIP。
2. `releases/` 快照用于应用配置回退。
3. 数据库回退不应自动执行，必须人工确认恢复策略。

### 6.5 停启服务要求

只停受影响服务，减少影响范围。

| 影响范围 | 停止服务 |
| --- | --- |
| 只改前端静态资源或 Nginx 配置 | `nginx` |
| 只改 API | `nginx`、`api-1`、`api-2` |
| 改 Worker | `worker` |
| 改数据库迁移 | 通常停止 `nginx`、`api-1`、`api-2`、`worker`，保留 `postgres`、`redis-state` |
| 改 Compose 网络、PostgreSQL、Redis | 进入维护窗口，按完整停启处理 |

推荐命令：

```bash
cd /opt/lianruan-crm-v3/compose
docker compose stop nginx
docker compose stop api-1 api-2 worker
docker compose up -d api-1 api-2 worker nginx
```

不要使用：

```bash
pkill -f node
pkill -f server.js
```

### 6.6 健康检查要求

升级后必须执行：

```bash
/opt/lianruan-crm-v3/scripts/health-check.sh
```

还要直接检查：

```bash
curl -fsS http://127.0.0.1/health/live
curl -fsS http://127.0.0.1/health/ready
curl -fsS http://127.0.0.1/health/dependencies
```

如果 `/health/dependencies` 被 Nginx 来源限制拦截，应在服务器本机执行，或通过 Compose 直接访问 API 容器。

## 七、KB 脚本模板

以下模板只使用 openEuler 常见基础命令，不依赖 tar、jq、python、rsync。

### 7.1 `scripts/precheck.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail

install_root="${1:-${INSTALL_ROOT:-/opt/lianruan-crm-v3}}"
script_dir="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
package_root="$(cd "${script_dir}/.." && pwd)"

失败() {
  echo "预检查失败：$*" >&2
  exit 1
}

提示() {
  echo "预检查：$*"
}

[ "$(id -u)" -eq 0 ] || 失败 "请使用 root 或 sudo 执行。"
[ "$(uname -m)" = "x86_64" ] || 失败 "当前架构不是 x86_64。"

if [ -f /etc/os-release ] && ! grep -Eiq 'openEuler|Euler' /etc/os-release; then
  echo "提示：当前系统未检测到欧拉标识，请确认兼容性。"
fi

command -v unzip >/dev/null 2>&1 || 失败 "未找到 unzip。"
command -v zip >/dev/null 2>&1 || 失败 "未找到 zip。"
command -v sha256sum >/dev/null 2>&1 || 失败 "未找到 sha256sum。"
command -v docker >/dev/null 2>&1 || 失败 "未找到 docker。"
docker compose version >/dev/null 2>&1 || 失败 "未找到 docker compose。"

[ -d "${install_root}" ] || 失败 "安装目录不存在：${install_root}"
[ -f "${install_root}/compose/docker-compose.yml" ] || 失败 "未找到 V3 Compose 文件。"
[ -f "${install_root}/config/v3.env" ] || 失败 "未找到 V3 环境配置。"
grep -q 'lianruan_crm_v3' "${install_root}/config/v3.env" || 失败 "当前目录不像 V3 生产目录。"

if [ -f "${package_root}/manifest/SHA256SUMS" ]; then
  (cd "${package_root}" && sha256sum -c manifest/SHA256SUMS)
fi

cd "${install_root}/compose"
docker compose ps >/dev/null

提示 "通过。安装目录：${install_root}"
```

### 7.2 `scripts/upgrade.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail

install_root="${1:-${INSTALL_ROOT:-/opt/lianruan-crm-v3}}"
script_dir="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
package_root="$(cd "${script_dir}/.." && pwd)"
meta_file="${package_root}/manifest/KB元数据.env"

if [ -f "${meta_file}" ]; then
  set -a
  # shellcheck disable=SC1090
  . "${meta_file}"
  set +a
fi

kb_id="${KB_ID:-KB-UNKNOWN}"
target_version="${TARGET_VERSION:-unknown}"
timestamp="$(date '+%Y%m%d-%H%M%S')"
log_dir="${install_root}/logs/install"
log_file="${log_dir}/${kb_id}-${timestamp}.log"
release_dir="${install_root}/releases/${target_version}-pre-${timestamp}"

mkdir -p "${log_dir}"
exec > >(tee -a "${log_file}") 2>&1

失败处理() {
  local exit_code="$1"
  echo "KB 升级失败，退出码：${exit_code}"
  echo "升级日志：${log_file}"
  echo "如需回退应用配置，可执行：bash ${script_dir}/rollback.sh ${install_root} ${release_dir}"
}
trap '失败处理 $?' ERR

echo "开始执行 ${kb_id}，目标版本：${target_version}"

bash "${script_dir}/precheck.sh" "${install_root}"

backup_dir="${install_root}/backups/local/${timestamp}-${kb_id}-preupgrade"
mkdir -p "${backup_dir}"

备份目录为zip() {
  local source_dir="$1"
  local output_file="$2"
  local parent_dir
  local source_name
  parent_dir="$(dirname "${source_dir}")"
  source_name="$(basename "${source_dir}")"
  [ -d "${source_dir}" ] || mkdir -p "${source_dir}"
  (cd "${parent_dir}" && zip -qr -X "${output_file}" "${source_name}")
}

echo "执行升级前 ZIP 备份：${backup_dir}"
cd "${install_root}/compose"
docker compose exec -T postgres pg_dump -U lianruan_app -d lianruan_crm_v3 > "${backup_dir}/postgres.sql"
备份目录为zip "${install_root}/data/uploads" "${backup_dir}/uploads.zip"
备份目录为zip "${install_root}/data/exports" "${backup_dir}/exports.zip"

echo "保存当前应用配置快照：${release_dir}"
mkdir -p "${release_dir}/compose" "${release_dir}/config" "${release_dir}/scripts"
cp "${install_root}/compose/docker-compose.yml" "${release_dir}/compose/docker-compose.yml"
cp "${install_root}/config/v3.env" "${release_dir}/config/v3.env"
[ -f "${install_root}/config/deploy.env" ] && cp "${install_root}/config/deploy.env" "${release_dir}/config/deploy.env"
[ -f "${install_root}/config/nginx/default.conf" ] && mkdir -p "${release_dir}/config/nginx" && cp "${install_root}/config/nginx/default.conf" "${release_dir}/config/nginx/default.conf"
cp "${install_root}/scripts/"*.sh "${release_dir}/scripts/" 2>/dev/null || true

cd "${install_root}/compose"

echo "停止受影响服务。"
docker compose stop nginx || true
docker compose stop api-1 api-2 worker || true

if [ -d "${package_root}/images" ] && ls "${package_root}/images/"*.docker-image >/dev/null 2>&1; then
  echo "加载 KB 镜像。"
  for image_file in "${package_root}/images/"*.docker-image; do
    docker load -i "${image_file}"
  done
fi

if [ -d "${package_root}/files/compose" ]; then
  echo "更新 Compose 文件。"
  cp "${package_root}/files/compose/docker-compose.yml" "${install_root}/compose/docker-compose.yml"
fi

if [ -d "${package_root}/files/config/nginx" ]; then
  echo "更新 Nginx 配置。"
  mkdir -p "${install_root}/config/nginx"
  cp "${package_root}/files/config/nginx/default.conf" "${install_root}/config/nginx/default.conf"
fi

if [ -d "${package_root}/files/scripts" ]; then
  echo "更新运维脚本。"
  cp "${package_root}/files/scripts/"*.sh "${install_root}/scripts/"
  chmod 750 "${install_root}/scripts/"*.sh
fi

if [ -d "${package_root}/database/migrations" ]; then
  echo "同步数据库迁移文件。"
  mkdir -p "${install_root}/database/migrations"
  cp "${package_root}/database/migrations/"*.sql "${install_root}/database/migrations/" 2>/dev/null || true
fi

if [ "${target_version}" != "unknown" ]; then
  echo "同步版本变量。"
  if grep -q '^V3_IMAGE_TAG=' "${install_root}/compose/.env"; then
    sed -i "s#^V3_IMAGE_TAG=.*#V3_IMAGE_TAG=${target_version}#" "${install_root}/compose/.env"
  else
    printf 'V3_IMAGE_TAG=%s\n' "${target_version}" >> "${install_root}/compose/.env"
  fi
  sed -i "s#^V3_BUILD_VERSION=.*#V3_BUILD_VERSION=${target_version}#" "${install_root}/config/v3.env"
fi

echo "执行数据库迁移。"
INSTALL_ROOT="${install_root}" "${install_root}/scripts/migrate-db.sh"

echo "启动服务。"
docker compose up -d api-1 api-2 worker nginx

echo "执行健康检查。"
INSTALL_ROOT="${install_root}" "${install_root}/scripts/health-check.sh"

if [ -x "${package_root}/tests/smoke.sh" ]; then
  echo "执行 KB 冒烟测试。"
  bash "${package_root}/tests/smoke.sh" "${install_root}"
fi

echo "KB 升级完成。"
echo "升级日志：${log_file}"
echo "升级前配置快照：${release_dir}"
```

### 7.3 `scripts/rollback.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail

install_root="${1:-${INSTALL_ROOT:-/opt/lianruan-crm-v3}}"

  exit 1
```

## 十二、不同修复场景的包内容

### 12.1 只修 API

包内应包含：

```text
images/lianruan-crm-v3-api-目标版本.docker-image
scripts/
manifest/
tests/
```

停启服务：

```text
nginx、api-1、api-2
```

### 12.2 只修前端工程化页面

包内应包含：

```text
images/lianruan-crm-v3-nginx-目标版本.docker-image
scripts/
manifest/
tests/
```

停启服务：

```text
nginx
```

如果 Nginx 镜像中已打入前端产物，必须重新构建 Web 镜像，不建议在生产容器里直接覆盖静态文件。

### 12.3 修 `apps/web/public` 旧静态入口

这仍属于 V3 部署产物的一部分，但必须在 KB 说明中写清楚：

```text
修复目标是 V3 包内保留的旧入口静态资产，不是修改 V2 旧系统 frontend/。
```

推荐仍重新构建 Nginx Web 镜像。

### 12.4 修数据库结构或数据

包内应包含：

```text
database/migrations/YYYYMMDD_KB_编号_说明.sql
scripts/
manifest/
tests/
```

必须：

1. 升级前备份。
2. 停止 API 和 Worker 写入。
3. 执行 SQL。
4. 执行数量和业务样本核验。
5. 说明数据库不自动回滚。

### 12.5 修部署脚本或 Nginx 配置

包内应包含：

```text
files/scripts/
files/config/nginx/
scripts/
manifest/
```

必须保存原配置快照，并在回退脚本中恢复。

## 十三、禁止使用的旧 V2 升级包模式

仓库中存在 V2 历史升级包，例如：

```text
upgrade-package/
company-search-upgrade/
deliverables/lianruan-crm-account-admin-fix-*.tar.gz
```

这些只能作为历史参考，不能作为 V3 生产升级规范。

V3 不能再使用以下 V2 思路：

```text
复制 files/server.js 到 backend/server.js
复制 files/admin-app.js 到 frontend/admin-app.js
pkill node 服务
nohup node server.js
python -m http.server 8080
tar.gz 发包
```

V3 必须使用：

```text
Docker 镜像
Docker Compose
PostgreSQL 迁移
V3 备份脚本
V3 健康检查
ZIP 包
```

## 十四、建议后续补充的自动制包脚本

建议后续新增：
