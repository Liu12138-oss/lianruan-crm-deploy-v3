# 旧前端组件拆分边界建议

生成时间：2026-07-23

## 1. 拆分原则

- 先按业务模块拆，不按旧文件行号机械切。
- 先迁移可验证页面，不做万能表格、万能表单和低代码配置。
- 管理端、渠道端共享业务组件，差异放在工作空间适配层。
- 移动端不直接复用桌面表格，只复用领域客户端、状态字典、金额和状态展示函数。
- 旧视觉习惯保留，明显溢出和不可点击问题在迁移时修正。

## 7. 公共组件边界

| 公共组件 | 使用模块 | 不应承担的职责 |
| --- | --- | --- |
| `ServerTable` | 列表页 | 不拼接口路径，不保存业务筛选语义 |
| `FilterBar` | 列表页 | 不知道角色和数据范围 |
| `DetailDrawer` | 详情页 | 不直接发业务请求 |
| `ConfirmActionDialog` | 审批、删除、状态变更 | 不决定动作是否可用 |
| `ReasonTextarea` | 驳回、调价、审批 | 不内置原因字典，字典由服务端提供 |
| `MoneyText` | 报价、订单、统计 | 不计算最终金额 |
| `StatusTag` | 全模块 | 不只依赖颜色表达状态 |
| `UploadTaskPanel` | 导入导出 | 不同步执行大文件导入 |
| `PermissionGate` | 按钮和页面 | 只控制体验，不替代后端权限 |

## 8. 组合函数边界

| 组合函数 | 职责 | 适用模块 |
| --- | --- | --- |
| `useServerList` | 分页、筛选、排序、取消过期请求 | 报备、商机、报价、订单、渠道、账号 |
| `useEntityDetail` | 详情加载、刷新、404、403、冲突提示 | 全业务详情 |
| `useSubmitAction` | 提交中、防重复、错误映射、成功刷新 | 创建、编辑、审批、状态变更 |
| `useIdempotencyKey` | 写请求幂等键生成和生命周期 | 报价、订单、移动写入 |
| `useQuotePreview` | 服务端试算、工作量预览、错误显示 | 报价 |
| `useWorkspacePermission` | 当前工作空间权限读取和按钮可见性 | 管理、渠道、移动 |
| `useUnsavedGuard` | 未保存离开确认 | 表单和编辑页 |

## 9. 拆分顺序

1. 先迁移客户端、错误模型、布局和路由守卫。
2. 再迁移不改变业务状态的只读列表和详情。
3. 再迁移创建、编辑、审批、状态变更。
4. 最后迁移导入导出、报价编辑器、移动写入等高风险页面。

## 10. 需要保留的旧行为

- 管理端、渠道端的主要导航结构和用户认知不变。
- 报备、商机、报价、订单的字段、状态中文名和操作入口不新增。
- 移动端二期未发布写契约时，写入口继续关闭。
- 旧静态前端保留到阶段8稳定期结束。
