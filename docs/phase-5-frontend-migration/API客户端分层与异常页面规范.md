# API客户端分层与异常页面规范

生成时间：2026-07-23

## 1. 目标

阶段5的新前端只通过统一客户端访问后端。页面不得直接拼接生产接口地址，不得自行追加操作者、角色、区域、渠道等身份字段，不得长期保存令牌。

## 2. 当前问题基线

| 文件 | 直接 `fetch` | `apiRequest` | `apiClient` 调用 | `localStorage` | 风险 |
| --- | ---: | ---: | ---: | ---: | --- |
| `frontend/admin-app.js` | 55 | 75 | 56 | 15 | 管理页面内仍有散落接口调用和本地身份恢复 |
| `frontend/partner-app.js` | 24 | 13 | 46 | 20 | 渠道页面依赖本地前缀身份和渠道参数 |
| `frontend/mobile-app.js` | 1 | 0 | 3 | 10 | 移动一期有本地会话和手写页面状态 |
| `frontend/mobile-v2-app.js` | 0 | 0 | 0 | 0 | 业务渲染和状态在单文件中，需要迁入模块 |
| `frontend/api-client.js` | 40 | 0 | 0 | 18 | 会按当前用户角色拼 `operatorId`、`operatorRole`、`region`、`partnerId` |
| `frontend/mobile-v2-api.js` | 1 | 0 | 0 | 3 | 有写契约和幂等键雏形，但仍使用二期临时会话 |

## 3. 目标分层

```text
api/
├── client.ts              # 统一请求、超时、请求编号、错误映射
├── errors.ts              # 中文错误模型
├── session.ts             # 会话读取、刷新、退出
├── upload.ts              # 上传、下载、进度、取消
├── contracts.ts           # 契约生成类型入口
└── modules/
    ├── account.ts
    ├── partner.ts
    ├── registration.ts
    ├── opportunity.ts
    ├── quotation.ts
    ├── order.ts
    ├── catalog.ts
    ├── notification.ts
    ├── audit.ts
    └── openApi.ts
```

## 4. 请求客户端要求

| 能力 | 阶段5要求 | 验收方式 |
| --- | --- | --- |
| 基础地址 | 只允许来自环境配置或同源反向代理，不在页面写死 `localhost:3000` 或生产域名 | 全工程搜索 |
| 会话 | 使用服务端同源安全 Cookie；页面刷新后调用会话接口恢复 | 修改本地存储不能恢复越权身份 |
| 请求编号 | 每个请求生成或读取 `X-Request-Id`，错误页展示可复制编号 | 前后端日志可关联 |
| 超时 | 默认 15 秒，导入导出和下载按任务接口单独设置 | 模拟超时 |
| 取消 | 列表筛选切换取消过期请求 | 快速切筛选无旧结果覆盖 |
| 幂等 | 写请求由客户端生成幂等键，服务端最终校验 | 重复点击只产生一次有效业务结果 |
| 上传下载 | 使用专用客户端，支持进度、取消、权限错误和任务结果下载 | 导入预览和执行流程 |
| 脱敏日志 | 控制台和上报不记录密码、令牌、密钥、完整客户资料 | 构建后检查 |

## 5. 业务客户端模块

| 模块 | 客户端文件 | 页面只允许调用的方法类型 |
| --- | --- | --- |
| 会话 | `session.ts` | `login`、`logout`、`getCurrentSession`、`switchWorkspace` |
| 工作空间 | `workspace.ts` | `getWorkspaces`、`getPermissions`、`getNavigation` |
| 报备 | `registration.ts` | 列表、详情、创建、修改、查重、审核、导入任务 |
| 商机 | `opportunity.ts` | 列表、详情、创建、修改、阶段推进、跟进、漏斗 |
| 报价 | `quotation.ts` | 列表、详情、服务端预览、创建、修改、确认、折扣审核 |
| 订单 | `order.ts` | 列表、详情、转单、一级确认、驳回、调价、履约 |
| 渠道 | `partner.ts` | 列表、详情、成员、档案、层级、审批 |
| 账号 | `account.ts` | 列表、创建、修改、状态、密码重置、导入任务 |
| 产品 | `catalog.ts` | 目录、分类、模块、功能、硬件、套餐、发布、工作量 |
| 通知 | `notification.ts` | 当前用户通知、已读、全部已读 |
| 系统 | `audit.ts`、`openApi.ts` | 审计、开放接口客户端、文档、日志 |

## 6. 禁止从页面传递的字段

| 字段类型 | 旧代码示例 | 阶段5处理 |
| --- | --- | --- |
| 操作者身份 | `operatorId`、`operatorName`、`operatorRole`、`operatedBy` | 由服务端会话确定 |
| 数据范围 | `region`、`bigRegion`、`partnerId`、`userId` | 作为筛选项时必须由服务端白名单校验，不能作为授权依据 |
| 价格结果 | `totalAmount`、`taxAmount`、`discountAmount`、价格版本 | 前端只展示服务端预览，提交时服务端重算 |
| 状态动作权限 | 前端根据 `role` 和状态自行判断 | 服务端返回可执行动作集合，前端只渲染 |
| 密码和密钥 | 密码、客户端密钥、令牌 | 不进入日志、地址、本地长期存储和错误上报 |

## 7. 错误模型

| HTTP状态 | 统一前端行为 | 用户提示要求 |
| --- | --- | --- |
| 400 | 表单或请求参数错误 | 指向具体字段或操作，不显示内部字段名 |
| 401 | 跳转会话失效页，清理敏感本地状态 | “登录已失效，请重新登录” |
| 403 | 显示无权限页或禁用操作 | “当前账号无权执行此操作”并给出返回入口 |
| 404 | 显示数据不存在页 | “数据不存在或已被删除” |
| 409 | 显示冲突提示，保留用户未提交内容 | “数据已被其他人修改，请刷新后重试” |
| 422 | 显示业务规则校验失败 | 使用服务端中文原因 |
| 429 | 显示请求过于频繁 | 提示稍后重试 |
| 500及以上 | 显示系统异常页 | 展示请求编号，提示联系管理员 |
| 网络超时 | 显示可重试状态 | 不自动重复写请求 |
| 维护中 | 显示维护页 | 展示维护时间、影响范围和刷新入口 |

## 8. 异常页面要求

### 8.1 会话失效页

- 清理内存会话和敏感本地状态。
- 保留原访问地址，重新登录后可按服务端允许范围跳回。
- 不读取旧 `admin_auth_token`、`partner_auth_token` 恢复身份。

### 8.2 无权限页

- 显示当前工作空间和页面名称。
- 提供返回工作台按钮。
- 不暴露“需要什么权限码”的内部细节给普通用户。

### 8.3 数据不存在页

- 适用于详情页、编辑页、审批对象。
- 提供返回列表和刷新按钮。
- 404 与 403 必须区分，避免越权数据被误提示为存在。

### 8.4 冲突页或冲突提示

- 适用于编辑、审批、状态变更和报价订单操作。
- 保留用户填写内容。
- 展示服务端返回的对象版本或更新时间说明。

### 8.5 维护页

- 适用于后端维护、迁移窗口、只读模式。
- 展示维护开始时间、预计结束时间、影响范围和联系电话字段。
- 写操作应在页面层禁用，读页面显示只读提示。

## 9. 路由守卫要求

1. 首次进入非公开路由时调用会话接口。
2. 根据服务端返回工作空间决定进入管理、渠道或移动空间。
3. 根据服务端导航清单生成菜单，不在前端写死角色菜单。
4. 深链进入页面时先确认页面权限，再加载业务数据。
5. 页面按钮隐藏只负责体验，接口仍必须拒绝无权限请求。

## 10. 构建检查要求

阶段5每次迁移合并前必须检查：

- 不存在新增硬编码生产地址。
- 不存在新增 `localStorage` 长期保存令牌。
- 不存在页面直接传 `operatorRole`、`operatorId` 作为授权依据。
- 不存在页面直接提交最终金额或价格版本。
- 不存在 `console.log` 输出用户资料、客户资料、密钥和响应体。
- 新增页面均有 401、403、404、409、500、维护中状态验收。
