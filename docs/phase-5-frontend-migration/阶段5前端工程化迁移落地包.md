# 阶段5前端工程化迁移落地包

生成时间：2026-07-23

## 1. 执行边界

本落地包只服务阶段5前端工程化迁移准备，不修改历史页面业务逻辑，不重做视觉，不新增公海池或其他新功能。阶段1前端工程骨架、阶段3认证权限、阶段4领域接口尚未稳定前，不直接抢跑完整 Vue 3 重构。

当前迁移目标是把旧静态前端拆成可排期、可验收、可回退的开发资产，等待工程骨架合入后按批次实施。

## 5. 状态迁移原则

| 状态来源 | 当前问题 | 阶段5目标 |
| --- | --- | --- |
| `localStorage` 用户与令牌 | 管理端、渠道端使用不同前缀恢复身份，仍可被本地修改 | 统一从服务端会话恢复身份，本地只保存非敏感偏好 |
| 前端角色过滤 | `api-client.js` 会按 `role`、`region`、`partnerId` 拼参数 | 前端只传筛选条件，不传操作者身份和数据范围 |
| 模块级 store | 旧脚本全局 `store` 混合页面数据、用户、通知和业务状态 | Pinia 按 `session`、`workspace`、`dictionary`、业务模块拆分 |
| 表单状态 | 大表单在组件内混合价格、工作量、产品、提交状态 | 表单状态、服务端预览、提交幂等键分层管理 |
| 移动二期写状态 | 已有 `idempotencyKeys` 和写契约保护 | 保留思想，迁入统一客户端和模块 store |

## 6. 阶段5准入和禁止项

- 未拿到阶段1工程骨架，不创建正式 `apps/web` 业务实现。
- 未拿到阶段3会话接口，不实现最终路由守卫。
- 未拿到阶段4领域接口，不迁移对应页面到生产入口。
- 不复制旧前端的前端身份字段信任逻辑。
- 不删除旧静态页面，旧页面保留到阶段8稳定期结束。
- 不新增菜单和业务能力，不把移动端关闭能力顺手打开。
