## 1. 执行结论

V3 可以建设 MCP，但必须将 MCP 定位为“受控协议适配层”，而不是新的业务系统、权限系统、流程引擎或数据库查询入口。

首期建议只建设业务只读 MCP，并遵守以下结论：

1. MCP 独立进程、独立开关、独立限流、独立健康检查；停掉 MCP 后，V3 登录、页面、接口、任务和业务流程必须继续正常运行。
2. MCP 不直接连接业务主库，不执行任意 SQL，不调用现有写接口，不改变任何业务状态。
3. MCP 不创建独立业务角色；首期同时支持内部人员和渠道人员，每次调用都映射到 `iam.users` 中的真实用户，并实时复用 V3 功能权限、数据范围和字段权限。首期不实现双重身份切换；用户存在多个身份且无法唯一解析时拒绝调用。
4. 工具列表也属于授权结果。用户只能看到和调用自己有权使用的工具，不能依赖“调用后再报错”作为唯一保护。
5. 超级管理员不会因为平台身份自动获得全部业务数据。其查看业务数据仍需要显式业务权限和显式数据范围。
6. 首期不提供创建、修改、审批、收款、领取、分配、导出、附件下载等写入或高风险能力。
7. 现有 OpenAPI 绑定用户未进入查询数据范围计算，现有部分业务接口仍存在兼容身份兜底。两项必须作为独立的生产前置门禁先收口、先回归、先发布；不得把修复混入 MCP 上线包。
8. 阶段一只建设不读取真实业务数据的协议骨架、健康检查和模拟数据工具；阶段二通过权限门禁后才开放真实只读工具。

### 1.1 推荐建设形态

```text
MCP客户端
    ↓
HTTPS反向代理和连接保护
    ↓
独立MCP适配服务
    ↓
V3可信身份和授权主体
    ↓
MCP专用只读内部接口
    ↓
现有领域服务或受控分析视图
    ↓
V3业务事实
```

已批准在 V3 主线新增 `apps/mcp`。该应用只负责协议、会话、工具编排、输入输出校验和调用审计；业务事实、权限判断和数据范围仍由 `apps/api` 负责。

本项目首期本地验收客户端固定为“赤兔 RedClaw”：优先使用 stdio 启动 `apps/mcp`；若 RedClaw 仅支持远程地址，再使用本机 HTTPS 或受控本地 Streamable HTTP。其他客户端不纳入首期兼容承诺。

## 2. 产品目标、非目标和红线

### 2.1 产品目标

- 让用户通过支持 MCP 的模型客户端查询自己在 V3 中原本就有权查看的信息。
- 同一问题由不同用户提出时，返回内容按照其唯一主身份、角色、数据范围和字段权限产生差异。
- 返回结构化、可追溯、有口径、有时间范围、有 V3 页面链接的结果。
- 让 MCP 成为 V3 分析智能底座可复用的工具入口，而不是形成新的旁路数据通道。
- 支持按用户、客户端、工具集和单个工具灰度开放，并可以随时关闭。

### 2.2 首期非目标

- 不建设自由问答模型网关、联网检索、大屏和企微机器人完整产品。
- 不建设通用数据库管理工具。
- 不把所有现有 OpenAPI 自动转换为 MCP 工具。
- 不允许模型决定角色、权限、数据范围、审批人或业务状态。
- 不提供批量导出、附件正文、合同正文、完整联系方式和凭据读取。
- 不提供任何写入、审批和状态流转工具。
- 不改变现有四套正式页面、统一入口、登录落点和页面会话。

### 2.3 强制红线

| 红线 | 强制要求 |
| --- | --- |
| 业务无侵入 | MCP 关闭或故障时，既有业务页面、API、Worker 和数据库事务不受影响 |
| 身份可信 | 禁止信任请求中的用户名、角色、`operatorId`、`x-v3-delivery-user` 或模型自报身份 |
| 权限复用 | 工具权限不能替代底层业务权限；两者必须同时通过 |
| 范围复用 | 列表、详情、统计和链接必须使用同一数据范围策略 |
| 默认拒绝 | 无身份、停用账号、授权版本失效、主身份不清或工具未授权时一律拒绝 |
| 首期只读 | MCP 进程、专用接口和数据库账号均不得具备业务写能力 |
| 禁止任意查询 | 不接受 SQL、表名、字段名、排序表达式或原始过滤语法透传 |
| 高敏回系统 | 高敏明细、附件、完整正文和批量结果返回 V3 受控页面链接 |
| 可审计 | 每次连接、工具发现、调用、拒绝、异常和结果摘要均可追溯 |
| 可停止 | 具备总开关、客户端开关、人员灰度和工具开关，关闭不依赖数据库回退 |

## 3. 现状基础与生产前置门禁

### 3.1 可复用基础

- Node.js 22、TypeScript、工作区和 Express 技术栈适合使用官方 MCP TypeScript SDK。
- `iam`、`org`、`channel` 已具备用户、角色、权限、组织、区域和渠道基础数据。
- 业务数据服务已有部分角色和数据范围计算逻辑。
- `audit.audit_logs`、OpenAPI 调用日志、请求编号和结构化日志可以扩展 MCP 审计。
- PostgreSQL、Redis、BullMQ 和单机 Compose 可以承载独立会话、限流和后续异步分析任务。
- `packages/contracts` 可以作为 MCP 工具输入输出契约的唯一来源。

### 3.2 当前阻断项

| 编号 | 阻断项 | 当前风险 | MCP生产要求 |
| --- | --- | --- | --- |
| P0-01 | 业务接口没有统一可信身份中间件 | 兼容请求头或参数可能参与身份推导 | 独立完成可信身份收口并通过四端回归 |
| P0-02 | OpenAPI查询没有传入绑定用户上下文 | 资源权限通过后仍可能读取范围外数据 | 修复并增加跨区域、跨渠道、跨人员负向测试 |
| P0-03 | 空用户上下文对多数模块默认返回全量条件 | 匿名或上下文丢失时可能扩大范围 | 改为默认拒绝，且不得改变明确公开接口 |
| P0-04 | 运行时功能权限尚未统一覆盖全部业务路由 | 页面菜单和角色名称可能被误当成权限 | 建成服务端权限判断并提供稳定权限代码 |
| P0-05 | OpenAPI契约与实际业务路由覆盖不完整 | 自动生成工具可能产生错误或越权映射 | 先补专用只读契约，不从现状全量生成 |
| P0-06 | 当前生产入口仍可能使用 HTTP | 远程令牌和业务结果可能被截获 | 远程 MCP 上线前必须完成 HTTPS |
| P0-07 | `iam.data_scope_bindings` 尚未接入既有业务运行时 | 配置界面的资源范围可能与实际查询范围不一致 | 确定唯一运行时范围来源，完成影子比对后再切换 |
| P0-08 | OpenAPI资源未配置时可能回退为 `*` | 空配置被解释为全资源，违反默认拒绝 | 改为未配置即无资源，并完成存量客户端影响核查 |

只读调研证据定位：

- `apps/api/src/business-routes.ts:623`：OpenAPI 查询在校验资源后调用列表服务，但未传入已绑定用户。
- `apps/api/src/business-store.ts:1252`：用户上下文为空时，除通知外返回全量查询条件。
- `apps/api/src/business-routes.ts:1044`：当前业务用户仍可能来自 V2 令牌、兼容请求头和 `operatorId`。
- `database/migrations/20260815_S10_005_组织数据范围与离职安全闭环.sql:46`：迁移注释明确说明资源级范围尚未接入既有业务运行时。
- `apps/api/src/business-store.ts:3095` 和 `apps/api/src/business-store.ts:3838`：资源为空时存在回退为 `*` 的路径。

### 3.3 门禁处理原则

- P0 门禁作为独立需求、独立提交、独立测试、独立升级包和独立验收处理。
- P0 修复不能以 MCP 为由改变客户报备、商机、报价、订单、渠道和账号的现有业务规则。
- 如果 P0 修复可能影响 V2 兼容调用，必须先观察身份来源，按接口分批切换，并保留一个发布窗口的兼容策略。
- 数据范围运行时切换前必须使用同一用户、同一资源、同一数据快照进行影子比对；差异由业务负责人确认，禁止静默扩大范围。
- OpenAPI默认拒绝改造前必须盘点存量客户端及其明确资源配置，避免用安全修复名义意外中断合法调用。
- P0 未全部通过时，`V3_MCP_ENABLED` 必须保持关闭，真实业务工具不得注册。

## 4. 用户、场景与产品边界

### 4.1 用户类型

MCP 不新增业务角色。以下仅表示需要覆盖的验收用户类型，不构成新的角色定义：

| 用户类型 | 典型诉求 | 授权原则 |
| --- | --- | --- |
| 超级管理员 | 平台配置、审计、故障定位 | 平台权限和业务权限分离，不自动获得业务经办数据 |
| 区域管理员 | 查看本区域渠道和业务汇总 | 只允许绑定区域树及其显式业务资源 |
| 渠道管理员 | 查看本渠道人员和业务 | 只允许本渠道或明确授权的渠道树 |
| 渠道员工 | 查询本人负责的报备、商机、报价和订单 | 默认本人范围，按业务授权扩展 |
| 销售或业务负责人 | 查询授权组织或团队业务 | 使用现有组织树、团队和对象负责人关系 |
| 审计人员 | 查看 MCP 调用和拒绝记录 | 只读审计权限，不等于业务明细权限 |
| MCP平台运维人员 | 查看进程、连接和非敏感指标 | 不因运维身份获得业务数据权限 |

### 4.2 首期使用场景

1. 用户查询自己可见的待处理客户报备。
2. 用户按客户、状态、时间范围查询自己可见的商机。
3. 用户查询自己有权查看的报价或订单摘要。
4. 用户查询产品、功能、硬件、套餐和工作量规则的已授权公开字段。
5. 用户读取单条业务摘要，并获得 V3 对应页面链接继续办理。
6. 用户询问“我为什么看不到某条数据”时，只返回权限类型和范围摘要，不泄露目标是否存在。
7. 审计人员按请求编号查看 MCP 调用结果摘要，不查看模型对话全文和敏感业务结果。

### 4.3 延后场景

- 经营指标和趋势分析：待分析视图、指标口径和快照完成后进入后续阶段。
- 企微私聊和群聊：待企微身份映射、群成员范围和消息底座完成后进入后续阶段。
- 写入、审批和状态变更：不进入首期；是否建设必须另行立项和业务签字。

## 5. 权限产品设计

### 5.1 总体授权公式

```text
允许一次MCP工具调用
  = MCP功能已开启
  且 客户端已批准
  且 用户会话有效
  且 账号和授权版本有效
  且 当前唯一有效主身份明确
  且 用户具备MCP接入权限
  且 用户具备工具所需业务权限
  且 查询目标位于该资源的数据范围
  且 返回字段通过字段权限策略
  且 场景、频率、数量和敏感级别允许
```

任何条件缺失都不能降级为共享账号、匿名账号、默认管理员或全量范围。

### 5.2 权限分层

| 层级 | 负责内容 | 示例 |
| --- | --- | --- |
| 接入权限 | 是否允许连接 MCP | `integration.mcp.connect` |
| 客户端权限 | 某客户端是否允许某用户使用 | 内部批准客户端、试点人员白名单 |
| 工具权限 | 是否向用户展示和允许调用某工具 | 工具策略声明所需业务权限 |
| 业务功能权限 | 用户能否查看对应业务对象 | 报备读取、商机读取、报价读取、订单读取 |
| 数据范围 | 能查看哪些对象 | 总部、组织树、区域、渠道、本人 |
| 字段权限 | 每个对象能返回哪些字段 | 完整、摘要、脱敏、拒绝 |
| 场景权限 | 在什么入口和会话环境中允许 | 内部客户端、私聊、受控测试环境 |
| 操作权限 | 是否允许写入 | 首期固定为禁止 |

建议新增的 MCP 管理权限代码如下，最终代码必须在业务基线和契约中确认：

- `integration.mcp.connect`
- `integration.mcp.client.manage`
- `integration.mcp.tool_policy.manage`
- `integration.mcp.audit.read`
- `integration.mcp.operations.read`

业务工具继续要求原业务域读取权限，不用 MCP 权限替代。例如报备查询必须同时满足 `integration.mcp.connect` 和最终确认的报备读取权限。

### 5.3 工具可见性

- `tools/list` 根据当前用户、客户端、唯一主身份和功能开关动态过滤。
- 未授权工具不出现在列表中；直接构造工具名称调用仍要再次校验。
- 工具集和单工具均采用显式允许清单，禁止“默认开放全部”。
- 新工具默认 `disabled`，只有契约、权限、测试和评审全部通过后才能灰度启用。
- 工具说明中不得包含其他角色才有权知道的字段和业务能力。

### 5.4 数据范围

每个资源独立计算数据范围，禁止把一个模块的全量范围借给另一个模块。

| 范围类型 | 说明 |
| --- | --- |
| 总部范围 | 显式授权的全量范围，不因超级管理员身份自动获得 |
| 组织树范围 | 主任职或授权组织及下级组织 |
| 区域范围 | 用户绑定区域及按规则允许的下级区域 |
| 渠道范围 | 当前渠道或显式授权渠道树 |
| 本人范围 | 本人负责、创建、经办或流程待办对象 |
| 自定义范围 | 经过平台配置和审计的特定对象集合 |

首期不实现双重身份选择或切换。每次调用只接受服务端解析出的一个唯一有效主身份：内部账号按内部身份授权，渠道账号按渠道身份授权。若存在多个有效身份、多个渠道成员关系或主身份无法唯一解析，直接拒绝业务工具调用，禁止合并两域权限和数据范围。

### 5.5 字段权限

| 字段级别 | MCP返回策略 |
| --- | --- |
| 普通业务字段 | 按业务权限返回 |
| 联系人、手机、邮箱 | 首期默认脱敏；确需完整显示必须另行确认 |
| 报价成本、底价、折扣 | 仅价格授权角色返回，其他用户隐藏或返回摘要 |
| 合同金额、收款信息 | 不进入首期工具；后续按合同和财务权限单独设计 |
| 正文、附件、凭据 | 不返回内容，只返回受控 V3 页面链接或固定拒绝 |
| 审计前后值 | 按审计权限脱敏返回，不提供批量下载 |

字段策略必须由服务端执行。模型提示词、工具描述和客户端展示不能承担字段脱敏责任。

### 5.6 建议权限矩阵

下表是首期产品建议，不是现有角色的静态授权。最终是否允许由运行时权限代码和数据范围决定。

| 能力 | 超级管理员 | 区域管理员 | 渠道管理员 | 渠道员工 | 审计人员 | MCP运维 |
| --- | --- | --- | --- | --- | --- | --- |
| 连接 MCP | 显式授权 | 显式授权 | 显式授权 | 试点授权 | 显式授权 | 显式授权 |
| 查询报备 | 需业务读取权限 | 区域范围 | 渠道范围 | 本人范围 | 默认禁止 | 禁止 |
| 查询商机 | 需业务读取权限 | 区域范围 | 渠道范围 | 本人范围 | 默认禁止 | 禁止 |
| 查询报价和订单摘要 | 需业务读取权限 | 区域范围 | 渠道范围 | 本人范围 | 默认禁止 | 禁止 |

## 6. 首期产品能力与工具清单

### 6.1 工具设计原则

- 一个工具只表达一个稳定业务意图，禁止设计“万能业务查询”工具。
- 输入字段使用严格结构，未知字段默认拒绝。
- 列表工具必须分页、限制最大页大小并返回是否截断。
- 详情工具必须再次执行对象级数据范围和字段权限校验。
- 返回数据包含请求编号、查询口径、数据时间、范围摘要和 V3 页面链接。
- 工具描述、输入契约、输出契约和权限要求均版本化。
- 业务数据中的文本视为不可信内容，不得把其中的指令当成系统指令或下一步操作。

### 6.2 第一批建议工具

| 稳定工具标识 | 中文用途 | 所需能力 | 返回边界 |
| --- | --- | --- | --- |
| `v3_current_context` | 读取当前用户和唯一主身份摘要 | MCP接入权限 | 不返回完整权限明细和敏感绑定信息 |
| `v3_registration_list` | 查询可见报备列表 | 报备读取权限 | 分页、摘要、脱敏字段 |
| `v3_registration_get` | 查询单条报备摘要 | 报备读取权限和对象范围 | 不返回完整联系人和附件 |
| `v3_opportunity_list` | 查询可见商机列表 | 商机读取权限 | 分页、摘要、脱敏字段 |
| `v3_opportunity_get` | 查询单条商机摘要 | 商机读取权限和对象范围 | 不返回范围外关联对象 |
| `v3_quote_list` | 查询可见报价摘要 | 报价读取权限 | 成本和底价按字段权限处理 |
| `v3_quote_get` | 查询单条报价摘要 | 报价读取权限和对象范围 | 不返回完整报价附件 |
| `v3_order_list` | 查询可见订单摘要 | 订单读取权限 | 分页、状态和必要金额摘要 |
| `v3_order_get` | 查询单条订单摘要 | 订单读取权限和对象范围 | 不改变订单状态 |
| `v3_product_search` | 查询产品、功能、硬件和套餐 | 产品读取权限 | 只返回已发布或有权查看的数据 |

### 6.3 暂不注册的工具

- 创建或修改报备、商机、报价和订单。
- 审批、驳回、确认、核销、冲销、领取、回收和分配。
- 批量导入、导出和文件下载。
- 任意 SQL、数据库结构浏览、服务器文件读取和命令执行。
- 密钥、配置、日志原文和未脱敏审计前后值读取。
- 组织、角色、权限和数据范围修改。

### 6.4 统一结果结构

工具结果至少包含：

- `requestId`：V3 请求编号。
- `toolCode` 和 `toolVersion`：工具及版本。
- `dataAsOf`：数据读取时间或快照时间。
- `scopeSummary`：本次使用的范围类型摘要，不返回内部条件表达式。
- `items` 或 `item`：经过权限和字段策略处理后的业务数据。
- `pageInfo`：页码、页大小、是否还有下一页和是否截断。
- `maskedFields`：本次被隐藏或脱敏的字段类别。
- `source`：V3 业务域或指标口径。
- `v3Link`：继续查看或办理的 V3 受控页面链接。

错误结果使用稳定中文错误代码和可执行提示，不返回数据库错误、堆栈、内部地址、令牌和原始第三方响应。

## 7. 用户体验流程

### 7.1 首次连接

1. 用户在批准的 MCP 客户端发起连接。
2. 浏览器打开 V3 授权页，复用现有登录或 IAM 单点登录。
3. V3 展示客户端名称、申请能力、数据使用说明和有效期。
4. V3 确认当前账号的唯一有效主身份；身份无法唯一解析时不签发业务访问令牌。
5. V3 签发短期、可撤销、限定客户端和受众的访问令牌。
6. MCP 返回当前允许的工具列表。

首期不开放任意动态客户端注册。客户端必须先由平台管理员登记和批准。

### 7.2 日常查询

1. 模型根据问题选择用户可见工具。
2. MCP 对输入进行严格校验，并生成请求编号。
3. V3 重新确认用户状态、授权版本、唯一主身份、业务权限和数据范围。
4. 内部只读接口执行受控查询和字段策略。
5. MCP 返回结构化结果、范围摘要和 V3 链接。
6. 调用元数据和结果摘要进入审计，不保存完整敏感结果。

### 7.3 拒绝体验

| 场景 | 用户提示原则 |
| --- | --- |
| 未登录或令牌过期 | 提示重新授权，不泄露令牌校验细节 |
| 无工具权限 | 提示当前账号未获该能力，不显示隐藏工具参数 |
| 超出数据范围 | 使用项目统一的 403 或保护性 404 策略，不确认目标是否存在 |
| 字段受限 | 返回可见摘要并说明部分字段受权限保护 |
| 结果过多 | 返回截断说明和缩小条件建议，不自动全量导出 |
| 服务繁忙 | MCP 主动降级或拒绝，不把压力转移到业务 API |

## 8. 技术架构设计

### 8.1 组件职责

| 组件 | 职责 | 明确禁止 |
| --- | --- | --- |
| `apps/mcp` | MCP协议、连接、授权跳转、工具发现、输入输出校验、内部接口调用、调用审计 | 直接访问业务主库、实现业务状态机、持有超级管理员凭据 |
| `apps/api` | 可信身份、权限、数据范围、字段策略、具体只读查询和 V3 链接 | 信任 MCP 自报权限或范围 |
| `packages/contracts` | 工具定义、输入输出结构、错误码和版本 | 从运行时代码反向猜测契约 |
| `packages/config` | MCP开关、地址、令牌、限流、超时和客户端配置校验 | 提供不安全默认值 |
| `apps/worker` | 后续长耗时分析、指标刷新和评测任务 | 首期简单查询绕到异步任务 |
| PostgreSQL | V3业务事实和增量MCP元数据 | 接受来自 MCP 的任意 SQL |
| Redis | 短期会话、撤销、限流和连接状态 | 保存完整业务结果和敏感正文 |

### 8.2 网络边界

- 本地开发可使用标准输入输出传输，只连接模拟数据或专用测试环境。
- 远程环境使用当前稳定协议支持的流式 HTTP 传输，必须位于 HTTPS 反向代理之后。
- MCP 应用端口默认只在容器内部网络暴露，不直接发布到宿主机公网。
- Nginx 只暴露稳定 MCP 路径和最小授权回调路径；MCP 内部业务接口不对公网代理。
- 非本地绑定必须校验主机白名单、来源白名单、受众、签发方和重放标识。
- MCP 进程使用非特权用户、只读根文件系统和最小文件挂载。

### 8.3 身份和令牌

建议采用“逐用户授权、短期访问令牌、服务端实时授权”的模式：

远程客户端若支持标准授权，推荐采用 OAuth 2.1 授权码模式和 PKCE；具体协议、回调方式及令牌生命周期必须在 RedClaw 兼容测试后定版，不能在客户端尚未确认时直接写死。

1. 用户通过 V3 现有登录能力完成身份确认。
2. 授权服务签发只面向 MCP 的短期令牌。
3. 令牌只保存用户编号、会话编号、客户端编号、受众、签发方、到期时间、授权版本和唯一主身份标识；不保存可切换的多身份集合。
4. 角色、权限和数据范围不以令牌声明作为最终事实，每次工具调用由 V3 服务端重新计算。
5. 用户停用、退出、改密、角色变化、主身份失效或管理员撤销客户端后，旧令牌必须失效。
6. 日志只保存令牌指纹，不保存令牌明文。

候选运行指标为：访问令牌有效期 5 至 15 分钟，停用、离职或撤权后 60 秒内失效。该数值须在目标客户端续期能力、Redis可用性和生产容量测试完成后由产品、安全和运维共同确认。

如果目标客户端不支持上述授权方式，只允许使用经过批准的兼容桥接方案；不得降级为所有用户共享一个业务账号。

### 8.4 内部只读接口

建议在 `apps/api` 增加独立、不可公网访问的 MCP 只读接口组。接口按具体资源定义，不设计通用 SQL 或通用方法调用入口。

建议接口仅表达以下动作：

- 解析当前用户和唯一主身份。
- 查询报备列表和摘要详情。
- 查询商机列表和摘要详情。
- 查询报价列表和摘要详情。
- 查询订单列表和摘要详情。
- 查询产品与工作量公开字段。

每个接口均需执行：服务身份校验、用户令牌校验、权限校验、资源数据范围、字段策略、分页、超时、审计和结果大小限制。

### 8.5 数据模型建议

首期只增加必要的、向前兼容的元数据，不复制业务数据：

| 对象 | 推荐逻辑域 | 用途 |
| --- | --- | --- |
| MCP客户端 | `integration` | 客户端名称、状态、回调地址、允许入口和创建人 |
| MCP授权会话 | `integration` | 会话编号、用户、客户端、唯一主身份、到期和撤销状态 |
| MCP调用记录 | `integration` 或 `audit` | 工具、版本、请求编号、结果、耗时、行数和风险摘要 |
| 工具发布版本 | 代码契约优先 | 工具说明、结构、所需权限、限制和发布版本 |

禁止保存完整模型对话、完整工具返回、密钥、令牌、附件正文和业务对象副本。确需保存问题或回答时，应进入后续 AI 问答专项设计，不由 MCP 接入层自行扩展。

### 8.6 工具注册策略

- 工具以代码和契约显式注册，不扫描业务路由自动暴露。
- 工具按客户关系、报价订单、产品规则、分析指标和平台运维分组。
- 启动时加载发布版本和总开关；每次列举工具时结合用户权限过滤。
- 工具数量保持最小，防止上下文膨胀和模型错误选择。
- 工具升级保留一个发布窗口兼容，破坏性变化使用新工具版本。

### 8.7 查询保护

- 所有过滤条件映射到预定义参数，不接受原始 SQL 和原始过滤表达式。
- 首期建议默认每页 20 条、最大 50 条；最终值由容量测试确认。
- 单次结构化响应建议限制在 256 至 512 千字节，超限返回摘要和游标，不允许以连续翻页规避导出限制。
- 每次工具调用设置独立查询超时、总超时、单用户并发和客户端并发。
- 查询必须命中数据范围索引；禁止先查全量后在 MCP 内存中过滤。
- 达到 API、数据库连接或响应时间阈值时，MCP 熔断并返回繁忙提示。
- 不允许 MCP 重试非幂等操作；首期全部为只读，临时错误只做有限次数退避重试。

## 10. 开发落地方案

### 10.1 阶段一：协议骨架与 RedClaw 模拟验收

目标：不读取真实业务数据，完成可启动、可停止、可被赤兔 RedClaw 发现和调用的 MCP 服务。

建议目录：

```text
apps/mcp
├── src
│   ├── server.ts
│   ├── transports
│   ├── auth
│   ├── tools
│   ├── v3-client
│   ├── audit
│   └── config
└── tests
```

交付项：

- 新增独立工作区、构建、类型检查和测试脚本，接入官方 TypeScript SDK。
- 实现 `server/discover`、`tools/list`、`tools/call`，支持 stdio；Streamable HTTP 仅实现协议骨架且默认关闭。
- 只注册协议自检、服务健康和模拟数据工具，提供固定内部、渠道测试用户夹具。
- 实现主机和来源校验、请求编号、结构化日志、优雅停止和健康检查。
- 配置 `V3_MCP_ENABLED=false` 默认关闭，并使用 MCP Inspector 与 RedClaw 完成协议兼容测试。

退出门禁：MCP 进程可独立启动和停止；RedClaw 能发现并调用模拟工具；不连接业务数据库、不调用真实业务接口、不影响任何 V3 服务。

### 10.2 阶段二：V3可信授权与真实只读工具

目标：先完成权限和身份前置收口，再按人员灰度接入真实 V3 只读工具。

必须独立完成的前置收口：

- OpenAPI 查询传入绑定用户上下文；空用户上下文对受保护资源默认拒绝。
- 隔离 V2 令牌、兼容请求头和 `operatorId` 等不可信身份来源。
- 确定 `iam.data_scope_bindings` 的唯一运行时事实来源并完成影子比对。
- OpenAPI 资源未配置时改为无资源，不回退为 `*`，并完成存量客户端影响核查。
- 完成内部、渠道、区域、本人和跨范围负向测试；上述修复必须独立提交、测试和发布。

真实 MCP 交付项：

- 客户端批准、逐用户授权、短期令牌、撤销、过期和唯一主身份解析。
- `tools/list` 按用户动态过滤，`tools/call` 每次重新校验身份、权限、范围、字段和审计。
- 新增 API 内部 MCP 只读路由、主体断言、固定查询、字段脱敏、分页、超时、限流、截断和错误映射。
- 按顺序开放当前身份、产品、报备、商机、报价和订单工具；每个工具单独完成契约、权限、范围、字段和测试。
- 在 RedClaw 中分别使用内部测试用户和渠道测试用户验证工具列表和结果差异。

退出门禁：未登录、停用、过期、伪造主体、身份不唯一和越权对象全部拒绝；工具列表和数据结果符合用户权限；敏感字段脱敏稳定；V3 登录、页面、业务接口和 Worker 回归通过。

### 10.3 阶段三：隔离部署、RedClaw验收与灰度交付

目标：完成独立部署、RedClaw 全量验收、按人员灰度和一键回退，证明 MCP 不影响 V3 主业务。

交付项：

- MCP 独立镜像、Compose 服务、资源限制和非特权用户。
- HTTPS、Nginx 最小路径、内部网络和健康检查。
- 环境变量模板、凭据文件、启动、停止、诊断和日志保留。
- 升级包、校验值、自检脚本、回退步骤和已知边界。
- 按人员白名单灰度，不按角色一次性全开。
- 业务负载基线、MCP 压力测试、熔断和故障演练。

建议试点至少覆盖一名区域管理员、一名渠道管理员和两名不同渠道或不同负责范围的员工；超级管理员仅在其具备显式业务权限时参与业务查询验收。

### 10.4 后续阶段

- 基于分析视图和指标口径增加固定经营指标工具。
- 与 V3 AI 问答、企微私聊和受控群聊共用同一工具层。
- 只有在只读阶段稳定、业务另行签字、状态机和幂等完整后，才讨论预览式写工具。

## 11. 文件和模块影响范围建议

以下是评审后的建议落点，不代表立即修改授权：

| 位置 | 计划内容 | 对既有业务的保护方式 |
| --- | --- | --- |
| `apps/mcp` | 新增独立 MCP 应用 | 独立进程和默认关闭，不进入现有页面请求链路 |
| `apps/api` | 新增可信授权服务和 MCP 专用只读内部路由 | 独立路径，不修改既有业务接口语义 |
| `packages/contracts` | MCP工具、内部接口和错误契约 | 契约先行，新增不破坏旧契约 |
| `packages/config` | MCP配置和启动校验 | 不安全配置导致 MCP 启动失败，不影响 API 启动 |
| `database/migrations` | MCP客户端、会话和审计的增量表 | 只做向前兼容新增，不修改业务表和业务状态 |
| `deploy/single-server` | 独立镜像、服务、开关、健康和回退 | 默认不开启，停止 MCP 不停止 API、Worker 和 Nginx 主业务 |
| `tests` | 协议、权限、越权、性能、部署和主业务回归 | 新增测试，不削弱现有断言 |
| `docs` | 用户、管理员、运维和验收文档 | 明确已知边界和关闭方式 |

`apps/mcp` 已纳入 V3 主线；新增目录仍必须遵守本手册的独立部署、默认关闭和回退要求。

## 12. 测试和验收方案

### 12.1 测试层次

| 层次 | 必测内容 |
| --- | --- |
| 单元测试 | 输入结构、工具过滤、字段策略、脱敏、分页、错误映射、令牌声明和配置校验 |
| 契约测试 | 工具标识、版本、必填字段、未知字段拒绝、稳定错误码和兼容性 |
| 集成测试 | 用户映射、权限、范围、PostgreSQL正式结构、Redis会话和审计 |
| 协议测试 | 初始化、工具列举、调用、会话关闭、超时、断线和客户端兼容 |
| 安全测试 | 伪造身份、跨用户令牌、重放、越权对象、字段泄露、提示注入、主机头、来源、跨站和服务端请求伪造 |
| 性能测试 | 单用户并发、客户端并发、分页、慢查询、连接池、熔断和资源隔离 |
| 回归测试 | 登录、统一入口、四套正式页面、报备、商机、报价、订单、渠道、账号和 Worker |
| 部署测试 | 开关、镜像、HTTPS、健康检查、日志、诊断、升级包、校验和回退 |

### 12.2 权限组合测试

每个工具至少覆盖：

- 未登录用户。
- 已停用用户。
- 有 MCP 权限但无业务读取权限的用户。
- 有业务权限但无 MCP 接入权限的用户。
- 同区域与跨区域。
- 同渠道与跨渠道。
- 本人与他人负责对象。
- 身份存在多个有效关系或无法唯一解析。
- 有字段权限与无字段权限。
- 权限变更前后的旧会话。
- 空数据、已删除或已归档对象。

### 12.3 强制验收指标

| 指标 | 门禁 |
| --- | --- |
| 越权工具可见 | 0 |
| 越权工具执行 | 0 |
| 越权记录泄露 | 0 |
| 越权字段泄露 | 0 |
| MCP业务写入 | 0 |
| 未审计工具调用 | 0 |
| 明文令牌或密钥日志 | 0 |
| MCP关闭时暴露业务工具 | 0 |
| MCP故障导致主业务不可用 | 0 |
| 现有主业务回归失败 | 0 |

性能门禁建议以实施前基线为准：在约定试点负载下，现有主业务接口的响应时间分位值、错误率和数据库连接使用不得出现超过评审阈值的劣化。建议初始警戒值为 5%，最终值由容量测试和生产硬件共同确认。

### 12.4 完成定义

一项 MCP 能力只有同时满足以下条件才算完成：

- 产品范围、工具语义、权限和字段规则已签字。
- 契约、实现、权限、范围、脱敏和审计全部完成。
- 正向、负向、越权、异常、性能和回归测试通过。
- 客户端兼容性验证通过。
- HTTPS、部署、健康、监控、诊断和回退完成。
- 功能默认关闭，灰度名单和总开关可用。
- 用户手册、管理员手册、运维手册和已知边界完成。

仅能在本地连接、仅能返回数据或仅完成协议演示，均不能标记为生产完成。

## 13. 审计、监控和告警

### 13.1 调用审计

每次工具调用至少记录：

- 请求编号、会话编号、客户端编号和令牌指纹。
- 用户编号、唯一主身份和授权版本。
- 工具标识、工具版本和工具集。
- 输入字段名称、筛选条件摘要和参数哈希，不保存不必要的敏感值。
- 使用的业务权限、数据范围类型和字段策略版本。
- 结果状态、返回数量、是否截断、脱敏类别和耗时。
- 拒绝代码、异常分类和重试情况。

审计不得保存完整业务返回、完整问题、完整答案、凭据、附件正文和令牌明文。

### 13.2 监控指标

- MCP 进程存活、会话数、连接数和异常关闭数。
- 各客户端、用户和工具的调用次数、成功率、拒绝率和耗时。
- 401、403、保护性 404、限流和熔断次数。
- 内部 API 和数据库查询耗时、连接数、超时和行数。
- 工具列表大小、结果截断和字段脱敏次数。
- 主业务 API 在 MCP 开启前后的响应分位值和错误率。

### 13.3 告警

- 跨用户或跨范围访问被连续拦截。
- 同一客户端认证失败、重放或异常并发增长。
- MCP 导致 API 或数据库资源超过隔离预算。
- 某工具错误率、超时率或结果数量异常增长。
- 审计写入失败。
- MCP 总开关或工具策略被非授权变更。
- HTTPS、令牌签发方、受众或授权版本校验异常。

## 14. 发布、灰度和回退

### 14.1 功能开关

建议至少提供：

- `V3_MCP_ENABLED`：总开关，默认 `false`。
- `V3_MCP_HTTP_ENABLED`：远程传输开关，默认 `false`。
- 客户端状态开关。
- 试点用户白名单。
- 工具集开关。
- 单工具开关和版本状态。
- 后续写工具总开关，首期代码和配置均不存在可用值。

### 14.2 灰度顺序

1. 开发环境模拟数据。
2. 测试环境脱敏数据和多角色自动化。
3. 内部技术人员协议验证，不开放业务工具。
4. 少量业务试点人员只读验证。
5. 按人员逐步扩展，不按角色一次性全开。
6. 稳定后再评审是否接入 V3 AI 问答或企微入口。

### 14.3 一键停止

出现越权、字段泄露、异常负载或身份映射错误时：

1. 关闭 `V3_MCP_ENABLED` 或撤销具体工具。
2. 从 Nginx 停止 MCP 路径并停止 MCP 容器。
3. 撤销全部 MCP 会话和客户端令牌。
4. 保留审计和诊断证据。
5. 验证 V3 API、Worker、四套正式页面和数据库主业务健康。

停止 MCP 不应要求回退业务数据库、业务状态或现有 API 镜像。

### 14.4 版本回退

- MCP 镜像可单独回退到上一版本。
- 工具版本可以单独停用和恢复。
- 数据库只采用向前兼容新增；回退时保留 MCP 元数据表，不自动删除审计。
- MCP 内部接口保持一个发布窗口兼容；无法兼容时先停 MCP，再回退 MCP 和内部接口版本。
- 升级包必须包含外层校验、包内校验、脚本语法检查、真实资源路径检查和本地等价断言。

## 16. 主要风险与控制措施

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| MCP绑定用户未进入数据范围 | 跨区域或跨渠道泄露 | 每次调用由 V3 重算授权范围；空用户上下文默认拒绝；负向测试零容忍 |
| 共享服务账号 | 所有人获得相同权限 | 逐用户授权；禁止共享业务凭据 |
| 自动暴露全部 OpenAPI | 写接口或管理接口被模型发现 | 专项契约、默认排除、人工允许清单 |
| 任意 SQL 或原始过滤透传 | 绕过字段和范围策略 | 具体业务工具、预定义参数、禁止主库通用查询 |
| 模型被业务文本提示注入 | 诱导调用其他工具或泄密 | 数据内容标记为不可信；工具调用仍由服务端授权 |
| 工具数量过多 | 上下文膨胀、误选工具 | 工具集、动态过滤和最小工具目录 |
| MCP占用主业务资源 | 页面和接口变慢 | 独立进程、连接预算、限流、超时、熔断和基线比较 |
| SDK和Zod版本冲突 | 全仓构建回归 | `apps/mcp` 隔离依赖并锁定版本，不全局升级 |
| 远程HTTP无加密 | 令牌和数据被截获 | HTTPS上线门禁、私有端口和反向代理 |
| 审计保存过多敏感内容 | 二次泄露 | 只存摘要和哈希，禁止完整结果与令牌 |
| 误把MCP当AI完整产品 | 范围和周期失控 | MCP只做受控工具层；模型网关、问答和企微另行分阶段 |

## 17. 已确认的产品决策（M-01至M-14）

| 编号 | 决策事项 | 已确认方案 | 开发约束 |
| --- | --- | --- | --- |
| M-01 | 首期使用者 | 内部人员和渠道人员同时支持 | 每次调用必须映射到真实 V3 用户 |
| M-02 | 首期验收客户端 | 赤兔 RedClaw；本地优先 stdio | 记录 RedClaw 版本并完成真实兼容验收 |
| M-03 | 远程访问范围 | 内网或受控终端，禁止公网匿名访问 | 远程入口必须经过 HTTPS 和来源白名单 |
| M-04 | 用户授权方式 | OAuth 2.1 + PKCE；本地 stdio 使用受控测试夹具 | 逐用户短期令牌，服务端实时校权 |
| M-05 | 双重身份 | 不做双重身份选择或切换；只接受唯一有效主身份 | 身份不唯一时拒绝业务工具调用，不合并权限 |
| M-06 | 首期业务域 | 产品、报备、商机、报价、订单只读摘要 | 不自动暴露全部 OpenAPI |
| M-07 | 联系方式字段 | 手机、邮箱等默认脱敏 | 完整联系方式需另行立项和授权 |
| M-08 | 金额和底价字段 | 按现有字段权限；成本、底价无权即隐藏 | 服务端执行字段策略 |
| M-09 | 超范围对象行为 | 工具未授权403；对象越权采用保护性404 | 全部工具保持一致 |
| M-10 | 审计保留期 | 至少3年，遵循现有审计基线 | 只保存摘要、哈希和元数据 |
| M-11 | HTTPS域名和证书 | 远程试点前完成 | 生产无 HTTPS 不开放远程 MCP |
| M-12 | 写入能力 | 首期固定禁止，后续另行立项 | 不提供创建、修改、审批、收款、领取、分配、导出和附件下载 |
| M-13 | MCP主线目录 | 批准新增 `apps/mcp` | 独立进程、默认关闭、不得连接业务主库 |
| M-14 | 业务性能阈值 | 以基线验收，初始劣化警戒值5% | 超过阈值立即停止灰度并回退 MCP |

上述决策已冻结，开发人员按《V3 MCP受控只读能力开发实施与交付手册》执行；真实业务接入仍须满足三阶段退出门禁。

## 18. 最终验收清单

- [ ] MCP 可以独立关闭、停止和回退。
- [ ] MCP 停止后所有 V3 主业务和四套正式页面正常。
- [ ] 所有用户均以真实 V3 身份调用，不存在共享业务账号。
- [ ] 工具列表按人员权限不同而不同。
- [ ] 同一工具对不同用户应用不同数据范围和字段策略。
- [ ] 超级管理员没有隐藏的业务全量绕过。
- [ ] 身份无法唯一解析时业务工具调用被拒绝，内部和渠道权限没有取并集。
- [ ] 首期工具全部只读，不存在业务写调用链。
- [ ] MCP 不连接业务主库，不接受任意 SQL。
- [ ] 越权工具、记录和字段泄露均为零。
- [ ] 每次连接、调用、拒绝和异常均有请求编号和审计。
- [ ] 令牌、密钥、附件和完整敏感结果不进入日志。
- [ ] 分页、超时、限流、熔断和结果截断有效。
- [ ] 现有主业务性能未超过约定劣化阈值。
- [ ] 协议、权限、集成、安全、性能、回归和部署测试全部通过。
- [ ] 升级包、健康检查、诊断、回退和用户说明全部完成。

只有以上清单全部通过，才能把 V3 MCP 标记为“生产只读试点完成”。
