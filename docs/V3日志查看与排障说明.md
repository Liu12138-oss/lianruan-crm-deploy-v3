# 联软 CRM V3 日志查看与排障说明

编写日期：2026-08-05  
适用范围：V3 工程化应用，包含 `apps/api`、`apps/worker`、单机 Docker Compose 部署和 OpenAPI 调用日志。  
适用人员：开发、测试、交付、运维和故障排查人员。

## 一、日志体系说明

V3 当前日志分为四类：

| 类型         | 用途                                               | 主要位置                                   |
| ------------ | -------------------------------------------------- | ------------------------------------------ |
| 接口运行日志 | 查看接口请求、认证、单点登录、错误、耗时、请求编号 | `logs/api-1/api.log`、`logs/api-2/api.log` |
| 任务运行日志 | 查看 Worker 启动、停止、健康任务执行情况           | `logs/worker/worker.log`                   |
| Nginx 日志   | 查看浏览器入口访问、反向代理状态、静态资源请求     | `logs/nginx/`                              |
| 数据库日志   | 查看 PostgreSQL 自身运行问题                       | `logs/postgres/`                           |

接口运行日志和任务运行日志是 JSON Lines 格式：一行是一条完整 JSON 日志。

示例：

```json
{
  "event": "auth.password.failed",
  "requestId": "req-test-001",
  "level": "warn",
  "message": "账号密码登录失败",
  "errorCode": "V3_AUTH_INVALID_CREDENTIALS",
  "errorMessage": "用户名或密码不正确。"
}
```

重点说明：

1. 普通日志仍输出到容器控制台，可以继续用 `docker compose logs` 查看。
2. 生产模板默认同时写入文件日志，文件到达指定大小后自动压缩备份。
3. 日志写文件失败不会影响登录、接口、任务和业务处理；系统会在控制台输出 `logger.file_write_failed`。
4. 日志会记录密码、令牌、密钥的诊断信息，但不会记录明文或完整值，而是记录指纹、长度、是否存在、是否写入等排障字段。

## 二、生产环境日志位置

单机部署默认安装根目录为：

```bash
/opt/lianruan-crm-v3
```

接口实例一：

```bash
/opt/lianruan-crm-v3/logs/api-1/api.log
/opt/lianruan-crm-v3/logs/api-1/api-*.log.gz
```

接口实例二：

```bash
/opt/lianruan-crm-v3/logs/api-2/api.log
/opt/lianruan-crm-v3/logs/api-2/api-*.log.gz
```

任务进程：

```bash
/opt/lianruan-crm-v3/logs/worker/worker.log
/opt/lianruan-crm-v3/logs/worker/worker-*.log.gz
```

Nginx：

```bash
/opt/lianruan-crm-v3/logs/nginx/
```

PostgreSQL：

```bash
/opt/lianruan-crm-v3/logs/postgres/
```

如果安装时修改了 `INSTALL_ROOT`，把上面的 `/opt/lianruan-crm-v3` 替换为实际安装目录。

## 三、本地开发日志位置

本地开发默认只输出到终端，不写日志文件。

如需本地写文件日志，可以在环境变量中开启：

```bash
LOG_TO_FILE=true
LOG_DIR=./logs
LOG_MAX_BYTES=10485760
LOG_MAX_FILES=10
LOG_COMPRESS_ROTATED=true
```

然后重新启动 API 或 Worker。

## 四、日志轮转配置

配置文件位置：

```bash
/opt/lianruan-crm-v3/config/v3.env
```

相关配置：

| 配置项                 | 示例值      | 说明                                                |
| ---------------------- | ----------- | --------------------------------------------------- |
| `LOG_LEVEL`            | `info`      | 最小输出级别，可选 `debug`、`info`、`warn`、`error` |
| `LOG_TO_FILE`          | `true`      | 是否写入文件日志                                    |
| `LOG_DIR`              | `/app/logs` | 容器内日志目录，单机部署已挂载到宿主机 `logs` 目录  |
| `LOG_MAX_BYTES`        | `10485760`  | 单个当前日志文件最大字节数，默认 10MB               |
| `LOG_MAX_FILES`        | `10`        | 每个服务实例保留的压缩备份数量                      |
| `LOG_COMPRESS_ROTATED` | `true`      | 轮转后是否压缩为 `.gz`                              |

修改配置后重启服务：

```bash
cd /opt/lianruan-crm-v3/compose
docker compose up -d api-1 api-2 worker
```

轮转规则：

1. 当前文件为 `api.log` 或 `worker.log`。
2. 当前文件写满后会重命名为类似 `api-20260805T065614Z-0001.log`。
3. 如果开启压缩，会生成 `api-20260805T065614Z-0001.log.gz`。
4. 备份数量超过 `LOG_MAX_FILES` 后自动删除更早的备份。
5. `api-1`、`api-2`、`worker` 分目录保存，互不覆盖。

## 五、最常用查看命令

实时看两个接口实例的容器输出：

```bash
cd /opt/lianruan-crm-v3/compose
docker compose logs -f --tail=200 api-1 api-2
```

实时看文件日志：

```bash
tail -f /opt/lianruan-crm-v3/logs/api-1/api.log
tail -f /opt/lianruan-crm-v3/logs/api-2/api.log
```

实时看 Worker：

```bash
tail -f /opt/lianruan-crm-v3/logs/worker/worker.log
```

按请求编号查当前日志：

```bash
grep -hF '"requestId":"这里替换成请求编号"' /opt/lianruan-crm-v3/logs/api-1/api.log /opt/lianruan-crm-v3/logs/api-2/api.log
```

按请求编号查压缩备份：

```bash
zgrep -h '"requestId":"这里替换成请求编号"' /opt/lianruan-crm-v3/logs/api-1/api-*.log.gz /opt/lianruan-crm-v3/logs/api-2/api-*.log.gz
```

查看所有认证失败：

```bash
grep -hE '"event":"auth\..*\.failed"' /opt/lianruan-crm-v3/logs/api-1/api.log /opt/lianruan-crm-v3/logs/api-2/api.log
```

查看所有接口错误：

```bash
grep -hF '"event":"api.request.failed"' /opt/lianruan-crm-v3/logs/api-1/api.log /opt/lianruan-crm-v3/logs/api-2/api.log
```

用 `grep` 粗查耗时超过 3000 毫秒的请求：

```bash
grep -hF '"event":"api.request.completed"' /opt/lianruan-crm-v3/logs/api-1/api.log /opt/lianruan-crm-v3/logs/api-2/api.log | grep -E '"durationMs":([3-9][0-9]{3}|[1-9][0-9]{4,})'
```

查看最近 200 行接口错误：

```bash
tail -n 200 /opt/lianruan-crm-v3/logs/api-1/api.log /opt/lianruan-crm-v3/logs/api-2/api.log | grep -F '"event":"api.request.failed"'
```

## 六、核心字段说明

| 字段           | 含义                   | 使用方式                                 |
| -------------- | ---------------------- | ---------------------------------------- |
| `time`         | 日志时间，标准时间格式 | 判断问题发生时间                         |
| `level`        | 日志级别               | `warn` 看业务拒绝，`error` 看系统异常    |
| `service`      | 服务名称               | `api` 或 `worker`                        |
| `appEnv`       | 应用环境               | 区分测试、预发、生产                     |
| `event`        | 稳定事件编码           | 最重要的筛选字段                         |
| `message`      | 中文日志说明           | 给人阅读                                 |
| `requestId`    | 请求编号               | 串联同一次请求的所有日志                 |
| `method`       | 请求方法               | 例如 `GET`、`POST`                       |
| `path`         | 请求路径               | 排查具体接口                             |
| `route`        | 匹配路由               | 判断是否命中预期路由                     |
| `statusCode`   | 响应状态码             | 判断成功、拒绝或系统错误                 |
| `statusFamily` | 状态码族               | 例如 `2xx`、`4xx`、`5xx`                 |
| `resultCode`   | 结果                   | `success` 或 `failed`                    |
| `durationMs`   | 耗时毫秒               | 排查慢请求                               |
| `queryKeys`    | 查询参数名列表         | 看请求带了哪些查询参数，不记录完整敏感值 |
| `bodyKeys`     | 请求体字段名列表       | 看请求体传了哪些字段，不记录完整敏感值   |
| `ip`           | 客户端 IP              | 排查来源和白名单问题                     |
| `userAgent`    | 浏览器或调用方标识     | 区分电脑、手机、脚本调用                 |
| `referer`      | 来源页面               | 排查从哪个页面跳转或提交                 |
| `errorCode`    | 后端稳定错误码         | 技术排查优先看这个                       |
| `errorMessage` | 中文错误原因           | 交付和运维判断问题                       |

## 七、认证和单点登录事件清单

账号密码登录：

| 事件                      | 说明                         |
| ------------------------- | ---------------------------- |
| `auth.password.started`   | 账号密码登录开始             |
| `auth.password.succeeded` | 账号密码登录成功，已签发会话 |
| `auth.password.failed`    | 账号密码登录失败             |

IAM 单点登录：

| 事件                              | 说明                           |
| --------------------------------- | ------------------------------ |
| `auth.iam_sso.started`            | IAM 单点登录开始               |
| `auth.iam_sso.provider_started`   | 开始调用 IAM 认证服务          |
| `auth.iam_sso.provider_succeeded` | IAM 认证服务校验通过           |
| `auth.iam_sso.succeeded`          | CRM 本地账号匹配成功并签发会话 |
| `auth.iam_sso.failed`             | IAM 单点登录失败               |

UniSDP JSON 单点登录：

| 事件                                 | 说明                           |
| ------------------------------------ | ------------------------------ |
| `auth.unisdp_sso.started`            | UniSDP JSON 单点登录开始       |
| `auth.unisdp_sso.provider_started`   | 开始调用 UniSDP 认证服务       |
| `auth.unisdp_sso.provider_succeeded` | UniSDP 认证服务校验通过        |
| `auth.unisdp_sso.succeeded`          | CRM 本地账号匹配成功并签发会话 |
| `auth.unisdp_sso.failed`             | UniSDP JSON 单点登录失败       |

UniSDP 门户单点登录：

| 事件                                        | 说明                                                                |
| ------------------------------------------- | ------------------------------------------------------------------- |
| `auth.unisdp_portal_sso.started`            | 门户单点登录开始                                                    |
| `auth.unisdp_portal_sso.provider_started`   | 开始调用 UniSDP 认证服务                                            |
| `auth.unisdp_portal_sso.provider_succeeded` | UniSDP 认证服务校验通过                                             |
| `auth.unisdp_portal_sso.succeeded`          | 已写入会话并返回过渡页                                              |
| `auth.unisdp_portal_sso.failed`             | 门户单点登录失败，通常会跳回 `/login?ssoFallback=1&provider=unisdp` |

| ------------------------ | ------------------------------- |

OpenAPI 认证：

| 事件                              | 说明                                             |

| `auth.open_api_token.succeeded`   | OpenAPI 访问令牌签发成功                         |
| `auth.open_api_token.failed`      | AppKey、AppSecret、IP 白名单或客户端状态校验失败 |
| `auth.open_api_session.started`   | 外部系统开始校验访问令牌                         |
| `auth.open_api_session.succeeded` | 访问令牌有效                                     |
| `auth.open_api_session.failed`    | 访问令牌缺失、无效或过期                         |

## 九、凭证指纹怎么用

日志不会保存明文密码、完整单点凭证、完整会话令牌、完整 AppSecret 或完整 AccessToken。

指纹字段用于排障：

1. 同一个环境、同一种用途、同一个原始值，会得到相同指纹。
2. 不同用途会得到不同指纹，例如同一个文本作为密码和单点凭证，指纹也不同。
3. 看到同一个 `passwordFingerprint`，说明这几次登录输入的是同一个密码。
4. 看到同一个 `ssoTokenFingerprint`，说明这几次单点请求使用的是同一个单点凭证。
5. 看到同一个 `accessTokenFingerprint`，说明 OpenAPI 多次调用使用的是同一枚访问令牌。

典型用法：

```bash
grep -hF '"passwordFingerprint":"这里替换成指纹"' /opt/lianruan-crm-v3/logs/api-1/api.log /opt/lianruan-crm-v3/logs/api-2/api.log
grep -hF '"ssoTokenFingerprint":"这里替换成指纹"' /opt/lianruan-crm-v3/logs/api-1/api.log /opt/lianruan-crm-v3/logs/api-2/api.log
grep -hF '"accessTokenFingerprint":"这里替换成指纹"' /opt/lianruan-crm-v3/logs/api-1/api.log /opt/lianruan-crm-v3/logs/api-2/api.log
```

注意：

1. 不要要求用户、渠道或外部系统把明文密码、完整令牌、完整密钥发到群里。
2. 如果必须确认“某个原始凭证是否就是日志中的那一个”，只能由授权运维在受控终端临时计算指纹，计算后不得保存明文。
3. 日志文件和诊断包仍属于敏感运维资料，不要公开发送。

## 十、典型问题排查

### 10.0 单点登录日志命令速查

下面命令默认生产安装目录是 `/opt/lianruan-crm-v3`。如果实际目录不同，先改 `root`。

先设置通用变量：

```bash
root="/opt/lianruan-crm-v3"
api1_log="${root}/logs/api-1/api.log"
api2_log="${root}/logs/api-2/api.log"
api1_gz="${root}/logs/api-1/api-*.log.gz"
api2_gz="${root}/logs/api-2/api-*.log.gz"
```

现场排障优先使用下面这些 `tail`、`grep`、`zgrep` 命令；它们不依赖 `jq`，精简服务器也能直接执行。

查看当前日志里的所有单点登录事件：

```bash
grep -hE '"event":"auth\.(iam_sso|unisdp_sso|unisdp_portal_sso)\.' "${api1_log}" "${api2_log}"
```

查看压缩备份里的所有单点登录事件：

```bash
zgrep -hE '"event":"auth\.(iam_sso|unisdp_sso|unisdp_portal_sso)\.' ${api1_gz} ${api2_gz} 2>/dev/null || true
```

只看当前日志里的单点登录失败：

```bash
grep -hE '"event":"auth\.(iam_sso|unisdp_sso|unisdp_portal_sso)\.failed"' "${api1_log}" "${api2_log}"
```

只看压缩备份里的单点登录失败：

```bash
zgrep -hE '"event":"auth\.(iam_sso|unisdp_sso|unisdp_portal_sso)\.failed"' ${api1_gz} ${api2_gz} 2>/dev/null || true
```

查 IAM 单点登录完整链路：

```bash
grep -h '"event":"auth.iam_sso.' "${api1_log}" "${api2_log}"
zgrep -h '"event":"auth.iam_sso.' ${api1_gz} ${api2_gz} 2>/dev/null || true
```

只查 IAM 单点登录失败：

```bash
grep -h '"event":"auth.iam_sso.failed"' "${api1_log}" "${api2_log}"
zgrep -h '"event":"auth.iam_sso.failed"' ${api1_gz} ${api2_gz} 2>/dev/null || true
```

查 UniSDP JSON 单点登录完整链路：

```bash
grep -h '"event":"auth.unisdp_sso.' "${api1_log}" "${api2_log}"
zgrep -h '"event":"auth.unisdp_sso.' ${api1_gz} ${api2_gz} 2>/dev/null || true
```

查 UniSDP 门户单点登录完整链路：

```bash
grep -h '"event":"auth.unisdp_portal_sso.' "${api1_log}" "${api2_log}"
zgrep -h '"event":"auth.unisdp_portal_sso.' ${api1_gz} ${api2_gz} 2>/dev/null || true
```

查 UniSDP 认证服务是否返回手机号：

```bash
grep -hE '"event":"auth\.unisdp(_portal)?_sso\.provider_succeeded"' "${api1_log}" "${api2_log}"
zgrep -hE '"event":"auth\.unisdp(_portal)?_sso\.provider_succeeded"' ${api1_gz} ${api2_gz} 2>/dev/null || true
```

只看 UniSDP 已返回手机号的记录：

```bash
grep -hE '"event":"auth\.unisdp(_portal)?_sso\.(provider_succeeded|succeeded)"' "${api1_log}" "${api2_log}" | grep -F '"uniSdpMobilePresent":true'
zgrep -hE '"event":"auth\.unisdp(_portal)?_sso\.(provider_succeeded|succeeded)"' ${api1_gz} ${api2_gz} 2>/dev/null | grep -F '"uniSdpMobilePresent":true' || true
```

只查 UniSDP 门户单点登录失败：

```bash
grep -h '"event":"auth.unisdp_portal_sso.failed"' "${api1_log}" "${api2_log}"
zgrep -h '"event":"auth.unisdp_portal_sso.failed"' ${api1_gz} ${api2_gz} 2>/dev/null || true
```

按 `requestId` 查单次单点登录完整上下文：

```bash
request_id="这里替换成请求编号"
grep -hF "\"requestId\":\"${request_id}\"" "${api1_log}" "${api2_log}"
zgrep -hF "\"requestId\":\"${request_id}\"" ${api1_gz} ${api2_gz} 2>/dev/null || true
```

### 10.2 IAM 单点登录失败

查看 IAM 失败：

```bash
grep -hF '"event":"auth.iam_sso.failed"' /opt/lianruan-crm-v3/logs/api-1/api.log /opt/lianruan-crm-v3/logs/api-2/api.log
```

常见判断：

| `errorCode`                  | 可能原因                        | 下一步                                    |
| ---------------------------- | ------------------------------- | ----------------------------------------- |
| `V3_AUTH_SSO_BAD_REQUEST`    | 缺少单点凭证或入口不明确        | 看 `bodyKeys`、`entry`、`ssoTokenPresent` |
| `V3_AUTH_SSO_PC_DISABLED`    | 旧 PC IAM 通道关闭              | 看 `clientType`，移动端应为 `mobile`      |
| `V3_AUTH_SSO_TIMEOUT`        | IAM 校验超时                    | 查网络、IAM 服务状态、`timeoutMs`         |
| `V3_AUTH_SSO_PROVIDER_ERROR` | IAM 服务不可用或响应异常        | 查第三方服务和 Nginx 出口网络             |
| `V3_AUTH_SSO_REJECTED`       | IAM 拒绝该凭证                  | 看 `errorMessage`，如凭证过期、用户禁用   |
| `V3_AUTH_SSO_USER_NOT_FOUND` | IAM 认证通过，但 CRM 没有该账号 | 补 CRM 用户或核对用户名映射               |
| `V3_AUTH_SSO_FORBIDDEN`      | CRM 账号未开通目标入口          | 核对 `entry` 和账号角色权限               |

完整链路应当至少看到：

```text
auth.iam_sso.started
auth.iam_sso.provider_started
auth.iam_sso.provider_succeeded
auth.iam_sso.succeeded
api.request.completed
```

如果停在 `provider_started` 后失败，优先查第三方认证服务。  
如果已经有 `provider_succeeded` 但最终失败，优先查 CRM 本地账号和入口权限。

### 10.3 UniSDP 门户单点登录失败后跳回登录页

重点看：

| 字段                   | 说明                                       |
| ---------------------- | ------------------------------------------ |
| `inputSource`          | 凭证来自 `body` 还是 `query`               |
| `ssoTokenPresent`      | 是否传了单点凭证                           |
| `failedStep`           | 是请求阶段、第三方阶段还是本地账号阶段失败 |

## 十一、审计日志和运行日志如何关联

运行日志使用 `requestId`。

业务审计日志表也保存 `request_id`，可用于关联：

```bash
cd /opt/lianruan-crm-v3/compose
docker compose exec postgres sh -lc 'PGPASSWORD="$(cat /run/secrets/postgres_password)" psql -U lianruan_app -d lianruan_crm_v3 -c "SELECT occurred_at, request_id, module_code, action_code, result_code, operator_name, message FROM audit.audit_logs WHERE request_id = ''这里替换成请求编号'' ORDER BY occurred_at DESC;"'
```

OpenAPI 访问日志表也保存 `request_id`：

```bash
cd /opt/lianruan-crm-v3/compose
docker compose exec postgres sh -lc 'PGPASSWORD="$(cat /run/secrets/postgres_password)" psql -U lianruan_app -d lianruan_crm_v3 -c "SELECT requested_at, request_id, resource_code, action_code, result_code, status_code, extra_json FROM integration.open_api_access_logs WHERE request_id = ''这里替换成请求编号'' ORDER BY requested_at DESC;"'
```

推荐排障顺序：

1. 从浏览器、接口响应或用户截图拿到 `requestId`。
2. 在 `api-1`、`api-2` 当前日志和压缩备份中查 `requestId`。
3. 如果涉及业务写入，再查 `audit.audit_logs`。
4. 如果涉及 OpenAPI，再查 `integration.open_api_access_logs`。
5. 如果接口日志显示请求未到达 API，再查 Nginx 日志。

| 错误码               | 含义         |
| -------------------- | ------------ |
| `V3_ROUTE_NOT_FOUND` | 接口不存在   |
| `V3_INTERNAL_ERROR`  | 系统内部错误 |

## 十三、日志交付和脱敏规则

对外提供日志前必须处理：

1. 只提供相关时间段、相关 `requestId`、相关事件，不要整包发送全部日志。
2. 保留 `requestId`、`event`、`errorCode`、`errorMessage`、`fingerprint`、`durationMs` 等排障字段。
3. 如日志中出现手机号、姓名、企业名、IP，应按问题需要最小化提供。
4. 不要提供 `.env`、数据库备份、密钥文件、完整 Cookie、完整令牌、完整 AppSecret。
5. 压缩备份日志 `.gz` 也按敏感文件处理。

建议导出单个请求相关日志：

```bash
request_id="这里替换成请求编号"
grep -hF "\"requestId\":\"${request_id}\"" /opt/lianruan-crm-v3/logs/api-1/api.log /opt/lianruan-crm-v3/logs/api-2/api.log > "/tmp/${request_id}.log"
zgrep -h "\"requestId\":\"${request_id}\"" /opt/lianruan-crm-v3/logs/api-1/api-*.log.gz /opt/lianruan-crm-v3/logs/api-2/api-*.log.gz >> "/tmp/${request_id}.log" 2>/dev/null || true
```

## 十五、上线检查清单

上线或升级后检查：

1. `LOG_TO_FILE=true`。
2. `LOG_DIR=/app/logs`。
3. 宿主机存在 `logs/api-1`、`logs/api-2`、`logs/worker`。
4. 登录一次后 `api.log` 出现 `auth.password.started` 和 `auth.password.succeeded`。
5. 打开页面后 `/api/auth/me` 出现 `auth.session.started` 和 `auth.session.succeeded`。
6. 故意输入错误密码后出现 `auth.password.failed`，且日志中没有明文密码。
7. 文件超过 `LOG_MAX_BYTES` 后能生成 `.log.gz` 备份。
8. `docker compose logs api-1 api-2 worker` 仍能看到控制台日志。
9. `requestId` 可以关联运行日志、业务审计日志和 OpenAPI 访问日志。
