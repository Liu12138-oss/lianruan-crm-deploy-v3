区管管理员手册

面向区域管理员，讲清从渠道商准入、客户报备审核、商机推进、报价治理、订单三级审批，到订单回退、履约协同和操作审计的完整主业务链。

适用角色：区管 / 区域管理员 文档版本：2026-11-09 阅读重点：主链、审批节点、异常兜底
区管看本区域

只处理账号数据范围内的渠道商、客户、商机、报价与订单，不跨区域操作。

标准报价要补价

标准产品报价全链路不展示价格，转单后必须由区管补充最终订单价格。

审批动作留痕

通过、驳回、调价、退回、重提和取消均写审批历史与操作审计。

01先看全局

区管的核心职责不是替代渠道做销售，而是守住三件事：渠道准入可信、客户归属不冲突、订单价格与审批链完整。所有业务动作都应顺着订单状态和历史记录推进，不通过线下消息跳过系统节点。

每日首先查看审核中心 → 待审批；订单中心 → 待我处理
重点跟踪对象本区域一级渠道、其直属二级渠道及关联业务
价格判断依据报价快照、区域覆盖价、渠道层级价、出货金额
风险留痕依据审批历史、状态历史、操作审计与附件
工作频率建议动作目标
每日清理客户报备、渠道账号、订单待办；检查被驳回或退回的业务。避免订单卡在区管节点。
每周检查停滞商机、异常低价、负利润订单、报价长期未转单。发现业务质量和价格风险。
每月核对渠道档案、分销层级、成员状态和订单履约结果。保证渠道数据可继续使用。

02角色与权限边界

角色可见范围在主链中的职责
超级管理员全平台维护管理配置、产品与价格规则；执行订单最终确认；处理跨区域异常。
区管管理员本区域渠道准入、客户报备审核、商机/报价监督、区管确认、补价、调价、驳回与退回。
渠道企业管理员本渠道及授权下级维护本企业成员账号、渠道关系和日常经营资料，组织员工开展业务。
渠道销售成员本渠道授权业务报备客户、建商机、写跟进、做报价、转订单、查看本渠道订单状态。
区管看不到什么

“业务全景”和“管理配置”是超级管理员能力，不应作为区管日常入口。区管只使用工作台、客户管理、商机作战、订单中心、审核中心、产品目录、消息中心和渠道管理等业务页面。

数据范围的判断方法

  • 列表只应出现本区域数据；如果看到跨区域数据，应先停止操作并反馈，不要继续审批。
  • 区域筛选、搜索词和标签只改变当前列表，不改变账号本身的权限范围。
  • 一级渠道可查看其直属二级渠道的基础关系和由其产生的待确认订单；不得据此查看对方的内部经营档案。
  • 渠道利润、内部成本、收益表等内部口径只对内部管理员展示，不应在渠道端传播。

03主业务链总览

新 UI 的主链可以压缩成八个阶段。区管不是每个动作的执行人，但要对关键门禁负责。

1渠道准入区管建档、资质与层级
→
2账号开通企业管理员提成员，两级审批
→
3客户报备渠道提交，区管审核归属
→
4商机推进七阶段、跟进与报价前置
→
5报价定价标准免价 / 渠道分销自动取价
→
6报价转单收货、出货、合同附件
→
7三级审批一级 → 区管 → 超管
→
8履约协同发货、完成、OA/企微

五个关键门禁

门禁一：客户报备未通过

不能创建商机，不能进入报价与订单。驳回必须写清原因，渠道修正后可重新提交。

门禁二：维保业务要有产品订单

维保商机必须关联同一客户、状态为已确认或已完成的产品订单，可关联多个。

门禁三：标准报价要补价

标准产品报价不展示价格，订单进入区管节点必须补充大于 0 的最终订单价，否则不能提交超管。

门禁四：一级渠道转单资料

一级渠道转订单必须填写出货金额并上传至少 1 个合同附件；二级渠道按选填处理。

门禁五：系统状态优先于口头结论

OA 是否受理、企微群是否建立，不等于 CRM 订单已经完成审批。最终状态必须看订单中心和审批历史。

04渠道商准入

入口：顶部一级菜单“渠道管理” → 新建渠道商或打开待审核渠道。

1
核对主体与区域

填写渠道商名称、所属区域、所在城市。区管新建的渠道商自动归属本区域，并按流程进入待审批；超级管理员直接创建时可直接生效。

2
确定合作级别与分销层级

合作级别可选核心渠道、钻石、金牌、银牌、铜牌、行业总代等；分销层级只设置一级或二级。二级渠道商必须至少绑定一个同区域一级渠道商。

3
补齐联系人与合作资料

渠道负责人和联系电话必填；协议编号、邮箱、开票能力、注册/办公地址、合作背景和经营能力按实际情况维护。

4
提交并跟踪审核状态

区管创建的渠道商显示待审批。审核通过后才能作为正式渠道开展账号与业务操作；被驳回时先看原因再修改。

建档检查要点

检查项通过标准常见问题
名称与企业主体一致，避免使用简称或项目名。名称重复、同一公司多个档案。
区域与城市区域决定区管数据范围和价格区域，必须准确。选错区域导致后续取价、审批人错误。
分销层级一级或二级明确；二级必须绑定正确的一级上级。上级不可选时，检查上级是否同级区域、是否仍为一级。
协议编号区管正式确认订单前应维护完整，便于合同追溯。为空时先补档案，不要带病进入订单审批。
合作背景写清合作历史、重点客户、覆盖行业和服务能力。只写“合作良好”等无判断价值的内容。
保存失败不要反复盲点

先看页面上的红色错误提示。常见原因包括必填字段缺失、电话格式不正确、二级渠道未绑定同区域一级渠道、名称重复或当前账号无权操作该区域。

05档案、层级与成员

核心档案与经营信息

在渠道商列表打开核心档案，维护主体、经营地址、合作背景、协议编号、开票能力、服务区域、代理品牌、典型客户、资质证书及合作进程。

  • 档案更新应保留历史和审批痕迹，不以口头说明替代系统记录。
  • “技术服务商类型”只应选择签约技术服务商、提名技术服务商或非技术服务商，避免填写自由文本造成统计失真。
  • 一级/二级分销层级异常时，优先修正渠道关系，不要通过新建重复渠道绕过。
  • 合作进程与持续运营资料用于经营判断，不作为订单审批的替代凭证。

成员账号审批

入口：渠道管理 → 对应渠道 → 成员维护。渠道企业管理员提交成员后，订单外的账号审批进入审核中心。

状态含义区管动作
待区管初审企业管理员已提交，等待区管核验。核对姓名、账号、角色、电话、岗位和所属渠道；通过后流转超管终审。
待超管终审区管已通过，等待超级管理员终审。不再重复审批；如需撤回或修正，联系超级管理员处理。
正常两级审批完成，可登录使用。用于日常业务；发现异常时停用账号并留原因。
已驳回区管或超管未通过。检查驳回原因，通知企业管理员修正后重新提交。
账号职责的区别

企业管理员负责本渠道账号与业务组织；销售成员负责客户、商机、报价和订单。渠道端不能自行创建企业管理员账号，企业管理员账号由内部管理端维护。

06客户报备审核

入口：审核中心 → 客户报备查看待办，或客户管理 → 待审核筛选。审批动作在客户详情或业务详情页完成。

客户报备的业务含义

报备不是普通“新增客户”。它同时完成客户档案、归属渠道、所属区域和跟进人员的确认；审核通过后才进入保护期，渠道才能据此创建商机。

1
看主体

客户名称是否为工商全称；统一社会信用代码是否为 18 位数字或大写字母；行业、规模、来源是否合理。

2
看查重

客户名称或统一社会信用代码与既有客户一致时，系统按冲突处理，不允许重复报备，并记录冲突审计。发现重复时应停止通过，定位原客户与原渠道。

3
看联系人和需求

主要联系人和电话必填，邮箱可空但格式必须正确；项目需求应能说明采购场景、范围和下一步，不写空话。

4
看归属和保护期

归属渠道、区域和跟进人员由账号自动带入。若“同时报备商机”，补充项目名称、预计端点范围、保护期和备注。

5
做决定

通过后保护期生效；驳回必须填写原因。被驳回记录会保留标识和原因，渠道看不到通过状态，也不能以此创建商机。

审核通过前检查

客户主体真实，名称与信用代码匹配。
没有同名或同信用代码的重复客户。
联系人、电话、行业、企业规模和客户来源完整。
归属渠道与区域符合当前账号数据范围。
如同时报备商机，项目名称和端点范围已填写，保护期合理。
营业执照、项目材料等附件可打开且与客户匹配。
驳回不是删除

驳回后记录仍保留。渠道修正后可重新提交，审批历史保留原意见；区管在历史审批意见中核对本轮修改是否真正回应了问题。

07商机监督

入口：商机作战。列表支持区域筛选、搜索、重点商机和停滞风险。点开商机后使用“跟进、报价、订单、档案与审计”四个页签。

七阶段口径

阶段进度区管关注点
客户建联10%关键联系人、客户需求和真实项目线索是否成立。
需求挖掘20%–30%痛点、预算、决策链和时间计划是否明确。
客户方案40%方案范围与报价口径是否一致。
POC 试用50%验收标准、测试范围和反馈是否记录。
立项推进60%–70%采购流程、合同主体和预算审批是否推进。
招投标80%–90%投标材料、报价版本和时间节点是否一致。
成单100%是否进入报价转订单和履约，不要只改阶段不落业务。

输单和项目取消属于终止结果，不应被误显示为普通阶段。

业务类型规则

产品商机

以新产品、硬件或产品实施服务为目标，可创建产品报价和产品订单。

维保商机

以续保或维保服务为目标，必须关联至少一个同客户、已确认或已完成的产品订单，可关联多个。

禁止混单

产品订单和维保订单分开下；维保报价只能包含维保服务，不能混入软件、硬件或普通实施服务。

跟进记录

商机页可直接记录跟进，不要求先打开客户跟进记录。至少填写本次沟通内容；同步推进阶段时只能推进到下一阶段或选择输单、项目取消，并必须填写变更原因。

  • 跟进方式：电话沟通、现场拜访、线上会议、微信沟通、客户反馈。
  • 沟通内容最多 2000 字；附件支持 PDF、Word、Excel、图片、ZIP，单个不超过 10MB，单次最多 5 个。
  • 页签中的跟进历史应同时展示阶段和具体内容；只有时间没有内容，不能作为有效推进依据。

08报价治理

报价从商机进入，也可从报价中心查看。新 UI 的报价不再设置报价审批环节；区管的控制点前移到价格规则和订单补价，而不是等待“报价通过”。

两类报价

类型价格展示转单后的处理
标准产品报价全程不展示价格，模块、数量和结构照常保存。渠道可提交订单；区管在区管节点补充最终订单价格，未补价不能提交超管。
渠道分销产品报价按标准价、区域覆盖价、渠道等级价和阶梯价由服务端取价。按报价快照和出货金额进入订单审批，区管可审价或调价。
报价类型创建后不可切换

如果报价体系选错，应重新创建报价，不要尝试在编辑页来回切换；切换会破坏价格口径和订单追溯。

三种报价方式

套餐报价入单模块来自所选套餐，套餐内模块固定，数量可按规则调整。
补充功能套餐内模块加上套餐之外的补充功能，补充项单独勾选。
自定义报价完全按所选模块和功能组装，不依赖套餐。
报价有效期可选 15、30、60、90 天，需与客户商务周期匹配。

选择顺序应与老 UI 一致地理解为“报价方式 → 模块 → 具体功能”。建议操作时先在报价方式面板完成选择，再在下方检查软件模块、硬件与服务和试算汇总；不要在尚未选择模块时直接依赖默认内容。

区管审价关注点

  • 关联商机、客户、区域、渠道层级是否一致。
  • 端点数量与模块数量是否符合项目范围，硬件数量是否合理。
  • 渠道分销报价是否命中正确的区域覆盖价和渠道等级价。
  • 报价明细与商机需求是否匹配；维保报价是否只含维保服务。
  • 报价快照、打印 PDF 与订单明细是否一致。

只有草稿或已驳回报价可以修改；已转订单报价不能重复转单。报价单支持“打印 / 下载 PDF”，正式发送客户前应核对客户名称、报价明细、有效期和金额。

09订单审批

入口：订单中心 → 待我处理 → 打开订单。区管只会收到到达区管节点的订单；不要在“待一级确认”阶段代替渠道执行一级确认。

订单状态与动作

状态当前责任人可用动作
待一级确认一级渠道商一级渠道执行“一级确认”或“一级驳回”；区管只读等待。
一级已确认 / 待区管确认区管区管确认、区管调价、区管补价（标准报价）、区管驳回。
待超管确认超级管理员超管确认或超管退回；区管不再重复确认。
已退回一级 / 二级 / 区管被退回方查看退回原因；符合条件时修订后重新提交。
已确认 / 处理中履约角色确认发货；按实际履约情况推进。
已发货履约角色客户签收或实施完成后完成订单。
已取消—终态，不再进入审批链；保留原因和历史。

区管确认

1
核对订单摘要

订单总额、来源报价、渠道层级、渠道名称、审批轮次和当前状态是否匹配。

2
核对商品与模块

逐项检查产品/模块、数量、订单单价和小计；订单明细来自报价快照，区管调价不覆盖原报价快照。

3
核对价格对比

查看原价、渠道订单价、出货金额、渠道订单折扣、出货折扣、渠道利润及出货/订单比例。负利润要以风险样式处理并写明原因。

4
核对附件与履约信息

检查收货人、联系电话、详细地址、合同附件；一级渠道的出货金额和附件应满足转单要求。

5
执行动作

正常订单点“区管确认”；需要改价时点“区管调价”；标准报价未定价时点“区管补价”。所有驳回、调价、退回均必须填写业务原因。

标准产品报价的区管补价

未补价不能继续提交

标准产品报价转成的订单会显示“待区管定价”。区管必须补充大于 0 的最终订单价格，才可进入超管确认；补价记录进入审批历史与审计。

价格与收益核对

订单处理页的价格对比区用于统一核对价格口径；收益表用于内部收益核算，仅对内部管理员且非标准报价场景展示。不要把渠道端可见的出货价格与内部收益混为一谈。

指标含义区管关注
原价标准价格口径。作为折扣和利润判断的基准。
渠道订单价渠道下单时的订单金额。与报价快照、明细合计是否一致。
出货金额渠道向最终客户出货的成交金额。一级渠道转单必填；与合同附件是否匹配。
渠道利润出货金额减去渠道订单价格。负利润必须说明并复核原因。

10退回、重提与取消

退回目标

区管驳回或超管退回时，必须明确退回目标：退回区域管理员、退回一级渠道商或退回二级渠道商。不要只写“退回修改”，否则执行人无法判断应改什么。

退回状态处理人下一步
已退回区管修改区管核对超管意见，修订后重新提交。
已退回一级修改一级渠道商核对区管/超管意见，修订后重新提交。
已退回二级修改二级渠道商核对退回原因，修订后重新提交。

重新提交规则

  • 至少保留一项明细；模块数量必须为大于 0 的整数。
  • 单价由系统按区域覆盖价、渠道等级价和阶梯价重新取价，不允许手工改单价。
  • 重新提交必须填写原因，结果写回订单审批历史和操作审计。
  • 已进入处理中、已发货、已完成或已取消的订单不能申请回退修改。
退回不等于取消

退回是给业务一次修订机会；取消是终止订单。取消后待办和通知关闭，不能在原订单上继续审批。确需重新下单时，以新订单和对应报价为准。

取消订单

在允许取消的审批状态中，由有权限的角色执行“取消订单”。必须填写取消原因，系统会保留取消人、时间和历史记录。取消前应先确认是否已有合同附件、发货动作或 OA 协同，避免外部流程与 CRM 状态脱节。

11OA 与企微协同

订单审批通过后，系统可在配置允许时自动生成正式报价 PDF、发起泛微 OA 预审、创建企业微信订单预审群并发送通知。是否执行取决于预审开关、OA 模板、区域映射、泛微身份和企微身份是否配置完整。

业务状态可能的自动化结果区管应做什么
普通订单区管确认后进入 OA 预审条件判断，条件满足时创建 OA 流程和企微群。核对订单摘要，等待自动结果；不要因群已建就认为 CRM 已终审。
调价订单超管确认后按配置触发后续 OA/企微协同。确认调价原因和历史已留痕。
自动化未执行订单仍可停留在 CRM 当前状态。联系超级管理员检查开关、模板、区域映射和外部凭据，不手工改数据库。
不要混淆两个“通过”

当前系统中，OA 协同记录可以标记为已受理，但 OA 审批结论不会自动推进 CRM 订单状态。CRM 订单的最终确认仍以超级管理员在订单中心的操作为准。

自动化异常排查顺序

  1. 先看订单是否已到正确触发状态，审批历史是否有对应动作。
  2. 检查订单的正式报价 PDF、合同附件和区域信息是否完整。
  3. 由超级管理员检查预审任务开关、OA 模板、区域映射、泛微身份和企微 UserId 映射。
  4. 在 OA、企微侧核对是否已建流程或群；不要重复点击导致重复流程。

12审核、消息与审计

审核中心

审核中心分为“待审批”和“已审批”。待审批覆盖客户报备、订单、渠道商和成员账号；已审批用于回看历史结论、审批人、时间和审批意见。

  • 客户报备和订单的最终动作在业务页面完成，审核中心用于集中发现待办和查看历史。
  • 账号审批需核对具体账号信息，而不是只看姓名；企业管理员创建的员工账号先区管初审，再超管终审。
  • 驳回后必须在业务记录中能查到原因，渠道侧也应看到已驳回标识和原因。

消息中心

消息中心用于查看站内通知、提醒规则和投递状态。业务提醒不能替代系统状态：收到“待审批”提醒后仍要进入对应业务页面核对详情；没有收到提醒也要按待办清单主动检查。

操作审计

管理配置中的操作审计用于追踪客户、线索、商机、渠道、订单和后台管理动作。排查问题时优先按对象和时间范围定位，再核对操作人、动作、结果与关联单据。

建议的审计排查顺序

先定位对象编号 → 再看最新状态与审批历史 → 最后用操作审计补齐登录、接口调用和后端动作。不要只截取列表结论，忽略前后因果关系。

13常见异常处理

现象优先检查处理建议
渠道列表没有目标渠道区域筛选、账号数据范围、渠道审批状态。先确认是否本区域、是否待审批或被驳回；不要重复新建。
新建二级渠道选不到一级上级上级是否为一级、是否同区域、是否已生效。先修正上级或区域；保存失败时查看明确错误提示。
成员账号一直不能登录状态是否为待区管初审、待超管终审或已驳回。按审核链处理；驳回后让企业管理员修正并重提。
客户报备无法通过名称/信用代码重复、字段格式、查重结果。保留原记录，驳回并写清冲突对象或修改要求。
渠道无法创建商机客户报备是否已通过、是否已过保护期。先完成报备审核或处理保护期，不要绕过系统限制。
报价转单按钮不可用报价状态、是否已转订单、报价是否过期或取消。只有草稿、已提交、已通过、已驳回等允许状态可转；同一报价只能转一次。
标准报价订单金额为空是否等待区管补价。在区管节点执行“区管补价”，填写大于 0 的金额后再提交超管。
一级渠道转单失败出货金额、合同附件、收货信息。补填出货金额并上传至少 1 个合规附件；地址和电话必须有效。
订单在待一级确认停留是否由一级渠道账号处理。区管不能越权代确认；联系对应一级渠道或升级异常。
OA 没有流程或企微没有群预审任务是否开启、模板/映射/凭据是否完整。由超级管理员排查配置；不要把群消息当作订单已审批。
遇到价格、权限或状态异常时

先停止重复提交，记录订单号/报价号、客户、渠道、发生时间、当前状态和页面提示，再交由超级管理员或技术负责人按审计与任务日志排查。不要自行修改数据库或绕过审批接口。

14区管检查清单

每日

审核中心没有超过一个工作日未处理的客户报备、账号和订单待办。
退回记录都有明确退回目标、原因和下一步责任方。
标准产品报价订单已完成区管补价，金额大于 0。
一级渠道转单的出货金额与合同附件齐全。

每周

检查停滞风险商机，推动补跟进、补报价或调整阶段。
抽查渠道分销报价是否命中正确区域覆盖价和渠道层级价。
核对负利润、大幅调价和重复退回订单的原因是否完整。
查看操作审计中的异常登录、批量操作和关键审批动作。

每月

核对渠道档案、协议编号、分销层级、成员状态是否仍然有效。
复盘客户报备驳回率、订单退回率、报价转单率和履约完成情况。
将共性异常整理给超级管理员，推动规则、配置或页面修复。
一条判断原则

只要客户、商机、报价、订单之间的编号和状态能互相追溯，审批意见能解释每一次变更，区管就守住了主业务链。反之，即使单据“看起来通过”，也不能视为业务完成。
