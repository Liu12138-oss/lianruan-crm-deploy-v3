# 阶段3角色权限矩阵落地版

生成日期：2026-07-23

## 1. 矩阵原则

本矩阵基于阶段0冻结结果，只覆盖已出现的四类常规角色：`superadmin`、`admin`、`partner_admin`、`staff`。历史角色未确认前不自动授权。

矩阵中的“允许”仅表示具备功能权限，真实执行时还必须同时通过账号状态、会话授权版本、数据范围、字段允许清单和业务状态机校验。

| 标记 | 含义 |
| --- | --- |
| 允许 | 允许执行该功能动作 |
| 范围允许 | 允许执行，但必须受绑定数据范围限制 |
| 禁止 | 默认拒绝 |
| 待确认 | 需要产品负责人或业务负责人确认后才能授权 |

## 2. 角色落地定义

| 角色代码 | 中文名称 | 阶段0来源 | 默认范围 | 阶段3策略 |
| --- | --- | --- | --- | --- |
| `superadmin` | 超级管理员 | 样本用户和代码 | 总部 | 系统管理和全局业务权限显式绑定，不使用隐藏绕过 |
| `admin` | 区域管理员 | 样本用户和代码 | 区域或大区 | 仅管理绑定区域或大区内账号、渠道、审批和业务数据 |
| `partner_admin` | 渠道管理员 | 样本用户和代码 | 一级渠道或二级渠道 | 管理本渠道及经确认下级渠道范围内业务和员工 |
| `staff` | 渠道员工 | 样本用户和代码 | 本人范围 | 仅处理本人创建、负责或被指派的数据 |

## 4. 历史角色待确认

| 历史代码或名称 | 当前证据 | 默认处理 | 需要确认 |
| --- | --- | --- | --- |
| `partner` | 代码中作为审批类型或渠道对象类型出现 | 不作为登录角色，不自动授权 | 是否曾在生产用户角色字段中使用 |
| `secondary_partner` | 代码中作为二级渠道审批类型出现 | 作为渠道层级或审批类型，不作为角色 | 二级渠道是否需要独立角色，还是由数据范围表达 |
| 企业管理员 | 用户手册中文名称 | 映射到 `partner_admin` | 无需新增角色，需业务确认命名 |
| 企业用户、渠道员工 | 用户手册中文名称 | 映射到 `staff` | 无需新增角色，需业务确认命名 |

## 5. 落地校验用例

| 场景 | 期望 |
| --- | --- |
| 无会话访问受保护接口 | 返回 401 |
| 会话过期或撤销 | 返回 401 |
| 有身份但无功能权限 | 返回 403 |
| 有功能权限但跨区域或跨渠道 | 统一返回 403 或 404，策略编码前确认 |
| 有功能和数据权限但状态非法 | 返回 409 |
| 篡改前端操作者、角色、区域、渠道 | 不影响授权，写入风险审计 |
| 停用账号继续使用旧会话 | 立即拒绝 |
| 权限变化后使用旧会话 | 按授权版本拒绝或刷新 |
| 导出跨范围数据 | 拒绝，且异步任务不能绕过 |
