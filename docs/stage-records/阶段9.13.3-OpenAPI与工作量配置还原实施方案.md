## 1. 目的

阶段9.13.3 的目的，是把 V2 已有的 OpenAPI 对接、Client 凭证管理、调用审计、工作量配置、产品映射规则，在 V3 新架构中按 V2 真实页面和业务流程还原。

本阶段不新增第三方业务能力，不改变 V2 对接方式和工作量配置流程。完成后，总部超级管理员应能像 V2 一样完成接口对接配置、密钥重签、调用排查、产品映射维护和交付工作量规则维护。

## 5. 当前问题判断

当前 V3 的 OpenAPI 和工作量配置页面主要是通用列表形态，不能满足 V2 专页验收。

主要问题：

1. `/admin/openapi-integration` 缺 V2 的对接总览、参数速览、文档下载、Client 凭证管理、调用审计。
2. Client 目前以只读迁移数据为主，缺新增、编辑、重置密钥、一次性展示 AppSecret、旧密钥失效。
3. 调用审计缺专用日志接口和表格结构。
4. `/admin/workload-config` 缺 V2 的产品映射规则和新版交付工作量规则编辑能力。
5. 后端当前只提供通用查询，缺专用写接口。
6. 迁移数据已经包含 OpenAPI Client、工作量映射和交付规则，但页面和接口没有完整承接。

## 8. 接口要求

### 8.1 OpenAPI 管理接口

| 能力 | 接口 | 要求 |
| --- | --- | --- |
| 对接总览 | `GET /api/open-api/overview` | 返回 Base URL、Token 地址、Token 有效期、核心资源、文档清单 |
| 文档清单 | `GET /api/open-api/docs` | 返回可下载文档 |
| 文档下载 | `GET /api/open-api/docs/:id/download` | 下载 Markdown 或接口说明文件 |
| Client 列表 | `GET /api/open-api/clients` | 返回 Client、AppKey、绑定用户、状态、IP 白名单、资源范围、有效期 |
| 新增 Client | `POST /api/open-api/clients` | 创建 AppKey 和 AppSecret，AppSecret 只返回一次 |
| 编辑 Client | `PUT /api/open-api/clients/:id` | 可改名称、绑定用户、状态、有效期、IP 白名单、资源范围、备注 |
| 重置密钥 | `POST /api/open-api/clients/:id/reset-secret` | 旧密钥立即失效，新 AppSecret 只返回一次 |
| 调用日志 | `GET /api/open-api/logs?limit=80` | 返回时间、Client、结果、接口、IP、说明 |

### 8.2 对外 OpenAPI 接口

P0 范围：

| 能力 | 接口 | 要求 |
| --- | --- | --- |
| 换取令牌 | `POST /api/open/v1/auth/token` | 使用 AppKey/AppSecret，校验状态、有效期、IP 白名单 |
| 当前身份 | `GET /api/open/v1/auth/me` | 返回绑定 CRM 用户和资源范围 |
| 核心业务只读 | `GET /api/open/v1/registrations` 等 | 覆盖客户报备、商机、报价、订单、渠道商、用户 |
| 工作量只读 | `GET /api/open/v1/workload/*` | 覆盖映射和交付规则只读 |
| 审计只读 | `GET /api/open/v1/audit-logs` | 按权限返回审计记录 |

| 能力 | 接口 | 要求 |

## 9. 权限和安全要求

1. OpenAPI 管理页只允许超级管理员访问和操作。
2. 工作量配置页按 V2 后台管理口径，建议只允许超级管理员编辑；区域管理员如进入，只读或无权限。
3. OpenAPI Client 必须绑定 CRM 用户，数据范围不得超过绑定用户角色权限。
4. OpenAPI 调用必须同时校验 Client 状态、有效期、IP 白名单、资源白名单。
5. AppSecret 只在新建或重置时返回一次，数据库只保存强散列。
6. 日志、审计、导出文件、错误信息不得出现 AppSecret 明文。
7. 迁移来的旧 Client 标记为需要重签，不尝试恢复旧密钥。
8. 所有 Client 管理动作、工作量配置写动作必须写入 `audit.audit_logs`。
9. 所有对外 OpenAPI 调用必须写入 `integration.open_api_access_logs`。

## 10. 数据库调整建议

### 10.1 推荐调整

建议为工作量映射补一个最小兼容迁移，使同一套映射能同时承载软件功能和硬件产品。

推荐字段：

| 字段 | 说明 |
| --- | --- |
| `item_type` | `feature` 或 `hardware` |
| `item_id` | 对应软件功能或硬件产品编号 |
| `item_name` | 展示名称冗余，便于导入和审计 |
| `item_code` | 产品编码或硬件型号 |
| `delivery_tags` | 交付产品类型标签 |
| `active` | 启用状态 |

推荐原因：

1. V2 工作量配置页面明确是“软硬件产品”映射。
2. 阶段8 已迁移硬件产品 15 条，报价配置也包含硬件。
3. 只映射软件功能会导致硬件工作量建议缺失。
4. 用结构字段比继续塞 `extra_json` 更稳定，后续百万客户规模下查询和索引更清楚。

### 10.2 临时替代方案

如本阶段不希望调整表结构，可以把硬件映射暂存在 `catalog.workload_mappings.extra_json`，用 `itemType`、`hardwareProductId`、`deliveryTags` 承载。

不推荐原因：

1. 查询和筛选不稳定。
2. 验收时容易出现软件能映射、硬件不能映射的边界问题。
3. 后续仍要补迁移，等于二次返工。

## 11. P0验收标准

1. `/admin/openapi-integration` 显示 V2 OpenAPI 专页，不再显示通用列表。
2. OpenAPI 页面包含对接总览、参数速览、文档下载、Client 凭证管理、调用审计。
3. 能看到迁移来的 4 个 Client，旧密钥不可查看。
4. 可新增 Client，新 AppSecret 只展示一次。
5. 可编辑 Client 的绑定用户、状态、有效期、IP 白名单、资源范围和备注。
6. 可重置 Client 密钥，旧密钥失效，新密钥可换取令牌。
7. 使用新令牌调用对外接口后，调用审计可见记录。
8. `/admin/workload-config` 显示 V2 工作量配置专页，不再显示通用列表。
9. 能看到 49 条产品映射和 15 条新版交付工作量规则。
10. 产品映射可编辑、保存、刷新后回读。
11. 新版交付规则可编辑、保存、刷新后回读。
12. 报价工作量试算读取最新映射和规则。
13. 非超级管理员不能访问或调用这些管理接口。
14. `npm run verify`、后端测试、前端 E2E、页面截图巡检通过。

## 12. P1验收标准

1. OpenAPI 调用日志支持分页、时间筛选、结果筛选。
2. OpenAPI 文档下载清单与 V2 一致。
3. OpenAPI 资源授权展示与 V2 一致，统计分析增强资源按需补齐。
4. 工作量映射支持搜索、编辑后回填、清空、刷新。
5. 工作量配置所有写动作都能在操作日志中查询。
6. OpenAPI 调用失败时，401、403、404 等结果写入调用审计。
7. 密钥重置结果在弹窗关闭后不能再次查看。

## 15. 风险和处理

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 尝试恢复旧 AppSecret | 安全风险且不可行 | 旧密钥统一重签 |
| 工作量映射不支持硬件 | 报价工作量不完整 | 推荐补最小数据库兼容迁移 |
| OpenAPI 权限只做前端限制 | 对外接口越权 | 所有管理和对外接口后端校验 |
| 调用审计不落库 | 无法排查对接问题 | 对外调用统一写 `integration.open_api_access_logs` |
| 工作量改动影响报价金额 | 业务风险 | 工作量只影响建议人天，不改变报价金额 |
| 一次性补全全部 OpenAPI 资源 | 阶段失控 | P0 先核心业务、工作量、审计只读，P1 再增强统计分析 |
