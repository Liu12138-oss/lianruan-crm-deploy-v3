```bash

sudo SERVER_HOST=服务器IP ./scripts/install-all.sh

```

## 4. 运行时方案

当前阶段7.1默认采用：

| 组件 | 版本 | 来源 | 说明 |
| --- | --- | --- | --- |
| Docker静态运行时 | `27.5.1` | Docker官方静态包 | 适合无Docker测试服务器离线验证 |
| Docker Compose插件 | `v2.32.4` | Docker Compose官方发布二进制 | 安装到Docker CLI插件目录 |

说明：

- 静态二进制方案不依赖欧拉具体RPM闭包，适合当前测试服务器快速验证。
- 正式生产如果要求RPM审计闭包，需要拿到实际 `cat /etc/os-release` 后补充对应 openEuler 版本的 RPM 离线闭包。
- 脚本不会自动删除 `podman`、`containerd`、`runc` 等系统包，发现相关包只记录提示，避免破坏服务器已有运行时。
- `download-runtime.sh` 使用 `.part` 临时文件、断点续传、重试和低速保护，避免半截Docker或Compose文件占用正式文件名。
- `package-offline.sh` 在打包前校验运行时SHA256、Docker压缩包可读性和Compose二进制体积及类型，防止损坏运行时进入交付包。

## 5. 安装日志

日志默认目录：

```text
/opt/lianruan-crm-v3/logs/install/
```

主要日志：

| 日志 | 说明 |
| --- | --- |
| `preflight-时间.log` | 安装前检测日志 |
| `install-runtime-时间.log` | Docker和Compose运行时安装日志 |
| `install-all-时间.log` | 一键安装总日志 |

日志要求：

- 成功和失败都必须保留日志。
- 日志必须记录系统架构、系统版本、Docker版本、Compose版本、安装目录和健康检查结果。
- 日志不得输出数据库密码、Redis密码和会话密钥。

## 6. 幂等策略

| 项目 | 策略 |
| --- | --- |
| 已安装Docker | 检测到 `docker` 后跳过二进制覆盖 |
| 已安装Compose | 检测到 `docker compose version` 可用后跳过安装 |
| 已有 `v3.env` | 阶段7 `install.sh` 不覆盖 |
| 已有 `docker-compose.yml` | 阶段7 `install.sh` 不覆盖，新模板写入 `.new` |
| 已有Nginx配置 | 阶段7 `install.sh` 不覆盖，新模板目录写入 `nginx.new` |
| 已有部署变量 | 阶段7 `install.sh` 不覆盖，新模板写入 `.new` |
| 已有密钥 | `generate-secrets.sh` 不应覆盖既有密钥 |
| 已有数据目录 | 只创建目录，不删除数据 |
| 镜像加载 | 允许重复 `docker load` |
| 服务启动 | `docker compose up -d` 可重复执行 |

## 8. 风险和注意事项

| 风险 | 说明 |
| --- | --- |
| 欧拉版本未确认 | 当前截图只有 `x86_64`，还需要生产或测试服务器执行 `cat /etc/os-release` |
| 静态二进制非RPM闭包 | 当前方案便于离线测试部署；正式生产审计可补RPM闭包方案 |
| 运行时冲突 | 如果已有podman/containerd/runc，脚本只提示，不自动删除 |
| Docker数据目录 | 新装Docker默认使用 `/opt/lianruan-crm-v3/runtime/docker-data`，已有Docker不自动迁移 |
| 无HTTPS | 当前仍为HTTP加服务器IP |
| 无正式业务迁移 | 阶段7.1只交付运行时和部署能力，不代表业务上线 |
