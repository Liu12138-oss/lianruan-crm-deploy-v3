## 1. 纠偏结论

当前 V3 不能定义为“完全交付”。  

更准确的状态是：V3 数据迁移已经完成，底层工程、容器部署、PostgreSQL、Redis、基础认证、基础业务接口和部分主链路自动化验证已经具备；但管理端真实页面、字段、按钮、页签、路由命中和人工业务流程与 V2 旧测试环境仍存在明显差距，尚未达到“V2 用户低感知切换”的验收标准。

本轮以用户提供的 V2 测试环境作为真实基线，已完成 17 个关键管理端页面截图对比和结构化差异记录。对比结果显示，V3 当前最大问题不是单纯颜色或间距，而是页面结构、业务动作和流程入口没有完整还原。

## 3. 已确认的严重问题

### 3.1 新建客户报备页面错位

V2 路由 `/registration/new` 是三步表单，包含客户信息、指派渠道、提交确认。  
V3 路由 `/admin/registration/new` 当前截图显示为客户报备列表页，不是新建表单。

影响：

1. 用户无法按 V2 方式完成新建客户报备。
2. 新建后审核中心不可见的问题大概率与页面提交动作、状态写入、待办生成链路有关。
3. 这是主业务链路第一步，必须优先修复。

### 3.2 审核中心没有还原 V2 审核台

V2 审核中心包含客户报备、渠道商、员工三个页签，并有通过、拒绝动作。  
V3 当前是通用待办列表，表头和动作均不一致。

影响：

1. 用户创建客户报备后，在审核中心无法按 V2 方式处理。
2. 报备保护、待审核、审核通过、审核拒绝这些状态没有形成可见闭环。
3. 管理员无法真实替代 V2 的审核工作台。

### 3.3 新建商机页面没有还原 V2 表单

V2 新建商机字段约 12 个，包含客户、合作伙伴、负责人、阶段、金额、预计关闭、项目描述等信息。  
V3 当前页面字段明显减少，并且抓图显示仍接近列表视图。

影响：

1. 报备客户到报备商机的流程不完整。
2. 商机信息承载不足，后续报价、订单链路缺少业务上下文。

### 3.4 新建报价没有还原 V2 智能报价配置器

V2 新建报价包含基本信息、报价方式、产品选择、硬件配置、报价汇总等结构。  
V3 当前页面仍未达到 V2 的配置器级别体验。

影响：

1. 渠道用户无法按原流程完成报价。
2. 报价转订单前的数据完整性存在风险。

### 3.5 账号管理、企业管理员、开放接口、工作量配置仍是通用页面

V2 这些页面都有明确业务结构：

1. 账号管理：超级管理员、大区管理员、员工导入、导出、重置密码、停用。
2. 企业管理员：创建企业管理员、现有企业管理员、使用说明。
3. 开放接口对接：对接总览、参数速览、文档下载、凭证管理、调用审计。
4. 工作量配置：标准工作量、产品映射规则、交付工作量规则。

V3 当前多处仍显示为通用表格或通用待办结构。

影响：

1. 后台管理能力不可用或不可验收。
2. 导入导出、接口对接、工作量配置无法支撑真实运营。

### 3.6 经营报表和渠道管理体感不足

V2 经营报表包含渠道商排名、级别分布、区域分布、技术服务商分布、经营明细。  
V3 当前更像渠道列表或简化报表。

影响：

1. 管理端查看渠道经营状态的能力不足。
2. 后续总部运营分析无法按原习惯执行。

## 5. 修复优先级

### 一级：必须先修主链路

目标：用户能按 V2 习惯完成客户报备、审核、商机、报价、订单闭环。

1. 修复 `/admin/registration/new`，必须显示 V2 三步新建客户报备表单。
2. 修复新建客户报备提交动作，必须生成待审核记录。
3. 修复 `/admin/admin-review`，必须展示 V2 审核中心页签、字段和通过/拒绝按钮。
4. 修复审核通过后客户报备状态、保护期、审核记录、操作日志。
5. 修复从客户报备进入报备商机入口。
6. 修复 `/admin/opportunity/new`，按 V2 字段和流程创建商机。
7. 修复 `/admin/quote/new`，按 V2 智能报价配置器创建报价。
8. 修复报价列表转订单、订单确认流程。

一级验收标准：

1. 新建客户报备后，审核中心立即可见待审核记录。
2. 审核通过后，客户报备列表状态正确变化。
3. 从报备客户可以创建商机。
4. 商机可以创建报价。
5. 报价可以转订单。
6. 订单可以确认。
7. 以上流程必须使用真实后端数据，不只使用前端模拟数据。

### 二级：恢复总部后台管理能力

目标：总部管理员能完成 V2 已有运营配置。

1. 账号管理按 V2 分组和按钮恢复。
2. 企业管理员创建、编辑、停用、重置密码、删除恢复。
3. 渠道商管理新增、编辑、删除、导入、导出恢复。
4. 操作日志按 V2 筛选字段和详情恢复。
5. 开放接口对接页面恢复凭证、文档、审计结构。
6. 工作量配置恢复产品映射和规则维护。

二级验收标准：

1. 页面字段、页签、表头、按钮与 V2 对照一致。
2. 所有按钮有真实动作或明确禁用说明，不能只是展示。
3. 导入导出可下载结果，失败行可追溯。

### 三级：恢复报表和细节体感

目标：用户视觉和操作习惯接近 V2，减少切换阻力。

1. 总览仪表盘恢复近期商机、最近报价单、主力产品线、销售漏斗。
2. 经营报表恢复排名、级别分布、区域分布、技术服务商分布、经营明细。
3. 产品目录恢复软件和硬件分区。
4. 分页、筛选、按钮文案、表格密度继续按 V2 调整。
5. 手机端跟随一级主链路复核。

## 7. 开发原则

1. V2 旧测试环境和 V2 源码只读参考，不修改 V2。
2. 不新增公海池等新功能，本轮只恢复 V2 已有页面和流程。
3. 优先修断路由、断流程、断动作，再修视觉细节。
4. 所有关键页面必须用真实后端数据验证。
5. 不再只用“页面可打开”作为验收标准，必须验证字段、按钮、状态流转和数据落库。
6. 每次发布 HexHub 前必须执行本地验证、接口验证、截图巡检。
7. 每次发布 HexHub 后必须重跑远端健康检查和主链路验收。
