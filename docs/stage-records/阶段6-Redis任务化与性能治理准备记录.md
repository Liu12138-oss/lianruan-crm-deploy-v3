## 3. 运维结论

- 12 核 32GB 可以作为 V3 单机容器首发资源起点，但必须强制执行连接池、队列并发、导出并发、缓存大小和查询超时限制。
- Redis 不作为业务唯一事实源。任务事实必须在 PostgreSQL，Redis 清空后可以补投。
- 建议即使单机也拆分 `redis-state` 和 `redis-cache` 两个实例，避免缓存淘汰影响会话和队列。
- 暂无备用服务器时，无法承诺整机故障 30 分钟接管；只能承诺容器和进程级恢复。上线必须具备异机备份和恢复演练。

## 4. 风险

| 风险 | 影响 | 当前处理 |
| --- | --- | --- |
| 暂不准备备用服务器 | 整机故障恢复时间不可控 | 架构预留接管流程，阶段7要求签字接受例外 |
| 单机同时承载数据库、接口、任务和 Redis | 高峰时资源争用 | 队列并发和数据库连接预算分离 |
| Redis 单实例混用 | 缓存淘汰可能影响队列和会话 | 建议拆分状态实例和缓存实例 |
| 百万客户规模导出和统计 | 容易拖慢普通查询 | 必须任务化、游标读取、统计刷新分离 |
| 历史权限和数据范围不统一 | 缓存可能放大越权风险 | 权限缓存必须短期、带授权版本、可精准失效 |
