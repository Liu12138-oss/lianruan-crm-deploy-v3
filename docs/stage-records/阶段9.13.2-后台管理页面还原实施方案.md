## 1. 目的

阶段9.13.2 的目的，是把 V2 已有后台管理页面按真实页面、真实字段、真实按钮、真实流程还原到 V3 新架构中。

本阶段不是新增后台功能，也不是重新设计管理后台。V3 只是替换底层架构、数据库、认证、部署和稳定性能力，不能改变总部管理员和区域管理员在 V2 中已经熟悉的后台管理体感。

阶段9.13.2 完成后，管理员应能继续按 V2 习惯完成账号管理、企业管理员管理、渠道商管理、操作日志查询、导入导出等后台运营动作。

## 3. 不做范围

1. 不新增公海池、线索池、营销活动等 V2 没有的功能。
2. 不修改 V2 源码和 V2 数据库。
3. 不恢复 V2 用户旧密码，继续使用 V3 初始化密码和重置密码策略。
4. 不改变 V2 的菜单命名、字段命名、按钮文案和主流程。
5. 不在本阶段重做经营报表、产品目录和手机端后台，这些归入阶段9.13.4。
6. 不直接把 V2 `admin-app.js` 整体复制进 V3 作为长期方案，只提取页面结构和流程，在 V3 Vue 工程中实现。

## 5. 当前问题判断

当前 V3 这些页面多为通用列表承载，已经具备基础路由和部分查询能力，但没有达到 V2 专页标准。

主要问题：

1. `/admin/account-manage` 仍偏通用账号列表，缺 V2 的统计卡、大区分组、管理员账号弹窗和账号动作。
2. `/admin/partner-admin` 没有完整还原 V2 左右双栏、企业管理员审批和使用说明。
3. `/admin/partners` 需要继续补齐 V2 表格列、分销层级、详情、员工管理和删除校验体感。
4. `/admin/audit-logs` 需要从通用审计数据恢复为 V2 审计专页。
5. 导入页目前偏本地预检留口，需要补为 V2 的模板、上传、预览、确认、结果链路。
6. 后端当前对账号、渠道商、审计、导入导出以查询为主，写操作、审计记录和权限拦截需要补齐。

## 6. V2真实页面结构

### 6.1 账号管理

V2 账号管理是超级管理员专属页面。

页面结构：

1. 顶部统计卡：超管账号数、区管账号数、启用区管、停用区管。
2. 右上动作：新增超管、工作量配置、员工账号导出、批量导入。
3. 超级管理员列表：账号、姓名、角色、状态、创建时间、备注、操作。
4. 大区管理员分组：大东区、大南区、西区、大北区，每组独立表格。
5. 行操作：编辑、重置密码、停用或启用、删除。
6. 新增/编辑弹窗：账号类型、所属大区、负责区域、登录账号、管理员姓名、头像字、状态、备注、初始密码提示。

### 6.2 企业管理员

页面结构：

1. 页面标题：企业管理员。
2. 页面说明：为渠道企业创建企业管理员账号，企业管理员可查看本企业所有员工的数据。
3. 左侧创建表单：登录账号、姓名、联系电话、邮箱、所属渠道企业、创建企业管理员按钮。
4. 右侧现有企业管理员：头像、姓名、所属企业、登录账号、状态、编辑、启用/禁用、重置密码、删除。
5. 超管待审批表格：账号、姓名、所属企业、联系电话、提交人、提交时间、通过、驳回。
6. 底部使用说明：企业管理员、普通员工、登录入口、审批规则。

### 6.3 渠道商管理

页面结构：

1. 搜索筛选：渠道商名称、联系人、城市关键字；合作级别；区域。
2. 顶部动作：新增渠道商、导出、批量导入。
3. 表格列：渠道商名称、级别、区域、联系人/电话、销售人数、报价/订单、累计金额、状态、操作。
4. 标签：合作级别、一级渠道商、二级渠道商、无层级、签约技术服务商、提名技术服务商、合作状态。
5. 新增/编辑弹窗：企业名称、合作级别、技术服务类型、所属区域、所在城市、联系人、联系电话、邮箱、状态。
6. 详情弹窗：渠道商信息简介、销售团队、企业基本信息、渠道资质认证、经营画像、行业产品矩阵。
7. 员工管理：添加员工、编辑员工、启用/禁用、重置密码、删除。
8. 分销层级管理：无层级、一级渠道商、二级渠道商；二级渠道商可绑定多个一级渠道商。
9. 删除校验：删除前校验账号、报备、商机、报价、订单、下级渠道和待审批数据。

### 6.4 操作日志

页面结构：

1. 筛选项：模块、动作、结果、开始日期、结束日期、关键词。
2. 操作按钮：查询、重置。
3. 表格列：时间、操作人、角色、模块、动作、对象、结果、说明、详情。
4. 分页：总数、页码、每页数量、上一页、下一页。
5. 详情弹窗：时间、请求编号、操作人、来源、对象、结果、说明、变更内容、变更前、变更后、附加信息。
6. 权限提示：非超级管理员不可查看敏感审计日志。

### 6.5 导入导出

导入页面结构：

1. 页面说明卡。
2. 下载导入模板。
3. 上传 Excel 文件。
4. 自动预检并显示文件名。
5. 预览表格：行号、字段列、状态。
6. 错误行中文原因。
7. 确认导入按钮。
8. 导入结果：新增、更新、失败、错误明细。

导出动作结构：

1. 列表页直接点击导出。
2. 按当前筛选条件导出。
3. 文件名包含实体名称和日期。
4. 导出失败时显示中文错误。

## 7. 数据和接口要求

### 7.1 账号管理接口

| 能力 | 接口建议 | 要求 |
| --- | --- | --- |
| 查询账号 | `GET /api/users` | 支持角色、区域、关键字、状态筛选 |
| 创建管理员 | `POST /api/admin/accounts` | 仅超管；默认密码按初始化策略生成 |
| 编辑账号 | `PUT /api/users/:id` | 可改姓名、头像、区域、状态、备注 |
| 修改状态 | `PUT /api/users/:id/status` | 启用、停用，内置超管限制停用 |
| 重置密码 | `PUT /api/users/:id/password` | 仅管理员；写审计 |
| 删除账号 | `DELETE /api/users/:id` | 删除前校验关联数据；写审计 |

### 7.2 企业管理员接口

| 能力 | 接口建议 | 要求 |
| --- | --- | --- |
| 查询渠道商 | `GET /api/partners` | 创建时选择所属渠道企业 |
| 创建企业管理员 | `POST /api/users` | 超管创建直接生效，区域管理员创建需审批 |
| 查询待审批 | `GET /api/approvals` | 类型包含企业管理员 |
| 处理审批 | `PUT /api/approvals/:id` | 通过后启用，驳回后记录原因 |
| 编辑、停用、重置、删除 | 复用用户接口 | 每个动作写审计 |

### 7.3 渠道商管理接口

| 能力 | 接口建议 | 要求 |
| --- | --- | --- |
| 查询渠道商 | `GET /api/partners` | 支持级别、区域、状态、关键字和分页 |
| 新增渠道商 | `POST /api/partners` | 字段按 V2；区域管理员创建需符合区域权限 |
| 编辑渠道商 | `PUT /api/partners/:id` | 保留主档、级别、区域、联系人、技术服务类型 |
| 删除渠道商 | `DELETE /api/partners/:id` | 必须做关联阻断校验 |
| 分销层级 | `PUT /api/partners/:id/level` | 支持无层级、一级、二级、多上级 |
| 渠道员工 | `POST/PUT/DELETE /api/partners/:id/staff` | 保留员工账号操作 |

### 7.4 操作日志接口

| 能力 | 接口建议 | 要求 |
| --- | --- | --- |
| 查询日志 | `GET /api/audit-logs` | 支持模块、动作、结果、日期、关键字、分页 |
| 查看详情 | `GET /api/audit-logs/:id` | 返回请求编号、来源、变更前后、附加信息 |

### 7.5 导入导出接口

| 能力 | 接口建议 | 要求 |
| --- | --- | --- |
| 模板下载 | `GET /api/import/:type/template` | 返回 Excel 或兼容 CSV 模板 |
| 导入预检 | `POST /api/import/:type/preview` | 返回预览行、错误行、总数、错误数 |
| 执行导入 | `POST /api/import/:type/execute` | 写入任务和结果，失败行可追踪 |
| 导出 | `GET /api/export/:type` | 按筛选导出文件 |
| 导入任务 | `GET /api/import-export/tasks` | 返回任务状态和结果 |

## 8. 权限要求

1. 超级管理员：可管理全部账号、渠道商、企业管理员、审计日志、导入导出。
2. 区域管理员：只能管理本区域渠道商、企业管理员申请和本区域业务数据；不能查看全局敏感审计。
3. 渠道企业管理员：不进入管理后台，只在渠道端查看本企业员工数据。
4. 渠道员工：不进入管理后台，只看自己业务数据。
5. 所有写操作必须经过后端鉴权，不能只靠前端隐藏按钮。
6. 所有敏感动作必须写入操作审计：创建、编辑、启停、删除、重置密码、审批、导入、导出。

## 9. P0验收标准

1. `/admin/account-manage` 显示 V2 账号管理专页，不再显示通用列表。
2. 账号管理包含统计卡、超级管理员列表、大区管理员分组、行操作和新增/编辑弹窗。
3. `/admin/partner-admin` 标题为“企业管理员”，包含创建表单、现有企业管理员、待审批和使用说明。
4. `/admin/partners` 保留 V2 搜索、级别筛选、区域筛选、新增、导出、批量导入和 V2 表格列。
5. `/admin/audit-logs` 包含模块、动作、结果、日期、关键词筛选，支持日志详情弹窗。
6. 四类导入页面至少完成模板下载、上传预检、错误行展示、确认导入、结果展示。
7. 列表导出可下载当前筛选结果。
8. 超管、区域管理员、普通渠道账号的菜单和接口权限不越权。
9. 所有页面按钮、空状态、错误信息为标准简体中文。
10. 页面截图与 V2 基线逐页对照并记录差异。

## 10. P1验收标准

1. 企业管理员审批通过或驳回后，账号状态和审计日志同步更新。
2. 渠道商分销层级支持多上级绑定，页面标签与 V2 一致。
3. 渠道商删除前阻断关联数据，提示具体阻断原因。
4. 导入失败结果可下载错误行文件。
5. 导出文件名包含模块名称和日期。
6. 操作日志详情展示变更前、变更后、附加信息，并支持分页。
7. 区域管理员筛选和数据范围与服务端一致。

## 13. 风险和处理

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 通用列表继续承载后台专页 | 用户体感继续不像 V2 | 必须拆专页结构 |
| 写接口补齐后越权 | 生产数据风险 | 后端角色和数据范围校验先于前端按钮 |
| 导入导出一次性做太重 | 阶段延期 | P0 先完成模板、预检、确认、结果，P1 再补错误文件下载增强 |
| 删除渠道商误删关联数据 | 数据破坏 | 删除前做强阻断校验 |
| 密码重置泄漏 | 安全风险 | 只展示初始化结果，不记录明文到日志 |
| 操作日志字段来源不齐 | 详情空洞 | 优先展示已有字段，缺失字段用中文空值，不造假 |

## 14. 开发前确认项

当前阶段9.13.2 无需额外业务确认，可以按本方案进入开发。

默认执行口径：

1. 页面结构严格按 V2。
2. 权限以超管最高、区域管理员按区域、渠道账号不进后台为准。
3. 账号密码不恢复旧密码，继续使用初始化和重置策略。
4. 导入导出 P0 先完成真实预检、确认执行和结果记录，错误文件下载作为 P1 增强。
