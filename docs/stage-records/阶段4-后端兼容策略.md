# 阶段4后端兼容策略

生成时间：2026-07-23T11:11:53.654Z

## 旧路径兼容

- 阶段4迁移期间保留现有 `/api`、`/api/mobile`、`/api/mobile/v2`、`/api/open/v1` 和 `/api/open-api` 路径。
- 新旧入口不能维护两套业务规则；旧入口只做请求字段映射、响应字段映射和错误映射，然后调用同一个领域服务。
- 兼容层记录接口编号、调用页面、调用版本、操作者、结果、耗时和失败原因，用于退出旧路径。
- 已确认无调用方的旧接口只能进入废弃候选清单，不能在阶段4直接删除。

## 新服务端鉴权接入

- 阶段3合入后，所有业务接口统一从服务端会话、令牌或开放接口客户端取得身份和数据范围。
- 旧请求中的 `operatorId`、`operatorRole`、`userId`、`region`、`partnerId` 等字段只允许作为兼容输入或筛选条件，不能决定授权。
- 移动端一期、移动端二期和桌面端调用同一领域服务，移动端只保留响应映射差异。
- 权限拒绝、状态冲突、重复请求和数据范围错误使用稳定中文错误；审计记录保留兼容来源。

## 开放接口兼容期

- 已发布 `/api/open/v1` 路径保持兼容，不在阶段4改版本号或删除字段。
- 建议兼容期不少于一个正式版本或90天；最终日期以实际调用方确认单为准。
- 新增字段只能向后兼容；字段收窄、敏感字段移除、错误码调整必须列入差异清单并提供灰度验证。
- 客户端密钥迁移为摘要存储，重置密钥只显示一次；访问日志和限流由服务端执行。

## 回退原则

- 本阶段不进行生产切换；每个模块使用路由开关在测试或预生产环境单独灰度。
- 数据结构采用扩展方式，代码回退不删除新增表、列、索引和事件历史。
- 写接口迁移前必须准备独立数据副本，新旧对照只比较业务事实和审计语义。
