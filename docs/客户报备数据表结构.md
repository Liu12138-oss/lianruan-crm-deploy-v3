# 联软 CRM V3 客户报备数据表结构

> 来源：`database/migrations/20260723_S2_004_业务主链路.sql`、`20260811_KB016_报备保护期与状态修复.sql`、`20260812_S9_023_客户报备业务编号统一.sql` 等正式迁移。
> 配套参考 DDL：`docs/客户报备数据表结构.sql`。生产数据库变更一律以 `database/migrations` 正式迁移为准。

## 一、核心表

### 1. crm.customers 客户主档

| 字段 | 类型 | 约束/说明 |
| --- | --- | --- |
| id | uuid | 主键，默认 `gen_random_uuid()` |
| customer_name | text | 客户名称，必填 |
| normalized_name | text | 归一化名称，查重依据，必填 |
| credit_code | text | 统一社会信用代码 |
| region_id | uuid | 外键 `org.regions(id)` |
| city_name | text | 城市名称 |
| owner_user_id | uuid | 外键 `iam.users(id)`，负责人 |
| owner_partner_id | uuid | 外键 `channel.partners(id)`，归属渠道 |
| status_code | text | `active / disabled / merged`，默认 `active` |
| merged_to_customer_id | uuid | 外键自身，合并目标客户 |
| created_at / updated_at | timestamptz | 默认 `now()` |
| extra_json | jsonb | 扩展字段 |

- 唯一索引：`ux_customers_normalized_active`（`normalized_name`，`status_code <> 'merged'`）
- 普通索引：`idx_customers_owner_partner`（`owner_partner_id, status_code`）

### 2. crm.customer_aliases 客户别名

| 字段 | 类型 | 约束/说明 |
| --- | --- | --- |
| id | uuid | 主键 |
| customer_id | uuid | 外键 `crm.customers(id)`，级联删除 |
| alias_name | text | 别名 |
| normalized_alias | text | 别名归一化 |
| source_code | text | 别名来源 |

- 唯一约束：`(normalized_alias, source_code)`

### 3. crm.registrations 客户报备

| 字段 | 类型 | 约束/说明 |
| --- | --- | --- |
| id | uuid | 主键，默认 `gen_random_uuid()` |
| v2_source_id | text | V2 迁移来源 ID，唯一 |
| registration_no | text | 报备编号，唯一，格式 `BB-提报账号-YYYYMMDD-流水` |
| customer_id | uuid | 外键 `crm.customers(id)`，禁止删除（RESTRICT） |
| partner_id | uuid | 外键 `channel.partners(id)`，报备渠道 |
| owner_user_id | uuid | 外键 `iam.users(id)`，报备负责人 |
| region_id | uuid | 外键 `org.regions(id)`，报备区域 |
| status_code | text | `draft / pending / approved / rejected / cancelled / converted` |
| submitted_at | timestamptz | 提交时间 |
| approved_at | timestamptz | 审批通过时间 |
| created_at / updated_at | timestamptz | 默认 `now()` |
| row_version | bigint | 乐观锁，默认 1 |
| extra_json | jsonb | 扩展字段 |

- 索引：`idx_registrations_partner_status`（`partner_id, status_code, created_at DESC`）
- 索引：`idx_registrations_region_status`（`region_id, status_code, created_at DESC`）
- 保护期（KB016）：`extra_json.protectDays`（默认 180 天）、`extra_json.expireAt`（保护到期日 `YYYY-MM-DD`）

| 字段 | 类型 | 约束/说明 |

| extra_json | jsonb | 扩展字段 |

### 5. crm.business_number_counters 业务编号计数器

| 字段 | 类型 | 约束/说明 |
| --- | --- | --- |
| document_type | text | `registration / quote / order / opportunity` |
| submitter_username | text | 提报账号（商机固定为 `global`） |
| business_date | date | 业务日期（上海时区自然日） |
| current_value | integer | 当前日流水，`> 0` |

- 编号函数：`crm.next_business_number('registration', 用户名)` 生成 `BB-账号-YYYYMMDD-4位流水`

## 三、报备状态机

```
draft(草稿) → pending(待审核) → approved(已通过) → converted(已转商机)
                ↓                 ↓
             rejected(驳回)    cancelled(取消)
```

- 状态变更留痕在 `crm.registration_events`。
- 报备审批记录在 `ops.approvals`（`target_type='registration'`），审批事件在 `ops.approval_events`。
- 已通过报备默认保护 180 天（`extra_json.protectDays`），到期日写入 `extra_json.expireAt`。

## 四、extra_json 常用业务字段（报备）

| 字段 | 说明 |
| --- | --- |
| assignedStaffId | 归属员工 ID（V2 来源或负责人映射） |
| submittedByUsername | 提报账号用户名 |
| protectDays | 报备保护天数，默认 180 |
| expireAt | 保护到期日 `YYYY-MM-DD` |
| legacyBusinessNumber | 历史旧编号（S9_023 统一编号时保留） |
| businessNumberNormalizedBy | 编号统一标记（如 `S9_023`） |
| statusRepair / protectionBackfilledBy | 历史数据修复标记（KB016） |

## 五、查询示例

```sql
-- 报备列表（含客户、渠道、区域、负责人）
SELECT
  r.registration_no,
  r.status_code,
  r.submitted_at,
  r.approved_at,
  c.customer_name,
  c.credit_code,
  p.partner_name,
  rg.region_name,
  u.display_name AS owner_name,
  r.extra_json->>'expireAt' AS protect_expire_at
FROM crm.registrations r
LEFT JOIN crm.customers c      ON c.id = r.customer_id
LEFT JOIN channel.partners p   ON p.id = r.partner_id
LEFT JOIN org.regions rg       ON rg.id = r.region_id
LEFT JOIN iam.users u          ON u.id = r.owner_user_id
ORDER BY r.created_at DESC;

-- 待审核报备数量
SELECT count(*) FROM crm.registrations WHERE status_code = 'pending';
```
