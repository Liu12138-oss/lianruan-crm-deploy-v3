# 生产 V3 数据同步到测试环境操作手册

- 适用版本：V3 单机部署（`deploy/single-server`），生产与测试均为 Docker Compose 部署
- 数据方向：生产（只读导出）→ 测试（覆盖导入）；**任何步骤都不会写生产数据**
- 配套脚本：
  - 生产侧只读导出：`deploy/single-server/scripts/导出生产V3测试迁移包.sh`
  - 测试侧覆盖导入：`deploy/single-server/scripts/导入生产V3数据到测试.sh`

## 一、安全边界

- 导出脚本只执行 `pg_dump` 一致性只读快照 + 打包 `data/uploads`，不停服务、不修改生产任何数据；建议在低峰执行。
- 迁移包只包含 PostgreSQL 逻辑备份和上传附件，不含 Redis、配置、密钥、导出文件。
- 导入脚本只允许在「已具备当前最新迁移记录」的测试库执行，防止误对生产库执行覆盖。
- 导入默认不启动业务服务、导入时自动推进事件截止时间，避免回放历史事件对外发起 OA / 企微 / 通知。

## 二、第一步：在生产服务器只读导出（不改生产数据）

```bash
# 生产服务器（需要 root）
sudo bash /opt/lianruan-crm-v3/scripts/导出生产V3测试迁移包.sh
```

如果生产服务器上还没有该脚本，先仅复制脚本文件过去（不涉及数据修改）：

```bash
scp deploy/single-server/scripts/导出生产V3测试迁移包.sh root@<生产服务器>:/tmp/
ssh root@<生产服务器> "install -m 750 /tmp/导出生产V3测试迁移包.sh /opt/lianruan-crm-v3/scripts/"
```

产物（默认输出到 `/opt/lianruan-crm-v3/backups/transfer/`）：

- `v3-production-to-test-<时间戳>.zip`：迁移包（postgres.sql + uploads.zip + manifest.env + SHA256SUMS）
- `v3-production-to-test-<时间戳>.zip.sha256`：外层校验文件

## 三、第二步：把迁移包传到测试服务器

```bash
scp "v3-production-to-test-<时间戳>.zip" "v3-production-to-test-<时间戳>.zip.sha256" root@10.9.86.66:/tmp/
```

## 四、第三步：测试服务器先干跑检查（不改任何数据）

```bash
# 测试服务器
sudo bash /opt/lianruan-crm-v3/scripts/导入生产V3数据到测试.sh \
  --package /tmp/v3-production-to-test-<时间戳>.zip
```

检查通过时会输出：

- 包内 `postgres.sql / uploads.zip / manifest.env` 校验成功
- `测试环境保护校验通过：已检测到最新迁移 ...`
- `当前为检查模式，未停止服务、未备份、未修改测试数据。`

前置条件（不满足会直接拒绝执行）：

- `config/v3.env` 中 `MESSAGE_WORKER_ENABLED`、`MESSAGE_WECOM_GROUP_ENABLED`、`MESSAGE_SMS_ENABLED`、`MESSAGE_EMAIL_ENABLED` 全部为 `false`
- 测试库已登记 `database/migrations` 中的最新迁移

## 五、第四步：正式导入（覆盖测试数据）

```bash
# 测试服务器
sudo bash /opt/lianruan-crm-v3/scripts/导入生产V3数据到测试.sh \
  --package /tmp/v3-production-to-test-<时间戳>.zip \
  --execute \
  --confirm 覆盖测试V3数据 \
  --start-services
```

脚本执行顺序：

1. 停止测试 nginx、api、worker、消息/预审任务进程（保留 postgres、redis）
2. 备份测试库、上传附件、导出文件到 `/opt/lianruan-crm-v3/backups/local/<时间戳>-production-data-import-preimport`
3. 清空测试 Redis、重建测试数据库并恢复生产备份
4. 用测试服务器当前迁移目录补齐数据库结构（含最新迁移）
5. 恢复测试附件（解压时校验越界路径），并把 `data/uploads` 属主调整为应用用户（1000:1000）
6. 把 `ORDER_PREAPPROVAL_EVENT_CUTOVER_AT`、`MESSAGE_EVENT_CUTOVER_AT`、`QUOTE_PROFIT_EVENT_CUTOVER_AT` 推进到导入时刻（备份为 `config/v3.env.bak-before-import-<时间戳>`），防止任务进程回放历史事件
7. 输出迁移版本、核心记录数、附件文件数
8. `--start-services` 时启动测试服务；不带该参数则保持停止，稍后手动执行：

```bash
sudo INSTALL_ROOT=/opt/lianruan-crm-v3 bash /opt/lianruan-crm-v3/scripts/start.sh
```

## 六、第五步：导入后核对

- 健康检查：`sudo INSTALL_ROOT=/opt/lianruan-crm-v3 bash /opt/lianruan-crm-v3/scripts/health-check.sh`
- 页面核对：`http://10.9.86.66`，账号 `liulonghai / LrCRM@2026!`（超管）、`chenqinyu / 123456`（区管）、`liulongfei / 123456`（渠道）
- 任务进程：导入后消息、预审进程默认仍为关闭；需要启用时先核对 `config/v3.env` 的开关与事件截止时间，再按运维文档以对应 profile 启动
- 企业微信成员映射缺口（区管 `admin_west`、`fangmiaoqin`、`linhaowen`）属数据问题，需管理员补录后才能自动建群

## 七、回退

- 数据回退：使用导入时输出的测试回退备份目录（`backups/local/<时间戳>-production-data-import-preimport`）恢复测试库与附件。
- 代码回退：`cd /opt/lianruan-crm-v3/compose && cp .env.bak-before-r42-protolign42 .env && docker compose up -d --no-deps api-1 api-2 worker`（回到 R41 的 `protolign38`）。
- 事件截止时间回退：恢复 `config/v3.env.bak-before-import-<时间戳>`。

## 八、边界说明

- 生产数据只读：导出脚本不包含任何写操作；测试导入不会反向写回生产。
- 若生产库缺少测试环境已有的迁移，导入后由测试服务器的迁移目录自动补齐；这也是「导入后必须跑 migrate-db.sh 并复核最新迁移」的原因。
- 迁移包包含业务数据与附件，属于敏感文件：传输后只在测试服务器 `/tmp` 暂存，导入完成后按数据安全要求删除。
