# 管理员角色与权限体系改造方案（单轨落地）

> 版本：v1.1（2026-08-21）
> 状态：已按单轨方案实施并完成本地与测试环境验证
> 关联文档：`docs/V3业务平台底座与业务扩展实施交付方案.md`（第 7.8 节、附录 E）、`docs/operations/组织架构内嵌管理员页面改造方案.md`
> 目标版本：V3 工程化应用（`apps/api`、`apps/web/public/admin-app.js`）

---

## 1. 背景与目标

### 1.1 现状问题

当前权限体系是**固定角色硬编码**：

- 角色固定为 `superadmin`（超级管理员）、`region_manager`（区域管理员）、`admin`（管理员）、`partner_admin`（渠道管理员）、`staff`（销售代表）。
- 角色权限在数据库 `iam.role_permissions` 中已按角色预置（每角色 10~16 个权限点），但**登录会话只带单一角色**，前端菜单与后端接口全部靠 `role === "superadmin"` / `roleCode === "region_manager"` 硬编码判断。
- 数据范围 `iam.data_scope_bindings` 表已建但**未配置数据**，区域范围靠 `region_manager` 角色硬编码推导。
- 用户与角色是多对多绑定（`iam.user_roles`），但页面没有「给用户分配/撤销角色」的管理界面。

### 1.2 改造目标

1. **管理员角色可编辑**：管理员角色（超管、区管、管理员、企业管理员、自定义角色）支持新建、编辑、停用，可配置「业务权限」与「组织范围」。
2. **用户可分配多个角色**：创建用户时可勾选角色（可不选 = 普通账号），创建后可随时增删角色。
3. **业务权限精细化**：商机、客户报备、报价、订单、经营报表、产品目录、渠道商管理、审核中心、操作日志、消息渠道、开放接口、工作量等按资源 + 动作拆分。
4. **用户权限精细化**：组织架构、账号管理按资源 + 动作拆分，并可配置可管理的部门、用户、渠道组织（大区/区域/渠道商）等组织范围。
5. **主链不回归**：既往业务主链路（商机/报备/报价/订单/审核/登录/单点登录）不受影响，数据与业务平滑迁移。

### 1.3 范围边界

- 渠道侧身份（`channel.partner_members` 企业管理员/普通成员）保持独立，不参与厂商侧角色体系。
- `superadmin` 为系统内置角色，不可删除、不可编辑，保证账号安全与单点登录兜底。
- 本期只做「管理员角色」管理，不改造渠道侧权限。

## 2. 数据模型设计

### 2.1 权限点字典（资源 × 动作）

动作统一四档：`read`（查看）、`create`（新增）、`edit`（修改）、`delete`（删除），加 `approve`（审核）、`admin`（管理）。

| 资源       | 权限点                                 | 说明                           |
| ---------- | -------------------------------------- | ------------------------------ |
| 商机       | `opportunity:read/create/edit/delete`  | 商机列表、详情、跟进、状态流转 |
| 客户报备   | `registration:read/create/edit/delete` | 报备池、报备单                 |
| 报价       | `quote:read/create/edit/delete`        | 报价单                         |
| 订单       | `order:read/create/edit/delete`        | 订单                           |
| 经营报表   | `report:read`                          | 经营报表页                     |
| 产品目录   | `catalog:read/create/edit/delete`      | 产品与目录                     |
| 渠道商管理 | `partner:read/create/edit/delete`      | 渠道商、企业管理员             |
| 审核中心   | `review:read/approve`                  | 审批流（区管/超管确认）        |
| 操作日志   | `audit:read`                           | 操作日志页                     |
| 消息渠道   | `message:read/admin`                   | 消息渠道配置                   |
| 开放接口   | `openapi:admin`                        | OpenAPI 对接                   |
| 工作量     | `workload:admin`                       | 工作量配置                     |
| 组织架构   | `organization:read/create/edit/delete` | 组织树、成员、部门             |
| 账号管理   | `account:read/create/edit/delete`      | 账号列表、角色分配、停用、删除 |

> 兼容映射：现有 `resource:write` 权限点迁移后拆分为 `resource:create/edit/delete` 三个，原已分配 write 的角色自动获得三者，能力不缩水。

### 2.2 角色表扩展

沿用 `iam.roles`，新增语义字段（写入 `extra_json`，不 ALTER 表结构）：

```json
{
  "isSystem": true,
  "builtinTemplate": "superadmin",
  "defaultScopes": ["all"]
}
```

- `isSystem: true`：系统内置角色（superadmin），不可删、不可编辑、不可停用。
- `builtinTemplate`：内置模板标识（superadmin/region_manager/admin/partner_admin/staff），新角色可复制。
- `defaultScopes`：模板默认组织范围。

### 2.3 数据范围表复用

沿用 `iam.data_scope_bindings`：

| scope_type    | scope_ref_id 含义          | 说明                        |
| ------------- | -------------------------- | --------------------------- |
| `all`         | 空                         | 全局所有数据（仅超管模板）  |
| `org_subtree` | 内部组织树节点 id          | 该部门及其全部子部门与成员  |
| `region`      | 渠道组织树大区/区域节点 id | 该大区/区域下的渠道商与成员 |
| `partner`     | 渠道商 id                  | 单个渠道商                  |
| `self`        | 空                         | 仅本人数据                  |

- 一个角色可配**多条**范围，一条绑定 = 一个范围项。
- 用户多角色范围取**并集**。

### 2.4 用户角色分配

- 沿用 `iam.user_roles`，一个用户可挂多个角色。
- 权限 = 全部角色权限并集；范围 = 全部角色范围并集。
- 用户无角色 = 普通账号（可登录，仅可见基础页面与本人数据）。

## 3. 接口设计

### 3.1 角色管理接口（`/api/rbac/roles`）

| 方法 | 路径                         | 说明                           |
| ---- | ---------------------------- | ------------------------------ |
| GET  | `/api/rbac/roles`            | 角色列表（含权限点、范围）     |
| POST | `/api/rbac/roles`            | 新建角色（名称、权限点、范围） |
| PUT  | `/api/rbac/roles/:id`        | 编辑角色（权限点、范围、状态） |
| POST | `/api/rbac/roles/:id/status` | 停用/启用角色                  |
| GET  | `/api/rbac/permissions`      | 权限点字典                     |

- 仅 `superadmin` 可管理角色。
- `isSystem` 角色禁止编辑/停用/删除，接口返回 `RBAC_SYSTEM_ROLE_PROTECTED`。

### 3.2 用户角色分配接口

| 方法 | 路径                            | 说明                                       |
| ---- | ------------------------------- | ------------------------------------------ |
| GET  | `/api/rbac/users/:userId/roles` | 查询用户已分配角色                         |
| PUT  | `/api/rbac/users/:userId/roles` | 全量覆盖用户角色（`roleIds: []` 表示清空） |

- 仅 `superadmin` 可操作；`superadmin` 角色的用户不能被移除其最后角色（保护账号安全）。
- 与组织架构删除用户、停用账号流程衔接：删除用户自动清理 `user_roles`。

### 3.3 会话权限摘要（向后兼容）

登录/单点登录响应在**原字段不变**基础上新增：

```json
{
  "user": {
    "role": "superadmin",
    "roles": ["superadmin"],
    "permissions": ["*"],
    "scopes": ["all"]
  }
}
```

- 原 `role` 字段保留，旧前端无感。
- 新字段 `roles / permissions / scopes` 供新角色体系使用。
- 会话 Cookie 仍为签名令牌，权限摘要随会话携带。

## 4. 运行时鉴权改造

### 4.1 统一鉴权函数

```ts
// apps/api/src/rbac.ts
校验业务权限(会话, "order:read"): void   // 无权限抛 RBAC_PERMISSION_DENIED
校验数据范围(会话, 实体, 归属字段): void  // 检查实体归属是否在角色范围并集内
```

- `superadmin` 拥有 `*` 全部权限与 `all` 全部范围，永远放行（与现状一致）。
- 其他角色按 `role_permissions` + `data_scope_bindings` 判定。

### 4.2 主链兼容策略（无双轨）

为保证既往主链不回归，采取**渐进迁移 + 保留硬编码兜底**：

1. **业务主链接口（商机/报备/报价/订单/审核）**：保留现有 `superadmin` / `region_manager` 硬编码判定，**不做改造**。这些接口的权限语义本期不变化。
2. **新增能力（角色管理、用户角色分配、组织架构账号管理）**：使用新的 RBAC 判定，仅 `superadmin` 可访问（与现状一致）。
3. **菜单显隐**：前端 `isSuperAdmin` 逻辑保留；角色管理页仅超管可见。
4. **数据范围**：`region_manager` 的「负责区域」范围本期仍由现有业务逻辑推导，不迁移到 `data_scope_bindings`；新范围配置只作用于新能力（组织架构账号管理、渠道组织筛选等）。

> 说明：这是「单轨」落地——不引入双写、不引入影子比对。旧角色语义完全保留，新能力只在新增界面与新增接口上生效，避免旧逻辑与新逻辑打架。

### 4.3 前端菜单显隐

- `角色管理` 菜单：仅 `superadmin` 可见。
- 组织架构内「账号管理」：仅 `superadmin` 可见（沿用现有组织架构权限门禁）。
- 业务菜单：本期不按权限点动态显隐（保留现状），后续如需再按 `permissions` 扩展。

## 5. 页面设计

### 5.1 角色管理页（组织架构 → 新增「角色管理」页签）

- 角色列表：名称、权限点数、范围数、状态、内置标记、操作（编辑/停用/启用）。
- 新建/编辑弹窗：
  - 基本信息：角色名称、描述。
  - 业务权限：按资源分组勾选（商机、报备、报价、订单、经营报表、产品目录、渠道商、审核、日志、消息、开放接口、工作量）。
  - 用户权限：组织架构、账号管理。
  - 组织范围：部门树勾选（支持多选）、渠道组织树勾选（大区/区域/渠道商）、全局、仅本人。
- 系统内置角色（superadmin）显示只读保护，不可编辑。

### 5.2 用户编辑抽屉（组织架构 → 组织与岗位）

- 新增「管理员角色」区块：
  - 多选角色（下拉 + 已选标签）。
  - 保存即生效（调用 `PUT /api/rbac/users/:userId/roles`）。
  - 与渠道角色、业务角色、证书区块并列。

### 5.3 新建用户弹窗

- 新增「管理员角色」多选（可不选 = 普通账号）。
- 创建用户后自动分配所选角色。

## 6. 迁移与数据保障

### 6.1 数据迁移（新迁移 SQL）

1. 权限点补全：
   - 新增 `report:read`、`review:read/approve`、`message:read/admin`、`organization:read/create/edit/delete`、`account:read/create/edit/delete`。
   - 现有 `resource:write` 拆分为 `resource:create/edit/delete`，并自动挂到已分配 write 的角色。
2. 角色 `is_system` 标记：`superadmin` 标记 `isSystem: true`。
3. 数据范围：本期不迁移现有 region_manager 范围（保留现状），仅建立空模板。

### 6.2 回退保障

- 新迁移可回滚（提供 rollback SQL）。
- 新接口仅超管可访问，不影响现有用户与业务。
- 主链接口零改动，回归测试锁定。

1. 权限点字典：16 旧权限点 + 新增权限点，迁移后旧角色权限不缩水。
