### 1.1 账号停用归档统一产品规则（2026-08-26）

- 历史业务账号一律不物理删除，页面动作统一命名为“停用归档并交接”。内置 `admin` 和当前登录账号禁止发起停用归档。
- 超管账号只能交给其他有效超管；区管账号优先交给同区域其他有效区管，也允许交给有效超管。接收人必须不是目标账号本人，账号有效、未处于离职流程，并满足目标业务对象的区域、渠道和权限要求。
- 发起前必须完成影响预览、填写停用归档原因、选择合格接收人并输入目标账号做二次确认。预览后到事务提交前必须重新校验目标账号、接收人、范围和授权版本；接收人已失效时阻断提交并要求重新选择。
- 第一阶段在短事务内立即停用账号、递增授权版本、结束有效任职、渠道成员关系和成员业务角色，创建交接单和发件箱事件；第二阶段由独立 Worker 通过领域适配器分批扫描和交接，失败不得恢复账号访问权。
- 原申请人、原提报人、创建人、历史审批人、审批意见和其他历史事实不得改写。待办只转移当前可转交的办理责任，并按既有角色和区域规则动态可见。
- 离职不自动撤销证书；证书历史事实保留。证书颁发、到期和撤销也不得自动授予或移除业务角色。
- `V3_AUTH_ACCOUNT_STATUS_CHECK_ENABLED` 是账号状态安全防护开关，`V3_ORGANIZATION_OFFBOARDING_ENABLED` 是停用归档与交接执行开关，两者默认均为 `false` 且职责分离。必须先保持交接执行关闭，开启并验收账号状态防护，再申请开启交接执行；交接为 `true` 而防护不为 `true` 时应用必须拒绝启动。
- 停用归档专项回退只关闭 `V3_ORGANIZATION_OFFBOARDING_ENABLED`，`V3_AUTH_ACCOUNT_STATUS_CHECK_ENABLED` 必须保持 `true`。回退只停止新发起、重试、关闭和新任务领取，不恢复已停用账号旧会话，也不自动反转已经完成的业务归属迁移。

- 渠道域组织 `channel_partner_id` 非空，内部域为空；渠道父子节点必须关联同一渠道商。
- `path_code` 使用不可变对象编号构造并包含根和自身，不使用名称或可变业务编码作为身份路径。

- 同一用户不能借助两条不同任职记录成为自己的负责人；同一时间只能有一个有效直属负责人，矩阵负责人可多条。

## 3. 子项 11.1：组织与岗位

### 3.1 数据库

迁移基线为 `20260813_S10_001_组织架构主体.sql`。该脚本已完成主体表验证，但在补齐以下约束前只标记为“主体已验证、生产约束未就绪”：

- 扩展 `org.org_units`，新增 `unit_type/path_code/channel_partner_id/manager_assignment_id/sort_order/effective_at/expired_at/source_code/source_external_id/sync_status_code/last_synced_at/status_code/row_version`；父级字段沿用既有 `parent_unit_id`，禁止另建 `parent_id`。
- `unit_type` 枚举（7.3 + D-04）：
  ```
  ('headquarters','division','big_region','region','province','city','department','team',
   'channel_company','channel_department','channel_team')
  ```
- `status_code` 枚举对应 7.5：(`draft`, `active`, `disabled`, `archived`)。
- `path_code` 用 `ltree`，建 GIST 索引。
- 新增 `org.positions`，`(org_unit_id, position_code)` 唯一。
- 跨域跨渠道约束：父子 `unit_type` 必须同域，渠道域父子 `channel_partner_id` 必须相同。跨行约束通过受控函数或约束触发器实现，不得误写成无法引用父行的普通 CHECK。
- 防环：路径包含根和自身；移动前禁止把组织移到自身或子孙下，移动事务锁定当前节点、目标父节点和受影响子树。
- 归档守卫：归档前断言无有效子组织、无有效任职。
- 岗位归属：增加可供组合外键引用的唯一键，任职的岗位必须属于任职组织。
- 迁移处理：若 S10-001 从未在任何共享环境执行，修订原脚本并重新验证；只要任一环境已执行，就新增后续约束修正迁移，禁止改写历史迁移。

### 3.2 后端

`apps/api/src/org/org-units-service.ts` 关键函数：

```ts
export async function 创建组织(入参, 请求上下文) {
  return pool.transaction(async client => {
    await 锁定并校验父组织(client, 入参.parentUnitId, 入参.unitType, 入参.channelPartnerId);
    const unitId = 生成UUID();
    const path = await 计算包含自身的稳定路径(client, 入参.parentUnitId, unitId);
    const unit = await 插入组织(client, { id: unitId, ...入参, path_code: path });
    await 写审计(client, 'org.unit.created', { unit, 请求上下文 });
    return unit;
  });
}

export async function 移动组织(unitId, 新parentUnitId, rowVersion, 请求上下文) {
  return pool.transaction(async client => {
    await 锁定组织移动范围(client, unitId, 新parentUnitId);
    await 校验版本同域同渠道并防环(client, unitId, 新parentUnitId, rowVersion);
    const before = await 读取组织(client, unitId);
    const after = await 更新父级和整棵子树路径(client, unitId, 新parentUnitId);
```

- 离职第一阶段提交后账号立刻停用：`iam.users.status_code='disabled'` 与授权版本递增在同一短事务内生效。
- 会话全部撤销：构造 3 个会话 → 发起离职 → 旧 cookie 立刻 401。
- 当前客户、报备、商机、报价、订单五领域明细完整：每个领域都有 `detail_json`；合同、审批任务和通用任务没有伪造明细或成功状态。
- 重新启用：旧 cookie 失效；新建会话使用新授权版本。
- 任一领域扫描失败时，账号仍保持停用且其他领域可继续；失败项可单独重试。
- 同一幂等键重复请求返回原交接单，不重复停权、不重复生成任务。
- 接收人为本人、停用账号、离职中账号或范围不匹配时明确拒绝并给出可操作中文提示。
- 原申请人、原提报人、创建人、历史审批人、审批意见和历史经办事实在交接前后完全一致；只改变允许转交的当前办理责任和业务归属。
- 离职前后的证书事实和证书历史不变；颁发、到期、撤销和离职均不自动改变业务角色。
- 独立开关默认关闭；关闭时发起、重试、关闭和 Worker 新任务领取均被阻断。回退后已经完成的业务归属迁移不被自动反转。

## 9. 子项 11.7：企业微信组织架构同步

> 11.7 拆为 11.7A“只读连接与预览”和 11.7B“审批与受控应用”。字段、官方限制、回调、安全、灰度与验收细节统一引用 `企业微信组织架构同步实施方案.md`，本节只登记工程落点。

### 9.1 数据库

迁移 `202608xx_S10_005_企微组织同步.sql`，编号以实际迁移登记为准：

- `integration.directory_connectors`：提供方、企业编号、应用编号、密钥引用、可见范围摘要、模式、状态和配置版本。
- `integration.directory_mappings`：企微部门或成员与 V3 对象的唯一映射；唯一键为连接器、对象类型和外部编号。
- `integration.directory_external_id_aliases`：保存成员编号变更历史，防止 `userid` 变更后重复建人。

- `integration.directory_sync_changes`：差异版本、风险级别、审批状态、应用状态和前后摘要。
- `integration.directory_callback_events`：回调幂等键、事件摘要、密文哈希、接收次数和处理状态。

凭据字段只能保存密钥引用。回调原文默认不保存解密后的完整内容，日志和错误摘要不得含令牌、密钥、手机号、邮箱或地址。

### 9.2 后端与任务进程

`wecom-directory-adapter.ts`：

- 按企业和应用隔离缓存 `access_token`，单飞刷新，凭证失效只刷新一次后重试。
- 读取可见部门编号、逐部门详情和逐部门成员详情；多部门成员按 `userid` 合并。
- 首期不请求手机号、邮箱、性别、头像、地址等敏感字段。
- 统一处理企业微信 `errcode`、超时、退避、限流和熔断，不依赖可变的 `errmsg` 匹配。

`wecom-contact-callback.ts`：

- GET 在 1 秒内完成签名校验、解密并返回 `echostr` 明文。
- POST 完成验签、解密、幂等落库并在 5 秒内应答，不在回调请求内拉取通讯录。
- 支持成员和部门新增、更新、删除事件；载荷只作触发，后台重新查询最终状态。

`directory-sync-service.ts` 与 `wecom-directory-sync-runner.ts`：

- 连接测试只读，不写映射和正式组织数据。
- 全量、增量和校准统一生成快照与差异；不完整全量禁止生成删除和失效候选。
- 首期所有差异必须审批；高风险差异只生成管理员任务。
- 批准后按父部门、子部门、外部身份、成员关系、岗位候选、负责人候选顺序应用。
- 应用项使用批次、差异编号和差异版本做幂等，执行前再次校验 `row_version`。
- 同步任务使用独立队列和并发上限，不阻塞登录、关键事件和业务请求。

## 12. 部署与回滚

### 12.1 部署顺序

1. 核对阶段零、OpenAPI、审计基础和 11.5A 验收证据，未通过则停止发布。
2. 备份当前数据库并完成可恢复性校验，不以“文件存在”替代恢复验证。
3. 查询各环境迁移执行事实，按附录E.12.3决定修订 S10-001 或新增约束修正迁移。
4. 执行上线前数据体检：跨域父子、渠道归属、路径一致性、岗位归属、重复有效任职、负责人自指和失效关系必须为零；否则生成清单并停止迁移。
5. 应用已批准迁移，并执行 `iam.user_roles` → `user_permission_roles` 初始复制和兼容双写。
6. 部署 API、任务进程和 Web，但组织菜单、组织写入、账号状态防护、停用归档和企微同步相关开关均保持关闭；`V3_ORGANIZATION_OFFBOARDING_ENABLED=false` 未通过专项门禁前不得调整。
7. 在交接执行保持关闭时，单独设置 `V3_AUTH_ACCOUNT_STATUS_CHECK_ENABLED=true`；先验证配置可启动和状态查询服务可用，再完成有效账号无感、已停用账号全部旧会话 401、状态服务异常 503、开放接口独立鉴权及主业务回归。
8. 验证 `V3_ORGANIZATION_OFFBOARDING_ENABLED=true` 且账号状态防护关闭时应用拒绝启动；只有状态防护灰度稳定且专项证据签字后，才可在书面批准范围内开启交接执行。
9. 配置企微密钥引用、回调地址和测试可见范围；先启用只读连接、回调收件和预览，生产至少观察 7 天。
10. 执行数据库约束、接口契约、权限影子比对、范围、旧会话失效、同步幂等、主链路和回退演练；客户报备、商机、报价、订单、渠道、账号、四套正式页面和既有开放接口必须逐项通过。
11. 仅对授权管理员灰度开启 `/admin.html#/organization/*`；完成两轮全量对账和差异签字后才可对测试部门开启企微应用开关。发现未批准差异、数量异常突降、主链路回归失败或异常放行时立即关闭应用、组织菜单和写开关，恢复旧权限读取路径后再排查。

### 12.2 回滚预案

- 首选应用回退：关闭菜单和写开关、回退 API/Web/Worker，数据库新增字段和事实数据保留，不执行破坏性降级。
- 权限切换兼容窗口保持双写和一致性比对；回退前把窗口内新表变更同步回 `iam.user_roles`，验证集合一致后再切回旧读取路径。
- 只有确认新表没有正式业务数据、没有后续迁移依赖且完成备份恢复验证时，才允许执行结构回滚；约束恢复失败必须终止脚本，禁止捕获异常后仍报告成功。
- 已产生组织、任职、证书或交接数据后，结构回滚改为前向修复，不删除业务事实。
- 停用归档专项回退只将 `V3_ORGANIZATION_OFFBOARDING_ENABLED=false`，`V3_AUTH_ACCOUNT_STATUS_CHECK_ENABLED` 必须保持 `true`；停止新发起、重试、关闭和新任务领取，已停用账号旧会话继续 401。已经完成的客户、报备、商机、报价或订单归属迁移不自动反转，确需调整时走新的受审计人工改派。合同、审批任务和通用任务当前未落地，不得出现在已完成迁移清单中。
- 企微同步回退先关闭应用开关并暂停新应用项；只读校准可保留。自动补偿只恢复本批次实际修改且之后没有人工修改的字段，版本冲突进入人工补偿任务。

### 12.3 监控指标

- 审计写入成功率（应 > 99.99%）。
- 离职交接完成时长（中位数 < 5 分钟）。
- 证书告警事件生成完整率应为 100%；外部渠道分别统计受理率、最终送达率和失败补偿结果，不以无法证明的“到达率 100%”作为单一指标。
- 企微令牌刷新成功率、回调验签失败率、重复率、积压和处理延迟。
- 同步批次成功率、快照完整性、对象数量突降、差异风险分布、待审批和人工任务积压。
- 同步应用成功率、部分失败率、版本冲突、重试次数和熔断状态。
- 权限双写集合差异必须为 0；双重身份跨上下文拒绝率和异常放行数必须可观测。
- 离职停权事务耗时、扫描任务积压、单项失败率和重试次数必须可观测。
