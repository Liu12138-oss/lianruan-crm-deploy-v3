# 组织架构首期落地开发方案（KB-20260813）

> 本文档是 `docs/V3业务平台底座与业务扩展实施交付方案.md` 第7章、第21章、附录E 的落地映射。
> 落地工作遵循"先理解、再动手；把握不足 98% 不动手；高风险动作必须先获得明确授权"。
> 与方案文档冲突时，以方案文档为准；本文件落地细节与方案冲突时需先回写方案。

## 0. 文档目标与读者

- 目标：把第11项组织架构（含渠道商内部组织、业务角色、证书、个人权限、数据范围、离职交接、同步占位）拆解成可独立开发、可独立验收的工程任务。
- 读者：后端、前端、数据库 DBA、QA、运维安全。
- 范围：**仅包含首期（11.1–11.7 七个子项）**；移动端组织能力不在本期。

## 1. 决策清单（与附录E一致）

| 编号 | 决策 | 结论 | 落地影响 |
| --- | --- | --- | --- |
| D-01 | 内部组织 vs 渠道组织 | 双域共享 `org_units` | `unit_type` 枚举扩展、CHECK 防跨域父子 |
| D-02 | 业务角色 vs 权限角色 | 完全解耦 | `business_roles` 与 `iam.roles` 通过 `business_role_permission_grants` 映射 |
| D-03 | 证书过期 | 仅告警不撤销 | worker 写 `certification_expiry_events`，发消息，不动 `business_roles` |
| D-04 | 渠道商内部组织 | 纳入 `org_units` 渠道域 | `unit_type IN ('channel_company','channel_department','channel_team')` |
| D-05 | 双重身份 | 单账号双 membership | session 同时返回 `internal_memberships` + `channel_memberships` |
| D-06 | 移动端 | 首期不做 | 不创建 `apps/web/src/pages/mobile/` 下任何组织页面 |
| D-07 | 同步 | 仅占位 | 4 个接口返 501，1 个页面展示占位 |
| D-08 | 数据范围首期 | 只做角色级 | 11.5 写接口拒绝 `subject_type='user'`；读接口可回显供审计 |
| D-09 | 离职未完成项 | 走 `workflow.process_tasks` | 11.6 `close` 后剩余项写入统一任务系统，可见者限定 `org.offboarding.handle` 权限的内部管理员与企业管理员 |
| D-10 | `iam.users.offboarding_status` | 加新字段 | 与 `status_code` 并存，离职时同时生效；用户列表按字段加 chip |
| D-11 | 数据范围落库 | 落库 | 11.5 全部从 `iam.data_scope_bindings` 读，禁止反推 |

export async function 创建组织(入参, 操作者) {
  return pool.transaction(async client => {
    const path = await 计算路径(client, 入参.parentId);   // 不含自身
    const unit = await 插入组织(client, { ...入参, path_code: path });
    await 写审计(client, 'org.unit.created', { unit, 操作者 });
    return unit;
  });
}

export async function 移动组织(unitId, 新parentId, 操作者) {
  return pool.transaction(async client => {
    await assertNoCycle(client, unitId, 新parentId);
    const before = await 读取组织(client, unitId);
    const after = await 更新parent(client, unitId, 新parentId);
    await 重算path_code(client, unitId);                  // 递归更新所有子孙
    await 写审计(client, 'org.unit.updated', { before, after, changed_fields: ['parent_id'], 操作者 });
  });
}

export async function 启停归档(unitId, 新状态, 原因, 操作者) {
  return pool.transaction(async client => {
    if (新状态 === 'archived') await assertArchivable(client, unitId);
    const before = await 读取组织(client, unitId);
    await 更新状态(client, unitId, 新状态);
    await 写审计(client, 'org.unit.status_changed', { before, after: 新状态, 原因, 操作者 });
  });
}
```

export async function 调整任职(assignmentId, 入参, 操作者) {
  return pool.transaction(async client => {
    const before = await 读取任职(client, assignmentId);
    // 调岗 = 结束旧 + 新建新（同一事务）
    await 结束任职(client, assignmentId, 入参.新expiredAt, 'reassigned');
    const 新任职 = await 新建任职(client, {
      user_id: before.user_id,
      org_unit_id: 入参.新orgUnitId ?? before.org_unit_id,
      position_id: 入参.新positionId ?? before.position_id,
      is_primary: before.is_primary,
      effective_at: 入参.新effectiveAt,
    });
    await 写审计(client, 'org.assignment.expired', { before, 操作者 });
    await 写审计(client, 'org.assignment.created', { 新任职, 操作者 });
    return 新任职;
  });
}
```

`permission-roles-service.ts`：

```ts
export async function 应用业务角色(userId, businessRoleId, 操作者) {
  return pool.transaction(async client => {
    const grants = await 读取业务角色映射(client, businessRoleId);
    for (const grant of grants) {
      if (!grant.is_auto_grant) continue;
      await 写入用户权限角色(client, {
        user_id: userId,
        role_id: grant.role_id,
        grant_source: 'business_role_auto',
        source_business_role_id: businessRoleId,
      });
    }
  });
}
```

`data-scopes-service.ts`：

```ts
export async function 计算数据范围(userId, resourceCode) {
  // 1. 读 user_permission_roles 拿到所有 role
  // 2. 读 data_scope_bindings，按 subject_type 合并
  // 3. 返回 SQL 片段或内存过滤条件
  return await 合并范围(userId, resourceCode);
}
```

**关键变更**：所有运行时权限判定必须从 `user_permission_roles` 读，**禁止**直接读 `iam.user_roles`。这是本次升级的核心安全门禁。

**D-08 首期实现**：写接口 `/api/org/data-scopes` 与 `/api/org/users/:id/data-scopes` 首期拒绝 `subject_type='user'`，返回 `409 DATA_SCOPE_USER_OVERRIDE_DISABLED`；读接口可返回 `subject_type='user'` 行仅供审计展示，**不参与权限判定**。启用用户级覆盖需 `feature_flag.data_scope_user_override=true` 且调用方具备 `identity.scope.user_override.manage` 权限。

**D-11 落库实现**：`iam.data_scope_bindings` 为唯一数据范围权威来源。计算函数 `计算数据范围(userId, resourceCode)` 三步：读角色 → 合并绑定 → 转 SQL 片段。每次绑定变更写 `org.data_scope.bound` / `org.data_scope.unbound` 审计。

`offboarding-service.ts`：

```ts
export async function 发起离职交接(userId, 入参, 操作者) {
  return pool.transaction(async client => {
    // 1. 创建交接单
    const 交接单 = await 创建交接单(client, { userId, ...入参, 操作者 });

    // 2. 立刻停用账号 + 撤销会话 + 结束任职（7.6 红线）
    await 停用账号(client, userId, 操作者);
    await 撤销所有会话(client, userId, 操作者);
    await 结束所有有效任职(client, userId, 操作者);
    await 更新用户offboarding_status(client, userId, 'offboarding');

    // 3. 扫描 6 领域，写交接明细（不直接 transfer）
    const 领域 = await Promise.all([
      扫描客户(client, userId, 入参.接收人),
      扫描报备(client, userId, 入参.接收人),
      扫描商机(client, userId, 入参.接收人),
      扫描合同(client, userId, 入参.接收人),
      扫描待办(client, userId, 入参.接收人),
      扫描审批(client, userId, 入参.接收人),
    ]);
    for (const 项 of 领域) await 写交接项(client, { 交接单, ...项 });

    // 4. 发件箱触发异步 transfer
    await 发件箱(client, 'org.offboarding.execute_transfers', { 交接单 });

    // 5. 写审计（粗粒度 + 每领域细粒度）
    await 写审计(client, 'org.offboarding.initiated', { 交接单, 操作者 });
    for (const 项 of 领域) await 写审计(client, 'org.offboarding.item_scanned', { 交接单, 项 });
    return 交接单;
  });
}
```

## 12. 部署与回滚

### 12.1 部署顺序

1. 备份当前数据库（`pg_dump`）。
2. 应用迁移 001–005（按编号顺序）。
3. 数据迁移：将 `iam.user_roles` 复制到 `user_permission_roles`。
4. 重启 API 与 worker。
5. 灰度开启组织架构相关菜单（默认隐藏，开启后仅 admin 可见）。
6. 监控审计写入失败率、会话撤销失败率。

### 12.2 回滚预案

- 迁移脚本提供反向脚本（drop table / drop column）。
- 灰度开关：发现严重问题可一键隐藏菜单，**不回滚数据库**。
- 数据迁移保留 30 天，期间可随时从 `iam.user_roles` 恢复授权状态。

### 12.3 监控指标

- 审计写入成功率（应 > 99.99%）。
- 离职交接完成时长（中位数 < 5 分钟）。
- 证书过期告警到达率（应 = 100%）。
- 同步占位接口 501 比例（应 = 100%）。
