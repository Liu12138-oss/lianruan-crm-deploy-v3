### 1.3 R3-001 可配置业务事件规则保存入口修正（2026-08-25）

订单状态变化与客户报备审批待办均为已启用的可配置系统规则。此前详情弹窗错误地只给强制规则显示“保存规则”，导致前者无法保存渠道、后者无法保存渠道及提醒范围。本修正将保存入口改为所有已启用的系统业务事件；停用规则仍仅显示“启用该规则”。客户报备审批待办的角色与指定用户范围会一并保存，接收人取并集并过滤停用账号。保存继续使用既有二次确认、乐观锁、审计与服务端白名单，不改变规则数据、接收人默认值、强制规则保护或业务事件处理。

### 1.4 R3-002 到期提醒规则保存 500 修正（2026-08-27）

测试环境日志确认，`PUT /api/messages/platform/rules/reminders/:ruleCode` 对两个系统到期规则均返回 500。根因是更新 SQL 实际传入十个参数，但返回列错误引用第七个参数作为最后更新人，导致 PostgreSQL 参数绑定失败；同时返回列遗漏模板、数据源与系统标记，不能满足规则页回显对象契约。修正将最后更新人改为第十个参数，并补齐缺失返回字段和模板系统标记查询。事务、乐观锁、二次确认、审计、规则策略与已生成提醒均保持不变。

本地隔离 PostgreSQL 已以 `BEGIN → UPDATE ... RETURNING → ROLLBACK` 验证 SQL 可执行且回滚后不保留规则变化；类型检查及 API 全量测试通过。测试环境尚未部署本修正，因此真实页面保存验收必须在部署后执行，并核验“保存成功、版本递增、页面回显、审计记录”四项。

任何阶段的“✅”只能在对应的真实环境命令、输出和测试证据写入验收记录后标记；本表中的“已具备”不等于生产验收完成。

### 7.1 本轮 M4 运维收口操作说明

1. `scripts/start.sh` 默认不会启动消息角色。只有 `MESSAGE_WORKER_ENABLED=true` 且已配置不可变的 `MESSAGE_EVENT_CUTOVER_AT` 时，才显式启动 `message`、`message-external` profile；投递角色即使运行也不会在通道未保存、未试发成功或未启用时发出外部请求，确保超管可直接在页面完成试发。
2. `scripts/health-check.sh` 在消息进程未启用时只报告跳过；启用后校验关键角色、维护角色和投递角色，再调用只读观测脚本。投递角色异常会被明确报告，避免超管试发长期停留在待处理状态。
3. `scripts/message-observability.sh` 只输出消息角色状态、消费/投递积压、最老待处理秒数、近 24 小时成功率、失败类型聚合和连续失败状态；不读取消息正文、接收人、Webhook、联系方式或响应摘要。`collect-diagnostics.sh` 会附带其输出，并对日志地址、邮箱、手机号和敏感配置行脱敏。
4. `scripts/message-data-retention.sh` 默认仅输出超过保留期的候选数量。执行删除必须同时设置一次性环境变量 `MESSAGE_DATA_CLEANUP_ENABLED=true`、传入 `--execute`，并使用当天日期 `--confirm-retention YYYY-MM-DD`；脚本只处理超过 365 天的归档通知、成功消费事实和投递尝试，不删除失败/死信、投递主记录或 `message` 架构，并记录不含业务数据的本地运维审计摘要。
5. 保留清理进入生产前仍需 DEC-0005 对应的合规审批、备份核验和非生产演练证据。任何未完成上述条件的环境只能执行 `--plan`。
