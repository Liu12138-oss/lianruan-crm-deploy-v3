# 组织架构内嵌管理员页面改造方案（方案 A 详细落地）

> 版本：v1.0（2026-08-20）
> 状态：已确认方案选型 A（内嵌转写）；导航采用内容区顶部页签；独立工作区路由默认保留为过渡预览通道。
> 关联文档：`docs/V3业务平台底座与业务扩展实施交付方案.md`（第 7.8 节、附录 E）、`docs/operations/组织架构前端UI设计.md`、`docs/operations/组织架构开发落地跟踪.md`。
> 实施状态：2026-08-20 已完成全部落地与测试验证。

---

## 1. 背景与目标

### 1.1 现状问题

组织架构当前是 `apps/web` 工程化应用内的独立工作区：

- 路由：`/workspace/admin/platform-admin/organization/*`（独立 Vue 应用，自带顶栏、侧边导航、面包屑、独立布局）
- 入口：`admin.html` 侧边栏"组织架构"点击后执行 `window.location.assign('/workspace/admin/platform-admin/organization/units')` **整页跳转**

用户反馈：点击组织架构后跳转到另一套页面，整个 UI 变化，与管理员后台其他页面（消息渠道配置、提醒规则管理）的交互形态不一致。

### 1.2 改造目标

1. 点击管理员侧边栏"组织架构"后**不整页跳转**，侧边栏与顶栏保持不变，仅在内容区（`.page-body`）切换显示组织架构。
2. 组织架构全部显示内容与操作（组织树、岗位、任职、业务角色、证书、权限与范围、离职交接、企微同步）**基于当前管理员页面视觉**呈现。
3. 七个栏目在内容区顶部以**页签**形式切换。
4. 独立工作区 `/workspace/admin/platform-admin/organization/*` **默认保留**，作为过渡预览通道，不再从正式入口跳转。
5. 权限与开关语义不变：仅超管可见入口；`未启用 / 只读观察 / 已启用` 三态由 `GET /api/org/status` 决定；写入口仍受后端双开关门禁。

## 2. 现状梳理（改造依据）

### 2.1 目标容器：admin.html / admin-app.js

- `apps/web/public/admin.html` 固定桌面端入口，引用：
  - `libs/element-plus.min.css`、`style.css?v=12`（当前版本号）
  - `libs/vue.min.js`、`libs/vue-router.min.js`、`libs/element-plus.min.js`
  - `data.js`、`enterprise-data.js`、`data-migration.js`、`api-client.js`、`message-client.js`、`admin-app.js?v=136`（当前版本号）、`partner-level-module.js`
- `apps/web/public/admin-app.js`（约 17.7k 行，914KB）：
  - Vue 3 + Vue Router（hash 模式）+ Element Plus（CDN 全局注册 `app.use(ElementPlus)`）
  - `MainLayout` 挂载在 `path: '/'`，业务页面为子路由，内容区为 `<router-view />`（`.page-body`）
  - 侧边栏"组织架构"入口已存在，含 `未启用 / 只读观察 / 已启用` 三态文案与 `nav-item-disabled` / `nav-item-readonly` 样式
  - 已有内部中文变量先例（如 `组织功能已启用`、`组织写入已启用`），转写可用中文命名保持风格一致
  - 路由守卫已有 `message-platform`、`message-rules` 的超管限制先例
- **关键事实**：`admin-app.js` 现有页面均未使用 `el-*` 组件（消息平台用原生 `table.table`），但 Element Plus 已全局注册，`el-*` 组件在模板中可直接使用；`style.css` 中**尚无**组织工作区样式（`.组织*` 样式当前仅存在于 SFC 的 scoped style 中）。

### 2.2 内容源：OrganizationWorkspacePage.vue（920 行）

- 七个栏目：`units`（组织与岗位）、`staff`（人员与任职）、`business-roles`（业务角色）、`certifications`（证书管理）、`access`（权限与范围）、`offboarding`（离职交接）、`directory-sync`（企微同步）
- 栏目判定：`route.meta.组织栏目`（当前路由元数据）
- 数据加载：`加载页面()` 并行拉取组织状态、组织树、岗位、任职、负责人关系、业务角色、成员业务角色、证书模板、成员证书、离职交接；同步启用时再拉企微状态/批次/差异
- 交互：`新建组织 / 新建岗位 / 新建业务角色 / 新建证书模板` 共用 `新建弹窗`（el-dialog + el-form），提交带 `Idempotency-Key` 幂等键；证书页统计近 7 天到期/已过期/有效；企微同步页只读展示批次与差异
- 权限：`可写 = 已启用 && writeEnabled`，写入按钮按 `可写` 显隐；`ORG_PERMISSION_DENIED` 时跳 `/403`
- 移动端：`window.innerWidth < 900` 时显示"仅支持桌面端"提示（内嵌后由 admin.html 桌面布局兜底）

### 2.3 数据层：organization-client.ts（539 行）

- 统一走签名 Cookie 会话：`fetch(path, { credentials: "include", headers })`
- 写请求带 `Idempotency-Key` 头；错误统一抛 `组织接口错误`（含状态码、错误码、请求编号）
- 接口路径全部以 `/api/org` 或 `/api/integrations/directory-sync` 开头，**不经过** `/api/v2` 的 `api-client.js`

### 2.4 相关测试

- `apps/web/tests/admin-organization-entry.test.ts`：断言超管入口、三态文案、`window.location.assign('/workspace/admin/platform-admin/organization/units')`、`fetch('/api/org/status')`、`admin-app.js?v=136`（**需随本方案更新**）
- `apps/web/tests/organization-workspace-routes.test.ts`：断言独立工作区路由存在（**保留**，不改）
- `apps/web/tests/organization-workspace-mobile-isolation.test.ts`：SFC 移动端隔离（**保留**，不改）

## 3. 方案选型结论

| 方案 | 结论 | 理由 |
|---|---|---|
| A 内嵌转写（本方案） | ✅ 采用 | 与消息平台、提醒规则的接入模式一致，单一 Vue 实例、会话共享、视觉统一 |
| B iframe 内嵌 | ❌ 不采用 | 视觉割裂、样式/会话隔离、弹窗错位，不符合"基于当前视觉" |
| C 库模式打包挂载 | ⏸ 远期演进 | 双 Vue 实例共存、Element Plus 样式冲突、路由嵌套复杂 |

### 4.3 数据客户端转写

在 `admin-app.js` 中新增组织架构接口封装（转写自 `organization-client.ts`）：

```js
// 组织架构接口客户端：只走签名 Cookie 会话，不经 /api/v2
function 组织请求(path, method, body, options = {}) {
  const headers = { ...(body ? { 'content-type': 'application/json' } : {}) };
  if (options.幂等键) headers['Idempotency-Key'] = options.幂等键;
  return fetch(path, {
    method: method || 'GET',
    credentials: 'include',
    headers,
    ...(body ? { body: JSON.stringify(组织构建写入内容(body, options)) } : {}),
  }).then(async (响应) => {
    const 内容 = await 响应.json().catch(() => null);
    if (!响应.ok || !内容?.success || 内容.data === undefined) {
      const 错误 = new Error(内容?.error?.message || `组织架构接口请求失败（HTTP ${响应.status}）`);
      错误.状态码 = 响应.status;
      错误.错误码 = 内容?.error?.code;
      错误.请求编号 = 内容?.meta?.requestId;
      throw 错误;
    }
    return 内容.data;
  }).catch((error) => {
    if (error.错误码) throw error;
    const 网络错误 = new Error('网络连接失败，请检查网络后重试。');
    网络错误.状态码 = 0;
    网络错误.错误码 = 'ORG_NETWORK_ERROR';
    throw 网络错误;
  });
}
function 组织读取(path) { return 组织请求(path); }
function 组织写入(path, method, body, options = {}) { return 组织请求(path, method, body, options); }
function 生成组织幂等键() {
  return (crypto?.randomUUID ? `org-${crypto.randomUUID()}` : `org-${Date.now()}-${Math.random().toString(16).slice(2)}`);
}
function 组织构建写入内容(内容, 选项 = {}) {
  return { ...内容, ...(选项.rowVersion !== undefined ? { rowVersion: 选项.rowVersion } : {}) };
}
```

各业务函数转写清单（函数名、路径、方法对应 `organization-client.ts`，见第 5 节接口映射表）。转写后全部以 `组织*` 前缀命名，避免与 `admin-app.js` 现有全局函数冲突。

## 10. 风险与注意事项

1. **Element Plus 组件首次大规模进入 admin-app.js**：当前现有页面用原生 table，本方案引入 `el-table`/`el-dialog` 等。需在第一步先做最小冒烟（渲染一个 el-table 页面）确认 CDN 版 Element Plus 完整可用，再继续转写。
2. **样式命名冲突**：`.组织*` 类名进入全局 style.css 后，需确认与独立工作区（SFC scoped）不冲突（scoped 样式带 data-v 属性，类名相同不互相污染，但建议保留前缀差异意识）。
3. **admin-app.js 为单文件大文件（914KB）**：改动集中在一个文件，需小心合入；分步提交，每步跑 `npm --workspace @lianruan/web run test`。
4. **版本号管理**：`admin.html` 引用的 `admin-app.js?v=146` 与测试断言绑定，改完必须同步 bump，否则浏览器缓存旧脚本。
5. **独立工作区保留策略**：`/workspace/admin/platform-admin/organization/*` 保留但不从正式入口跳转；后续如需彻底下线，须单独评审并清理其路由、测试与文档（本次不做）。
6. **ORG_PERMISSION_DENIED 处理变化**：内嵌后不再跳 `/403`（避免离开 admin 后台），改为内容区错误卡片；与独立工作区行为不同，测试需覆盖。
7. **会话一致性**：组织接口走签名 Cookie 会话，与 admin.html 登录态天然一致；不读取 `/api/v2` 令牌，避免引入兼容层风险。
8. **Element Plus 中文文案**：CDN 版默认英文；本方案页面文案全部自定义（empty-text、按钮文字），暂不引入 zh-cn locale 配置，与现有 admin.html 现状保持一致。如需全中文（如 el-pagination），作为后续独立优化项。
