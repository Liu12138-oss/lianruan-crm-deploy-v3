# 阶段6 Redis职责边界与键命名规范

## 1. 目标

本文件用于阶段6启动前统一 Redis 的使用边界。Redis 只承担可恢复、可重建或可从 PostgreSQL 事实表补投的运行态能力，不作为业务唯一数据源。

生产首发按单机容器部署，Redis 必须支持后续迁移到备用服务器或独立 Redis 主机。所有键必须带环境、用途、模块和版本信息，避免未来接管、清理和审计时无法判断来源。

## 2. 职责边界

| 用途 | 是否允许 | 数据来源 | 丢失后的处理 | 持久化要求 |
| --- | --- | --- | --- | --- |
| 会话 | 允许 | 登录服务和用户表 | 用户重新登录或从会话事实表重建在线索引 | 建议开启 AOF |
| 权限短缓存 | 允许 | PostgreSQL 权限、角色、数据范围表 | 回源数据库并按授权版本重建 | 可重建，必须设置过期 |
| 稳定元数据缓存 | 允许 | 字典、地区、已发布产品树、工作量规则 | 回源数据库 | 可重建，必须设置过期 |
| 接口限流计数 | 允许 | 请求入口 | 丢失后重新计数 | 不要求长期持久化 |
| BullMQ 队列 | 允许 | PostgreSQL 任务事实表 | Redis 清空后从任务事实表补投 | 建议开启 AOF |
| 任务进度快照 | 允许 | 任务处理器 | 从任务事实表和检查点恢复 | 可重建 |
| 分布式短锁 | 限制使用 | 当前执行上下文 | 超时释放，失败后由任务补偿 | 必须设置短过期 |
| 业务主数据 | 禁止 | 不适用 | 不允许 | 不适用 |
| 无界集合和整表缓存 | 禁止 | 不适用 | 不允许 | 不适用 |

## 3. 推荐 Redis 拆分

单机容器也建议使用两个 Redis 实例或至少两个独立配置，避免缓存淘汰影响队列和会话。

| 实例 | 用途 | 内存策略 | 持久化 | 初始内存上限 |
| --- | --- | --- | --- | ---: |
| `redis-state` | 会话、限流、BullMQ、短锁、任务进度 | `noeviction` | AOF 每秒刷盘 | 3GB |
| `redis-cache` | 字典、权限短缓存、产品树、统计短缓存 | `allkeys-lru` 或 `volatile-lru` | 可关闭 AOF，保留 RDB 快照即可 | 2GB |

如果首发只能部署一个 Redis 实例，必须使用 `noeviction`，所有缓存键必须设置较短过期时间和大小上限；缓存写入失败不能影响主业务。

## 4. 键命名总规则

统一格式：

```text
crm:v3:{环境}:{用途}:{模块}:{版本或范围}:{标识}
```

字段说明：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| `环境` | `dev`、`test`、`staging`、`prod` | `prod` |
| `用途` | `session`、`cache`、`rate`、`queue`、`lock`、`progress`、`idempotency` | `cache` |
| `模块` | `auth`、`partner`、`registration`、`opportunity`、`quote`、`order`、`product`、`openapi`、`stats` | `product` |
| `版本或范围` | 授权版本、数据版本、窗口、租内范围，不使用中文 | `v42` |
| `标识` | 业务编号哈希、会话编号、任务编号、路由哈希 | `task_202607230001` |

禁止事项：

- 禁止使用没有过期时间的缓存键。
- 禁止把手机号、密码、令牌、客户全称、统一社会信用代码直接放进键名。
- 禁止使用 `keys *` 做生产清理，清理必须按前缀、版本或任务编号精准处理。
- 禁止把大列表、全量客户、全量渠道、全量订单放进单个键。
- 禁止不同环境共用同一 Redis 前缀。

## 5. 会话键

| 键 | 示例 | 过期 | 说明 |
| --- | --- | --- | --- |
| 用户会话 | `crm:v3:prod:session:auth:v1:sid:{会话编号}` | 闲置过期 | 保存最小登录态、用户编号、授权版本、来源地址摘要 |
| 用户会话索引 | `crm:v3:prod:session:auth:v1:user:{用户编号}` | 与最长登录时间一致 | 保存该用户有效会话编号集合 |
| 授权版本 | `crm:v3:prod:session:auth:v1:authver:{用户编号}` | 不短于会话 | 权限变化时递增，旧会话下次请求失效 |

会话值不得保存密码、明文令牌、完整敏感请求头。会话闲置时间、最长时间和并发设备数仍需产品确认。

## 6. 缓存键

| 缓存 | 键 | 建议过期 | 失效方式 |
| --- | --- | ---: | --- |
| 地区字典 | `crm:v3:prod:cache:dict:v{字典版本}:regions` | 6至24小时 | 字典发布后递增版本 |
| 已发布产品树 | `crm:v3:prod:cache:product:v{发布版本}:tree:{条件哈希}` | 5至30分钟 | 产品发布后递增版本 |
| 工作量规则 | `crm:v3:prod:cache:quote:v{规则版本}:workload:{条件哈希}` | 5至30分钟 | 规则发布后递增版本 |
| 权限短缓存 | `crm:v3:prod:cache:auth:v{授权版本}:scope:{用户编号哈希}` | 1至5分钟 | 权限变化后递增授权版本 |
| 统计短缓存 | `crm:v3:prod:cache:stats:v{口径版本}:{范围哈希}:{时间哈希}` | 30秒至5分钟 | 统计刷新任务写新版本 |

缓存值必须记录生成时间、数据版本和来源摘要。单个缓存值超过 512KB 必须评审，超过 2MB 禁止上线。

## 7. 限流键

| 场景 | 键 | 窗口 | 说明 |
| --- | --- | --- | --- |
| 登录失败 | `crm:v3:prod:rate:auth:{分钟窗口}:login:{账号哈希}` | 1分钟、15分钟 | 防暴力尝试 |
| 用户接口 | `crm:v3:prod:rate:api:{分钟窗口}:user:{用户编号}` | 1分钟 | 保护普通业务接口 |
| 开放接口客户端 | `crm:v3:prod:rate:openapi:{分钟窗口}:client:{客户端编号}` | 1分钟 | 结合调用方额度 |
| 来源地址 | `crm:v3:prod:rate:edge:{分钟窗口}:ip:{地址哈希}` | 1分钟 | Nginx 或后端入口保护 |

限流必须返回中文可操作提示，不能让请求无限等待。

## 8. BullMQ 键

BullMQ 统一设置前缀：

```text
crm:v3:prod:queue:{队列名}
```

任务编号使用 PostgreSQL 任务事实表编号作为 `jobId`。同一个任务重复投递必须命中同一 `jobId`，不能生成多份有效任务。

## 9. 锁和幂等键

锁只用于短时间互斥，不用于长任务占有。

| 类型 | 键 | 过期 | 说明 |
| --- | --- | ---: | --- |
| 任务执行短锁 | `crm:v3:prod:lock:task:v1:{任务编号}` | 30秒至5分钟 | 处理器持有期间续期 |
| 文件生成短锁 | `crm:v3:prod:lock:file:v1:{文件编号}` | 5分钟 | 防止重复生成 |
| Redis 短幂等 | `crm:v3:prod:idempotency:{模块}:v1:{摘要}` | 10分钟至24小时 | 只做短期防抖，最终以 PostgreSQL 唯一约束为准 |

## 10. 监控指标

必须纳入阶段7告警：

- Redis 可用性、内存使用率、连接数、每秒命令数、慢命令。
- 大键、热键、无过期缓存键数量。
- BullMQ 等待、运行、失败、延迟、停滞任务数。
- Redis AOF 重写状态和最后持久化时间。
- 缓存命中率和回源失败率。

## 11. 阶段6验收

- 所有生产 Redis 键能归类到本文件。
- 抽样 Redis 键没有明文敏感信息。
- 缓存 Redis 清空后业务可回源，队列 Redis 清空后任务可从 PostgreSQL 补投。
- 队列键与缓存淘汰策略隔离，不因缓存淘汰丢任务。
