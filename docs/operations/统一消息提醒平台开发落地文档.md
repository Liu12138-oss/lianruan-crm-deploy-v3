## 1. 背景与目标

V3 业务平台底座与业务扩展实施交付方案第 11 项要求建设**统一消息提醒能力**，覆盖站内通知、企微应用、企微群、短信、邮箱五类渠道；与合同、应收、公海、报备、证书等业务事件对接，并支持免打扰、频控、退订、模板版本与投递回执。

第 11 项是 V3 业务平台底座最高优先级之一，本文档把它分解为：

- 4 个实施切片（M1 – M4），每切片独立可验收、可回滚。
- 11 张新表（建在 `message` schema 下，**不动既有任何 schema**）。
- 1 套独立 API（路径前缀 `/api/messages`，**不挂入既有 `/api`、`/api/v2`、`/api/auth`**）。
- 1 套独立 Worker（条件启动，**默认开启**）。
- 1 套前端独立页面（`/messages`，**不破坏入口分流**）。

## 2. 设计原则

1. **零侵入既有代码**：所有新增模块以"侧挂"方式接入；既有 `apps/api/src/business-store.ts`、`business-routes.ts`、`create-app.ts`、`apps/worker/src/worker.ts`、`queue.ts` 关键路径**只允许追加，不允许修改既有核心逻辑**。
2. **复用既有事件入口**：复用 `ops.outbox_events` 作为事件总线，**不新建事件表**；订单业务函数已经在写出件箱事件，消息平台只消费。
3. **数据模型平级**：新表全部建在 `message.*` schema 下，与 `ops.*` / `iam.*` / `crm.*` / `channel.*` / `org.*` 平级。
4. **配置集中扩展**：环境变量集中在 `packages/config/src/index.ts` 新增，**不动既有字段**。
5. **渐进上线**：M1 默认先跑站内渠道，外部渠道（M2/M3）按业务节奏启用，每片都有独立开关。
6. **可逆优先**：任何迁移只新增对象，不修改既有对象；新消费者读 `ops.outbox_events` 时**只消费 `created_at >= worker_启动时间` 的事件**，避免历史告警刷屏。

## 4. 数据模型（11 张表）

### 4.1 Schema 与命名

- 全部建在 `message` schema 下。
- 主键统一使用 `uuid PRIMARY KEY DEFAULT gen_random_uuid()`。
- 时间戳统一使用 `timestamptz`。
- 字段命名沿用 `apps/api/src/business-store.ts` 现有的"业务对象 + 复数"风格。

## 8. 状态机

### 8.1 `ops.outbox_events`

```
pending → dispatched → ack / failed_retry / dead
```

- `pending`：业务事务已写入，未被 worker 领取。
- `dispatched`：worker 已领取。
- `ack`：worker 处理成功。
- `failed_retry`：可重试失败，等待 backoff。
- `dead`：重试耗尽，等待人工处理。

### 8.2 `message.deliveries`

```
pending → sending → success / failed / cancelled / ignored
```

- `pending`：已写入待投递。
- `sending`：worker 已发送请求。
- `success`：投递成功。
- `failed`：可重试 / 永久失败。
- `cancelled`：偏好变更或主动取消。
- `ignored`：未授权/已退订。

### 8.3 `message.notifications`

```
unread → read / archived
```

### 8.4 `message.reminder_schedules`

```
scheduled → fired / cancelled / suppressed
```

## 9. 接收人解析与权限

- 接收人解析 **复用** `apps/api/src/request-context.ts` 已经注入的 `用户、组织、角色、渠道` 快照，**不重新解析权限**。
- 模板变量全部从 PostgreSQL 已有数据取，**不调业务接口重算**。
- 业务链接全部使用 **V3 相对路径**，进入统一入口后由 `apps/web/src/router/entry-target.ts` 重新鉴权。
- 投递记录中手机号/邮箱只存摘要 + 权限码（按 `iam.data_scope_bindings` 走）。

## 10. 模板引擎

- 语法：Handlebars-lite（`{{var}}` / `{{#if}}` / `{{#each}}`）。
- 变量白名单：发布时声明 `variables`，渲染时只允许清单内键。
- 三态预览：草稿 / 预览 / 已发送样本（使用脱敏样例）。
- 版本不可变：每次修改生成新版本，已发送消息保留旧版本快照。
- 长度限制：短信 70 字（GSM-7）/ 67 字（UCS-2）；邮件标题 78 字。
- 脱敏函数：内置 `mask(phone)`、`mask(email)`、`abbr(name)`。

## 11. 渠道适配器

所有渠道实现同一接口，**业务代码只调接口**：

```ts
export interface MessagingChannel {
  readonly channel: 'inapp' | 'wecom' | 'wecom_group' | 'sms' | 'email';
  send(input: {
    tenantId: string;
    deliveryId: string;
    to: { userId: string; wecomUserId?: string; phone?: string; email?: string };
    templateId: string;
    templateVersion: number;
    variables: Record<string, unknown>;
    businessLink?: string;
    idempotencyKey: string;
  }): Promise<{
    vendorMessageId?: string;
    status: 'submitted' | 'success' | 'failed' | 'ignored';
    failureType?: 'identity_missing' | 'rate_limit' | 'credential' | 'template' | 'network' | 'compliance';
    receiptStatus?: 'submitted' | 'delivered' | 'failed' | 'unknown';
  }>;
}
```

每一种实现都是独立文件、可独立进程隔离。

## 12. 幂等、重试、补偿

- **幂等键**：`dedupe_key = sha256(event_code + user_id + channel + window_key)`，在 `message.deliveries` 上加唯一索引。
- **退避**：指数 + 抖动，上限 8 次（与阶段6规划一致）。
- **可恢复**：`network` / `rate_limit` / `credential`（临时） → 重试。
- **不可恢复**：`template`（未发布）/ `identity_missing` / `compliance`（已退订/未授权） → 直接 `failed`，生成管理员待办。
- **补偿**：`retry-task` 周期性扫 `failed` 且 `retryable=true` 且 `next_retry_at <= now`。
- **死信**：超过上限 → `failed` + 告警 + 平台待办，**不静默丢弃**（阶段6明文要求）。

## 13. 安全与合规（文档 11.10 收口）

- [ ] 群机器人过敏感字段组合白名单（客户名 + 金额 / 手机号 / 邮箱 + 金额）。
- [ ] 短信正文长度超限 / 包含敏感字段 → 发送前阻断 + 审计。
- [ ] 邮件 HTML 走白名单标签 + 链接只允许 V3 相对路径。
- [ ] 所有投递记录中手机号/邮箱只存摘要（按权限码脱敏）。
- [ ] 业务链接不带 token；点击进入 V3 仍走统一入口鉴权。
- [ ] 测试发送强制接收人白名单 + 审计。
- [ ] 模板预览用脱敏样例。
- [ ] `dedupe_key` 唯一约束 + 同窗口不重复。
- [ ] 停用账号 / 失效身份过滤后再发送。
- [ ] 短信供应商失败不影响站内 + 企微；邮件服务失败不影响其它三条。
- [ ] 频控 / 预算超限 → 停止非强制短信 + 告警。
