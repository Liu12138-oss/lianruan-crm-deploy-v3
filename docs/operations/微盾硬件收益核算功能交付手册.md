# 微盾＋硬件报价收益核算功能交付手册

## 1. 文档说明

### 1.1 交付范围

本手册适用于 V3 工程化应用中的“微盾＋硬件报价收益核算”功能，覆盖：

- 微盾软件与配套硬件的收益计算。
- 同型号硬件多台报价、订单、PDF 和收益数量一致。
- 区管和超管的收益查看、年限维护、重算与正式冻结。
- 超管在现有硬件管理入口维护版本化内部成本。
- 订单确认后的异步收益冻结、幂等处理与成本补齐自动重试。
- 数据库迁移、配置开关、验证、发布顺序和回退边界。

本期不支持 XCAD 收益核算。报价中混入 XCAD 或未明确归类产品时，整单标记为“不适用”，不输出部分收益。

### 1.2 本地交付状态

本地开发、专项测试、全量测试、生产构建和敏感信息扫描已通过。生产数据库迁移、生产配置变更、升级包制作、生产发布和历史订单回填尚未执行，必须另行取得明确授权。

## 2. 业务口径

### 2.1 产品范围

| 项目         | 口径                                                           |
| ------------ | -------------------------------------------------------------- |
| 微盾         | `catalog.product_categories.category_code = CAT-LEP`           |
| XCAD         | `catalog.product_categories.category_code = CAT-1779261229045` |
| 产品范围标识 | `weidun`、`xcad`、`unclassified`                               |
| 硬件型号     | 13 个 Excel 型号按稳定编码或受控历史映射匹配                   |
| 特殊映射     | Excel `LV-7050A` 对应数据库 `LV-7050-A`                        |

产品范围以结构化字段为准，不按名称猜测。

### 2.2 金额与年限

- 金额按权威 Excel 含税口径使用，不重复拆分或扣减增值税。
- 默认质保年限为 3 年，允许 1 至 20 年。
- 默认采购维保年限为 0 年，允许 0 至 20 年。
- 年度质保和采购维保 V1 共用同一年度成本字段。
- `LV-7050-A` 的年度质保/维保成本当前保持空值，空值表示“未知”，不能当作 0。

### 2.3 计算公式

```text
合同额（产品） = 软件折后价 + 硬件报价
合同额（服务） = 维保及服务报价
硬件内部成本 = Σ（硬件数量 × 单台内部销售成本）
产品税费 =（合同额（产品）- 硬件内部成本）× 5%
服务税费 = 合同额（服务）× 7%
质保成本 =（硬件年度质保/维保成本合计 + 软件公开报价 × 0.5%）×（质保年限 - 1）
采购维保成本 =（硬件年度质保/维保成本合计 + 软件公开报价 × 0.5%）× 采购维保年限
合同有效收入 =（合同额（产品）- 硬件内部成本）× 95% + 合同额（服务）× 93%
项目收益 = 合同有效收入 - 质保成本
```

重要口径：

- 采购维保成本保存并展示，但不从项目收益再次扣减。
- 项目收益允许为负，不归零、不取绝对值。
- 正式冻结使用订单最终总额；软件折后价按“订单总额 - 硬件金额 - 服务金额”反算。
- 正式冻结使用订单进入 `confirmed` 的事件时间对应的成本规则，Worker 延迟不改变该时点结果。

## 3. 页面和角色

### 3.1 角色权限

| 角色                          | 可查看收益 | 可维护年限 | 可维护成本 | 数据范围               |
| ----------------------------- | ---------- | ---------- | ---------- | ---------------------- |
| 超级管理员                    | 是         | 是         | 是         | 全部区域               |
| 区管 `region_manager`         | 是         | 是         | 否         | 本人有效多区域数据范围 |
| 历史 `admin` 且有正式区域绑定 | 是         | 是         | 否         | 本人有效正式区域       |
| 普通管理员                    | 否         | 否         | 否         | 无                     |
| 渠道管理员及渠道账号          | 否         | 否         | 否         | 无                     |
| 员工、销售、停用、过期会话    | 否         | 否         | 否         | 无                     |

后端每次请求都会复核账号启用状态、当前有效角色和正式区域，不信任前端 Cookie 中的角色摘要。

### 3.2 报价录入

1. 管理端或渠道端进入新建报价、编辑报价或快速报价。
2. 选择硬件型号后，在型号卡片上输入数量。
3. 数量必须是 1 至 9999 的整数。
4. 同一型号不能重复出现；需要多台时只填写一个数量。
5. 套餐自带硬件和手工加配同型号时，页面展示合计数量，提交时合并为一条 `hardwareItems`。

请求正式字段：

```json
{
  "hardwareItems": [{ "productId": "硬件产品编号", "quantity": 2 }]
}
```

旧字段 `hardwareIds` 继续兼容，每个型号按 1 台处理，但新页面统一提交 `hardwareItems`。

数量为 2 时，以下项目均按 2 倍计算：

- 硬件销售金额。
- 硬件内部销售成本。
- 年度质保/维保成本基准。

软件阶梯价、区域价格、渠道比例、专属价和服务报价规则不变。

### 3.3 报价详情收益

超管、所属区域区管打开报价详情后，可以看到“内部收益核算”区块：

1. 查看状态、公式版本、报价版本、计算版本和硬件成本明细。
2. 填写质保年限和采购维保年限。
3. 点击保存或重算，服务端重新读取报价、目录和成本规则后计算。
4. 页面显示实时预估、草稿、不完整、已冻结或不适用状态。
5. 已是正式快照时，所有输入和操作只读。
6. 收益为负时显示风险提示，不隐藏负号。
7. 收益接口异常时只让收益区块降级，不影响报价详情、PDF 下载和转订单。

### 3.4 超管成本配置

入口：管理员端“产品目录 → 硬件管理”。

操作步骤：

1. 在硬件型号列表点击“成本配置”。
2. 查看当前内部销售成本、年度质保/维保成本和历史版本。
3. 点击“新增版本”，填写内部销售成本、年度质保/维保成本、生效时间和来源说明。
4. 保存后，旧版本自动关闭，新版本成为新的有效版本。
5. 年度成本留空表示未知，填写 0 表示已经明确为零，两者语义不同。
6. V1 只允许当前或过去时间生效，不允许未来生效。

历史版本只读，不能在原记录上直接覆盖金额。内部成本不会写入对外硬件目录字段，也不会通过 `/api/v2/hardware` 返回。

## 4. 状态与流程

### 4.1 收益状态

| 状态             | 含义                               | 是否正式 |
| ---------------- | ---------------------------------- | -------- |
| `estimated`      | 接口实时预估，不持久化             | 否       |
| `draft`          | 已保存草稿，输入可能完整或待确认   | 否       |
| `incomplete`     | 缺成本、公开价、区域或明确归类     | 否       |
| `frozen`         | 订单确认后固化的正式快照           | 是       |
| `void`           | 报价修订后废弃的旧草稿或未冻结版本 | 否       |
| `not_applicable` | 非微盾范围报价，仅供内部诊断       | 否       |

### 4.2 冻结流程

```text
报价保存并固化价格依据
  → 区管/超管填写年限并保存或重算
  → 订单沿用既有审批状态机
  → 超管确认订单
  → 订单事务写 crm.quote.profit.freeze.requested
  → Worker 重新读取订单、报价、明细和成本规则
  → 规则齐全：生成 frozen 快照
  → 规则缺失：生成 incomplete，等待补齐后重试
```

收益冻结失败不回滚订单确认。成本规则补齐后，Worker 扫描“订单已确认且收益仍不完整”的受影响记录并自动重试。

## 5. 接口清单

收益接口挂在 `/api`，不挂在 `/api/v2`，也不进入 OpenAPI 和 MCP。

| 方法   | 路径                                                  | 用途                   | 权限               |
| ------ | ----------------------------------------------------- | ---------------------- | ------------------ |
| `GET`  | `/api/quotes/:quoteId/profit-calculation`             | 查询收益、实时预估     | 超管、所属区域区管 |
| `PUT`  | `/api/quotes/:quoteId/profit-calculation/draft`       | 保存年限并生成草稿     | 超管、所属区域区管 |
| `POST` | `/api/quotes/:quoteId/profit-calculation/recalculate` | 服务端重算             | 超管、所属区域区管 |
| `POST` | `/api/quotes/:quoteId/profit-calculation/freeze`      | 投递正式冻结请求       | 超管               |
| `GET`  | `/api/quote-profit/hardware-cost-rules`               | 查询成本规则及历史版本 | 超管               |
| `POST` | `/api/quote-profit/hardware-cost-rules`               | 新增成本规则版本       | 超管               |

草稿、重算和冻结请求只接受年限、期望行版本等白名单字段。请求中出现金额、成本或收益字段会直接拒绝，服务端不会采用前端金额。

常见错误码：

| 错误码                                       | 含义                           |
| -------------------------------------------- | ------------------------------ |
| `V3_QUOTE_PROFIT_NOT_FOUND`                  | 报价不存在或当前用户无区域权限 |
| `V3_QUOTE_PROFIT_ROLE_DENIED`                | 当前角色无权访问               |
| `V3_QUOTE_PROFIT_REGION_REQUIRED`            | 区管无正式区域绑定             |
| `V3_QUOTE_PROFIT_NOT_APPLICABLE`             | 报价不属于微盾核算范围         |
| `V3_QUOTE_PROFIT_INCOMPLETE`                 | 输入不完整，不能冻结           |
| `V3_QUOTE_PROFIT_FROZEN_READ_ONLY`           | 正式快照不可覆盖               |
| `V3_QUOTE_PROFIT_VERSION_CONFLICT`           | 报价或收益行版本冲突           |
| `V3_QUOTE_PROFIT_AMOUNT_READ_ONLY`           | 请求试图提交服务端计算金额     |
| `V3_QUOTE_PROFIT_COST_RULE_FUTURE_FORBIDDEN` | V1 不允许未来生效成本规则      |
| `V3_QUOTE_PROFIT_HARDWARE_NOT_UNIQUE`        | 硬件编号无法唯一匹配           |

### 6.3 冻结与版本约束

- 同一硬件型号的有效成本规则不能重叠。
- `frozen` 行不能被原记录覆盖，新审批轮次只能创建新计算版本。
- 同一订单、公式版本和输入指纹只能冻结一次。
- 成本规则变更只影响未冻结或新计算版本，不改变历史正式快照。

### 6.4 回退边界

- 回退前必须先关闭报价收益 Worker。
- 如果没有正式冻结、人工成本版本或新格式硬件数量，可执行迁移回退脚本。
- 如果已经存在上线后业务数据，回退脚本会输出中文阻断原因，只允许应用级回退并保留新表、新列和冻结快照。
- 不得删除审计日志和已冻结快照。

## 7. Worker 配置与运行

### 7.1 配置项

| 配置项                          | 默认值  | 说明                                           |
| ------------------------------- | ------- | ---------------------------------------------- |
| `QUOTE_PROFIT_WORKER_ENABLED`   | `false` | 是否启用报价收益任务                           |

### 7.2 启用顺序

1. 完成数据库备份和迁移预检。
2. 执行数据库迁移和 13 条初始成本种子。
3. 发布 API、Worker、Web，保持 `QUOTE_PROFIT_WORKER_ENABLED=false`。
4. 验证收益只读接口、成本配置、多区域权限和页面降级。
5. 设置一次性、持久化的 `QUOTE_PROFIT_EVENT_CUTOVER_AT`。
6. 设置 `QUOTE_PROFIT_WORKER_ENABLED=true` 并重建主 Worker 容器。
7. 使用受控订单走完整审批，确认生成 `frozen` 或可解释的 `incomplete`。

历史订单不会自动回填正式收益，只处理切换时间之后的新确认事件。

### 7.3 运行检查 SQL

待处理和失败事件：

```sql
SELECT event_type, status_code, count(*) AS count
FROM ops.outbox_events
WHERE event_type IN (
  'crm.quote.profit.freeze.requested',
  'crm.quote.profit.cost_rule.changed'
)
GROUP BY event_type, status_code
ORDER BY event_type, status_code;
```

不完整和正式冻结数量：

```sql
SELECT status_code, count(*) AS count
FROM crm.quote_profit_calculations
WHERE formula_version = 'weidun-v1'
GROUP BY status_code
ORDER BY status_code;
```

最近冻结记录：

```sql
SELECT q.quote_no, o.order_no, p.status_code, p.frozen_at, p.frozen_by_user_id
FROM crm.quote_profit_calculations p
JOIN crm.quotes q ON q.id = p.quote_id
LEFT JOIN crm.orders o ON o.id = p.order_id
WHERE p.status_code = 'frozen'
ORDER BY p.frozen_at DESC NULLS LAST
LIMIT 20;
```

缺失年度成本的硬件：

```sql
SELECT h.hardware_code,
       h.hardware_name,
       r.version_no,
       r.effective_from,
       r.annual_warranty_maintenance_cost
FROM catalog.hardware_products h
LEFT JOIN LATERAL (
  SELECT id, version_no, effective_from, annual_warranty_maintenance_cost
  FROM catalog.hardware_profit_cost_rules r
  WHERE r.hardware_product_id = h.id
    AND r.status_code = 'active'
    AND r.effective_from <= now()
    AND (r.effective_to IS NULL OR r.effective_to > now())
  ORDER BY r.version_no DESC
  LIMIT 1
) r ON true
WHERE h.status_code <> 'archived'
  AND (r.id IS NULL OR r.annual_warranty_maintenance_cost IS NULL)
ORDER BY h.hardware_name;
```

最后一条 SQL 如现场数据库字段或类型不同，可使用页面的“只看成本缺失”筛选替代，不要直接改写生产数据。

## 10. 已知边界

1. V1 不支持未来生效成本规则。
2. 历史订单不自动生成正式收益。
3. 同型号数量上限 9999，重复型号不会自动累加。
4. 明细无法明确归类、区域无法确定或公开价无法重建时，收益保持 `incomplete` 或 `not_applicable`。
5. 年度质保和采购维保 V1 共用同一 Excel 年度成本字段；拆分字段需要重新评审公式、迁移和历史快照。
6. 本次交付没有生产副作用；所有生产操作必须基于新授权执行。
