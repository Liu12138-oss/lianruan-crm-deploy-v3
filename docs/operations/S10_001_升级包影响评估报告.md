# S10-001 升级包影响评估报告（KB-20260813）

## 评估目标

确认 `20260813_S10_001_组织架构主体.sql` 集成到升级包后，不会破坏现有 V2 → V3 数据迁移流程。

## 风险假设

| 风险点 | 假设 |
|---|---|
| 扩展字段默认值 | V2 数据装入后扩展字段应取默认值，不需手工回填 |
| CHECK 约束扩展 | `status_code` 从 `active/disabled` 扩展为 `draft/active/disabled/archived`，V2 已存在的 `active`/`disabled` 应仍合法 |
| EXCLUDE 约束 | V2 数据无任职概念，EXCLUDE 不会触发 |
| path_code 回填 | V2 数据只有 1 个根组织（联软总部），回填应无错 |
| 函数依赖 | `assert_no_cycle` / `assert_archivable` 不被现有 V3 业务调用，加进去不影响 |

## 测试方法

在独立测试库 `lianruan_crm_v3_upgrade_test` 上**完整模拟升级包**流程：

1. 前置迁移（S2_001 ~ S8_001，7 个脚本）
2. V2 暂存装载（`00-prepare` + `01-load` + 1091 条原始记录）
3. S8_004 正式落表（V2 → V3 转换）
4. 后置迁移（S9_013 ~ S9_024 + KB016 + **S10_001**，12 个脚本）

跑完后与升级前主库 `lianruan_crm_v3` 行数对比。

## 执行结果

### 各阶段全部成功

- 前置 7 个迁移：全成功
- V2 装载：1091 条原始记录 + 20 实体期望，全部落进 `migration.v2_raw_records`
- S8_004 正式落表：71 用户 / 1 组织 / 71 员工档案 / 192 渠道商
- 后置 12 个迁移（含 S10_001）：全成功，无 ERROR

### 字段默认值

- iam.users 扩展字段（`origin_code`/`origin_sync_status`/`offboarding_status`）全为默认（local/manual/active）
- org.org_units.path_code 根节点为空（nlevel=0）

### 兼容性回归

- `iam.users LEFT JOIN org.org_units` 业务查询：正常返回
- 视图 `org.v_org_units_active_tree`：可查询
- 函数 `org.assert_no_cycle` / `org.assert_archivable`：可用

## 结论

**S10-001 集成到升级包后不影响 V2 → V3 数据迁移流程**。

- 所有新字段带默认值，对 V2 数据透明
- CHECK 约束扩展兼容 V2 的 `active`/`disabled` 状态
- EXCLUDE 约束对无任职数据的 V2 数据零影响
- path_code 回填对单一根组织场景正确
- 函数 / 视图作为新增能力，不破坏现有调用

## 建议

1. **升级包交付检查表**追加 S10_001：升级脚本完成前必须实际跑一遍"V2 装载 → S8_004 → S10_001"，记录 NOTICE 输出。
2. **生产部署监控**：S10_001 跑完后 30 分钟内，关注 `audit.audit_events`（应无相关事件）+ `org.staff_assignments` 计数（应保持 0）+ `path_code` GIST 索引（应正常）。
3. **回滚预案**：保留 `S10_001_组织架构主体.rollback.sql`，与升级脚本一同打包。回滚条件：迁移后任何核心业务查询失败。
