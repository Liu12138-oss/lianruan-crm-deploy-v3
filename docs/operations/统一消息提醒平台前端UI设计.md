## 0. 文档目标

- 基于 V3 当前视觉和交互风格设计消息平台，不另起一套界面体系。
- 明确管理端、渠道端、桌面端和移动端的页面边界。
- 让前端、后端、测试和业务方对字段、接口、权限和交互形成同一理解。
- 保证统一入口、正式页面落点和消息业务跳转不被破坏。

文档版本：v1.6（2026-09-03）。

## 1. 设计边界

### 1.1 正式入口

消息平台不新增根路径 `/messages`，只在四套正式页面内建设：

| 用户端     | 正式页面               | 消息中心内部路由          |
| ---------- | ---------------------- | ------------------------- |
| 管理桌面端 | `/admin.html`          | `#/notifications`         |
| 渠道桌面端 | `/partner.html`        | `#/notifications`         |
| 管理移动端 | `/admin-mobile.html`   | `#/admin/notifications`   |
| 渠道移动端 | `/partner-mobile.html` | `#/partner/notifications` |

`admin-mobile.html` 和 `partner-mobile.html` 继续负责正式入口分流，并将查询参数与内部路由交给 `mobile.html`、`mobile-app.js` 执行；消息功能不得绕过这两个正式入口另建移动站点。

未登录访问时先进入统一登录；登录成功后根据账号、设备和权限回到对应正式页面。禁止跳向工程化迁移中的未替换页面。

### 1.2 角色边界

| 能力                     | 超级管理员 | 区域管理员 | 渠道管理员 | 渠道员工 |
| ------------------------ | ---------- | ---------- | ---------- | -------- |
| 查看本人通知             | 是         | 是         | 是         | 是       |
| 修改本人普通消息偏好     | 是         | 是         | 是         | 是       |
| 查看平台投递监控         | 是         | 按权限     | 否         | 否       |
| 管理模板                 | 是         | 按权限     | 否         | 否       |
| 管理企微、短信和邮箱渠道 | 是         | 否         | 否         | 否       |
| 人工重试外部投递         | 是         | 按权限     | 否         | 否       |

平台能力不因前端隐藏而视为授权，所有接口仍需服务端权限校验。

### 1.3 普通渠道用户提醒边界

普通渠道用户不是“无提醒角色”。M1 必须为其提供站内提醒、桌面铃铛与完整通知中心，移动端同步提供消息页。提醒内容仅限当前登录用户对业务对象拥有访问权限且与其职责相关的记录。

| 场景                         | 提醒触发                       | 用户动作                                   | 数据边界                             |
| ---------------------------- | ------------------------------ | ------------------------------------------ | ------------------------------------ |
| 客户报备通过、驳回或退回补充 | 报备审批结果状态变化           | 查看本人报备并继续跟进或补充材料           | 仅本人创建、分配或被授权访问的报备   |
| 商机待跟进或长期未更新       | 到达跟进时点或超过规则时限     | 打开本人商机并补充跟进记录                 | 仅本人负责或被授权协作的商机         |
| 客户报备保护期即将到期       | 到期前按规则生成提醒           | 查看报备并确认续期或后续计划               | 仅本人可见客户的报备保护记录         |
| 报价、订单进展               | 提交、退回、客户确认或状态变化 | 查看关联报价或订单                         | 仅本人可见且当前状态允许访问的记录   |
| 权限、归属或业务对象失效     | 用户点击提醒时二次校验失败     | 显示“无权访问或记录已失效”，不泄露对象摘要 | 不返回其他渠道、团队或已回收对象信息 |

普通渠道用户不得看到审批队列、团队经营数据、其他渠道数据、平台投递监控、渠道配置或外部投递重试入口。前端筛除只用于减少误操作；接口和业务跳转必须再次执行用户、渠道、数据范围和对象状态校验。

## 5. UI-01：顶栏铃铛与通知抽屉

### 5.1 入口

- 复用现有 `.header-btn` 圆形按钮。
- 铃铛按钮固定 36px × 36px，触控和键盘焦点区域不得小于 36px。
- 未读数量为 1 至 99 时显示实际数字，超过 99 显示 `99+`。
- 未读为 0 时不显示红色数字，但铃铛入口保留。
- 页面初始化、重新获得焦点、每 30 秒刷新未读数；移动端每 60 秒刷新。

### 5.2 桌面抽屉结构

```text
┌──────────────────────────────────┐
│ 通知中心              全部已读  × │
├──────────────────────────────────┤
│ 全部  待办  业务提醒  系统通知     │
├──────────────────────────────────┤
│ ● 待确认订单                      │
│   订单 DD20260814001 等待您处理    │
│   2分钟前                 去处理 › │
├──────────────────────────────────┤
│   合同即将到期                    │
│   合同摘要将在 7 天后到期          │
│   今天 09:30              查看 › │
├──────────────────────────────────┤
│            查看全部通知            │
└──────────────────────────────────┘
```

建议尺寸：

- 桌面宽度 400px，最大高度为视口高度减 72px。
- 标题区 52px，分类栏 44px，底部操作区 48px。
- 列表单项最小高度 84px，标题最多一行，摘要最多两行。
- 未读项使用左侧 3px 主色条和浅蓝背景，不使用整块高饱和蓝色。

### 5.3 交互

- 点击通知项先调用单条已读接口，再解析业务目标。
- 接口失败时保留未读状态并显示中文错误，不做浏览器内假成功。
- “全部已读”只更新当前用户当前可见通知，成功后同步刷新未读数。
- 无权、已失效或未知目标不跳转，显示统一安全提示。
- 点击遮罩、关闭按钮或按下退出键关闭抽屉。

### 5.4 状态

- 加载：显示 3 条骨架项。
- 空状态：铃铛浅色图标、“暂无通知”和“新的待办与提醒会显示在这里”。
- 错误：显示“通知加载失败”和“重新加载”按钮，保留上次成功的未读数并标记可能过期。
- 离线：显示“网络不可用，恢复后自动刷新”，不循环弹错误提示。

### 6.2 页面头部

- 面包屑：`首页 / 消息通知`。
- 标题：`消息通知`。
- 描述：`查看待办、业务提醒、系统和安全通知`。
- 主操作：`全部已读`。
- 次操作：`偏好设置`。

### 6.3 分类与筛选

| 控件     | 默认值     | 说明                            |
| -------- | ---------- | ------------------------------- |
| 分类标签 | 全部       | 标签上显示当前分类未读数        |
| 仅看未读 | 关闭       | 开启后只查未读                  |
| 时间范围 | 最近 30 天 | 可选 7 天、30 天、90 天、自定义 |
| 关键词   | 空         | 只搜索已脱敏标题和摘要          |
| 归档状态 | 未归档     | 可切换已归档                    |

默认每页 20 条，最大不超过 100 条。列表按 `created_at DESC, id DESC` 稳定排序。

### 6.4 通知项

每项显示：

- 未读点和分类标签。
- 标题、两行摘要。
- 相对时间，悬停可查看完整时间。
- 主动作按钮：查看、去处理或去审批。
- 次动作：归档。

强制消息使用危险色细边框和“强制”文字标签，但不能整项使用红底。安全通知正文只显示必要摘要。

### 6.5 管理端与渠道端差异

- 管理端可见本人负责的审批、平台异常和权限内业务提醒。
- 渠道端只可见本渠道和本人的通知，不显示平台供应商、费用、内部错误堆栈或其他渠道信息。
- 两端使用相同布局和组件，数据与动作由服务端权限决定。

### 7.2 交互规则

- 顶部栏使用现有 `.mobile-header`，标题居中，左侧返回按钮最小 44px。
- 分类使用横向分段控件，分类多时允许横向滚动，不压缩到无法点击。
- 通知使用白色卡片列表，卡片圆角 14px，卡片间距 10px。
- 主动作整行可点；归档放在更多操作中，避免误触。
- 下拉刷新；滚动到底按游标加载下一页，每次 20 条。
- 保留底部安全区，不被底部导航遮挡。

## 10. UI-06：渠道配置

正式入口为 `admin.html#/message-platform`，采用四张外部渠道卡：企微群机器人、企微自建应用、短信和 SMTP 邮箱。站内通知不依赖本页配置，始终由消息规则与个人偏好单独管理。

- 企微群机器人卡只显示 Webhook 掩码，用于脱敏团队汇总；试发不填写接收人，必须投递至 Webhook 绑定的专用测试群。
- 企微自建应用卡配置企业 ID、AgentId 和 Secret；试发必须填写临时测试成员 UserId，以验证令牌、应用可见范围和点对点投递。
- SMTP 卡配置主机、端口、加密方式、账号、密码和发件人；试发允许超管临时填写合法收件邮箱。
- 临时邮箱与临时 UserId 只密文暂存用于当前试发，达到最终投递状态后清除；任何读取、刷新或投递状态均不得显示该值。
- 页面顶部展示“运行前置检查”：通道配置加密密钥、消息投递角色、首次启用时间。任一项未就绪时禁用试发，并说明需要部署人员完成的动作。
- 页面底部展示“最近外部投递状态”，仅显示时间、通道、测试/正式标识、状态、尝试次数和脱敏摘要，不显示接收人、正文、凭据或原始供应商响应。

### 10.1 企业微信客户端呈现边界

本文件中的卡片、抽屉和通知中心是 V3 站内页面原型，不等同于企业微信客户端的消息界面。自建应用当前按企业微信官方“发送应用消息”接口发送 `msgtype=markdown`，只使用 Markdown 子集：加粗标题、引用块字段和 `info`、`warning`、`comment` 状态色，正文上限为 2048 字节（UTF-8）。因此企业微信中不会呈现站内卡片的完整布局；旧的 `msgtype=text` 消息或历史消息中的 `**字段：**` 会按纯文本显示星号，新代码仅影响后续新投递。若要实现带按钮、详情跳转的卡片视觉，需另行确认 HTTPS 详情地址后使用 `template_card`，不能仅依据站内原型推断客户端样式。

每张卡显示：

- 当前启用状态。
- 配置完整度。
- 最近一次测试结果和时间。
- 单日额度、已用量和频控摘要。
- “配置”“测试连接”“停用”操作。

凭据只显示“已配置/未配置”和版本，不显示明文。试发、启用和停用均要求输入“确认”二次确认；试发必须交由消息投递角色执行，页面不直接发起网络调用。停用外部渠道前提示影响范围，但不得影响站内通知。

### 11.1 顶部指标

- 永久失败数量。

- 最老待处理任务年龄。

### 11.2 筛选

- 时间范围。
- 渠道。
- 状态。
- 事件代码。
- 错误类型。
- 业务对象编号。
- 请求编号。

普通列表不显示完整手机号、邮箱、消息正文或敏感业务载荷。

### 11.3 详情

详情抽屉分为：基本信息、状态时间线、供应商回执、脱敏载荷摘要、重试记录和审计记录。

“人工重试”只在 `retry_wait` 或允许重试的 `failed` 状态显示。确认对话框必须说明将重新检查账号、权限、模板和退订状态；禁止编辑任务载荷后重试。

### 11.4 提醒规则管理

正式入口为 `admin.html#/message-rules`，仅服务端会话角色为 `superadmin` 的用户可访问。区域管理员、渠道管理员和渠道用户即使直接输入地址也必须由路由守卫回到工作台。

- 列表分为“业务事件”和“到期提醒”；展示提醒事项、稳定事件代码、固定接收人、已启用渠道、状态、版本和最后更新人。
- 强制规则使用“强制启用”状态标签和不可操作按钮；页面不得提供停用、删改接收人或删除历史规则的入口。
- 已启用的系统业务事件，无论是强制或可配置规则，详情对话框都必须显示“保存规则”按钮，用于二次确认保存渠道；客户报备审批待办可保存受控的角色与指定用户范围，员工账号待审核和渠道商待审核可保存指定用户范围。两类审核待办初始仅选择 `liulonghai`，保存时至少保留一名启用指定用户。可配置规则另可启停；请求必须携带规则版本，发生并发修改时提示刷新后重试。
- 审核待办规则卡片的说明文字固定展示“首期仅提醒指定用户；可由超管调整范围”。员工账号审核字段预览为“员工姓名、渠道商名称、提交人”；渠道商审核字段预览为“渠道商名称、提交人”。页面不显示或编辑企微 UserId、邮箱、凭据等外部投递参数。
- 到期规则详情可维护提前 `30 / 7 / 1` 天、工作日 `09:00`、即时/`15` 分钟/`1` 小时合并窗口和启停状态。保存请求必须携带完整策略、规则版本与二次确认，并只影响后续扫描生成的提醒。
- 当前接收人固定为当前负责人、渠道固定为站内提醒；指定角色、指定用户、抄送和外部渠道仍需服务端组织、角色、数据范围、个人授权和外部通道状态校验后才可开放，页面不得自造可选项。
- 规则变更只影响后续事件；已生成通知不撤回。详情页说明必须始终可见。

## 14. 业务目标映射

后端返回业务目标：

- `aggregateType`
- `aggregateId`
- `targetAction`

前端按当前正式页面、角色和设备映射内部路由。禁止后端模板直接下发任意绝对地址或带令牌地址。

映射失败时统一显示：`该记录不存在、已失效或当前账号无权访问。`

映射成功后仍由目标业务接口重新执行权限和数据范围校验。

## 15. 可访问性

- 所有按钮可通过键盘聚焦和操作。
- 抽屉打开后焦点进入抽屉，关闭后返回铃铛按钮。
- 未读、优先级和状态同时使用文字、图标和颜色。
- 正文和状态颜色达到常用对比度要求。
- 动态未读数量使用温和的辅助技术播报，不连续打断用户。
- 移动端触控目标不小于 44px × 44px。
- 减少动态效果偏好开启时，关闭抽屉滑动和数字跳动动画。
