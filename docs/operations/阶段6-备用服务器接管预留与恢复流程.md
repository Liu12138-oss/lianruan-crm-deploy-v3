# 阶段6 备用服务器接管预留与恢复流程

## 1. 当前结论

用户已确认首发暂不准备备用服务器。该决策可以支持单机容器首发，但不能承诺整机故障 30 分钟内接管。阶段6和阶段7必须把部署留口、备份、恢复脚本、域名切换和演练流程准备好，后续只要增加备用服务器即可接入。

## 2. 接管能力预留原则

- 所有容器镜像必须可重复构建，并记录镜像摘要。
- 生产配置通过环境变量或配置文件注入，不写入源码。
- PostgreSQL、Redis、上传文件、导出文件、审计日志和任务结果必须有异机备份。
- Redis 不保存业务唯一数据；队列可从 PostgreSQL 任务事实表补投。
- 域名 TTL 建议不高于 60 秒。
- 监控必须在业务服务器外部有探测点。
- 备用服务器目录结构、容器编排文件和恢复脚本与主服务器保持一致。

## 3. 部署留口

| 留口 | 首发单机做法 | 后续备用服务器接管做法 |
| --- | --- | --- |
| 镜像 | 本机构建或制品上传 | 备用服务器拉取同一摘要镜像 |
| 配置 | `.env.production` 不入库 | 备用服务器保存同结构配置 |
| 数据库 | PostgreSQL 单机容器 | 从 pgBackRest 或物理备份恢复 |
| Redis | AOF 和快照 | 恢复 AOF 或直接由 PostgreSQL 补投队列 |
| 文件 | 本地挂载目录 | 定时同步或从异机备份恢复 |
| 域名 | 指向主服务器 | 故障时切换到备用服务器 |
| 监控 | 外部探测主服务器 | 探测主备并记录切换 |

## 4. 异机备份要求

| 数据 | 频率 | 保留 | 校验 |
| --- | --- | --- | --- |
| PostgreSQL 增量备份 | 持续归档或 5 分钟级恢复点 | 按合规确认，建议不少于 30 天 | 每日至少一次校验 |
| PostgreSQL 全量备份 | 每日 | 建议不少于 7 份 | 每周恢复演练 |
| Redis AOF 或快照 | 每 5 至15 分钟同步 | 建议不少于 7 天 | 校验文件大小和加载能力 |
| 上传、导出和任务结果文件 | 每小时或按变更同步 | 按文件保留期 | 抽样校验摘要 |
| 部署配置和镜像摘要 | 每次发布 | 永久保留发布记录 | 发布前后核对 |

备份必须存放在业务服务器以外的位置。只在本机保留备份不满足高可用和容灾要求。

## 5. 主服务器故障恢复流程

没有备用服务器时：

1. 外部监控确认主服务器不可用。
2. 运维负责人判断是否为网络、进程、容器、磁盘或整机故障。
3. 若容器或进程故障，先在本机重启对应容器。
4. 若整机不可恢复，准备新服务器或临时服务器。
5. 安装容器运行时，拉取生产镜像。
6. 恢复 PostgreSQL 最近可用备份。
7. 恢复文件目录。
8. 恢复 Redis；若 Redis 不可恢复，则启动系统后执行任务补投。
9. 执行健康检查、接口冒烟、权限抽样和任务队列检查。
10. 切换域名或入口地址。
11. 记录恢复点、恢复时间和数据损失范围。

有备用服务器后：

1. 确认主服务器故障且无法在 10 分钟内恢复。
2. 冻结自动任务消费者，避免主备同时写入。
3. 在备用服务器恢复最新数据库和文件。
4. 启动 PostgreSQL、Redis、后端、任务消费者、前端和 Nginx。
5. 执行只读健康检查。
6. 切换域名到备用服务器。
7. 打开任务消费者，执行 PostgreSQL 任务补投。
8. 业务代表完成核心流程抽样。

## 6. 回切流程

故障主服务器恢复后不得直接重新接入流量。

1. 比对主备数据库时间线和备份链路。
2. 以当前生产服务器为准重新建立备份。
3. 清理旧主服务器未完成容器和任务消费者。
4. 重新同步文件和配置。
5. 经过一次完整冒烟后，决定是否回切。

## 7. 接管演练验收

| 演练 | 首发单机最低要求 | 有备用服务器后的要求 |
| --- | --- | --- |
| 备份恢复 | 在临时目录恢复 PostgreSQL 和文件 | 在备用服务器完整恢复 |
| Redis 丢失 | 清空 Redis 后从 PostgreSQL 补投任务 | 同左 |
| 域名切换 | 准备切换手册和责任人 | 实测 TTL 和切换时间 |
| 接口冒烟 | 登录、列表、任务、下载 | 同左 |
| 数据校验 | 数量守恒和关键业务抽样 | 同左 |

## 8. 风险登记

暂不准备备用服务器时，整机故障恢复时间取决于新服务器准备、备份下载和恢复速度，无法承诺 30 分钟接管。该风险必须在阶段7上线准入会议中由产品总负责人和运维负责人签字接受。
