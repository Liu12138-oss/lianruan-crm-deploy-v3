# 组织架构正式管理员入口与只读观察验收说明（KB-20260817-ORG-ENTRY-001）

> 适用版本：联软渠道管理平台 V3。  
> 当前状态：已完成本地代码交付和一次受控测试环境观察；组织功能、组织写入和企微目录同步当前均保持关闭。  
> 本次准入范围：仅评审“超级管理员进入组织工作区并只读浏览”。不代表组织写入、权限运行时切换、证书告警、离职执行或企微真实同步已开通。  
> 关联基线：`docs/V3业务平台底座与业务扩展实施交付方案.md` 第 6、7、17、18、21 章、`docs/operations/组织架构阶段一至五交付验收记录.md`、`docs/operations/企业微信组织架构同步实施方案.md`。

## 1. 目标、范围与不可突破边界

本 KB 的唯一目标是在不影响现有 V3 业务的前提下，为超级管理员受控开启组织架构的只读浏览并完成观察。正式管理员页仅提供入口，组织业务逻辑仍在工程化工作区中执行。

- 正式入口：`/admin.html` 左侧“管理后台”分组的“组织架构”。
- 目标地址：`/workspace/admin/platform-admin/organization/units`。
- 可见范围：仅签名 Cookie 会话中的超级管理员；渠道端和两个移动端均不展示入口。
- 跳转方式：使用浏览器整页跳转；工作区重新按签名 Cookie 校验会话和超级管理员权限。
- 正式页面状态：只读取 `/api/org/status` 呈现“未启用”“只读观察”或“已启用”；读取失败时保守显示“未启用”。服务端始终是权限和开关的最终判定方。
- 四套既有正式页面必须保持原落点和业务行为：`/admin.html`、`/admin-mobile.html`、`/partner.html`、`/partner-mobile.html`。

本轮不得调用 `/api/v2` 组织接口，不得从页面修改环境开关，不得新增或修改组织、证书、任职、角色、数据范围、离职或企微同步数据。组织工作区不可用或再次回退时，客户报备、商机、报价、订单、渠道、账号、登录和退出登录仍须独立可用。

## 2. 开关基线与本轮允许动作

| 开关 | 当前基线 | 本轮受控观察允许值 | 作用与限制 |
| --- | --- | --- | --- |
| `V3_ORGANIZATION_ENABLED` | `false` | 仅观察窗口可设为 `true` | 只开放组织读取门禁。 |
| `V3_ORGANIZATION_WRITE_ENABLED` | `false` | 必须始终为 `false` | 任何组织写接口必须返回 `403 ORG_WRITE_DISABLED`，不得写入业务数据。 |
| `V3_DIRECTORY_SYNC_ENABLED` | `false` | 必须始终为 `false` | 不连接企微、不创建同步任务、不执行预览或应用。 |

开关只可由经授权的部署会话变更；管理员页面、组织工作区和本 KB 均不提供改动服务器配置的能力。观察结束、任何异常或验收未通过时，三个开关均立即恢复为 `false`。

## 3. 已发生的测试环境回退事实与原因边界

### 3.1 现场事实

在测试环境版本 `3.0.0-stage9.41.20260817-sp002` 的一次受控开启中，组织状态接口、超级管理员只读访问和组织写入拒绝均通过；但正式 `/admin.html` 仍显示“未启用”。为避免正式入口状态与服务端实际状态不一致，现场立即将三个开关恢复为 `false`。

回退后的已核验状态如下：

- 两套 API 健康检查正常；
- `org.*` 发件箱事件数为 `0`；
- 目录同步批次和连接器数均为 `0`；
- 未开启组织写入和企微目录同步，未发生组织业务写入、同步应用或任务领取。

### 3.2 发布链路原因证据与禁止推断项

2026-08-18 的本地复核确认，`sp001` Nginx 镜像内的 `admin-app.js` 的 SHA256 以 `727f32...` 开头，且与旧 `dist` 文件完全一致：该文件仅包含工作区跳转，缺少 `/api/org/status` 查询和“只读观察”展示逻辑。当前 `apps/web/public/admin-app.js` 源码的 SHA256 以 `c61cd9...` 开头，已包含这两项逻辑。

这构成“发布链路未带入最新正式页面静态资源”的原因证据；它**不能**用于推断 `sp002` 镜像内 `admin-app.js` 的哈希或其具体构建内容。`sp002` 的现场表现只记录为“正式 `/admin.html` 显示未启用”，不得扩写为未经取证的镜像结论。

## 4. 再次启用的硬性前置条件

必须在新的目标版本上完成以下三层验证，任一层未通过即不得开启 `V3_ORGANIZATION_ENABLED`：

| 验证层 | 必须留存的证据 | 通过标准 |
| --- | --- | --- |
| 新目标版本 | ZIP 校验值、`manifest`、`SHA256SUMS`、镜像版本和发布记录 | 明确本次目标包与版本，按《V3生产升级包制作规范》完成外层及包内校验、脚本语法检查和升级前配置快照。 |
| 镜像内静态资源 | Nginx 镜像中实际 `admin-app.js` 的路径、完整 SHA256、关键逻辑核验记录 | 文件同时包含 `/api/org/status` 查询和“只读观察”状态呈现逻辑；不得以本地源码、旧 `dist` 或文件名替代镜像取证。 |
| 服务器实际响应 | 发布后从服务器获取的 `/admin.html`、其引用的脚本内容或完整哈希、浏览器实测记录 | 超级管理员页面能够按服务端状态显示“只读观察”；非超级管理员不见入口；静态资源缓存和浏览器缓存均已按实际引用文件复核。 |

三层证据由发布负责人、测试负责人和运维负责人共同确认后，才可进入只读观察。不得把“接口可用”或“本地源码存在”视为正式页面已更新。

## 5. 发布前、发布中与发布后验收清单

### 5.1 发布前

1. 确认三个开关当前均为 `false`，记录配置快照、应用镜像版本、数据库迁移版本、备份恢复点和发布包校验结果。
2. 核对目标环境 `migration.schema_migrations` 执行事实；在生产同规模副本确认阶段 8 暂存装载与正式落表先完成，S9、S10 后置迁移再按文件顺序执行，并记录锁等待、执行时长、数据体检和回退步骤。部署脚本与本地测试脚本顺序不一致时不得发布。
3. 按第 4 章完成新目标版本、镜像内静态资源、服务器实际响应三层验证；发布包必须按 ZIP 规范执行解压、包内校验、`bash -n`、Shell 变量标识检查、关键脚本运行测试和关键断言本地等价验证。
4. 以签名 Cookie 会话准备超级管理员、非超级管理员和渠道账号测试样本；不得使用兼容请求头或客户端自报身份替代。
5. 留存组织域基线：组织相关表计数、`org.*` 发件箱事件数、目录同步连接器数和同步批次数。若基线不为零，必须逐项说明来源并由验收负责人批准。
6. 完成四套正式页面的登录、退出登录和主链路基线：管理员和渠道端的客户报备、商机、报价、订单、渠道、账号。

### 5.2 受控开启与即时验证

1. 仅将 `V3_ORGANIZATION_ENABLED` 设为 `true`，保持 `V3_ORGANIZATION_WRITE_ENABLED=false`、`V3_DIRECTORY_SYNC_ENABLED=false`，重启受影响的 V3 服务并记录时间、操作者和配置差异。
2. 验证 `/health/live`、`/health/ready`、`/health/dependencies` 正常，且 `/admin.html`、`/login` 正常响应。
3. 超级管理员从 `/admin.html` 进入组织工作区，确认正式页面显示“只读观察”，工作区能够读取允许范围内的组织信息。
4. 非超级管理员、渠道端和两个移动端不得展示组织入口；直接访问工作区或组织接口仍应由服务端拒绝未授权访问。
5. 对一个组织写接口执行无副作用验证，必须得到 `403 ORG_WRITE_DISABLED`；不得用真实创建、修改、颁发、延期、撤销或离职动作试探写门禁。
6. 再次核验组织相关表、`org.*` 发件箱、目录同步连接器和同步批次与发布前基线一致；发现非预期变化立即执行第 8 章回退。
7. 回归四套正式页面及第 5.1 节的既有业务主链路；任何登录、跳转、权限、读取或写入回归失败均阻断观察。

### 5.3 发布后与七天观察

连续观察至少 7 天；每日记录一次以下项目，且至少完成两轮组织只读数据对账：

- 服务健康、`api.request.completed`、`api.request.failed` 中的组织相关请求、HTTP 错误和拒绝写入结果；
- 超级管理员入口状态与 `/api/org/status` 一致性；
- 组织只读查询结果与批准的组织基线差异；任何差异只登记、复核，不通过本轮开关修复数据；
- 组织相关表、`org.*` 发件箱、同步连接器和同步批次是否保持基线；
- 管理端、渠道端、两个移动端的登录和主链路抽检结果。

现有可用观测为通用结构化 API 日志和三项健康检查。当前没有组织域专用指标、阈值、告警路由或自动化生产对账脚本，因此不得声称已完成组织告警闭环；观察记录应以人工日检、请求编号和数据库只读查询作为临时证据。

## 6. 企微、证书与离职的本轮处理

企微组织同步不准入本轮只读观察：`V3_DIRECTORY_SYNC_ENABLED` 必须保持 `false`。当前运行时尚未注入并完成真实企业微信通讯录适配器验证，也未满足独立凭据、回调验签解密、令牌缓存、全量校准、可见范围确认、监控告警和自动化对账条件；因此不能称为企微真实只读同步、真实全量快照、真实对账或七天同步观察。

证书和离职也不属于本轮必要运行项：

- 证书到期只允许预警，绝不自动撤销业务角色或改变权限；本轮只验证不会创建证书写入或告警任务。
- 离职仅保留只读影响预览、交接单详情和扫描请求边界；不得自动停用账号、结束任职或渠道成员关系、改变 CRM 负责人、转移审批或业务归属。本轮只验证不会触发这些执行动作或任务。

本轮不将上述能力的 Worker、自动任务、实时权限切换或外部调用纳入验收结论。

## 7. 准出责任与交付证据

只读观察完成后，由下列责任人共同签字决定“继续保持只读”或“关闭功能”；本 KB 不授权开启组织写入或企微同步。

| 责任角色 | 必须确认的内容 |
| --- | --- |
| 发布负责人 | 新目标版本、发布包校验、配置快照、镜像版本与可恢复应用版本完整。 |
| 测试负责人 | 三层静态资源验证、访问控制、拒写、主链路回归、两轮只读对账和七天记录完整。 |
| 运维负责人 | 健康检查、日志、基线计数、备份恢复点、开关关闭和应用回退演练可执行。 |
| 业务负责人 | 只读范围、差异处理方式及不影响既有业务的结论已确认。 |

证据应归档在对应 SP/KB 的 `README`、`manifest`、`SHA256SUMS`、`precheck.sh`、`upgrade.sh`、`verify.sh`、`rollback.sh`、`tests/smoke.sh` 输出和发布记录中；不得以口头确认替代。

## 8. 异常处理与回退

以下任一情况立即回退：正式入口状态与服务端状态不一致、三层静态资源验证失败、未批准权限差异、组织数据或发件箱非预期变化、任何企微调用或同步批次出现、既有主链路回归失败、健康检查异常。

回退顺序如下：

1. 将三个开关均设为 `false`，重启受影响的 V3 服务，确认组织读取、写入和目录同步均被门禁关闭。
2. 若页面、路由或 API 仍异常，使用经验证的 SP/KB `rollback.sh` 恢复升级前的应用镜像、Compose、`v3.env`、Nginx 和相关脚本配置；保留回退日志和配置快照。
3. 验证 `/health/live`、`/health/ready`、`/health/dependencies`、`/login`、`/admin.html` 以及四套正式页面的主链路；复核组织相关表、`org.*` 发件箱、同步连接器和同步批次。
4. 数据库迁移和已生成的审计、预览证据均保持向前兼容并留存对账，禁止在生产删除组织表、审计记录或执行破坏性数据库回退。

回退完成不等于可以立即再次启用。再次启用必须重新满足第 4 章三层验证，并重新完成本章所列发布前和即时验收；不得沿用本次失败现场的静态资源或缓存结论。
