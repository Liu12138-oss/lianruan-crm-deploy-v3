## 2. 已确认的问题

### 2.1 内部组织树成员计数重复累加（P0）——已修复（2026-08-24）

当前实现中：

- `构建树节点()` 已经把子孙节点成员聚合到当前节点 `members`；
- `节点成员数()` 仍使用“当前节点的 `members.length` + 所有子节点递归求和”。

因此叶子节点计数正常，但父级节点会重复计算子孙成员。例如“大南区”右侧面板如果显示 8 名成员，树节点数字可能显示为 12 或更高。

**修复内容**：`节点成员数()` 已改为直接返回 `(节点.members || []).length`，与聚合结果一致（与渠道树的 `渠道节点成员数()` 实现对齐），并补充测试断言禁止回归旧写法。`admin.html` 资源版本号同步提升至 `admin-app.js?v=148`。

### 2.2 两套页面实现不一致（P1）

- `apps/web/public/admin-app.js`：当前正式运行时页面，包含最新聚合、整卡编辑、证书筛选、RBAC、角色分配等逻辑。
- `apps/web/src/pages/admin/platform-admin/OrganizationWorkspacePage.vue`：仍保留旧的“只取直属成员”“人员与任职栏目”“只读数据来源提示”等内容。

该文件当前可能与正式页面冲突，也可能误导后续开发和测试。建议明确 `admin-app.js` 为唯一运行时来源，并将 Vue 工作区标记为废弃或同步后再移除。

### 2.3 RBAC 渠道范围类型映射错误（P1）——已修复（2026-08-24）

前端 `组装角色范围提交()` 对渠道组织列表统一提交：

```text
{ scopeType: "region", scopeRefId: 渠道节点Id }
```

但渠道树中包含大区、区域、渠道商三种节点。后端 `rbac-store.ts` 和 `org-store.ts` 已支持：

```text
scopeType = "region"  // 对应 org.regions
scopeType = "partner" // 对应 channel.partners
```

如果用户选择的是渠道商节点，当前会被错误标记为区域范围，后续查询可能无法命中或校验失败。需要按节点类型分别提交 `region` 或 `partner`。

**修复内容**：`组装角色范围提交()` 已按节点实际类型判定——从 `平铺渠道组织列表` 查找目标节点，含 `partnerName`/`partnerCode` 的渠道商节点提交 `partner`，大区/区域节点提交 `region`（判别方式与 `构建渠道树节点()` 一致）。编辑回填逻辑无需调整：回填仅收集 `scopeRefId`，保存时按树节点实际类型重新判定，旧脏数据可被自动纠正。已补充测试断言。

### 2.4 历史证书/业务角色联动测试（已废弃为验收标准）

执行：

```text

```

当前失败原因：

```text
column "linked_certification_template_id" of relation "business_roles" does not exist
```

这不是业务代码失败，而是本地测试库未应用以下迁移：

- `database/migrations/20260821_R02_001_渠道组织编辑与证书业务角色联动.sql`
- `database/migrations/20260821_R01_001_RBAC权限点与角色管理.sql`

**历史修复事实**：R01、R02 已应用到本地测试库（`lianruan_crm_v3_test`），并按 `migrate-db.sh` 相同格式登记 `migration.schema_migrations`（含 SHA256 校验和）。当时重跑 `org-rbac-integration.test.ts` 4 个用例全部通过。

**最新纠偏**：上述用例中“颁发证书自动授予业务角色、撤销证书自动移除业务角色”的断言已被产品规则废弃，不能继续作为通过标准。正确标准是证书与业务角色完全解耦：颁发、到期、撤销和持有人离职均不自动改变业务角色；离职不撤销证书，角色调整另行人工确认并独立审计。

**额外发现并修复（重要）**：两个迁移执行脚本存在顺序缺陷——`deploy/single-server/scripts/migrate-db.sh` 与 `scripts/prepare-postgresql-test.mjs` 均未把 R 系列迁移后置于 S10 建表之后执行：

- `migrate-db.sh` 第一轮循环只跳过 `S8_004/S9_/S10_`，R01/R02 会在 `org.business_roles`、`org.certification_templates`（由 `20260815_S10_002` 创建）建表之前执行，全新环境必然中断；
- `prepare-postgresql-test.mjs` 的前置列表未排除 R 系列，同时后置列表又包含 R 系列，R01/R02 会被重复执行两次，且第一次会因缺表失败。

两个脚本均已修复：R 系列（`^[0-9]{8}_R[0-9]{2}_` 模式）统一后置到 S9/S10 之后执行。`bash -n` 与 `node --check` 语法校验通过。

### 2.5 管理账号和渠道成员匹配准确性待验证（P1）

用户反馈“很多渠道组织用户没有匹配到对应渠道商”“很多超管、区管没有匹配到对应部门”。当前实现：

- 渠道成员以 `channel.partner_members` 为准，成员必须存在有效的渠道成员关系；
- 超管归集到根部门；
- `admin` 同样归集到根部门；
- 区管通过 `iam.users.region_id` 匹配 `org.regions` 并创建对应部门。

若历史数据缺少 `partner_members`、`region_id` 或角色编码不统一，就会产生未匹配账号。需要增加“未匹配账号明细”和“手动匹配/修复”能力，而不是只依赖一键同步。

### 10.2 当前自动交接边界

当前后台任务只自动转移客户、报备、商机、报价、订单五类对象的负责人。审批申请人、审批结果和历史事实保持不变；动态待办按新的有效角色与区域范围接手。合同、通用流程任务和完整 `workflow.process_tasks` 尚未落地，不得宣传为“所有未处理任务已自动改派”。

### 10.3 测试服务器发布顺序

1. 备份数据库和现有配置，核对迁移账本与当前镜像摘要。
2. 只读检查固定销售/技术角色无语义冲突，一人多条有效任职查询必须返回零行。
3. 依次执行 `20260827_S10_009_渠道成员统一业务角色`、`20260827_S10_010_任职编辑一致性修正`。
4. 发布 Web/API/Worker，核对 `/admin.html` 同时引用 `admin-app.js?v=159` 和 `style.css?v=16`。
5. 首次验证保持 `V3_ORGANIZATION_ENABLED=false`、`V3_ORGANIZATION_WRITE_ENABLED=false`、`V3_AUTH_ACCOUNT_STATUS_CHECK_ENABLED=false`、`V3_ORGANIZATION_OFFBOARDING_ENABLED=false`。
6. 先开放组织只读观察，再开放普通组织写入；完成超管、区管、渠道账号和主业务回归。
7. 单独灰度账号状态防护；交接执行继续关闭。

### 10.4 回退门禁

- 交接执行尚未开启时，可关闭组织写入或组织总开关并回退应用镜像；`S10_009`、`S10_010` 作为向前兼容结构保留。
- 已开启账号状态防护后，禁止回退到不具备同等防护的快照；回退脚本必须拒绝该操作。
- 停用归档交接仍为开启状态时，禁止直接回退应用；必须先关闭交接开关并确认 Worker 停止领取新任务。
- 配置文件改为关闭不足以证明任务静止；回退脚本还必须确认运行中主 Worker 的实际环境不为 `true`、未完成交接单为零、`pending/processing/failed` 交接扫描事件为零。
- 若数据库存在 `offboarding_status` 字段且已有 `offboarding/offboarded` 账号，目标快照必须继续开启账号状态防护；脚本先判断列是否存在，再读取停用归档账号，兼容尚未执行组织迁移的旧环境。
- 一旦产生停用归档业务事实，不自动恢复账号、角色、任职、渠道关系或业务负责人；需要恢复时走人工审计流程。
