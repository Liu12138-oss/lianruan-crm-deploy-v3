# 渠道商等级功能集成指南

## 概述

本文档说明如何在联软CRM系统中集成渠道商等级功能。该功能已完成后端开发和数据迁移，现在需要在前端集成。

## 一、后端状态（✅ 已完成）

### 1.1 数据迁移
- ✅ 已为所有渠道商添加 `partnerLevel` 字段（默认 'none'）
- ✅ 已为所有产品添加 `priceForPrimary` 和 `priceForSecondary` 字段
- ✅ 二级渠道商价格比一级高10%

### 1.2 API接口（已实现）
| 接口 | 方法 | 说明 |
|-----|------|------|
| `/api/partners/:id/level` | PUT | 设置渠道商等级 |
| `/api/partners/:id/unbind` | PUT | 解绑二级渠道商 |
| `/api/partners/:id/rebind` | PUT | 重绑定二级渠道商 |
| `/api/partners/secondary/apply` | POST | 一级渠道商申请创建二级 |
| `/api/partners/secondary/pending` | GET | 获取待审批的二级渠道商申请 |
| `/api/partners/secondary/:id/approve` | PUT | 审批通过 |
| `/api/partners/secondary/:id/reject` | PUT | 审批驳回 |
| `/api/orders/:id/primary-confirm` | PUT | 一级渠道商确认订单 |
| `/api/orders/:id/primary-reject` | PUT | 一级渠道商驳回订单 |

### 2.3 修改 partner-app.js（报价和订单功能）

#### 步骤1：修改报价计算函数

在 `partner-app.js` 中找到 `calcFeatureTotal` 函数，替换为：
```javascript
function calcFeatureTotal(features, endpoints) {
  // 使用模块提供的分级价格计算
  if (window.PartnerLevelModule) {
    return window.PartnerLevelModule.calcFeatureTotalByLevel(features, endpoints);
  }
  
  // 降级处理：使用原始逻辑
  if (!features.length) return 0;
  let total = 0;
  const qty = endpoints || 0;
  
  features.forEach(feat => {
    if (feat.priceFixed) {
      total += feat.priceFixed * (feat.discount || 1);
    } else if (feat.tiers && feat.tiers.length) {
      const tier = feat.tiers.find(t => qty >= t.min && qty <= t.max) || feat.tiers[0];
      if (tier) {
        const price = feat.unitPrice ? feat.unitPrice * tier.discount : (tier.price || 0);
        total += price * qty;
      }
    } else if (feat.unitPrice) {
      total += feat.unitPrice * qty;
    }
  });
  return Math.round(total);
}
```

#### 步骤2：修改 `getFeaturePrice` 函数

替换为：
```javascript
function getFeaturePrice(fid) {
  const feat = allFeatures.value.find(f => f.id === fid);
  if (!feat) return 0;
  
  // 使用模块提供的分级价格获取
  if (window.PartnerLevelModule) {
    return window.PartnerLevelModule.getFeaturePriceForDisplay(feat, form.endpoints);
  }
  
  // 降级处理
  if (feat.priceFixed) {
    return feat.priceFixed * (feat.discount || 1);
  }
  if (feat.tiers && feat.tiers.length) {
    const tier = feat.tiers.find(t => form.endpoints >= t.min && form.endpoints <= t.max) || feat.tiers[0];
    return tier ? (feat.unitPrice ? feat.unitPrice * tier.discount * form.endpoints : tier.price || 0) : 0;
  }
  if (feat.unitPrice) {
    return feat.unitPrice * form.endpoints;
  }
  return 0;
}
```

## 三、数据流说明

### 3.1 渠道商等级设置流程
```
区管/超管 → 渠道商详情页 → 设置等级按钮 → 调用API → 更新数据库 → 刷新界面
```

### 3.2 二级渠道商绑定流程
```
区管/超管 → 渠道商详情页 → 设为二级 → 选择上级渠道商 → 绑定 → 调用API → 完成
```

### 3.3 分级报价流程
```
用户登录 → 获取用户信息（含partnerLevel） → 报价计算时选择对应价格字段 → 显示不同价格
```

### 3.4 二级渠道商订单确认流程
```
二级渠道商下单 → 订单状态pending → 一级渠道商收到通知 
→ 一级渠道商确认/驳回 → 区管/超管审批 → 订单流转
```

## 五、注意事项

### 5.1 兼容性
- 保留了原有的 `level` 字段（LEP/钻石/金牌等），不受影响
- 新增的 `partnerLevel` 是独立字段
- 降级处理：如果模块加载失败，会使用原始逻辑

### 5.2 安全性
- 后端API已做权限校验，只有区管和超管可以设置等级
- 二级渠道商绑定必须同区域
- 订单确认只有对应的一级渠道商可以操作

### 5.3 性能优化
- 价格计算在前端完成，不影响后端性能
- 等级信息从登录用户信息获取，无需额外请求

## 七、常见问题

**Q1: 为什么有些渠道商没有等级？**
A: 现有渠道商默认为"无等级"，需要管理员手动设置等级。

**Q2: 二级渠道商价格为什么比一级高10%？**
A: 这是业务规则，二级渠道商通过一级渠道商发展，价格有所上浮。

**Q3: 如何判断当前用户的渠道商等级？**
A: 用户登录后，系统会获取其所属渠道商的 partnerLevel 字段。

**Q4: 订单确认流程具体是怎样的？**
A: 
- 一级/无等级渠道商：pending → processing → shipped → completed
- 二级渠道商：pending → primary_confirmed → processing → shipped → completed
