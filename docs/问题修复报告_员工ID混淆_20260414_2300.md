**问题严重程度**: 高（影响核心功能）  
**影响范围**: 员工管理模块

## 问题描述

### 用户反馈
区管创建的企业管理员，超管审批后：
1. ❌ 登录不了
2. ❌ 修改该账号密码时提示"员工不存在"
3. ❌ 切换状态失败

### 实际错误
- 错误提示：`"切换状态失败：请求失败: HTTP 404: {"error":"员工不存在"}"`
- API返回404错误

## 问题分析

### 根本原因

**前端与后端使用了不同的ID概念**：

#### 数据结构
```javascript
// 渠道商员工记录
{
  id: 'P001-01',        // 员工记录ID（渠道商内的序号）
  userId: 'PA001',      // 用户ID（对应 db.users 中的记录）
  username: 'liu3',
  name: '刘三',
  role: 'partner_admin',
  status: 'active',
  ...
}
```

#### 错误代码（前端）
```javascript
// admin-app.js 第5978行
const res = await apiRequest('PUT', `/users/${s.id}/status`, { status: newStatus });
// ❌ 使用 s.id (P001-01)，而后端期望 userId (PA001)
```

#### 后端API期望
```javascript
// server.js 第2340-2346行
app.put('/api/users/:id/status', (req, res) => {
  const { id } = req.params;  // ✅ 期望用户ID (PA001)
  const user = db.users.find(u => u.id === id);
  if (!user) {
    return res.status(404).json({ error: '员工不存在' });
  }
  ...
});
```

### ID概念对比

| ID类型 | 示例 | 来源 | 用途 |
|-------|------|------|------|
| 员工记录ID | P001-01 | partner.staff[].id | 渠道商内的员工序号 |
| 用户ID | PA001 | user.id | 系统用户唯一标识 |

**关键区别**：
- `id` 是员工在渠道商中的记录ID，格式为 `{渠道商ID}-{序号}`
- `userId` 是用户在系统中的唯一ID，格式为 `{角色前缀}{序号}`
- 后端用户相关API需要的是 `userId`，而不是员工记录 `id`

## 数据流程说明

### 创建员工流程

```
前端创建员工请求：
POST /api/users
{
  username: 'liu3',
  name: '刘三',
  role: 'partner_admin',
  partnerId: 'P001',
  ...
}

后端处理（server.js 第2018-2119行）：
1. 创建用户记录：
   db.users.push({
     id: 'PA001',          // ✅ 用户ID
     username: 'liu3',
     status: 'pending',
     ...
   });

2. 创建员工记录：
   partner.staff.push({
     id: 'P001-01',        // ✅ 员工记录ID
     userId: 'PA001',      // ✅ 关联用户ID
     username: 'liu3',
     status: 'pending',
     ...
   });

3. 创建待审批记录：
   db.pendingApprovals.push({
     id: 'APR-xxx',
     type: 'partner_admin',
     targetId: 'PA001',    // ✅ 用户ID
     ...
   });
```

### 审批员工流程

```
前端审批请求（超管）：
PUT /api/pending-approvals/APR-xxx
{
  action: 'approve',
  approvedBy: 'admin'
}

后端处理（server.js 第2823-2837行）：
1. 找到用户：
   const user = db.users.find(u => u.id === apr.targetId);  // 'PA001'
   user.status = 'active';

2. 找到员工记录：
   const partner = db.partners.find(p => p.id === apr.targetPartnerId);
   const sf = partner.staff.find(s => s.userId === apr.targetId);  // ✅ 使用 userId 匹配
   sf.status = 'active';

3. 更新审批记录：
   apr.status = 'approved';
```
