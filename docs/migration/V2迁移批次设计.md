
# V2迁移批次设计

生成日期：2026-07-23

## 1. 批次总览

| 批次 | 名称 | 输入实体 | 输出目标 | 阻断条件 |
| --- | --- | --- | --- | --- |
| 00 | 源快照导出 | `crm.db`、`audit.db` | `migration.v2_raw_records`导入文件 | 快照摘要不一致、JSON解析失败 |
| 01 | 字典和组织 | 区域、角色、状态、产品状态样本 | `org.regions`、`iam.roles`、状态映射 | 未知角色或区域无处理结论 |
| 02 | 用户和身份 | `users` | `iam.users`、凭据、角色、外部身份 | 用户名重复、密码散列失败 |
| 03 | 渠道和成员 | `partners`、`partnerProfiles`、`partnerProfileProducts`、用户渠道字段 | `channel.*` | 上级渠道断裂、环形关系 |
| 04 | 产品价格工作量 | `categories`、`modules`、`features`、`hardwareProducts`、`packages`、工作量实体 | `catalog.*` | 产品编号重复、金额非法 |
| 05 | 报备和审批 | `registrations`、`pendingApprovals` | `crm.registrations`、`ops.approvals` | 客户归一化失败、状态未知 |
| 06 | 商机和跟进 | `opportunities` | `crm.opportunities`、跟进、阶段历史 | 商机阶段无法映射且未批准隔离 |
| 07 | 报价 | `quotes` | `crm.quotes`、明细、快照 | 金额重算差异未批准 |
| 08 | 订单 | `orders` | `crm.orders`、明细、状态历史 | 订单引用报价断裂、重复转单 |
| 09 | 通知、开放接口、审计 | `notifications`、`openApiClients`、`audit_logs` | `ops.notifications`、`integration.*`、`audit.audit_logs` | 开放接口调用方和密钥策略未确认 |
| 10 | 全量校验 | 所有批次 | `migration.validation_results` | 数量、外键、金额、状态、权限任一失败 |

## 2. 可重复执行策略

- 每次演练生成新的 `migration.migration_batches.id`。
- `migration.v2_raw_records` 对同一批次、实体名、原始编号建立唯一约束。
- 正式装载使用 `v2_source_id` 唯一约束，重复执行同一批次不会产生重复业务记录。
- 中断后从最后一个成功批次继续；如果映射版本变化，必须重新跑受影响批次。
- 正式切换前至少完成三次全量演练，阶段2先准备第一次演练资产。

## 3. 失败处理

| 失败类型 | 默认动作 | 是否阻断下游 |
| --- | --- | --- |
| JSON解析失败 | 阻断迁移 | 是 |
| 明文密码 | 自动转换散列 | 否 |
| 未知角色 | 业务补录或阻断 | 是 |
| 未知状态 | 按映射隔离或阻断 | 视对象而定 |
| 断裂外键 | 业务补录或隔离 | 是，除非批准隔离 |
| 金额重算差异 | 阻断，等待业务确认 | 是 |
| 空样本实体 | 保留映射，不阻断 | 否 |
