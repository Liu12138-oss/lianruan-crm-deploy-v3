# V3版本生产部署文档

文档版本：2.0  
适用版本：`3.0.0-stage9.20260727`  
生成日期：2026-07-27  
目标环境：openEuler x86_64单机服务器  
安装目录：`/opt/lianruan-crm-v3`

## 1. 部署结论

V3阶段9采用单机Docker Compose离线部署。安装包内包含业务镜像、PostgreSQL镜像、Redis镜像、Docker离线运行时、Docker Compose二进制、安装检测脚本、安装脚本、迁移脚本、健康检查脚本、备份脚本、回退脚本和诊断脚本。

服务器具备Linux x86_64和足够磁盘后，可以通过一条安装命令完成部署：

```bash
sudo SERVER_HOST=服务器IP ./scripts/install-all.sh
```

## 2. 服务器要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | openEuler x86_64 |
| 处理器和内存 | 建议12核心、32GB或更高 |
| 磁盘挂载 | `/opt/lianruan-crm-v3` |
| 对外端口 | HTTP `80`，后续有域名证书后增加HTTPS `443` |
| 数据库 | PostgreSQL 16.4容器 |
| 缓存和任务 | Redis 7.2.5容器 |
| 部署方式 | ZIP离线包 |
| 备用服务器 | 暂不启用，保留备份和恢复配置位 |

生产服务器如已安装Docker和Docker Compose，安装脚本会优先复用。未安装时，会尝试使用安装包内置离线运行时安装。

## 3. 安装包

阶段9离线包默认路径：

```text
tmp/phase7-package/lianruan-crm-v3-offline-3.0.0-stage9.20260727.zip
tmp/phase7-package/lianruan-crm-v3-offline-3.0.0-stage9.20260727.zip.sha256
```

包内关键目录：

| 目录 | 内容 |
| --- | --- |
| `compose/` | Docker Compose编排 |
| `config/` | 应用环境变量模板、部署变量模板、Nginx配置 |
| `images/` | 阶段9业务镜像、PostgreSQL镜像、Redis镜像 |
| `runtime/` | Docker和Docker Compose离线运行时 |
| `scripts/` | 安装、启动、停止、健康检查、迁移、备份、回退、诊断脚本 |
| `database/migrations/` | 数据库结构和阶段9正式落表迁移SQL |
| `migration/stage8-official/` | V2只读导出后的阶段8官方暂存装载包，存在时由迁移脚本自动装载 |
| `docs/` | 部署说明和本文件 |

## 4. 上传和校验

把ZIP包和`.sha256`文件上传到生产服务器同一目录，例如：

```text
/tmp/lianruan-crm-v3-offline-3.0.0-stage9.20260727.zip
/tmp/lianruan-crm-v3-offline-3.0.0-stage9.20260727.zip.sha256
```

在服务器执行：

```bash
cd /tmp
sha256sum -c lianruan-crm-v3-offline-3.0.0-stage9.20260727.zip.sha256
if command -v unzip >/dev/null 2>&1; then
  unzip -q lianruan-crm-v3-offline-3.0.0-stage9.20260727.zip
else
  python3 -m zipfile -e lianruan-crm-v3-offline-3.0.0-stage9.20260727.zip .
fi
cd lianruan-crm-v3-offline-3.0.0-stage9.20260727
```

如果服务器同时缺少 `unzip` 和 `python3`，需要先安装其中一个；推荐优先安装 `unzip`。

## 5. 一键安装

执行：

```bash
sudo SERVER_HOST=服务器IP ./scripts/install-all.sh
```

安装脚本会自动完成：

1. 安装前检测。
2. 安装或复用Docker运行时。
3. 安装Docker Compose。
4. 创建 `/opt/lianruan-crm-v3` 目录结构。
5. 生成PostgreSQL、Redis和会话密钥。
6. 加载离线镜像。
7. 写入生产配置。
8. 启动Nginx、双API、Worker、PostgreSQL、Redis。
9. 执行健康检查。
10. 自动记录安装日志。

安装日志目录：

```text
/opt/lianruan-crm-v3/logs/install/
```

## 6. 数据库迁移

首次安装完成后执行：

```bash
sudo /opt/lianruan-crm-v3/scripts/migrate-db.sh
sudo /opt/lianruan-crm-v3/scripts/health-check.sh
```

迁移脚本会按顺序执行：

1. V3基础数据库结构迁移。
2. 阶段8官方暂存包装载。
3. 阶段9正式业务表落表迁移。
4. 迁移版本记录写入 `migration.schema_migrations`。

迁移日志目录：

```text
/opt/lianruan-crm-v3/logs/install/
```

迁移完成后，可进入数据库抽查：

```bash
cd /opt/lianruan-crm-v3/compose
sudo docker compose exec -T postgres psql -U lianruan_app -d lianruan_crm_v3 -c "select count(*) from iam.users;"
sudo docker compose exec -T postgres psql -U lianruan_app -d lianruan_crm_v3 -c "select count(*) from channel.partners;"
sudo docker compose exec -T postgres psql -U lianruan_app -d lianruan_crm_v3 -c "select count(*) from crm.registrations;"
sudo docker compose exec -T postgres psql -U lianruan_app -d lianruan_crm_v3 -c "select count(*) from crm.opportunities;"
sudo docker compose exec -T postgres psql -U lianruan_app -d lianruan_crm_v3 -c "select count(*) from crm.quotes;"
sudo docker compose exec -T postgres psql -U lianruan_app -d lianruan_crm_v3 -c "select count(*) from crm.orders;"
```

## 7. 访问验收

浏览器访问：

```text
http://服务器IP/login
```

默认验收账号：

```text
admin / LrCRM@2026!
```

建议按以下顺序验收：

1. `/login` 登录成功。
2. `/unified` 统一入口指标可见。
3. `/admin/dashboard` 管理端仪表盘可见。
4. `/admin/registration` 客户报备列表可查询。
5. `/admin/registration/new` 新建客户报备。
6. `/admin/registration` 审核通过报备。
7. `/admin/opportunity/new` 新建商机。
8. `/admin/quote/new` 试算并新建报价。
9. `/admin/quote` 报价确认或转订单。
10. `/admin/order` 订单确认。
11. `/partner/dashboard` 渠道端入口可见。
12. `/mobile/partner/home` 和 `/mobile/admin/home` 手机端入口可见。

## 9. 备份和回退

上线前必须至少做一次手工备份：

```bash
sudo /opt/lianruan-crm-v3/scripts/backup.sh --type manual
```

当前只启用本机备份目录，异机备份留口在 `/opt/lianruan-crm-v3/config/deploy.env`：

```text
BACKUP_REMOTE_ENABLED=false
BACKUP_REMOTE_TARGET=
```

回退脚本只回退应用镜像和配置，不自动回滚数据库：

```bash
sudo /opt/lianruan-crm-v3/scripts/rollback.sh --dry-run
```

正式上线前如涉及真实迁移，需要保留V2最终快照、V3数据库备份、文件备份和迁移日志。

## 10. 上线注意事项

- 没有域名和证书时只能用HTTP加服务器IP测试，不建议直接开放公网。
- 单机部署能处理容器故障，不能处理整机故障；后续备用服务器接管需要按备份留口扩展。
- V2停业务迁移窗口建议控制在5至8小时。
- V2密码不恢复，正式用户需初始化新密码。
- OpenAPI旧密钥不恢复，正式对接前重新签发密钥。
- 公海池和其他新增功能不在阶段9范围内。
