# V3版本生产部署文档

生成时间：2026-07-23 20:58 CST

## 1. 文档结论

本文件用于指导联软渠道管理平台V3在单台生产服务器上完成首发部署准备、预生产验证、生产发布、回退、备份和恢复演练。

当前代码基线为阶段0至阶段6底座交付版本，已在Node.js 22.13.1和npm 10.9.2环境通过完整 `npm run verify`。当前交付重点是工程化骨架、数据底座、权限审计方案、迁移资产、前端迁移准备、Redis任务化和性能治理资产；完整业务功能迁移、生产镜像、生产编排和真实数据切换仍属于后续阶段7和阶段8工作。

生产首发建议采用单机容器部署，目标服务器按12核心、32GB内存规划，数据库使用PostgreSQL，缓存和任务队列使用Redis。当前暂不准备备用服务器，但部署目录、备份、域名切换和恢复流程必须预留后续备用服务器接管能力。

## 6. 生产环境变量

生产环境必须准备独立环境文件，例如 `/opt/lianruan-crm-v3/config/v3.env`。

```bash
APP_ENV=production
LOG_LEVEL=info
API_HOST=0.0.0.0
API_PORT=3100
REQUEST_BODY_LIMIT=10mb
TRUSTED_PROXY_IPS=127.0.0.1,::1,反向代理容器实际来源IP
CORS_ORIGIN=https://你的正式域名
SESSION_SECRET=至少32位的随机密钥
DATABASE_URL=postgres://应用账号:密码@postgres:5432/lianruan_crm_v3
REDIS_URL=redis://:密码@redis-state:6379/0
HEALTH_DEPENDENCY_MODE=real
WORKER_ENABLED=true
WORKER_HEALTH_QUEUE=v3-health
V3_BUILD_VERSION=3.0.0
V3_BUILD_COMMIT=实际提交号
V3_BUILD_TIME=实际构建时间
```

注意事项：

- `APP_ENV=production` 时，`DATABASE_URL`、`REDIS_URL`、`SESSION_SECRET` 是强制项。
- `SESSION_SECRET` 长度必须不少于32位，必须用随机生成值，不得使用示例值。
- `HEALTH_DEPENDENCY_MODE=real` 后，`/health/ready` 会真实检查PostgreSQL和Redis。
- `CORS_ORIGIN` 必须填写正式域名，不得使用 `*`。
- 当前可信代理配置只支持精确IP清单，不支持网段写法；阶段7若要支持容器网段，需同步改造配置解析。
- 环境文件不得进入代码仓库、交付压缩包和前端构建产物。

## 7. 单机容器拓扑

首发推荐服务清单：

| 服务 | 数量 | 说明 |
| --- | ---: | --- |
| Nginx | 1 | HTTPS入口、静态资源、反向代理 |
| API | 2 | 无状态接口实例，便于滚动发布和单实例恢复 |
| Worker | 1 | 任务消费者，后续按队列扩展 |
| PostgreSQL | 1 | 唯一业务数据库 |
| Redis状态实例 | 1 | 会话、限流、BullMQ队列、短锁 |
| Redis缓存实例 | 1 | 可重建缓存，后续按阶段6规范接入 |
| 监控组件 | 1组 | Prometheus、Grafana、日志和告警按阶段7落地 |

必须明确：单机部署只能做到容器级恢复，不能消除整机单点。无备用服务器时，不能承诺整机故障固定分钟级接管。

## 8. Compose落地模板

阶段7需要在 `deploy/single-server` 固化生产编排。下面是部署文档模板，真实落地时必须替换镜像地址、密码、域名、证书路径和资源限制。

```yaml
services:
  nginx:
    image: registry.example.com/lianruan-crm-v3/nginx:版本号
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - /opt/lianruan-crm-v3/config/nginx:/etc/nginx/conf.d:ro
      - /opt/lianruan-crm-v3/secrets/certs:/etc/nginx/certs:ro
      - /opt/lianruan-crm-v3/logs/nginx:/var/log/nginx
    depends_on:
      - api-1
      - api-2

  api-1:
    image: registry.example.com/lianruan-crm-v3/api:版本号
    restart: unless-stopped
    env_file:
      - /opt/lianruan-crm-v3/config/v3.env
    environment:
      API_PORT: 3100
    volumes:
      - /opt/lianruan-crm-v3/data/uploads:/app/uploads
      - /opt/lianruan-crm-v3/data/exports:/app/exports
    depends_on:
      postgres:
        condition: service_healthy
      redis-state:
        condition: service_healthy

  api-2:
    image: registry.example.com/lianruan-crm-v3/api:版本号
    restart: unless-stopped
    env_file:
      - /opt/lianruan-crm-v3/config/v3.env
    environment:
      API_PORT: 3100
    volumes:
      - /opt/lianruan-crm-v3/data/uploads:/app/uploads
      - /opt/lianruan-crm-v3/data/exports:/app/exports
    depends_on:
      postgres:
        condition: service_healthy
      redis-state:
        condition: service_healthy

  worker:
    image: registry.example.com/lianruan-crm-v3/worker:版本号
    restart: unless-stopped
    env_file:
      - /opt/lianruan-crm-v3/config/v3.env
    volumes:
      - /opt/lianruan-crm-v3/data/uploads:/app/uploads
      - /opt/lianruan-crm-v3/data/exports:/app/exports
      - /opt/lianruan-crm-v3/data/migration:/app/migration
    depends_on:
      postgres:
        condition: service_healthy
      redis-state:
        condition: service_healthy

  postgres:
    image: public.ecr.aws/docker/library/postgres:16.4-alpine
    restart: unless-stopped
    environment:
      POSTGRES_DB: lianruan_crm_v3
      POSTGRES_USER: lianruan_app
      POSTGRES_PASSWORD_FILE: /run/secrets/postgres_password
      TZ: Asia/Shanghai
    volumes:
      - /opt/lianruan-crm-v3/data/postgres:/var/lib/postgresql/data
    secrets:
      - postgres_password
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U lianruan_app -d lianruan_crm_v3"]
      interval: 10s
      timeout: 5s
      retries: 30

  redis-state:
    image: public.ecr.aws/docker/library/redis:7.2.5-alpine
    restart: unless-stopped
    command: ["redis-server", "/usr/local/etc/redis/redis.conf"]
    volumes:
      - /opt/lianruan-crm-v3/config/redis-state.conf:/usr/local/etc/redis/redis.conf:ro
      - /opt/lianruan-crm-v3/data/redis-state:/data
    healthcheck:
      test: ["CMD-SHELL", "redis-cli -a '替换为Redis状态实例密码' ping | grep PONG"]
      interval: 10s
      timeout: 5s
      retries: 30

  redis-cache:
    image: public.ecr.aws/docker/library/redis:7.2.5-alpine
    restart: unless-stopped
    command: ["redis-server", "/usr/local/etc/redis/redis.conf"]
    volumes:
      - /opt/lianruan-crm-v3/config/redis-cache.conf:/usr/local/etc/redis/redis.conf:ro
      - /opt/lianruan-crm-v3/data/redis-cache:/data

secrets:
  postgres_password:
    file: /opt/lianruan-crm-v3/secrets/postgres_password
```

## 9. Nginx路由要求

推荐路由：

| 路径 | 目标 |
| --- | --- |
| `/` | 前端静态资源 |
| `/assets/` | 前端摘要静态资源，长期缓存 |
| `/health/live` | API存活检查 |
| `/health/ready` | API就绪检查 |
| `/health/dependencies` | API依赖检查，仅允许管理来源访问 |
| `/api/` | 后端业务接口，后续阶段4迁移后接入 |

基础要求：

- 80端口只做HTTPS跳转。
- 443使用正式证书。
- 静态资源和接口同源。
- 入口文件短缓存，摘要静态资源长期缓存。
- 设置安全响应头、请求大小上限、上传超时和接口限流。
- 向API转发请求编号、真实来源地址和协议。

## 10. 发布流程

### 10.1 发布前检查

```bash
cd /opt/lianruan-crm-v3/compose
docker compose config
docker compose pull
docker compose ps
```

必须确认：

- 当前发布版本、提交号和构建时间已记录。
- `npm run verify` 已在Node.js 22环境通过。
- 数据库备份和文件备份已经完成。
- 回退镜像和上一版配置可用。
- 维护窗口和通知责任人已确认。

### 10.2 首次部署

```bash
cd /opt/lianruan-crm-v3/compose
docker compose up -d postgres redis-state redis-cache
docker compose ps
docker compose up -d api-1
curl -f http://127.0.0.1:3100/health/live
curl -f http://127.0.0.1:3100/health/ready
docker compose up -d api-2 worker nginx
docker compose ps
```

### 10.3 滚动发布

```bash
cd /opt/lianruan-crm-v3/compose
docker compose pull api-1 api-2 worker
docker compose up -d --no-deps api-1
curl -f https://你的正式域名/health/ready
docker compose up -d --no-deps api-2
curl -f https://你的正式域名/health/ready
docker compose up -d --no-deps worker
docker compose ps
```

### 10.4 发布后检查

```bash
curl -f https://你的正式域名/health/live
curl -f https://你的正式域名/health/ready
docker compose logs --tail=200 api-1 api-2 worker nginx
docker compose ps
```

人工确认：

- 登录入口可打开。
- 管理端、渠道端、移动端入口可打开。
- 健康检查返回成功。
- 日志无密钥明文。
- 告警系统没有一级和二级异常。

## 11. 回退流程

回退触发条件：

- 发布后核心入口不可用。
- `/health/ready` 持续失败。
- 错误率或延迟超过上线门槛。
- 数据库迁移校验失败。
- 出现敏感信息泄露或权限绕过风险。

回退步骤：

```bash
cd /opt/lianruan-crm-v3/compose
cp /opt/lianruan-crm-v3/releases/上一版本/docker-compose.yml ./docker-compose.yml
cp /opt/lianruan-crm-v3/releases/上一版本/v3.env /opt/lianruan-crm-v3/config/v3.env
docker compose pull
docker compose up -d api-1 api-2 worker nginx
curl -f https://你的正式域名/health/ready
```

如果已执行不可逆数据库迁移，禁止直接回退应用后继续写入，必须先由数据负责人判断是否进入数据库时间点恢复或逻辑修复。

## 12. 备份和恢复

### 12.1 PostgreSQL备份

上线前必须完成：

- 每日增量备份。
- 每周全量备份。
- 持续归档日志。
- 异机备份传输。
- 备份加密和摘要校验。
- 最后成功备份时间告警。

建议使用pgBackRest。没有成功恢复演练记录的备份，不能视为有效备份。

### 12.2 文件备份

必须备份：

- 上传文件。
- 未过期导出文件。
- 迁移输入和结果文件。
- 生产配置模板。
- 密钥恢复材料。

密钥恢复材料必须独立加密并双人保管。

### 12.3 恢复演练

每次上线前至少执行一次隔离环境恢复演练：

1. 从异机备份恢复PostgreSQL。
2. 恢复上传、导出和迁移文件。
3. 启动API、Worker和Nginx。
4. 执行 `/health/ready`。
5. 执行登录、列表、任务和下载冒烟。
6. 记录恢复点、恢复耗时和数据损失范围。

## 13. 监控和告警

上线前必须可见：

- 主机处理器、内存、磁盘、网络。
- 容器重启次数和资源使用。
- API请求量、错误率、延迟、版本号。
- PostgreSQL连接、慢查询、锁等待、磁盘和备份。
- Redis内存、连接、AOF、慢命令和队列积压。
- Worker任务等待、运行、成功、失败和重试。
- Nginx 4xx、5xx、请求大小和响应时间。
- 外部存活探测。

一级告警必须实际触发并确认通知到达，包括：服务不可访问、PostgreSQL不可用、Redis不可用、磁盘即将写满、备份失败、证书即将过期。

## 14. 安全要求

- 生产强制HTTPS。
- 数据库和Redis不得暴露公网。
- 应用容器使用非特权用户运行。
- 真实密钥不得进入代码仓库、镜像层、前端构建产物和普通日志。
- 日志必须屏蔽密码、令牌、密钥、完整Cookie和个人敏感字段。
- 本地应急管理员默认关闭，启用时必须双人保管、来源地址白名单和全量审计。
- 开放接口必须设置调用方、权限、限流、审计和兼容期限。
