# 决策记录

## 2026-09-07：企业微信映射来源和确认方式

- 用户确认上传文件“账号”列即企业微信 `UserId`。
- 用户确认采用“上传、预览、冲突校验、超级管理员确认、审计”的受控流程。
- 用户确认同时支持 Excel 与 CSV、姓名严格匹配 V3 姓名、一个 V3 用户只能有一个有效企业微信 `UserId`。
- 用户确认文件未出现的旧映射不自动停用。

## 2026-09-07：自动拉群边界

- 用户确认订单预审自动拉群仍只包含固定成员和订单所属区域区管或区管审批人。
- 导入文件只维护企业微信身份绑定；不以文件成员列表改变群成员、角色、区域、订单或 OA 流程。

## 2026-09-07：未来人员处理

- 当前文件包含后续可能需要自动拉群的人员。
- 为避免给不存在的 V3 用户预写身份记录，未找到启用 V3 账号的行只保留在本次预览中，提示账号创建或启用后重新上传全量文件；不视为阻断项，也不写入生产或测试数据库。

## 2026-09-07：并发与文件名兼容

- 确认导入使用既有组织幂等服务和可串行化事务；并新增企业微信有效身份的用户侧唯一索引，防止并发导入使同一 V3 用户产生多条有效企业微信身份。
- 生产迁移如发现既有重复有效映射将明确阻断，不自动删除或覆盖历史数据。
- 对 multipart 上传中可能按 latin1 错解的中文文件名，仅在可无损还原为受支持中文文件名时恢复；原始上传内容不落盘、不进入日志或审计正文。
