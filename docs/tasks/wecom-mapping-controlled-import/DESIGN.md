# 企业微信身份映射受控导入设计

## 目标与边界

超级管理员可在 V3 组织架构的“企微同步”页上传企业微信映射文件，先查看服务端校验结果，再显式确认写入有效映射。映射只写入 `iam.external_identities` 的 `provider_code='wecom'` 记录，供既有订单预审自动拉群读取。

本任务不改动角色、区域、任职、订单状态、泛微 OA 身份、企微应用参数或自动拉群成员算法。自动拉群仍为固定成员加订单所属区域的区管或区管审批人，不会将文件中的全部人员加入群。

## 已确认规则

1. 文件“账号”列就是企业微信 `UserId`；文件必须有“姓名”“账号”两列。
2. 同时支持 UTF-8 CSV 和 XLSX；文件最大 5 兆字节，最多 5,000 条数据行。
3. 文件姓名必须与 V3 启用账号的 `display_name` 严格一致；不按登录名、区域或模糊姓名猜测匹配。
4. 一个 V3 用户只允许一条有效企业微信身份；一个企业微信 `UserId` 也只能绑定一个 V3 用户。
5. 文件内重复、空值或格式错误、同名启用账号不唯一、既有映射不同、企业微信 `UserId` 已被其他账号占用均为阻断项。存在任一阻断项时确认导入整体拒绝，绝不部分写入。
6. 文件中尚未创建或启用对应 V3 账号的人员只提示“待账号创建后重新导入”，不是阻断项，也不会预写身份记录。后续账号创建或启用后，重新上传同一份全量文件即可补齐。
7. 已有相同有效映射记为“已一致”，不重复写入；文件未包含的旧映射不自动停用。
8. 每一条新增映射均写入组织审计，记录来源文件名、文件 SHA-256、源行号、姓名和企业微信 `UserId`；服务端不保存原始上传文件。

## 接口与流程

1. `POST /api/org/wecom-identities/import-preview` 接收 `multipart/form-data` 的 `file`，仅超级管理员且组织写入已开启可访问。服务端解析并返回逐行状态和汇总，不写数据库。
2. `POST /api/org/wecom-identities/import-confirm` 再次上传同一个文件。服务端在可串行化事务内重新校验数据库现状；无阻断项时只新增“可导入”行，并逐条审计。调用方必须携带幂等键。
3. 两个接口均依赖现有签名 Cookie 会话，拒绝客户端自报操作人。确认接口不接受客户端提交的预览结果或映射行，避免篡改预览后直接写入。

## 验收、回归与回退

- XLSX、CSV、必填表头、空值、重复、姓名严格匹配、已一致、待账号创建、冲突和确认拒绝均有自动测试。
- 仅超级管理员可调用；组织写入关闭时预览和确认均被服务端拒绝；确认使用幂等键。
- 页面仅在现有组织架构入口展示，明确说明不会修改 OA、订单或群成员规则。
- 回退方式为下线页面入口和接口路由；已导入的错误映射不物理删除，须先核对影响，再由超级管理员按受控流程停用并重新导入正确映射。
