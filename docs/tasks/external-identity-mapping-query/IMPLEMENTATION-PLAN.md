# 外部身份映射批量查询页面落地方案

## 1. 任务目标

在 V3 管理端组织架构中增加一个只读的“外部身份映射”页面，集中查看 V3 账号对应的泛微 OA 身份和企业微信身份。

页面用于解决以下问题：

- 无法批量确认哪些账号已经维护泛微 OA userid。
- 无法批量确认哪些账号已经维护企业微信 UserId。
- 需要逐个打开账号详情才能核对映射，效率低且容易漏查。
- 订单预审发起前，无法快速发现区管或固定群成员的身份映射缺失。

本任务只增加查询和展示能力，不改变现有身份导入、泛微身份确认、订单预审和企业微信自动拉群逻辑。

## 2. 当前事实与实现边界

### 2.1 已有能力

当前系统已经具备：

- `iam.users`：V3 用户主档。
- `iam.user_roles`、`iam.roles`：系统角色关联。
- `org.regions`：账号区域信息。
- `iam.external_identities`：泛微和企业微信正式身份映射。
- `iam.external_identity_candidates`：泛微 OA 待核验候选映射。
- `GET /api/org/users/:userId/eteams-identity`：单个账号查询泛微正式身份、泛微候选和企业微信身份。
- 组织架构账号详情抽屉：已有泛微 OA 和企业微信身份展示。
- 企业微信 Excel/CSV 上传预览和确认导入功能。

### 2.2 当前缺口

当前没有面向全员的批量映射查询接口和页面。

### 2.3 明确不做的内容

本任务不得修改：

- `iam.external_identities` 中的任何身份数据。
- 泛微 OA 身份候选、确认、驳回和停用接口。
- 企业微信映射文件导入、冲突校正和停用规则。
- 订单预审 Worker、泛微 OA 发起流程和自动拉群算法。
- 订单状态机、订单权限和区域权限。
- 企微应用凭据、消息通道配置和生产开关。
- V2 目录、旧版页面和旧版接口。

本任务不新增数据库迁移。查询使用现有正式表和候选表。

## 3. 推荐业务方案

### 3.1 页面入口

在以下路径增加新栏目：

```text
平台管理 → 组织架构 → 外部身份映射
```

建议路由：

```text
/workspace/admin/platform-admin/organization/external-identities
```

页面仅允许桌面端组织架构工作区访问，移动端继续保持现有隔离规则。

### 3.2 页面默认范围

默认查询所有启用的 V3 账号，并支持按角色、区域和映射状态筛选。

不默认隐藏渠道商员工，以便超级管理员能够发现全局映射缺失；如业务确认仅需要订单预审人员，可通过角色筛选快速查看超级管理员、管理员、区域管理员和固定群成员。

### 3.3 页面筛选条件

至少支持以下筛选：

| 筛选项 | 说明 |
|---|---|
| 关键词 | 按登录名或姓名模糊查询 |
| 区域 | 按 `org.regions` 筛选 |
| 系统角色 | 按 `iam.roles.role_code` 筛选 |
| 映射类型 | 全部、仅泛微、仅企微 |
| 映射状态 | 完整、泛微缺失、企微缺失、任一异常 |
| 账号状态 | 默认启用，可选包含停用账号 |
| 分页 | 默认每页 20 条，最大 100 条 |

关键词查询应使用防抖或回车触发，避免每次按键都请求接口。

### 3.4 页面统计卡片

页面顶部显示当前筛选范围内的统计：

- 账号总数。
- 泛微 OA 已确认数量。
- 泛微 OA 缺失数量。
- 泛微 OA 待核验数量。
- 企业微信已维护数量。
- 企业微信缺失数量。
- 映射异常数量。

统计必须与当前筛选条件一致，不能展示未筛选全量数据造成误解。

### 3.5 列表字段

| 字段 | 说明 |
|---|---|
| 登录名 | `iam.users.username` |
| 姓名 | `iam.users.display_name` |
| 账号状态 | 启用、停用、锁定 |
| 区域 | 当前有效区域名称 |
| 系统角色 | 当前有效角色名称，可多个 |
| 泛微 OA 状态 | 已确认、待核验、已停用、缺失、重复 |
| 企业微信状态 | 已维护、缺失、停用、重复 |
| 操作 | 查看账号详情 |

外部 userid 的显示规则：

- 列表默认只显示状态，不直接展示全部外部编号。
- 超级管理员点击“查看详情”后，复用现有账号编辑抽屉查看完整 userid。
- 若后续增加导出功能，必须单独增加权限校验和审计，不能默认开放。

### 3.6 状态判定

泛微 OA 状态：

- `已确认`：存在且仅存在一条 `provider_code='eteams' AND status_code='active'` 正式映射。
- `待核验`：不存在有效正式映射，但存在 `iam.external_identity_candidates` 中 `provider_code='eteams' AND status_code='pending'` 候选。
- `已停用`：没有有效正式映射，但存在停用的泛微正式映射。
- `重复`：同一账号存在多条有效泛微正式映射，属于数据异常。
- `缺失`：没有正式映射，也没有待核验候选。

企业微信状态：

- `已维护`：存在且仅存在一条 `provider_code='wecom' AND status_code='active'` 正式映射。
- `停用`：没有有效企微映射，但存在停用企微映射。当前业务通常不应出现停用企微身份，页面只读展示异常。
- `重复`：同一账号存在多条有效企微映射，属于数据异常。
- `缺失`：没有有效企微映射。

外部身份编号的唯一性和账号侧数量均需分别校验；不能只看 `external_subject` 是否存在。

## 4. 后端接口设计

### 4.1 新增接口

```text
GET /api/org/external-identities
```

接口只读，仅超级管理员可访问，并且必须满足现有组织架构功能开关和会话校验。

不得接受或信任以下客户端自报字段作为授权依据：

- `operatorId`
- `username`
- `role`
- 兼容令牌
- 其他客户端自报身份字段

### 4.2 请求参数

```text
keyword       可选，登录名或姓名，最长 100 个字符
regionId      可选，区域 UUID
roleCode      可选，系统角色代码
provider      可选，all、eteams、wecom
mappingStatus 可选，all、complete、eteams_missing、wecom_missing、abnormal
includeInactive 可选，默认 false
page          可选，默认 1，最小 1
pageSize      可选，默认 20，最大 100
```

参数不合法时返回现有组织接口统一错误格式和 400 状态码。

### 4.3 返回结构

建议返回：

```json
{
  "items": [
    {
      "userId": "用户编号",
      "username": "登录名",
      "displayName": "姓名",
      "statusCode": "active",
      "regionId": "区域编号",
      "regionName": "湖南区",
      "roleCodes": ["region_manager"],
      "roleNames": ["区域管理员"],
      "eteams": {
        "status": "active",
        "externalSubject": "泛微userid",
        "externalUsername": "泛微姓名",
        "updatedAt": "时间",
        "rowVersion": 1
      },
      "eteamsCandidate": {
        "status": "pending",
        "externalSubject": "候选userid",
        "externalUsername": "候选姓名"
      },
      "wecom": {
        "status": "missing",
        "externalSubject": null,
        "externalUsername": null,
        "updatedAt": null,
        "rowVersion": null
      }
    }

    "total": 20,

```

### 4.4 查询实现要求

- 使用单次聚合查询或有限数量的固定查询完成列表和统计，禁止逐个账号调用单账号身份接口形成 N+1 查询。
- 账号列表必须以 `iam.users` 为主表。
- 角色使用有效角色关联，停用角色不计入当前角色展示。
- 区域使用账号当前有效区域；没有区域时返回空值，不得根据姓名或角色猜测区域。
- 泛微正式身份只能使用 `provider_code='eteams'`。
- 企业微信正式身份只能使用 `provider_code='wecom'`。
- 泛微候选必须单独读取，不能把候选误标为正式映射。
- 默认只查询启用账号；`includeInactive=true` 时才追加停用或锁定账号。
- 返回完整 userid 前必须由服务端完成超级管理员鉴权。
- 不返回密码散列、会话令牌、通道密钥、完整扩展 JSON 或其他无关敏感字段。
- 查询结果必须支持稳定排序，建议按姓名、登录名、用户编号排序。

## 5. 前端落地设计

### 5.1 路由和导航

在以下类型和路由列表中增加 `external-identities`：

- `页面栏目` 类型。
- 组织架构工作区路由列表。
- `导航项列表`。
- 页面当前栏目判定。

建议导航名称为“外部身份映射”，放在“企微同步”之前或之后，保持组织相关功能集中。

### 5.2 数据加载

- 进入“外部身份映射”栏目时调用批量接口。
- 其他组织栏目保持现有加载行为，不因新增查询而改变原有接口调用顺序。
- 支持加载中、空数据、请求失败和重新加载状态。
- 切换筛选条件时回到第 1 页。
- 请求失败时显示后端脱敏错误信息和“重新加载”按钮。

### 5.3 操作边界

页面只提供：

- 查询。
- 筛选。
- 分页。
- 刷新。
- 打开账号详情。

页面不得提供：

- 新增泛微映射。
- 确认泛微候选。
- 停用映射。
- 修改企微 userid。
- 批量覆盖身份。
- 批量删除身份。

需要维护身份时，点击“查看账号详情”，继续使用现有受控页面和现有权限。

### 5.4 现有页面兼容

- 账号详情抽屉中的泛微和企微区块保持不变。
- 企业微信映射导入页签保持不变。
- 泛微候选确认和停用按钮保持原有权限与行为。
- 组织架构关闭或只读时，批量查询页面遵守现有状态提示。
- 移动端继续不开放组织架构管理页面。

## 6. 测试方案

### 6.1 后端路由测试

建议新增或扩展：

```text
apps/api/tests/org-routes.test.ts
apps/api/tests/org-rbac-integration.test.ts
```

2. 非超级管理员访问返回 403。

4. 默认只返回启用账号。

9. 泛微正式映射、泛微待核验候选和企微正式映射不混淆。
10. 缺失、待核验、停用和重复状态判定准确。
11. 分页、页大小上限和总数准确。

## 7. 发布和回退方案

### 7.1 发布前门禁

- 本地构建成功。
- 后端和前端定向测试通过。
- 组织架构、账号登录、订单、客户报备和企微导入回归通过。
- OpenAPI 契约与实现一致。
- 不新增数据库迁移。
- 生产发布包通过内部校验和外层校验。
- 生产发布前创建全量备份并完成完整性校验。

### 7.2 生产发布

生产发布只包含 API、前端和契约变更，不修改生产身份数据。

发布后至少验证：

1. 统一入口和管理员登录正常。
2. 组织架构页面正常加载。
3. 只有超级管理员可以访问映射清单。
4. 映射状态和数据库只读核对结果一致。
5. 账号详情中的泛微和企微映射仍可查看。
6. 企微导入预览功能正常。
7. API、Worker、订单预审 Worker 和 Nginx 健康。

### 7.3 回退

- 优先使用上一版本应用镜像回退。
- 本任务没有数据库迁移，不需要执行数据库回退脚本。
- 回退不得删除或修改已有身份映射。
- 回退后重新验证登录、组织架构、订单和消息相关健康状态。

## 8. 验收标准

满足以下条件才算完成：

- 超级管理员可以从页面查看全员外部身份映射。
- 可以按登录名、姓名、区域、角色和映射状态筛选。
- 可以明确识别泛微缺失、泛微待核验、企微缺失和映射异常账号。
- 页面展示的正式映射与数据库事实一致。
- 点击账号能够进入既有详情页继续处理。
- 非超级管理员无法读取该批量接口或完整外部 userid。
- 页面没有新增任何未经确认的身份写入能力。
- 现有泛微 OA、企微自动拉群、企微导入、订单和组织架构功能回归通过。
- 不新增数据库表，不改变现有身份数据，不改变订单状态机。

## 9. 后续可选增强

以下内容不属于本次首期范围，需单独评审：

- 导出映射清单。
- 仅导出缺失账号。
- 订单预审可用性检查。
- 区域泛微真实选项映射检查。
- 固定群成员完整性检查。
- 映射异常审计报表。
- 页面内受控维护入口。

如果增加导出或批量维护，必须单独设计数据脱敏、权限、审计、幂等和回退机制。
