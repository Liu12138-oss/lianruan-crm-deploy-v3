# 第三轮测试失败项修复设计

## 目标

依据《渠道测试系统测试用例（3）.xlsx》中的 23 条失败用例，修复 V3 新 UI、V3 API、V3 Worker 的真实缺陷；对与现行业务规则冲突的旧口径，保留现行规则并补齐页面提示、防误操作和验收说明。

## 范围与边界

- 只修改 V3：`apps/web`、`apps/api`、`apps/worker`、`database/migrations` 及测试。
- 只操作测试环境 `http://10.9.86.66`；不连接、不读取、不修改生产 `10.20.3.10`。
- 老 UI / V2 不改。
- 不清理测试环境业务数据；不覆盖他人正在使用的账号和业务对象。
- 工作区存在大量历史未提交变更，禁止 `reset`、`checkout`、`restore`、`clean`。

## 业务口径

1. 渠道端一级导航保持 6 项业务菜单：工作台、客户管理、商机作战、报价管理、订单中心、产品目录。渠道关系与成员维护仅对渠道企业管理员开放，收口到右上角「企业管理」菜单，不删除能力。
2. 渠道端工作台不展示内部审批待办；业务趋势、近期商机、最近报价保留。区域管理员待办只显示本区域当前阶段可处理的审批，不显示超管阶段。
3. 维保报价只允许维保服务项，不含普通产品或硬件；页面增加明确提示，不回退业务规则。
4. 报价免审批直接转单规则不变；审核中心只处理真实待审批的订单、报备和账号事项。状态已变化的过期审批必须从待办消失，旧页面提交返回 409。
5. 客户报备驳回原因按纯文本展示，清除历史 HTML 标签并解码实体，保留换行；禁止 `v-html`。
6. 组织账号创建前必须校验任职部门已绑定正式区域；区域管理角色不得选择仅作为大区、未绑定区域的部门。后端错误信息必须透传到页面。
7. 证书模板支持编辑名称、类别、颁发机构和有效期，保留行版本并发控制。
8. 消息中心新增个人通知偏好：按待办、业务、系统、安全四类分别控制站内、企微、短信、邮件；偏好按当前登录人隔离。归类关闭后，新站内通知不得进入未读列表。
9. 登录连续失败达到阈值后，在窗口期内即使输入正确密码也拒绝登录；窗口结束后自动恢复。停用账号仍给出明确提示。
10. 审计关键词若识别为业务编号，按精确编号和解析出的业务主键检索，不再用全 JSON 模糊匹配带出无关记录。
11. 超级管理员可在客户与商机详情转移负责人；转移写审计，新负责人即时获得数据范围，原负责人按新数据范围失去编辑权。

## 技术方案

### 组织与账号

- `org.org_units` 查询补充 `regionId`，前端组织单元类型同步。
- 新建用户提交前校验部门区域绑定；区域管理角色必须选择已绑定区域的部门。
- 账号创建成功但任职失败时，提示明确失败原因，并停止后续授权，避免误以为完整成功。
- 成员卡片增加停用/启用入口；部门维护条把「归档」明确为「删除部门（归档保留历史引用）」。

### 消息偏好

- 新增迁移：`message.user_preferences.category_preferences jsonb`，保存四类渠道开关。
- 新增数据库触发器：新通知写入时若对应分类站内开关关闭，直接置为 `archived`，保证所有投递入口一致生效。
- 消息中心增加个人偏好面板，支持保存、刷新后保持。

### 登录锁定

- 新增登录前限流检查：窗口内失败次数达到阈值时直接返回 429，不再校验密码。
- 保持默认会话 12 小时；`AUTH-06` 中“等待 5 分钟应退出”属于测试理解偏差，按“会话过期后写操作不得半成功”验收。

### 负责人转移

- 复用现有 `PUT /api/registrations/:id` 与 `PUT /api/opportunities/:id` 的归属解析能力。
- 客户详情、商机详情增加「转移负责人」弹窗；仅超级管理员可见。
- 转移时提交 `ownerUserId` 与变更原因，后端继续执行渠道成员匹配、区域校验和审计。

## 验收

- 23 条用例逐条给出通过、按现行规则通过、阻塞或待确认结论，并附测试环境证据。
- API 定向测试、Web 类型检查与生产构建通过。
- 发布后在测试环境用超管、江苏区管、渠道管理员三个账号复测关键链路。
