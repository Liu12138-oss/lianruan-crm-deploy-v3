# 决策日志 · customer-registration-source-order-warranty

## 2026-10-22 — 需求来源与 Preflight 事实

- 需求来源：用户提出新 UI 客户报备、客户档案、订单质保与客户列表提示共 9 项调整。
- 需求域：客户查重冲突拦截与审计、报备表单字段精简、企业规模与行业选项、客户来源、可选同时报备商机、质保从客户级迁移到订单级、客户列表订单到期提示。
- 目标用户：渠道用户提交客户报备；区管、超管审核与维护客户/订单；现有管理员配置能力不受影响。
- 范围边界：只改新 UI `apps/web`、`apps/api` 和必要的 `database/migrations`；不改老 UI，不改生产环境，不清理现有测试数据。
- 技术事实（只读核查）：
  - 新 UI 报备页为 `apps/web/src/features/customer/CustomerCreatePage.vue`，当前包含客户等级、企业规模自由输入、预计金额、预计签约时间和项目需求。
  - 当前前端查重按客户名称包含匹配、信用代码精确匹配，仅提示相似客户，不阻止提交；后端 `创建报备` 按归一化客户名称查询或创建客户，不按信用代码拦截。
  - 老 UI 的“同时报备商机”只采集项目名称、端点范围、预计金额、预计签约日期、保护期和备注，提交时仍是一条客户报备记录，没有立即创建独立商机。
  - 客户级质保目前保存在报备 `extra_json` 的 `warrantyStart`、`warrantyEnd`；订单已有质保年限和采购维保年限参数，但没有订单质保/维保起止日期。
  - 审计日志已有通用写入能力，可新增客户查重冲突动作，不需要新增审计表。
  - 上一轮质保任务 `docs/tasks/customer-lifecycle-warranty-overview/` 已实现客户级质保字段；本次需要按用户新要求停止客户级质保口径，改为订单级。
- 环境域：沿用既有测试环境 `10.9.86.66`；生产环境 `10.20.3.10` 禁止连接和修改。测试账号与部署方式从既有部署资料提取，不在代码或日志中写入明文凭据。
- 验收与质量域：需要覆盖服务端查重、冲突审计、报备字段、可选商机、订单质保维护、客户列表颜色边界、权限与数据范围回归；验收结果以测试环境实际页面、接口响应和自动化测试为准。
- 汇报域：最终输出中文报告，包含变更文件、测试结果、部署版本、风险与回滚方式。

## 2026-10-22 — 共识确认

- 问了什么：客户查重冲突审计频率、同时报备商机的创建时机、订单质保日期维护方式与权限。
- 定了什么：用户回复“确认按此执行”，确认采用三项推荐方案：
  - 每次重复报备立即写完整冲突审计，并提供每周汇总查询，不限制为每周只记一条；
  - 报备时采集项目信息，客户报备审核通过后自动创建关联商机；
  - 每个订单保存质保、维保起止四个日期，按订单规则自动带出，区管和超管可手工修改并记录审计；客户级质保从新 UI 移除，历史数据保留。
- 其他确认口径：企业规模补齐 `500-1000人` 档；行业和客户来源沿用老 UI 选项；客户名称归一化后完全相同或统一社会信用代码一致即禁止报备；客户列表订单条目按质保到期日显示剩余 30 天内黄色、已过期红色，取消订单不参与。
- 否了什么：不采用同一客户每周仅记一条、每周批量延迟记录、提交报备时立即创建商机、渠道用户维护订单质保等方案。
- 权衡了什么：即时审计更利于追溯，审批后创建商机避免未审核数据进入商机池；订单质保自动带出兼顾效率与人工纠偏。

## 2026-10-22 — 交付前收口与权限口径

- 已知事实：操作审计属于管理配置，现有页面和接口只对超级管理员开放；客户查重周报承载跨渠道冲突数据，不适合下放给区管或渠道账号。
- 决定了什么：客户查重周报沿用“仅超级管理员”权限，前端入口与后端接口保持一致；区域管理员、渠道管理员访问返回 403。
- 为什么：避免跨渠道客户信息通过周报接口扩散，同时保持管理配置现有权限边界，不新增独立权限点。
- 验收证据：超级管理员请求返回 200；区域管理员和渠道管理员请求均返回 403，错误码为 `V3_PERMISSION_DENIED`。
- 并发测试固化为 API 集成测试：两条相同报备并发提交时，一个请求返回 200、另一个返回 409，数据库只落一条报备和一条冲突审计。
- 日期边界实测：到期日剩余 30 天为黄色，剩余 31 天为普通样式，当天到期为黄色；边界验收后已恢复测试订单原始质保日期。
