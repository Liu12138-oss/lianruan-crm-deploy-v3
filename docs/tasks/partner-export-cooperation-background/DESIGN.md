# 渠道商导出新增"合作背景"列 修改方案

> 由 hgrill-feature 访谈自动生成，来源：docs/tasks/partner-export-cooperation-background/docs/DECISION-LOG.md。术语表沿用仓库文档。

## Problem Statement（问题陈述）

- 现状：渠道商管理页面的"📤 导出"生成的《渠道商导出.xlsx》包含 22 个渠道商简介列（地址、老板、成立时间……资料是否已核验），但没有"合作背景"。
- 且"合作背景"这一字段只在"渠道商信息简介"里维护（保存在渠道商简介记录中），渠道商主档不含该字段；当前导出链路只读主档数据。
- 用户诉求：导出把"合作背景"也带上；生产已有 21 家渠道商填写了该字段（渠道商共 270 家、有效简介 209 份）。

## Solution（解决方案）

- 渠道商导出在末尾新增第 23 个简介列"合作背景"，取值以"渠道商信息简介"中保存的合作为准；未填写的渠道商该格留空。
- 其余 22 列的名称、顺序、取值逻辑完全不变；导出文件名、表头结构、接口地址与权限范围不变。
- 渠道商导入模板与导入逻辑保持原样（不新增导入列）。
- 不修改任何前端页面：导出列由后端统一定义，旧界面与重构界面的导出按钮共用同一后端接口，后端生效即两套界面同时生效。

## 涉及模块（Implementation Impact）

- 数据层：无 schema 变更、无数据迁移；只读既有"渠道商信息简介"存储（extra_json 中的合作背景字段）。
- 接口层：`GET /api/v2/export/partners` 响应内容新增一列；契约形态（xlsx、表头行+数据行）与鉴权、数据范围逻辑不变，不新增参数。
- 前端：无改动。
- 逻辑：导出列定义（导出侧独立组合"渠道简介列 + 合作背景"，不影响导入侧共用的列清单）；导出取数在既有列表查询之后，增加一次按渠道商批量读取简介中合作背景的只读查询并合并到导出行；导出行构建追加该列。

## Compatibility（兼容性分析）

- 存量数据：合作背景已存在于 21 家渠道商的简介中，导出直接可见；未填写的渠道商输出空值。
- 存量调用方：导出文件仅末尾多一列，Excel 按表头读取的老使用者不受影响；前端无需改版。
- 第三方对接：无（该导出为管理端功能，不在对外 OpenAPI 范围内）。
- 需要跟随更新：发布记录/CHANGELOG；无需跟随的配置与脚本变更。
