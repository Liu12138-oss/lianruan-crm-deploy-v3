### 技术域（已核查事实）
- 导出列由后端集中定义：`apps/api/src/v2-compat-routes.ts` 的 `V2渠道简介列`（22 列，含地址/老板/成立时间/…/资料是否已核验），`V2导出配置.partners.headers` 与 `构建导出行` 引用它；前端（旧 UI `admin-app.js` 的"📤 导出"按钮）只负责下载，不定义列 —— **改动可完全落在后端**。
- 数据存储：合作背景保存在 `channel.partner_profiles.extra_json`（简介保存接口 `PUT /partners/:id/profile`），**不写入** `channel.partners.extra_json`（主档）。
- 导出取数链路：`查询导出数据` → `service.查询列表("partners")` → `渠道查询SQL`（仅合并 `partners.extra_json`，**未关联 partner_profiles**）→ `构建导出行`。
- 生产实测：渠道商 270 家；有效简介 209 份；含 `cooperationBackground` 的简介 21 份（最长 23 字符、无换行）；`partners.extra_json` 含该键 0 份 → 即使加列，不改取数逻辑会全空。
- 同类问题：资料来源/资料是否已核验/统一社会信用代码/主要行业/服务区域 等字段"仅存在简介、主档缺失"的各约 19 家。
- 生产已部署代码（api 镜像构建提交 `bab11f6-quotefix1`）与区域修复工作区 `codex/region-price-profit-oa-20260923`（HEAD `bab11f6`）一致；生产 nginx 内的 `admin-app.js` 已含合作背景展示/编辑。
- 重构 UI（`apps/web/src`）无渠道商导出页面；两套 UI 均走同一后端导出接口 → 后端改动对旧 UI 即生效。
- 现有测试：仅覆盖 `/api/v2/export/registrations` 返回 200，未覆盖 partners 导出列内容。
