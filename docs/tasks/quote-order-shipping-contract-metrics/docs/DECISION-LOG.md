# 报价双体系与转单履约增强决策日志

## 2026-10-29 — 预检与首轮待确认口径

- 问了什么：确认“标准产品报价 / 渠道分销产品报价”的业务定义与访问范围；确认报价转订单的必填、附件限制、出货金额口径、价格对比与可见范围、渠道人工订单指标字段、订单取消权限与状态范围。
- 定了什么：本轮尚未形成用户确认的业务决定。已决定先按仓库规则完成只读预检和口径确认，确认前不修改业务代码、不部署测试环境、不接触生产环境。
- 否了什么：暂不采用“直接把三种现有报价方式改成两套页面”的猜测方案，因为这会破坏现有套餐、补充功能和自定义报价结构；暂不采用“仅在上传时记录文件名”的轻量方案，因为无法满足附件鉴权、下载和审计要求。
- 权衡了什么：需要同时兼容新 UI 的现有报价结构、存量报价数据、一级/二级渠道定价规则与订单审批链；需要把人工维护的订单指标和系统自动经营摘要分开展示，避免人工数覆盖真实业务统计。

### 已核查事实

- 新建报价页当前提供“套餐报价、补充功能、自定义报价”三种报价方式，尚未提供“标准产品 / 渠道分销产品”的报价类型选择。
- 现有报价定价已支持标准价、区域覆盖价、一级渠道比例、二级渠道比例和最终单价。
- 报价记录的 `extra_json` 已保存报价方式、产品清单、硬件清单和定价快照，可作为存量数据兼容基础。
- 管理端与渠道端当前复用同一个报价页面组件。
- 报价转订单当前只提交报价编号并直接创建订单，没有独立的转单表单。
- 当前没有订单收货人、联系电话、收货地址、出货金额和合同附件的结构化存储或上传接口。
- 当前订单已有取消状态、状态历史和取消事件；订单处理页对草稿、已确认、处理中、已发货状态提供取消入口。
- 当前订单按所属渠道的分销层级进入审批链：一级订单进入区管确认，二级订单先进入一级渠道确认。
- 渠道档案当前已有自动计算的合作经营摘要，包括客户数、商机数、报价数、订单数、商机金额、订单金额和转化率。
- 客户报备已有附件上传、文件类型校验与受控下载能力，可作为订单合同附件的实现参照，但不能直接把报备附件表复用于订单。

### 首轮待用户确认

1. 两类报价的业务定义与访问范围。
2. 现有“套餐报价、补充功能、自定义报价”是否保留为两类报价内部的二级报价方式。
3. 一级、二级渠道的判定依据，以及无分销层级渠道的处理方式。
4. 转订单必填字段、收货信息默认值、附件格式、单文件大小和附件数量。
5. 原价、渠道订单价格、出货金额、折扣比例、渠道利润和出货订单比例的计算口径。
6. 渠道订单价格、原价、出货金额与渠道利润对内部用户、渠道用户的可见范围。
7. 渠道人工订单指标的具体字段、维护角色、统计年度和展示位置。
8. 订单取消的状态范围、操作角色、取消原因、待办与通知闭环，以及取消后报价能否重新转单。

## 2026-10-29 — 用户确认六项业务口径

- 问了什么：两类报价的定义与访问范围、转订单必填与附件限制、价格对比口径、数据可见范围、渠道人工订单指标和订单取消规则。
- 定了什么：
  1. 标准产品报价除内部用户外，渠道用户也必须可以使用；标准产品报价不展示报价价格，最终订单价格由区管角色补充。
  2. 收货人、联系电话、详细收货地址在转订单时始终必填；一级渠道的出货金额与合同附件强制填写上传，二级及无层级渠道非强制；附件支持图片、PDF、Word、Excel，单个不超过 20MB，每单最多 10 个。
  3. 原价为报价明细标准单价乘数量的合计；渠道订单价格为报价最终成交总价；出货价格为转单填写金额；折扣、渠道利润与出货订单比例按已确认公式计算，负利润允许录入并标红。
  4. 内部管理员和区管可见全部价格与渠道利润；渠道用户可见本订单订单价、原价、折扣与本人填写的出货金额，不展示渠道利润，服务端负责脱敏。
  5. 渠道人工订单指标只维护年度订单目标金额，不维护目标数量；完成情况由系统自动统计；超管维护全部渠道，区管维护本区域渠道，渠道用户只读。
  6. 渠道创建人可取消本人未确认订单；区管可取消本区域待审批、已确认、处理中订单；超管可取消除已完成外的订单；取消必须填写原因并关闭待办、发送通知、写入状态历史与审计；取消后原报价保持已转订单，重新下单需新建报价。
- 否了什么：渠道人工订单目标数量不纳入本期；转单不引入 ZIP 附件。
- 权衡了什么：标准产品报价免价可以减少渠道侧价格暴露，但会使订单初始金额为零，必须依赖区管在审批节点补价；因此需要把标准产品报价的区管补价设为审批必经步骤，并避免与渠道分销报价的自动取价混淆。

### 用户确认后仍需澄清的依赖决策

1. 标准产品报价是否对所有角色都不展示、不计算价格，统一由区管在订单审批时填写最终订单价格。
2. 渠道分销产品报价是否继续沿用现有标准价、区域覆盖价和渠道等级价自动试算，并展示本订单价格。
3. 标准产品报价转换出的订单，区管补充订单价格是否必须发生在“区管确认并提交超管”之前，未补价不得进入超管确认。

## 2026-10-29 — 最终口径确认

- 问了什么：确认标准产品报价是否全角色免价、是否由区管在提交超管前强制补价，以及渠道分销报价是否继续自动取价。
- 定了什么：用户回复“1、没问题”，确认标准产品报价全角色不展示、不计算报价价格，订单由区管强制补价后才能提交超管；渠道分销产品报价继续自动取价；内部管理员和渠道用户均可进入两套报价页面。
- 否了什么：无。
- 权衡了什么：标准报价采用服务端标准价快照用于后续原价对比，但报价接口不返回价格；订单初始金额为零，区管补价成为审批硬门禁。

### 存量数据前置项

- 区管确认或调价生成正式订单编号时，服务端强制要求渠道商已维护协议编号；地市没有可用区号时也会拦截正式编号生成。
- 测试环境当前有 3 个状态为 `active` 的一级渠道未维护协议编号：`临沂普悦天诚信息科技有限公司`、`江苏汇鸿中天科技有限公司`、`联软科技湘潭`。其中前两家同时未维护国家电话区号，`联软科技湘潭` 已有国家电话区号 `86`。
- 另有 18 个已归档验收渠道同样缺少协议编号或区号，不属于当前有效经营渠道。测试数据导入或上线前应优先核查有效一级渠道，避免在区管正式审批节点才被业务校验拦截。

```sql
SELECT id, partner_name, status_code, agreement_no, country_calling_code
FROM channel.partners
WHERE partner_level_code = 'primary'
  AND status_code <> 'archived'
  AND (
    COALESCE(agreement_no, '') = ''
    OR COALESCE(country_calling_code, '') = ''
  )
ORDER BY partner_name;
```
