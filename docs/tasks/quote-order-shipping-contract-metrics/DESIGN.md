# 双报价体系与渠道订单履约增强修改方案

> 由 hgrill-feature 访谈自动生成，来源：本任务决策日志。术语见仓库 `docs/CONTEXT.md`。

## Problem Statement（问题陈述）

当前新 UI 只有套餐、补充功能和自定义三种报价方式，没有标准产品报价与渠道分销产品报价的上层业务区分；渠道用户创建标准产品报价时仍会看到价格，订单价格也没有明确的区管补价环节。报价转订单只提交报价编号，缺少收货人、联系电话、收货地址、出货金额和合同附件。订单无法在一个区域集中对比原价、渠道订单价格、出货价格、渠道利润和比例，渠道档案也不能人工维护年度订单目标金额。订单取消虽然有底层状态，但入口、权限、原因和待办通知闭环不完整。

## Solution（解决方案）

### 双报价体系

- 报价新增“标准产品报价”和“渠道分销产品报价”两个独立入口，内部管理员和渠道用户均可使用。
- 标准产品报价不展示、不返回报价价格；产品与数量仍由服务端校验并保存标准价快照。报价转订单后进入待定价状态，区管在订单审批的区管节点补充最终订单价格，未补价不能提交超管确认。
- 渠道分销产品报价继续沿用现有标准价、区域覆盖价和一级/二级渠道价格规则，报价页面按现有权限展示本报价价格。
- 现有套餐报价、补充功能和自定义报价继续作为两类报价内部的报价方式，不破坏存量报价结构。
- 报价类型创建后不可切换；历史报价按渠道归属和取价快照自动归类，存量金额和明细保留。

### 转订单与合同附件

- 报价转订单改为弹窗流程，收货人、联系电话、详细收货地址始终必填。
- 订单所属渠道为一级渠道时，出货金额和合同附件必填；二级渠道和无分销层级渠道允许填写，但不强制。
- 合同附件支持 JPG、JPEG、PNG、PDF、DOC、DOCX、XLS、XLSX，单个不超过 20MB，每单最多 10 个；服务端校验扩展名、文件头、大小、数量和权限。
- 附件使用独立元数据表与受控下载接口存储，不在订单扩展字段里只保存文件名。

### 订单价格对比

- 原价为报价明细标准单价乘数量的合计，包含软件与硬件。
- 渠道订单价格为报价最终成交总价；标准产品报价订单在区管补价前显示“待区管定价”。
- 出货价格为转单时填写的出货金额。
- 页面展示渠道订单折扣、出货折扣、渠道利润、出货与渠道订单价格比例，并放在订单明细总价下方。
- 渠道利润只对内部管理员和区管返回；渠道用户可见本订单渠道订单价、原价、折扣和本人填写的出货金额，服务端不返回渠道利润字段。
- 负利润允许保存，页面以红色风险样式提示。

### 渠道订单目标金额

- 渠道档案新增按自然年维护的订单目标金额和备注，实际完成金额继续由系统自动统计。
- 超级管理员可维护全部渠道，区管只能维护本区域渠道，渠道用户只读。
- 维护结果写审计，并区分“人工目标”和“系统实际完成”。

### 订单取消

- 渠道创建人可取消本人尚未最终确认的订单；区管可取消本区域待审批、已确认和处理中订单；超级管理员可取消除已完成外的订单。
- 取消必须填写原因，状态历史、审计、审批待办和通知必须同步关闭或更新。
- 已取消报价保持“已转订单”，重新下单需新建报价，避免同一报价产生多张有效订单。

## 涉及模块（Implementation Impact）

- 数据层：新增报价类型、订单履约与价格快照字段、订单合同附件表、渠道年度订单目标表；为存量报价和订单回填报价类型、原价和定价状态。
- 接口层：报价试算和保存增加报价类型；新增带附件的报价转订单接口、合同附件受控下载接口、渠道订单目标维护接口；订单详情返回价格对比、履约信息和附件元数据，并按角色脱敏。
- 前端：报价中心与报价构建器增加双报价入口和标准报价免价模式；转订单改为完整弹窗；订单中心与订单处理页增加价格对比、收货信息、附件下载、区管补价和取消入口；渠道档案增加订单目标维护。
- 业务逻辑：标准报价不信任客户端价格；区管补价由服务端写入并写审计；附件、取消、渠道目标均在服务端做权限和数据范围校验。

## Compatibility（兼容性分析）

- 存量报价保留原金额、明细和报价方式；迁移按渠道归属与取价快照归类，无法判断时归为渠道分销产品报价，避免回退到免价流程。
- 存量订单新增字段均有默认值，原价缺失时按可用的报价快照回填，仍无法回填时使用订单金额作为只读兜底。
- 现有套餐、补充功能、自定义报价、维保报价、审批链、OA 预审和 V2 兼容接口不改变状态码与既有字段。
- 新 UI 转订单改走新接口；旧 UI 与移动端原调用保持兼容。新 UI 产生的订单严格执行收货与附件规则。
- 不修改老 UI 页面代码，不连接生产环境。
