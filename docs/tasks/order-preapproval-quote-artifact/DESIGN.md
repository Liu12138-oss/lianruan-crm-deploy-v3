# 订单预审正式报价单与采购内容

## 目标

订单预审自动发起时，两个泛微 OA 附件均使用与页面“下载 PDF”一致的正式报价单成品；采购内容字段只列软件产品和服务项，并包含数量（软件产品显示授权端点数）及小计金额。

## 已确认事实

1. 当前页面下载按钮是在报价单预览页调用浏览器打印，不是调用后端文件接口。
2. 当前 Worker 使用独立的简化 PDF 生成器，内容和页面正式报价单不一致。
3. 当前 Worker 的采购内容仍固定为“详见采购订单上传处的报价单”。
4. 页面报价单明细包含软件产品、硬件设备和服务项，并始终显示“标准质保服务（赠送1年）”。本次 OA 采购内容按用户要求只输出软件产品和服务项，不输出硬件设备。

## 设计决定

- 将 Worker 的 PDF 生成器升级为正式报价单成品生成器：保留正式报价单页眉、报价元数据、软件产品/硬件设备/服务项分组、金额汇总和签章区；不通过浏览器自动化，不改变人工下载入口。
- 页面下载入口改为调用服务端 `/api/quotes/:id/pdf`（V3）或 `/api/v2/quotes/:id/pdf`（正式兼容页面），页面只负责接收 Blob 并下载；不再拼接 HTML 或调用 `window.print()`。
- API 与 Worker 均从报价快照、报价明细和服务端时间生成同一份确定性 PDF；Worker 使用报价创建时间、项目名称、有效期和端点数量，避免页面下载与 OA 附件内容漂移。
- Worker 从订单明细关联的报价产品类型、产品目录和名称规则读取产品类型；无法识别为服务且不是硬件的项目按软件产品处理。标准质保服务自动补入服务项，避免与页面预览不一致。
- 两个 OA 附件使用同一份本地固化 PDF 内容，但分别上传取得独立 `fileid`，继续作为两个主表附件字段提交。
- 采购内容格式固定为：

  ```text
  软件产品：
  1. 产品名称，授权端点数：200 点，小计：¥54,000

  服务项：
  1. 标准质保服务（赠送1年），数量：1 年，小计：¥0
  ```

- 金额使用人民币符号和千分位，整数不显示无意义的小数；小数金额最多保留两位。
- 继续使用 `ops.files` 按订单预审请求幂等固化文件；已有文件直接复用，避免重复生成或内容漂移。

## 页面与 Worker 一致性

页面下载和 OA 上传都使用 `packages/shared/src/formal-quote-pdf.ts` 的 `生成正式报价单PDF`。Worker 以 `order-preapproval-formal-quote-pdf:<requestId>` 固化正式版本文件；历史简化版文件键不复用。旧订单已经固化的旧 PDF 不自动替换，如需修正需按现有人工重发或修改“OA渠道订单预审”处理。

## 兼容与风险

- 不改变报价、订单状态机、OA 字段编号、OA 幂等、企微建群或人工下载页面。
- 旧订单明细中的 `product_ref_type='manual'` 通过报价快照和名称规则兼容；无法识别的非硬件项目仍归入软件产品，保证采购内容不丢失。
- PDF 仍使用标准中文字体并由 Worker 本地生成，未引入浏览器、外部网络或新的生产依赖。

## 验收

- 同一请求两个上传调用接收相同文件名和相同 PDF 字节内容。
- PDF 包含正式报价单页眉、软件产品、服务项、报价总额和签章区。
- 采购内容只包含“软件产品”和“服务项”两个分组，包含数量/端点数与小计金额。
- 现有 OA/企微客户端、订单状态机和 Worker 默认关闭行为回归通过。
