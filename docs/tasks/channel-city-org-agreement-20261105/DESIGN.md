# 渠道城市检索、组织树、内部搜索与协议编号修复方案

> 由 hgrill-feature 访谈自动生成，来源：docs/tasks/channel-city-org-agreement-20261105/docs/DECISION-LOG.md。术语表见仓库 docs/CONTEXT.md。

## Problem Statement（问题陈述）

新 UI 在渠道新建、组织架构和渠道档案三个区域存在以下问题：

1. 新建渠道的所在城市只能手工输入，不能按中文、全拼或首字母检索并回填标准城市。
2. 江苏区一级渠道候选只有两个，需要确认是规则结果还是权限或数据故障。
3. 渠道组织树的大区、区域和未分配区域节点全部显示为“渠道商”，成员聚合也不完整，历史归档和测试残留进一步造成结构混乱。
4. 组织架构顶部的快捷选择只能选部门，右侧成员搜索只覆盖当前部门，无法按姓名或账号定位全局用户。
5. 新建渠道没有协议编号入口；核心档案虽有字段但位置不直观。

期望行为是：城市可检索回填，一级渠道规则保持稳定，渠道组织树名称和成员正确，内部用户可以统一搜索定位，协议编号在新建和核心档案中都可维护。

## Solution（解决方案）

- 城市：新增标准地市选项接口。前端按中文、全拼和首字母过滤，选择后回填标准名称；无匹配时明确提示将按自定义城市保存。
- 一级渠道：保持同区域、生效中、一级渠道三项条件；待审批和已归档渠道不进入候选。
- 渠道组织树：按老 UI 的节点类型判断修复名称；区域使用区域名称，渠道使用渠道商名称；聚合子节点成员；默认隐藏已归档渠道，待审批渠道增加状态标识。
- 内部搜索：顶部改为统一的部门与用户搜索，支持姓名和登录账号；选择用户后定位其部门、过滤出该成员并高亮。
- 协议编号：新建渠道表单增加选填字段；核心档案第一个分组增加协议编号输入框；保留服务端唯一性校验和区管正式订单确认前的必填校验。

## 涉及模块（Implementation Impact）

- 数据层：不新增表、不新增迁移；复用现有城市区号映射中的标准地市名称。
- 接口层：新增只读标准地市选项接口；不修改旧 UI 已使用的渠道地市元数据接口。
- 前端：渠道新建弹窗、渠道核心档案、组织架构工作区。
- 逻辑：城市拼音匹配、组织树节点构建与成员聚合、统一搜索定位、协议编号新建载荷。

## Compatibility（兼容性分析）

- 标准城市为新增能力，现有城市自由文本继续可显示和保存。
- 协议编号字段后端已支持，新增前端入口不改变既有保存契约。
- 组织树只调整前端展示和默认过滤，不删除渠道主档，不影响渠道列表、商机、报价和订单取数。
- 旧 UI、V2 页面接口和生产环境不修改。

## Rollback Plan（回滚方案）
