# 渠道城市检索、组织树、内部搜索与协议编号修复决策日志

## 2026-11-05 — 只读核查与确认口径

- 问了什么：渠道新建“所在城市”是否支持中文和拼音检索；江苏区为何只有两个一级渠道候选；渠道组织树名称为何全部变成“渠道商”；内部组织搜索为何搜不到用户；协议编号维护入口在哪里；区管新增渠道成员为何被拒绝。
- 查到了什么：
  1. 新 UI 城市字段是普通文本框，没有接入旧 UI 的地市数据源和自动完成。
  2. 江苏区管可见的 65 家渠道中，符合“同区域、生效中、一级渠道”的只有 P175 和 P066；其余 18 条显式一级渠道均已归档，不是权限共性故障。
  3. 新 UI 构建渠道树时只读取 `partnerName/partnerCode`，区域节点的 `name` 被忽略，因此大区、区域和未分配区域全部回落为“渠道商”；老 UI 已有正确的类型判断和成员聚合逻辑。
  4. 顶部控件实际是“快捷选择部门”，右侧成员搜索只过滤当前部门及子部门，没有全局用户搜索。
  5. 新建渠道表单缺少协议编号；核心档案已有协议编号字段，区管对 P175 的档案编辑权限正常。
  6. 区管渠道成员写入被现有权限白名单主动拦截，属于权限设计问题。
- 定了什么：
  1. 城市字段使用标准地市数据源，支持中文、全拼和首字母检索，选择后自动回填；列表外城市保留明确的自定义城市提示和保存能力。
  2. 一级渠道候选继续执行“同区域、生效中、一级渠道”规则，不纳入待审批和已归档渠道。
  3. 渠道组织树按老 UI 的“区域 → 渠道商”结构修复节点类型、名称和成员聚合；默认隐藏已归档渠道，待审批渠道保留并标识；测试环境中的测试残留经备份后清理。
  4. 内部组织搜索改为“部门 + 用户”统一搜索，匹配姓名和登录账号；选择用户后定位所属部门并高亮成员。
  5. 新建渠道增加协议编号选填字段，核心档案前置展示并允许区管编辑；创建时不强制，区管正式确认或调价生成正式订单编号前必须维护。
  6. 第 6 项区管成员权限本轮未获得确认，暂不修改。
- 否了什么：
  - 不放宽一级渠道同区域和生效状态限制。
  - 不把渠道组织树改造成“区域 → 一级 → 二级”上下级树；本轮保持老 UI 的区域结构。
  - 不批量改写历史渠道城市数据。
  - 不修改老 UI、V2 页面和生产环境。
- 权衡了什么：
  - 城市标准列表优先保证新建数据质量，同时保留自定义入口，避免标准列表未覆盖的特殊城市阻断业务。
  - 组织树隐藏已归档渠道可以降低测试残留和历史数据干扰，但不删除渠道主档，保留追溯能力。
  - 用户搜索采用前端统一检索已加载的组织与任职数据，不新增高成本搜索接口。

## 待确认

- 第 6 项区管渠道成员权限尚未确认，本轮不调整成员写入权限。
