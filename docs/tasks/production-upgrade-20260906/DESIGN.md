# 生产升级包设计

## 目标

将生产实际运行的 `3.0.0-stage9.40.20260813-kb022` 升级至冻结目标版本 `3.0.0-stage10.20260906-prod1`，交付可离线执行、可校验、可回退应用的 V3 `SP-APP` 升级包。

## 已确认事实

- 生产为 openEuler 24.03 x86_64，Docker 27.5.1、Docker Compose 2.32.4。
- 实际运行的 API、Worker、Nginx 均为 `kb022`，其镜像标识已记录于生产基线。
- `compose/.env` 指向 `kb026`，而实际容器仍为 `kb022`；升级包必须以实际容器镜像和摘要作为来源事实，不能按配置标签猜测。
- 生产迁移记录停在 `20260817_S9_025_V2区域管理员账号恢复`，目标目录存在多份未记录的历史迁移，禁止盲目按目录全量执行。
- 用户确认当前本地全部已确认改动纳入发布，目标版本为 `3.0.0-stage10.20260906-prod1`。
- 用户要求保留生产数据，允许今日最多三小时维护窗口，升级前必须完成隔离演练。
- 本次不自动填写渠道商地市区号；字段保持为空。
- 本次仅启用泛微 OA 订单预审能力；企微应用消息和邮件外发保持关闭。
- OA 正式参数由生产管理员通过安全渠道自行配置，不进入仓库、升级包、日志或任务记录。

## 方案

1. 为 `kb022` 固化 API、Worker、Nginx 源镜像摘要和数据库迁移谱系。
2. 增加源环境专用迁移预检查：逐项验证缺失历史迁移的结构和数据前置条件，拒绝把不明历史迁移直接应用到生产。
3. 冻结工作区为可追溯提交，构建 API、Worker、Nginx 完整离线镜像。
4. 生成 `SP-APP` 包，包内保留生产已有密钥和配置；仅说明 OA 参数的安全配置步骤，不携带密钥。
5. 在隔离的 PostgreSQL 副本完成迁移、数据数量与关键状态校验、应用回退演练和业务冒烟。
6. 生产执行时，先备份数据库、上传文件、导出文件、配置与镜像引用；失败自动恢复应用快照，不自动恢复数据库。

## 数据边界

- 禁止删除、覆盖或从备份自动恢复生产数据库。
- 历史数据修正必须先输出数量和对象范围；异常数据中止升级，不静默修复。
- 外部 OA 调用只在密钥、区管正式泛微身份、区域映射、模板和切换时间均准备完成后发生；否则任务安全拒绝并转人工。
- 已被对方 OA 受理的流程不因应用回退而撤销或删除。

## 回退

应用启动、健康检查或业务冒烟失败时，恢复升级前 Compose、配置、脚本及 API、Worker、Nginx 的实际镜像引用。数据库仅允许保留向前兼容结构；数据库恢复必须由生产负责人单独确认。
