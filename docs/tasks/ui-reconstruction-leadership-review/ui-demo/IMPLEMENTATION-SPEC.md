# 联软渠道管理平台 V3 UI 视觉优化与交互实现规格

## 1. 文档定位

本文档是 UI 视觉优化正式进入前后端开发前的实施规格，供前端 Agent、后端 Agent、测试和发布人员共同使用。

本文档不是业务代码的替代品，也不授权直接修改生产数据库、生产配置或对外接口。研发应以现有 V3 鉴权、权限、数据范围、状态机和审计规则为最高约束，再按本文档实现视觉和交互。

交互原型入口：

- `index.html`
- 页面截图：`screenshots/`
- 关键窗口截图：`screenshots/windows-v3/`

全量 UI 升级总蓝图：`FULL-UI-DESIGN-BLUEPRINT.md`。

开发 Agent 还必须同时使用：

- `MODULE-STATUS-AND-SCOPE-MATRIX.md`：当前/未来模块范围和开关。
- `PAGE-ROUTE-PERMISSION-MATRIX.md`：四端路由、角色、字段和动作权限。
- `ACTION-API-IDEMPOTENCY-CONTRACT.md`：动作、接口、幂等、并发和错误契约。
- `IMPLEMENTATION-TICKETS.md`：研发任务切片、依赖、验收和回退。
- `TEST-AND-ROLLBACK-MATRIX.md`：测试、环境门禁和模块回退。

目标视觉模型：

- `../visual-designs/screenshots/02-war-full.png`
- `../visual-designs/versions/02-war-room.html`
- `../visual-designs/assets/visual-ui.css`

## 2. 实施目标

本次工作只做 UI 视觉优化、信息架构调整、交互补齐和前后端接口对接，不新增未经确认的 CRM 业务能力。

必须保持：

1. 登录、IAM、UniSDP、本地应急登录和四套正式页面会话规则不变。
2. 管理员、渠道企业管理员、渠道员工、区域管理员的权限和数据范围不变。
3. 客户、商机、报价、订单、渠道、组织、消息和开放接口的正式事实来源不变。
4. 金额、折扣、税费、工作量、收益和订单总额继续由服务端计算。
5. 高风险状态变化通过状态机、审计、幂等和任务机制执行。
6. V2 兼容接口保留，但新页面不向 V2 静态结构继续堆逻辑。

## 3. 交付边界

### 3.1 前端负责

- 按固定画板和三栏作战室结构实现页面。
- 使用现有 Vue 3、Pinia、Vue Router、Element Plus 和工程化组件。
- 完成菜单、路由、列表、详情、抽屉、弹窗、表单和状态反馈。
- 调用服务端接口，不在浏览器计算正式报价、收益或订单金额。
- 按角色和数据范围控制页面可见性，但服务端仍是最终鉴权方。
- 处理加载、空状态、错误、无权限、冲突和重复提交。
- 保持 1440px 设计坐标和窄窗口横向滚动，不进行桌面端响应式重排。

### 3.2 后端负责

- 提供页面所需的稳定查询、详情和动作接口。
- 从服务端会话解析用户、角色、组织和数据范围。
- 对客户、商机、报价、订单、渠道成员和价格规则执行字段级、动作级权限校验。
- 返回标准成功和错误响应，错误消息使用中文。
- 对高风险动作返回业务错误码和可展示原因。
- 为区域筛选提供明确的区域可见范围，不接受任意客户端区域越权。
- 提供状态历史、审计、幂等键和任务结果。
- 为列表返回服务端分页、排序和总数，不要求前端加载全量数据。

## 4. 固定视觉基线

### 4.1 画板

| 类型                 | 尺寸             |
| -------------------- | ---------------- |
| 列表和业务页         | `1440px × 740px` |
| 新增、编辑和长表单页 | `1440px × 900px` |

浏览器宽度变化时：

- 大于 1440px：画板居中。
- 小于 1440px：出现横向滚动。
- 不折叠导航、不减少指标列、不改变三栏宽度、不自动换行。

### 4.2 页面坐标

| 区域       | 规则                               |
| ---------- | ---------------------------------- |
| 顶部导航   | 高度 `62px`                        |
| 六项指标区 | 顶部 `73px`，高度 `96px`，固定六列 |
| 三栏业务区 | 顶部 `180px`，占满画板剩余高度     |
| 三栏列宽   | `304px / 自适应 / 342px`           |

### 4.3 视觉令牌

| 用途     | 色值      |
| -------- | --------- |
| 品牌主色 | `#2f69ed` |
| 主色悬停 | `#1557d6` |
| 品牌深蓝 | `#17345e` |
| 成功     | `#159873` |
| 警告     | `#c58a17` |
| 危险     | `#ce4b58` |
| 流程     | `#7254d8` |
| 页面底色 | `#eef4fa` |

### 4.4 组件规则

- 表格操作使用 `table-actions`，操作文字无边框、无底色、固定单行。
- 同一行面板必须等高、顶部对齐、底部对齐。
- `war-tab` 使用 `inline-flex`，文字横向和纵向居中。
- 页面级按钮使用页面导航，原地动作使用弹窗。
- 管理账号侧栏必须直接展示“消息中心”；顶部铃铛只作为快速查看入口。
- 超级管理员侧栏必须直接展示“人天与工作量配置”，产品目录内同时保留页签入口。
- 详情使用右侧抽屉，新增、审批、退回、导入使用居中弹窗。
- 高风险动作必须二次确认，驳回和退回必须填写原因。

## 5. 角色与数据范围

| 角色           | 主要范围                                       | 不允许                         |
| -------------- | ---------------------------------------------- | ------------------------------ |
| 超级管理员     | 全量业务、组织、权限、审计、价格规则和系统状态 | 不代替业务角色完成日常经办     |
| 区域管理员     | 正式绑定区域内的客户、商机、报价、订单和渠道   | 跨区域查看和操作               |
| 普通管理员     | 按角色权限点和数据范围                         | 超级管理员配置能力             |
| 渠道企业管理员 | 本渠道企业全部成员及其业务数据                 | 其他渠道企业、内部成本和收益   |
| 渠道员工       | 本人负责、本人创建或授权协作的数据             | 企业其他成员数据和其他渠道数据 |
| 审核人员       | 被授权业务类型下的审批任务                     | 未授权业务详情和跨范围对象     |

区域筛选规则：

- 客户、商机、报价、订单列表对超级管理员显示区域筛选。
- 普通渠道、企业管理员和区域管理员不显示区域筛选。
- 区域筛选只缩小超管查询范围，不替代服务端鉴权。

## 7. 核心页面实施规格

### 7.1 工作台

布局：

- 六项指标卡。
- 业务趋势。
- 我的待办。
- 最近业务。

要求：

- 趋势和待办两张面板同高、顶部和底部对齐。
- 最近业务与上方网格间距固定 `12px`。
- 待办动作必须跳转对应业务详情或审核页。

后端数据：

- 指标统计。
- 趋势聚合。
- 当前用户待办。
- 最近业务事件。

### 7.2 客户管理

布局：

- 左侧客户列表。
- 中间客户档案、联系人、保护和关联业务。
- 右侧客户健康度、下一步建议和最近动态。

动作：

- 新建客户：页面导航，进入客户新增页。
- 编辑客户档案：打开档案编辑弹窗。
- 客户跟进：打开关联商机选择和跟进录入弹窗。
- 查看商机：进入对应商机工作区。

客户档案编辑字段：

- 客户名称。
- 统一社会信用代码。
- 行业。
- 客户等级。
- 经营状态。
- 所属区域。
- 归属渠道。
- 客户负责人。
- 保护期结束时间。
- 主要联系人、电话、邮箱。
- 注册地址和备注。

后端要求：

- 客户编号和创建时间只读。
- 客户名称和信用代码变更必须有审计。
- 区域、渠道和负责人变更必须校验当前操作者数据范围。

### 7.3 客户跟进

布局：

- 左侧待跟进客户。
- 中间客户上下文和跟进记录。
- 右侧下一步计划、关联业务和提醒。

业务规则：

- 跟进记录归属关联商机，不新增独立客户跟进表。
- 一个客户有多个商机时，记录跟进必须选择商机。
- 客户页面按时间聚合展示商机跟进记录。

### 7.4 商机完整工作区

商机是完整销售链路的上下文入口，顶部页签固定为：

`概览 / 跟进 / 报价 / 订单 / 档案与审计`

概览：

- 商机基本信息、阶段、金额、概率和负责人。
- 关联报价摘要。
- 最近跟进和下一步建议。

商机阶段统一使用以下七个推进阶段，输单和项目取消作为终止结果：

| 顺序 | 阶段     | 进度区间 |
| ---- | -------- | -------- |
| 1    | 客户建联 | 10%      |
| 2    | 需求挖掘 | 20%-30%  |
| 3    | 客户方案 | 40%      |
| 4    | POC 试用 | 50%      |
| 5    | 立项推进 | 60%-70%  |
| 6    | 招投标   | 80%-90%  |
| 7    | 成单     | 100%     |

现有后端阶段代码不能在未迁移前直接删除。接口先建立兼容映射，再统一返回七阶段值；“立项推进”没有现有独立代码，必须由后端明确新增状态或派生规则，前端不得自行推断。

跟进：

- 跟进记录时间线。
- 下一步计划。
- 记录商机跟进。
- 跟进后阶段、成单概率和预计成交时间。

报价：

- 报价版本列表。
- 当前有效报价摘要。
- 新建报价版本。
- 查看报价详情。
- 修改报价。
- 报价转订单。

订单：

- 尚未转单时显示报价前置条件。
- 已转单后显示订单编号、审批节点和履约状态。
- 已转订单不再修改报价。

档案与审计：

- 创建人、负责人、最后更新。
- 商机状态历史。
- 报价、订单和外部集成的审计摘要。

后端要求：

- 一个商机可以有多份报价版本。
- 报价仍保存在独立 `crm.quotes`。
- 商机页面的报价摘要为只读派生数据。
- 商机阶段与报价状态通过事件联动，不复制金额和明细。

### 7.5 报价页面

报价管理保留为“报价审核与查询”管理入口，不作为普通用户的一级业务菜单。

报价编辑器包含：

- 客户和关联商机。
- 端点数量、区域和渠道层级。
- 套餐、补充功能、自定义报价模式。
- 软件模块明细。
- 硬件数量明细。
- 服务项目。
- 标准阶梯价。
- 区域价格覆盖。
- 一级和二级渠道折扣率。
- 工作量和报价快照。
- 报价单预览。
- 保存草稿、生成报价单。

转订单规则：

- 只从对应报价单发起。
- 订单中心不显示报价转订单。
- 已转单报价只读。
- 前端不提交最终金额，后端重新试算并固化快照。

### 7.6 订单中心

订单中心只处理已生成订单的审批和履约。

按状态显示动作：

- 待一级确认：一级确认、一级驳回并退回二级。
- 一级已确认（待区管处理）：区管确认、退回一级或二级、区管调价。
- 待超管确认：超管确认、退回区管、一级或二级。
- 待回退修订审核：批准或驳回回退修改。
- 待重新提交：从产品目录修改模块、数量和系统单价后重新提交。
- 履约中：确认发货、完成订单或取消订单。

规则：

- 页面只显示当前角色允许的动作。
- 服务端必须再次鉴权。
- 驳回、退回必须填写原因。
- 调价后必须重新进入超管确认。

### 7.7 渠道商与渠道成员

渠道商管理：

- 渠道核心档案：工商主体、经营规模、注册地址、联系人、合作背景、主要行业、代理品牌、授权产品线、资质认证、典型客户、服务区域、回款周期和授权提醒。
- 核心档案可从渠道列表、渠道详情和渠道画像页进入，编辑弹窗按四组字段连续维护。
- 渠道产品能力、技术服务商评分和行业产品矩阵在渠道画像中维护。
- 档案空值显示待补充，不允许前端生成示例值作为正式数据。
- 层级。
- 区域。
- 企业管理员。
- 合作状态。
- 成员和证书入口。

渠道成员管理：

- 成员资料。
- 企业管理员或普通员工身份。
- 销售或技术业务角色。
- 启用和停用。
- 重置密码。
- 证书授权与撤销。

边界：

- 渠道查看和编辑权限分开校验；区域管理员只能维护绑定区域，渠道企业管理员只能维护本企业。
- 核心档案保存写字段变更审计，敏感联系方式按角色脱敏。
- 业务角色不自动授予系统权限。
- 成员账号与组织任职分开保存。
- 成员页面必须有返回渠道商列表入口。
- 证书到期只告警，不自动撤销权限或修改业务角色。

### 7.8 产品与模块价格

产品目录：

- 软件模块、硬件产品和套餐。
- 公开销售价格。
- 状态和发布状态。
- 工作量规则。
- 硬件成本规则，仅超管可见。
- 价格规则直接编辑入口。

模块价格规则：

- 固定价或阶梯价。
- 一级渠道折扣率。
- 二级渠道折扣率。
- 区域覆盖。
- 区域数量阶梯。
- 生效时间。
- 价格版本。
- 内部成本与公开价格隔离。

计算顺序：

`基础价 / 阶梯价 → 区域价格覆盖 → 渠道折扣率 → 报价单价`

### 7.9 审核与消息

审核中心：

- 按业务类型展示待办。
- 显示申请对象、申请人、数据范围、时效和风险。
- 通过和驳回保留审批意见。

消息中心：

- 站内通知。
- 企微应用、企微群、短信和邮件投递状态。
- 读取、归档和偏好。
- 业务跳转。
- 失败原因和重试状态。

### 7.10 组织与权限

组织与账号：

- 内部组织和渠道组织分域。
- 部门、岗位、任职和负责人。
- 外部身份映射。
- 账号归档、恢复、合并和离职交接。

角色与权限：

- 系统角色。
- 业务角色。
- 权限点。
- 数据范围。
- 用户角色分配。
- 授权差异和回收任务。

### 7.11 审计与系统

- 审计日志。
- 数据库迁移状态。
- 服务健康。
- 备份与恢复。
- 任务执行和失败补偿。
- OpenAPI 调用和异常请求。

## 11. 状态与错误处理

### 11.1 页面状态

- 加载：保留布局，显示骨架或加载文字。
- 空状态：说明原因，保留筛选条件。
- 无权限：说明角色或数据范围限制，不展示对象详情。
- 错误：显示中文原因和请求编号。
- 冲突：提示刷新、重新选择或进入最新版本。
- 成功：右下角轻提示。

### 11.2 关键业务错误

| 场景             | 前端提示                     | 后端要求                    |
| ---------------- | ---------------------------- | --------------------------- |
| 重复转单         | 该报价单已生成订单           | 唯一约束和状态检查          |
| 已转单报价修改   | 已转单报价不可修改           | 拒绝状态变化                |
| 跨区域操作       | 当前账号无权访问该区域       | 返回 403                    |
| 驳回无原因       | 请填写驳回原因               | 400                         |
| 调价后未重新审批 | 调价订单必须重新进入超管确认 | 状态机拒绝                  |
| 价格规则缺失     | 产品价格规则不完整           | 返回缺失字段                |
| 收益不完整       | 成本规则或产品分类不完整     | 不阻断订单，记录 incomplete |

## 12. 前后端契约

### 12.1 前端不得自行决定

- 当前用户身份。
- 客户、渠道和区域归属。
- 报价金额、折扣、税费和工作量。
- 订单金额和正式编号。
- 审批节点和可操作按钮。
- 产品成本和收益。
- 是否存在报价或订单。

### 12.2 后端必须返回

- 当前用户角色和有效权限。
- 当前对象允许的动作。
- 业务状态和状态名称。
- 下一次允许状态。
- 操作失败的中文原因和错误码。
- 乐观锁版本或行版本。
- 幂等结果和重复请求提示。

### 13.2 路由和入口

禁止把完整客户、报价、订单或组织数据长期缓存在 Pinia。

## 14. 后端实现建议

1. 为视觉原型缺少的字段补稳定查询响应，不修改原业务字段语义。
2. 为区域筛选增加受控的可见区域列表。
3. 为渠道成员提供成员列表、档案、角色和证书聚合接口。
4. 为商机提供关联报价摘要和版本列表。
5. 为报价提供价格命中详情和区域覆盖快照。
6. 为订单提供当前状态可执行动作列表。
7. 为价格规则提供版本、阶梯和区域覆盖的读写接口。
8. 为所有页面提供审计和幂等支持。

如果某功能只在前端临时造数据，则不能进入生产验收。

## 15. 测试与验收

### 15.1 前端

- 1440px、1200px、900px、1800px 固定画板检查。
- 页面不换行、不折叠、不改变列数。
- 所有页面主按钮和返回路径可操作。
- 所有弹窗、抽屉和确认动作可关闭和提交。

- 金额和工作量输入不能被前端覆盖。

- 客户报备到商机闭环。

- 订单退回、修订、重提闭环。
- 渠道成员添加、编辑、停用、证书授权闭环。
