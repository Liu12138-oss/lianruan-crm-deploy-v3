## 2. 优化目标

本轮架构优化解决六类问题：

1. 一级导航无法直接发现消息、工作量和平台配置入口。
2. 管理配置页曾采用卡片墙，无法表达配置层级、风险和生效范围。
3. 订单审批只看见金额，无法追溯来源报价、商品模块和价格差异。
4. 报价与商机的上下文虽然打通，但需要明确报价仍是独立业务实体。
5. 组织、权限、证书、消息和外部身份跨域关系容易混写。
6. 前后端职责边界不清，容易出现前端复制状态机或任务逻辑。

## 3. 四端入口架构

| 入口       | 文件                                  | 定位                                   |
| ---------- | ------------------------------------- | -------------------------------------- |
| 管理员 PC  | `apps/web/public/admin.html`          | 完整业务、平台配置、审批、审计和运维   |
| 管理员移动 | `apps/web/public/admin-mobile.html`   | 待办、审核、查询和关键确认             |
| 渠道 PC    | `apps/web/public/partner.html`        | 渠道报备、商机、报价、订单、成员和产品 |
| 渠道移动   | `apps/web/public/partner-mobile.html` | 高频跟进、录入、审批和订单动作         |

统一登录后由服务端会话、账号类型、设备类型和安全 `redirect` 决定正式落点。四端共用同一身份、权限、数据范围、状态机、消息和审计底座。

## 4. 顶层信息架构

管理端一级导航固定为：

`业务全景 / 工作台 / 客户管理 / 线索管理 / 商机作战 / 渠道管理 / 订单中心 / 产品目录 / 消息中心 / 管理配置`

规则：

- 报价不作为普通用户的一级导航，商机中承载报价上下文。
- 管理员跨商机报价查询位于管理配置。
- 消息中心必须为一级导航，顶部铃铛只用于快速查看。
- 管理配置进入配置中心，左侧按业务域分组，中间查看和编辑，右侧显示状态、风险、依赖和审计。
- 订单中心负责审批和履约，不负责报价转订单；报价转订单从报价动作发起。

## 5. 系统分层

| 层             | 内容                                                    | 边界                         |
| -------------- | ------------------------------------------------------- | ---------------------------- |
| 终端与入口     | 管理员 PC / 移动、渠道 PC / 移动                        | 只负责页面承载和会话接入     |
| 页面与领域组件 | 客户、商机、报价、订单、渠道、产品、消息、组织          | 不复制状态机和金额规则       |
| 应用服务       | 鉴权、权限、数据范围、状态机、任务、消息、审计、OpenAPI | 统一业务规则和事务边界       |
| 领域数据       | 客户主档、商机、报价快照、订单、渠道、产品、组织和账号  | 按领域归属，禁止跨域直接写表 |
| 基础设施       | PostgreSQL、Redis、Worker、文件存储、IAM、企微、OA      | 外部失败不得回滚已提交主业务 |

| 平台治理   | 审计、导入导出、OpenAPI、备份和健康        | 查询、下载、重试、恢复演练                    | 导入、导出、备份和诊断       |

## 7. 关键业务链

### 7.1 客户到订单

```text
客户报备
→ 运营审核与保护期
→ 创建商机
→ 跟进并推进阶段
→ 从商机创建报价
→ 服务端价格与工作量试算
→ 客户确认报价
→ 从报价转订单
→ 一级 / 区管 / 超管审批
→ 履约交付
→ 收益冻结
→ 审计归档
```

### 7.2 订单跟踪

订单列表必须显示来源报价、商品摘要、审批节点和修订状态。订单详情和所有审批窗口必须显示：

- 报价单号与版本。
- 客户确认时间和价格版本。
- 商品模块、数量、报价单价、订单单价和差异。
- 审批轮次和回到的节点。
- 回退修订对原报价和订单的同步关系。

订单中的报价与商品信息只读。修改必须走回退修订，不得直接覆盖报价快照。

### 7.3 渠道与成员

渠道商主体、企业管理员、销售人员、技术人员和证书记录共享统一成员事实，但分别维护：

- 渠道主体资料和核心档案，包括工商主体、经营规模、注册地址、联系人、合作背景、经营画像、产品能力、评分和提醒。
- 账号身份。
- 销售或技术业务角色。
- 系统角色和数据范围。
- 证书模板与持证记录。

证书变化不自动修改业务角色和系统权限，但生成权限复核任务。

渠道核心档案入口必须从渠道商列表、渠道详情和渠道画像页可达。保存动作按角色和数据范围鉴权，并记录字段变更审计。

### 7.4 消息与提醒

```text
业务事件
→ 规则匹配
→ 收件人校验
→ 消息模板渲染
→ 站内 / 企微 / 短信 / 邮件投递
→ 结果记录
→ 失败重试或人工补偿
```

消息中心负责展示，消息渠道配置负责投递能力，提醒规则负责事件和收件人，任务模板负责生成规则。

## 8. 状态机总览

| 对象     | 核心状态                                                                                                                                                             |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 客户报备 | 草稿、待审核、已通过、已驳回、已取消、已转商机                                                                                                                       |
| 商机     | 七个推进阶段：客户建联（10%）、需求挖掘（20%-30%）、客户方案（40%）、POC 试用（50%）、立项推进（60%-70%）、招投标（80%-90%）、成单（100%）；输单和项目取消为终止结果 |
| 报价     | 草稿、已提交、已确认、已驳回、已转订单、已取消                                                                                                                       |
| 订单     | 主链：草稿、待一级确认、一级已确认、待超管确认、已确认、处理中、已发货、已完成；异常：一级已驳回、已驳回、退回区管/一级/二级、待回退修改审核、已取消、已替换         |
| 渠道     | 待审核、已启用/合作中、已驳回、已停用；续签和协议到期是风险派生值                                                                                                    |
| 后台任务 | 排队中、执行中、已成功、已失败                                                                                                                                       |
| 消息投递 | pending、sending、retry_wait、success、failed、dead、ignored                                                                                                         |

所有状态变化必须由服务端校验，写状态历史和审计日志。

商机现有 `contacted / registered / quoted / budget / design / testing / negotiation / won / lost / cancelled` 代码不能在未迁移前直接删除。接口边界先映射为新七阶段展示；其中“立项推进”当前无独立代码，必须由后端明确新增状态或派生规则后方可作为正式可写阶段。

完整的字段、派生值和原型修正结果见 `BUSINESS-FACT-AND-PROTOTYPE-AUDIT.md`。

## 9. 角色与数据范围

| 角色           | 数据范围                                 | 主要禁止项                   |
| -------------- | ---------------------------------------- | ---------------------------- |
| 超级管理员     | 全量业务和组织配置                       | 不代替日常经办人完成所有业务 |
| 区域管理员     | 绑定区域内的客户、商机、报价、订单和渠道 | 跨区域访问                   |
| 普通管理员     | 角色权限点和指定数据范围                 | 超级管理员配置能力           |
| 渠道企业管理员 | 本企业及下属成员数据                     | 其他渠道、内部成本和收益     |
| 渠道员工       | 本人负责或参与的数据                     | 企业其他成员数据             |
| 审核人员       | 被授权业务类型的审批任务                 | 未授权对象详情               |

区域筛选只对超级管理员展示，并且只缩小查询范围，不替代服务端鉴权。

## 11. UI 架构模式

### 11.1 列表业务工作台

用于客户、商机、报价、订单、渠道、产品、审核和消息。固定三栏：

`对象列表 / 当前业务上下文 / 状态与决策`

### 11.2 管理配置中心

固定三栏：

`业务板块 / 配置列表与编辑 / 状态、待处理、范围、依赖和审计`

查看状态显示当前状态、版本、负责人、生效范围和最近变更。编辑状态显示变更预览、影响范围、校验结果和提交生效。

### 11.3 订单上下文

订单工作区固定显示：

- 报价来源。
- 商品与价格快照。
- 价差和修订状态。
- 审批轮次。
- 履约状态。
- 可执行动作。

### 11.4 表单与高风险动作

- 新建、编辑和长文档使用独立页面。
- 详情使用右侧抽屉。
- 审批、退回、调价、导入和证书动作使用居中弹窗。
- 高风险动作必须二次确认并记录原因。

## 12. 接口与后端职责

| 接口域     | 主要能力                                 | 关键约束                           |
| ---------- | ---------------------------------------- | ---------------------------------- |
| 认证       | 登录、SSO、会话、改密和落点              | HttpOnly Cookie 和页面会话         |
| 客户与报备 | 查重、提交、审核、编辑和保护期           | 名称和信用代码唯一性               |
| 商机       | 创建、跟进、阶段和赢单                   | 阶段只能服务端校验                 |
| 报价       | 试算、保存、发送、确认、撤回、转单和收益 | 金额、折扣、税费和工作量服务端计算 |
| 订单       | 审批、调价、退回、修订、履约和归档       | 批准后商品快照只读                 |
| 渠道       | 准入、层级、成员、证书和报表             | 主体、身份、业务角色分离           |
| 产品       | 目录、发布、价格、区域覆盖和工作量       | 内部成本不对外返回                 |
| 组织       | 组织、成员、角色、数据范围和身份         | 内外组织分域                       |
| 消息       | 渠道、规则、模板、任务和投递记录         | 敏感配置加密且不回显               |
| 审计与运维 | 日志、导入导出、任务、备份和健康         | 日志只追加                         |
| OpenAPI    | 客户端、资源、密钥和调用审计             | 服务端解析数据范围                 |

## 13. 数据与快照规则

- 客户主档是客户事实唯一来源。
- 报备记录负责保护期和归属，不复制完整客户档案。
- 商机只保存销售过程和关联关系，不复制完整报价明细。
- 报价保持独立业务实体，保存服务端试算和价格快照。
- 报价转订单后，订单保存商品、价格、折扣和报价版本快照。
- 已确认订单的商品和金额只读，修订必须产生新版本和审计记录。
- 收益和内部成本只在授权角色接口中返回。

## 14. 异步任务与补偿

| 任务         | 触发               | 失败处理                     |
| ------------ | ------------------ | ---------------------------- |
| 消息投递     | 业务事件和提醒规则 | 重试、记录通道和人工补偿     |
| 订单 OA 预审 | 订单进入指定节点   | 超时重试，不自动跳过审批     |
| 收益冻结     | 订单超管确认       | 重算和补偿，保存正式快照     |
| 导入导出     | 用户创建任务       | 部分成功、错误明细和文件过期 |
| 备份与诊断   | 管理员动作         | 结果记录、校验和和恢复演练   |

## 16. 开发完成定义

前端 Agent：

- 使用固定 1440px 画板，不因浏览器窗口缩放自动换行。
- 使用统一设计令牌和组件，不复制原型 JavaScript。
- 所有加载、空、错误、无权限和冲突状态完整。
- 页面动作和跳转与原型一致。

后端 Agent：

- 所有身份、权限和数据范围从服务端会话解析。
- 状态机、金额、折扣、工作量和收益不得由前端提交。
- 关键动作提供幂等、版本和审计。
- 异步任务失败可重试或补偿。

测试 Agent：

- 覆盖四端、角色、数据范围、状态机、接口、任务和回退。
- 订单必须验证报价来源、商品快照、价差和修订链路。
- 管理配置必须验证可见入口、编辑影响和历史审计。
- 消息、证书、账号和组织变更必须验证跨域隔离。
