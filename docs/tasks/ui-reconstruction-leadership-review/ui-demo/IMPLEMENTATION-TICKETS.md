# V3 UI 架构优化实施任务单

更新日期：2026-09-21

## 1. 执行规则

1. 任务按依赖顺序执行，未满足前置任务不得开始。
2. 每个任务必须独立提交、独立测试、可独立回退。
3. 涉及接口的改动必须先更新 `packages/contracts`，再实现 API、前端和测试。
4. 涉及数据库的改动必须有正向迁移、回退脚本、数据校验和隔离环境演练。
5. 任务完成必须同时具备代码、测试、文档、截图或验收证据。
6. 当前功能开关默认关闭的模块不得因 UI 开发自动开启。
7. 任何未来模块任务在业务规则未签字前只能做契约和页面占位，不得写正式业务。

## 2. 任务状态

| 状态       | 含义                               |
| ---------- | ---------------------------------- |
| `待开始`   | 前置和范围已明确，可以领取         |
| `依赖阻塞` | 依赖其他任务或业务签字             |
| `开发中`   | 已领取并开始实现                   |
| `待验收`   | 代码和测试完成，等待业务或环境验收 |
| `完成`     | 代码、测试、文档和证据齐全         |
| `取消`     | 用户明确不作                       |
