# 联软渠道管理平台 V3 UI 重构视觉设计文档

## 1. 文档目的

本设计文档用于指导 V3 管理端、渠道端和移动端页面重构。原型只调整视觉、布局和交互，不改变现有登录、角色、权限、数据范围、业务字段、状态机、接口契约和审计规则。

交互原型入口：`index.html`。

前后端实施规格：`IMPLEMENTATION-SPEC.md`。

目标视觉来源：`docs/tasks/ui-reconstruction-leadership-review/visual-designs/screenshots/02-war-full.png`。对应实现基线为 `visual-designs/versions/02-war-room.html`、`visual-designs/assets/visual-ui.css` 和 `visual-designs/assets/visual-ui.js`。

## 2. 设计系统

### 2.1 颜色

| 用途       | 令牌            | 色值      |
| ---------- | --------------- | --------- |
| 品牌主色   | `--blue`        | `#2f69ed` |
| 主操作悬停 | `--blue-strong` | `#1557d6` |
| 品牌深蓝   | `--blue-deep`   | `#17345e` |
| 成功       | `--green`       | `#159873` |
| 警告       | `--amber`       | `#c58a17` |
| 危险       | `--red`         | `#ce4b58` |
| 流程       | `--purple`      | `#7254d8` |
| 页面底色   | `--page`        | `#eef4fa` |

状态颜色必须跨列表、详情、审批和消息保持一致。品牌色用于主操作、选中态和关键数字，不用于大面积背景。

### 2.2 排版

- 页面标题：22px，700。
- 面板标题：12px，700。
- 表格和表单：9-11px。
- 关键数字：23-28px，800，使用等宽数字。
- 辅助说明：8-9px，使用 `--text-3`。

### 2.3 间距与容器

- 基础间距：4、8、12、16、20、24px。
- 卡片圆角：8px。
- 弹窗圆角：10px。
- 状态标签圆角：5px。
- 数据表格行高：表头 32px，数据行 43px。
- 表单控件最小高度：34px。
- 筛选项高度：32px。

### 2.4 组件规则

- 主操作每页最多一个，使用品牌蓝实心按钮。
- 危险操作使用红色描边或文字，必须二次确认。
- 列表详情优先使用右侧抽屉，跨模块任务使用居中弹窗。
- 信息卡不嵌套信息卡，重复对象才使用卡片。
- 所有图标使用统一的 Lucide 风格线性图标。
- 金额、编号和比例使用等宽数字，金额不在前端计算。
- 表格操作统一使用 `table-actions`，查看、编辑、成本配置等文字操作不带按钮边框和底色，固定单行排列。
- 页面操作、筛选项、标签和表格操作不允许自动换行；空间不足时由固定画板横向滚动承载。
- 同一行面板必须等高且顶部、底部对齐，网格中的第二张面板不得额外产生顶部外边距。
- `war-tab` 标签使用 `inline-flex` 水平和垂直居中，固定单行，不随窗口缩放换行。

## 3. 全局框架

管理端与 `02-war-full.png` 保持一致，采用固定顶部导航和单画板内容区结构，不使用左侧导航。

- 顶部导航：品牌、业务全景、工作台、客户管理、商机作战、渠道管理、订单中心、产品目录、消息中心、管理配置和当前页面主操作。
- 报价不作为普通业务一级导航；商机内承载报价上下文和动作，管理员通过“管理配置 → 报价审核与查询”处理跨商机报价。
- 页面地图：通过顶部入口或评审页头打开全部页面，不占用业务画板宽度。
- 页面级动作使用页面导航，原地操作使用弹窗；新建客户、新建商机、新建报价和返回列表不得用弹窗代替页面跳转。
- 内容区：页面标题、页面操作、六项指标、筛选区、业务内容和三栏上下文。
- 三栏业务页：左侧对象列表，中间业务上下文，右侧决策和操作。
- 列表页固定坐标：导航高 `62px`，指标区顶部 `73px`、高度 `96px`，三栏区顶部 `180px`。
- 三栏固定列宽：`304px / 自适应 / 342px`。
- 客户、商机、报价和订单列表在超级管理员视图下显示区域筛选；普通渠道、企业管理员和区管不显示该筛选控件。
- 区域筛选只缩小超管当前查询范围，不替代服务端数据范围校验。
- 消息中心必须作为一级导航明确可见；顶部铃铛作为快速查看入口，不再作为进入消息页面的唯一路径。
- 人天与工作量配置必须从产品目录直接可见，并由服务端权限决定是否展示给当前管理账号。

渠道端沿用同一设计系统，但导航只保留工作台、客户报备、商机、报价、订单和产品目录。渠道端不展示内部成本、收益、组织权限和系统配置。

## 5. 页面交互

### 5.1 客户管理

- 客户列表支持名称、信用代码、编号、状态、区域、渠道和保护期筛选。
- 点击记录打开客户详情抽屉，不离开当前筛选和列表位置。
- 详情展示客户档案、联系人、归属、健康度、关联业务和最近跟进。
- 客户更新、账号归档和数据范围变化必须记录审计。

### 5.2 客户新增

- 客户名称支持工商查询，信用代码、法定代表人、经营状态和注册地址自动回填。
- 区域、渠道、创建人和权限范围由服务端会话决定，不由页面自由提交。
- 提交前执行名称和信用代码查重。
- 审核通过后进入保护期，并生成客户编号和报备编号。
- 客户档案编辑包含客户名称、信用代码、行业、等级、经营状态、区域、渠道、负责人、保护期、联系人和备注。

### 5.3 客户跟进

- 客户跟进是客户视角的聚合视图，不新增独立客户跟进数据模型。
- 正式跟进记录继续写入关联商机；客户存在多个商机时，记录跟进必须明确选择关联商机。
- 跟进记录、下一步动作和提醒时间在同一表单中提交。
- 客户时间线汇总展示所有关联商机的跟进记录，并保留来源商机。

### 5.4 商机管理

- 列表和看板共享同一份业务事实，阶段切换不得在本地静默推断。
- 记录商机跟进时同步填写跟进内容、阶段变化、赢单概率和预计成交时间；不单独设置“推进商机”操作。
- 商机必须关联已审批的报备客户，同一客户可以存在多个商机。
- 转报价前校验商机状态、客户和渠道归属。
- 商机详情和商机业务区提供明确的“创建报价单”入口。
- 报价单保持独立业务实体，商机详情只展示关联报价上下文、版本和状态，不把报价明细复制到商机字段。
- 商机中的报价入口与报价管理使用同一报价编辑器和同一状态机；报价管理仍承担全局查询、修改、折扣审批和转订单。

### 5.5 报价管理

- 报价金额、折扣、税费、价格版本和工作量全部由服务端计算。
- 页面只提交产品、数量、端点和业务参数。
- 报价预览保留正式报价单结构，转订单前校验重复转单和报价状态。
- 修改报价入口位于“报价管理 → 报价单列表 → 报价详情 → 修改报价”；已转单报价只保留查看和下载，不允许继续修改。
- 报价转订单入口位于“报价管理 → 对应报价单 → 转订单”；订单中心不提供报价转订单入口，只处理已生成订单的审批和履约。
- 报价管理选中报价单后，中间业务区固定显示查看详情、修改报价和转订单，左侧列表操作只作补充。
- 模块价格按“基础固定价 / 阶梯价 → 区域价格覆盖 → 一级 / 二级渠道价格比例 → 数量阶梯”计算，区域覆盖优先于渠道比例。
- 报价保存时必须固化命中的价格版本、阶梯、区域覆盖和渠道比例，后续改价不得改变历史报价快照。
- 报价编辑器必须展示软件、硬件、服务明细，以及正式报价单预览和试算汇总。
- 内部成本、收益和成本规则不通过渠道端、OpenAPI 或普通报价接口返回。

### 5.6 订单管理

- 订单状态机在列表、详情、审批和消息中使用同一状态语义。
- 审批、驳回、回退修订和重新提交必须保留状态历史和审计记录。
- 订单修订时只能从产品目录选择产品，不能手工修改产品名称。
- 回退修改批准后同步更新原报价和原订单，并重新进入审批链。
- 一级渠道确认或驳回、区管确认或调价、超管确认或退回、回退修订批准或驳回、修订后重新提交、发货、完成和取消都属于独立订单动作。
- 订单审批动作必须按当前状态、当前角色和服务端数据范围显示与校验。
- 订单中心直接显示当前状态的审批动作，不先跳转到通用审批列表。

### 5.7 渠道与产品

- 渠道商资料、企业管理员、员工和证书分开维护，但共享同一成员事实；渠道资料编辑入口统一命名为“编辑渠道商信息”。
- 渠道成员支持查看、添加、编辑、启停、重置密码、销售/技术角色调整和证书授权；业务角色不自动授予系统权限。
- 渠道成员页面提供返回渠道商列表入口，证书与风险使用统一主题列表样式。
- 产品目录提供“人天与工作量配置”的显式入口，超级管理员不再需要从隐式页签寻找。
- 产品公开价格与内部成本分表保存，不通过渠道接口返回内部成本。
- 硬件成本规则版本化保存，历史版本只读。
- 产品范围不明确时，收益计算标记为不完整，不能猜测或静默归零。

### 5.8 审批与消息

- 审批动作必须显示业务上下文、申请人、时效和风险提示。
- 驳回必须填写原因，并通过才允许可选审批意见。
- 消息中心只负责通知和待办展示，不能替代业务审批页。
- 外部投递失败必须显示通道、失败原因和重试状态。

### 5.9 组织与权限

- 内部组织和渠道组织分域展示，普通业务不能直接取两域权限并集。
- 业务角色、系统角色、数据范围和用户级覆盖相互独立。
- 角色变更、停用、离职和证书变化必须触发权限差异检查。
- 组织同步差异必须人工批准，不自动停用账号或修改业务归属。

| 审批详情     | 审核和驳回         | 驳回原因必填，动作写入状态历史           |
| 批量导入     | 导入正式数据       | 下载模板、上传、预检、执行和结果下载     |
| 产品选择器   | 报价或修订选择产品 | 支持产品线、类型和关键词检索             |
| 权限差异检查 | 处理权限变化       | 显示来源、差异和确认期限                 |
| 消息面板     | 快速查看通知       | 查看详情和进入业务页面                   |

## 7. 状态与反馈

- 加载状态：保留页面骨架，不改变布局尺寸。
- 空状态：说明原因，保留筛选条件，并提供可用的创建入口。
- 错误状态：显示中文原因、请求编号和重试入口，不显示堆栈或 SQL。
- 无权限状态：说明角色和数据范围限制，不暴露对象详情。
- 冲突状态：提示刷新或重新选择，不静默覆盖。
- 成功反馈：右下角轻提示，不中断当前任务。

## 8. 固定画板与移动端

- 桌面端列表和业务页固定为 `1440px × 740px`，新增流程固定为 `1440px × 900px`。
- 浏览器窗口窄于 1440px 时保持页面原尺寸，通过横向滚动查看，不能因为拉伸窗口破坏三栏和表格布局。
- 六项指标固定六列，三栏列宽固定，页面不出现左侧导航，不增加额外页面标题。
- 移动端不复用桌面表格，使用独立手机画板承载待办、审批、查询、详情和关键录入。
- 审批、订单确认和状态修改在移动端必须二次确认。
