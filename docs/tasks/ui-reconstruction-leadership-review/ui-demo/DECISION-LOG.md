# V3 UI 架构优化决策日志

更新日期：2026-09-22

## 1. 文档用途

本日志记录需求负责人和开发负责人已经确认的 UI 重构决策，用于约束前端、后端、测试和运维 Agent。若本文与早期草案冲突，以本文和正式原型为准，但不得绕过仓库 `AGENTS.md`、V3 鉴权、权限、数据范围、状态机、审计和功能开关规则。

## 2. 已确认决策

### UI-01：新视觉原型是正式目标

- 结论：顶部导航、固定 1440px 画板、三栏工作区和统一设计令牌是 UI 重构目标。
- 旧左侧导航只作为迁移期适配，不作为目标形态。
- 影响：所有页面外壳、导航、菜单和公共组件按新原型收口。

### UI-02：前端采用渐进式架构迁移

- 结论：只做 UI 重构，不做大爆炸式全量前端重写。
- 保留统一入口、正式 `.html` 路由、现有接口和业务状态机。
- 新页面优先进入 Vue 工作区；客户、商机、报价、订单等复杂页面按领域逐页替换。
- 旧页面通过兼容适配层继续运行，禁止新旧页面各维护一套业务规则。

### UI-03：报价和订单保持原有业务逻辑

- 报价保持独立业务实体、状态机、快照和确认逻辑。
- 商机中的报价入口与报价管理共用同一报价编辑器和同一服务端业务规则。
- 商机已有的“确认报价并转订单”快捷入口可以保留，但必须打开同一份报价确认和转订单窗口，不能复制第二套逻辑。
- 订单中心不提供报价转订单动作。

### UI-04：订单调价保持原有逻辑

- 区管按订单金额级调价，不新增逐模块调价规则。
- 调价必须填写原因，保留旧金额、新金额、操作人和时间。
- 调价后订单进入 `pending_superadmin_confirm`，由超管再次确认。
- 报价原始快照不因订单调价被覆盖。

### UI-05：移动二期范围

- 移动二期指独立入口 `mobile-v2.html` 和 `/api/mobile/v2/*`。
- 已确认业务能力：商机跟进、读取电脑端已确认且未转单报价并发起转订单。
- 明确不做：手机端新建报价、编辑报价、试算、折扣审批、报价确认和打印。
- 当前写入仍受独立认证、部署、安全、真机、灰度、性能和回退门禁约束。
- UI 必须根据服务端功能开关展示只读、写入冻结或已开放状态。

### UI-06：未来能力只做占位设计

- 合同与协议、收款与应收、保证金、客户公海与报备池、AI 分析与大屏、备份与恢复中心只做原型占位。
- 占位页展示业务边界、依赖和上线门禁，不展示正式写操作，不创建正式业务数据。
- 不得因页面入口存在而开启功能开关。

### UI-07：MCP 需要管理页面

- 按现有原型模板补 MCP 管理页面。
- 范围：连接状态、客户端登记、工具授权、调用审计、限流、熔断和降级。
- 页面不展示凭据原文、数据库地址、Redis 主状态密码或 Docker 套接字。
- MCP 仍默认关闭，页面不能绕过协议、权限和生产授权门禁。

### UI-08：功能开关展示

- 超级管理员看到真实状态：未启用、只读观察、写入关闭或已启用。
- 普通管理员不显示无权访问的配置入口。
- 前端隐藏按钮不替代服务端拒绝。
- 组织、消息、收益、MCP 和未来模块继续使用独立开关。

### UI-09：管理配置中心编辑方式

- 配置中心负责发现、状态、风险、影响范围、依赖和审计。
- 具体编辑进入对应模块自己的页面、抽屉或弹窗。
- 不在配置中心再造通用业务表单和重复校验。

### UI-10：指标口径暂缓

- 工作台先使用服务端已有的数量和真实待办。
- 转化率、趋势、履约率、合同额、回款额等指标暂不进入正式验收。
- 指标口径、刷新频率和时间范围待业务另行签字。

### UI-11：商机统一为七阶段进度

- 结论：商机步骤和进度统一为客户建联（10%）、需求挖掘（20%-30%）、客户方案（40%）、POC 试用（50%）、立项推进（60%-70%）、招投标（80%-90%）、成单（100%）。
- 输单和项目取消保留为终止结果，不占用七个推进阶段的位置。
- UI 不再直接展示旧的十阶段文案；现有阶段代码通过接口边界兼容映射。
- “立项推进”当前无独立后端阶段代码，后端必须先明确新增代码或派生规则，前端不得静默推断。
- 原“赢单概率”在 UI 中统一显示为“成单概率”，字段语义和计算规则不变。
- 复核确认（2026-10-12，R33 交付轮）：对照《统一使用手册 V2.4.0》商机推进流程十段口径（1% 已联系上客户 / 10% 商机明确并报备 / 20% 正式报价 / 30% 明确预算 / 40% 技术交流·方案设计 / 50% 产品测试 / 70% 招投标·商务谈判 / 100% 赢单 / 项目取消 / 输单），用户明确“按新 UI 的阶段”，即维持本条七段推进视图不变，不改为手册十段；旧代码继续由 `apps/web/src/shared/stages/opportunity-stage.ts` 兼容映射。

### UI-12：渠道核心档案必须可见可维护

- 结论：渠道管理增加完整核心档案视图，入口从渠道列表、渠道详情和渠道画像页直接可达。
- 档案分组固定为工商主体、经营规模与注册地址、联系人与合作区域、产品能力与资质提醒。
- 成员、证书和账号仍按独立入口维护，不混入成员维护流程。
- 核心档案保存写审计，空值显示待补充，查看和编辑按角色、区域和数据范围分别鉴权。

### UI-13：第一版只做线索管理检索与呈现

- 结论：第一版只建设外部招投标线索的检索、详情、来源状态和轻量处理能力。
- 线索管理是独立一级业务板块，在顶部导航中与客户管理、商机作战平级，不归入客户管理或商机作战。
- 爬虫采集、清洗、去重和原文快照由独立采集模块负责，UI 不直接访问目标网站。
- 第一版不做报名、投标、保证金、标书、开标、中标登记和自动转商机，也不建立客户或商机关联。
- 线索管理与商机七阶段中的“招投标（80%-90%）”分开；线索详情预留客户与商机关联位置，后续版本再开放。
- 采集状态、公告生命周期状态和业务处理状态必须分开展示，不混用同一字段。

## 3. 开发约束

1. 契约先于实现，新增接口先进入 `packages/contracts` 并评审。
2. 身份、角色、区域、渠道和数据范围只由服务端会话解析。
3. 金额、折扣、工作量、收益、订单金额和下一状态由服务端计算。
4. 高风险写动作必须有幂等、版本、审计和状态前置校验。
5. 外部系统失败不得回滚已提交的 V3 主业务事实。
6. 每个任务独立提交、独立测试、独立回退。
7. 文档和原型不授权直接修改生产数据库、生产配置或对外接口。
