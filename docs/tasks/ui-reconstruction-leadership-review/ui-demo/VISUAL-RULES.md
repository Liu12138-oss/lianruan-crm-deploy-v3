# 02-war 目标视觉模型实施规则

本规则以 `docs/tasks/ui-reconstruction-leadership-review/visual-designs/screenshots/02-war-full.png` 为目标，对应源码为 `visual-designs/versions/02-war-room.html`、`visual-designs/assets/visual-ui.css` 和 `visual-designs/assets/visual-ui.js`。后续设计文档、交互原型、截图和研发实现统一按本规则验收。

## 1. 固定画板

1. 桌面端列表和业务页固定为 `1440px × 740px`。
2. 新增流程使用 `1440px × 900px` 的长画板。
3. 浏览器宽度大于 `1440px` 时画板居中；小于 `1440px` 时只横向滚动。
4. 不允许随浏览器尺寸折叠侧栏、减少指标列数、改变三栏宽度或让按钮自动换行。
5. 画板边框为 `1px solid #cadbed`，圆角 `14px`，阴影和底色沿用 `visual-ui.css`。

## 2. 页面外壳

1. 业务画板必须使用 `artboard war-artboard` 结构，不增加左侧导航。
2. 顶部导航使用 `top-nav`，高度 `62px`，包含品牌、业务菜单、工具和当前页面主操作。
3. 业务菜单固定为：业务全景、工作台、客户管理、线索管理、商机作战、渠道管理、订单中心、产品目录、消息中心、管理配置。
4. 报价不再作为普通用户的一级业务分组；报价统一在商机上下文内处理，管理员跨商机查询位于“管理配置 → 报价审核与查询”。
5. 页面切换使用顶部菜单或页面地图；页面地图不进入业务画板截图。
6. 页面级动作使用页面导航，原地操作使用弹窗；新建、返回列表和进入详情不得误用弹窗动作。
7. 消息中心必须是一级菜单；铃铛只保留快速查看能力。
8. 人天与工作量配置必须从产品目录直接进入，不能只藏在不可发现的后置页签中。

## 3. 列表页固定坐标

1. 六项指标区使用 `war-kpis`，固定在画板顶部 `73px`，左右边距 `20px`，高度 `96px`。
2. 指标区固定六列，每项包含名称、趋势图标、数字、单位和补充说明。
3. 同一行的数据面板必须顶部、底部完全对齐；网格中的第二张面板不得额外产生顶部外边距。
4. 三栏业务区使用 `war-layout`，固定在顶部 `180px`，占满画板剩余区域。
5. 三栏列宽固定为 `304px / 自适应 / 342px`。
6. 不允许在 `war-kpis` 和 `war-layout` 之间增加额外页面标题或面包屑。

## 4. 左侧业务列表

1. 使用 `war-list`、`war-list-head` 和 `war-list-body`。
2. 标题行包含列表名称和数量徽标。
3. 搜索框使用 `war-search`，状态切换使用 `war-tabs`。
4. `war-tab` 必须使用 `inline-flex`，文字横向和纵向居中，固定单行。
5. 列表项使用 `war-record`，选中项使用浅蓝背景、蓝色左边线和轻阴影。
6. 每条记录至少包含名称、摘要、状态、负责人或归属、金额或时效。
7. 客户、商机、报价和订单列表仅对超级管理员显示区域筛选；普通渠道、企业管理员和区管不显示。
8. 区域筛选只用于缩小超管查询范围，不能代替服务端的数据范围校验。
9. 渠道成员页面必须提供返回渠道商列表入口。

## 5. 中间业务上下文

1. 顶部使用 `war-center-head`，展示对象名称、编号、归属和当前主操作。
2. 流程区使用 `stage-band`、`step-head` 和 `step-dots`，当前阶段为蓝色描边，完成阶段为浅蓝底。
3. 详情区使用两列 `detail-grid` 和 `detail-card`。
4. 字段使用 `info-grid` 和 `info-item`，标签在上、值在下。
5. 长文本使用 `note-box`，不继续嵌套卡片。

## 6. 右侧决策区

1. 使用 `war-right` 和 `right-section`。
2. 第一张 `right-card highlight` 展示业务状态快照。
3. 第二张 `right-card` 展示趋势、健康度或完成率。
4. 第三张 `right-card` 展示最近动态、提醒或下一步建议。

## 7. 新增流程

1. 使用 `artboard tall`，画板高度 `900px`。
2. 顶部导航保持 `62px`。
3. 标题区使用 `create-head`，固定在顶部 `74px`，左右边距 `40px`。
4. 表单主体使用 `create-body`，固定在顶部 `134px`，左右边距 `40px`，底部 `26px`。
5. 主体固定为两列：主表单自适应宽度，右侧说明栏 `314px`。
6. 表单控件、必填标记、只读字段和底部操作统一使用 `visual-ui.css` 的表格与表单样式。

## 8. 颜色和状态

1. 品牌主色 `#2f69ed`，主色悬停 `#1557d6`，品牌深蓝 `#17345e`，亮蓝 `#55c8ff`。
2. 成功使用 `#159873`，警告使用 `#c58a17`，危险使用 `#ce4b58`。
3. 同一状态在列表、详情、审批和消息中使用同一颜色和文字。
4. 品牌蓝只用于主操作、选中态、关键数字和当前流程，不用于大面积业务背景。

## 9. 字号、间距和控件

1. 页面标题 `19-22px / 700`，区块标题 `11-12px / 700`，正文和表格 `9-11px`。
2. 关键数字 `21-28px / 800`，使用等宽数字。
3. 基础间距使用 `4 / 8 / 10 / 12 / 16 / 20px`。
4. 卡片圆角 `8-12px`，状态标签圆角 `5px`，画板圆角 `14px`。
5. 表格数据行高度约 `43-51px`，筛选项高度 `32px`。
6. 表格操作必须包在 `table-actions` 中，使用 `action-link` 样式：无边框、无底色、蓝色文字、固定 `10px` 间距、单行排列。
7. “查看”“编辑”“成本配置”等操作文字不得使用浏览器默认按钮样式，也不得因空间不足换到第二行。
8. 页面操作组、筛选组、标签组和表格操作组统一使用 `flex-wrap: nowrap`。

## 10. 弹窗和抽屉

1. 单对象详情、历史记录和快速查看使用右侧抽屉。
2. 新增、审批、退回、导入和跨模块操作使用居中弹窗。
3. 高风险操作必须展示对象、影响范围和二次确认。
4. 驳回、退回和拒绝必须填写原因。
5. 底部操作排列为次级操作在左、主操作在右。
6. 客户档案编辑必须包含名称、信用代码、行业、等级、区域、渠道、负责人、联系人、保护期和备注。
7. 报价编辑器必须包含软件、硬件、服务明细、价格命中说明和报价单预览。

## 11. 业务图和状态图

1. 业务图使用固定节点卡、箭头和状态标签表达真实业务顺序，不依赖装饰性连线。
2. 主业务链必须覆盖客户报备、审核、商机、报价、订单、履约和收益。
3. 支撑链必须覆盖渠道、账号权限、审批消息、订单预审和报价收益。
4. 状态图必须保留状态文字、流转顺序和关键审批门禁。
5. 业务图节点和状态标签保持单行，禁止因浏览器窗口变化自动换行。

## 12. 订单审批与模块价格

1. 订单审批动作必须覆盖一级确认、一级驳回、区管确认、区管调价、超管确认、超管退回、回退修订审批、修订后重提、发货、完成和取消。
2. 驳回和退回必须选择退回目标并填写原因；调价必须重新进入超管确认。
3. 模块价格必须展示基础固定价或阶梯价、一级 / 二级渠道价格比例和区域价格覆盖。
4. 区域价格覆盖优先于渠道价格比例，报价保存时固化命中的价格版本和阶梯。
5. 内部成本、收益和成本规则不通过渠道端或普通报价页展示。
6. 订单中心直接显示当前状态可执行动作，不先跳转通用审批列表。
7. 产品与套餐的价格规则操作直接打开产品价格编辑，且必须显示区域覆盖明细表。
8. 商机详情必须展示关联报价上下文，但报价单仍保持独立实体；商机内可新建和查看报价，报价管理继续承担全局管理、修改、审批和转订单。

## 13. 移动端

1. 移动端不复用桌面 `war-layout`。
2. 移动端使用独立手机画板，围绕待办、审批、查询、详情和关键录入重组信息。
3. 审批、订单确认和状态修改必须二次确认。
4. 同一账号在移动端和桌面端共享登录、角色、数据范围和业务状态。

## 14. 业务数据边界

1. 客户跟进是客户视角的聚合视图，正式跟进记录仍归属关联商机。
2. 商机必须关联已审批的报备客户，同一客户可以有多个商机。
3. 报价必须关联客户和活跃商机，金额、折扣、税费和工作量由服务端计算；修改报价入口位于报价详情，已转单报价只读。
4. 报价转订单入口只能出现在报价管理的对应报价单上，订单中心不得提供报价转订单入口。
5. 报价管理右侧选中报价单的中间业务区必须始终显示“查看详情、修改报价、转订单”，不能只依赖列表滚动区域中的操作。
6. 订单审批、退回、修订和重提必须保留状态历史和审计记录。
7. 渠道端、OpenAPI 和普通页面不得出现内部成本、收益或系统配置数据。
8. 渠道核心档案编辑入口统一命名为“编辑渠道商信息”或“维护核心档案”，必须从渠道列表、渠道详情和渠道画像页可见；成员、证书和账号入口分开。

## 15. 验收清单

1. 列表画板宽度始终为 `1440px`，高度为 `740px`；新增画板高度为 `900px`。
2. 顶部导航高度始终为 `62px`。
3. 六项指标区顶部坐标为 `73px`，高度为 `96px`，固定六列。
4. 三栏业务区顶部坐标为 `180px`，列宽为 `304px / 自适应 / 342px`。
5. 浏览器宽度为 `900px`、`1200px`、`1440px`、`1800px` 时布局结构完全一致。
6. 页面不出现左侧业务导航，不出现额外页面标题，不因窗口缩放自动换行。
