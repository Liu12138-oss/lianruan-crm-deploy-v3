# V3 UI 重构交互原型

本目录是一份可点击的 HTML 视觉设计文档，直接沿用 `visual-designs/screenshots/02-war-full.png` 的顶部导航、固定画板、六项指标和三栏作战室格式，覆盖 V3 管理端、渠道端、移动端、业务全景、系统架构、渠道成员、订单审批、价格规则、认证、证书、提醒、组织、账号、产品、工作量、导入导出、审计运维和关键业务窗口。当前包含 45 个页面和 83 个关键窗口截图。

桌面端固定为 1440px 画板。浏览器窗口变化时不会自动折叠侧栏、减少指标列数或让按钮换行；窄窗口通过横向滚动完整查看。移动端使用独立手机画板展示。

## 使用方式

直接打开 `index.html`。通过顶部业务导航、顶部“页面地图”或评审页头切换页面；页面按钮、列表行、标签页和卡片均可点击，详情抽屉、审批弹窗、导入、产品选择和状态反馈均使用演示数据。

## 产出

- `DESIGN.md`：视觉设计规范、页面清单、交互和研发交付说明。
- `VISUAL-RULES.md`：以 `02-war-full.png` 为目标视觉模型提炼的固定画板、顶部导航、三栏列宽和验收规则。
- `IMPLEMENTATION-SPEC.md`：前后端 Agent 实施规格，包含页面、角色、接口、状态、测试和发布门禁。
- `FULL-UI-DESIGN-BLUEPRINT.md`：全量 UI 升级总蓝图，覆盖四套正式页面、全部路由、动作、移动端和页面设计图索引。
- `FEATURE-COVERAGE-MATRIX.md`：全量功能覆盖矩阵，193 项均已覆盖，并记录测试环境只读核对结果。
- `ARCHITECTURE-OPTIMIZATION-BLUEPRINT.md`：全量系统分层、业务域、页面架构、接口职责、实施切片和开发交接主文档。
- `NEW-UI-DEVELOPMENT-HANDBOOK.md`：新 UI 开发、老 UI 保护、分支并行、模块灰度、回退和旧 UI 清理规范。
- `PROTOTYPE-EVIDENCE.json`：页面和关键窗口截图的生成时间、数量和文件清单。
- `index.html`：交互式原型入口。
- `demo.css`：设计令牌和组件样式参考。
- `demo.js`：页面结构、示例数据和交互行为参考。
- `screenshots/`：45 个页面截图，2 倍分辨率输出。
- `screenshots/windows-v3/`：83 个关键弹窗、抽屉和确认动作截图，截图视口为 1440 × 1000。

## 业务边界

- 不改变现有登录、角色、权限、数据范围、业务字段、状态机和接口契约。
- 客户跟进是客户视角的聚合视图，正式记录仍归属关联商机。
- 金额、折扣、税费、工作量、收益和订单总额由服务端计算。
- 内部成本、收益和系统配置不对渠道端或 OpenAPI 暴露。
- 页面中的数据、编号、客户名称和金额均为演示数据。

## 重新生成截图

在仓库根目录运行：

```bash
node docs/tasks/ui-reconstruction-leadership-review/ui-demo/generate-prototype.mjs
```

## 说明

原型只用于视觉、信息架构和交互评审。正式实现应按 `DESIGN.md` 和现有 V3 工程约束形成页面迁移任务、接口契约、权限测试和回退方案后再编码。对测试环境和 Agent 的调用频率控制在每分钟 30 次以内。
