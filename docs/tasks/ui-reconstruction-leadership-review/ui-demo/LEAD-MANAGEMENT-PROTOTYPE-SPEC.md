# 线索管理第一版 UI 原型规格

## 1. 定位

第一版只解决外部招投标线索的检索、查看、来源追踪和轻量处理，不负责投标过程管理，也不建立客户或商机联动。

线索管理是独立一级业务板块，在顶部导航中与“客户管理”“商机作战”平级。它拥有独立入口、页面组、权限范围和数据来源状态页，不放入客户管理或商机管理的子菜单。

业务链路：

```text
外部来源采集
→ 清洗与归一化
→ 线索库
→ 检索与查看
→ 关注、忽略和轻量处理
```

后续版本再在线索详情中开放“关联客户或商机”。第一版只保留入口位置、字段位置和数据契约，不提供正式联动动作。

爬虫、清洗、去重和原始快照由独立采集模块负责。本模块不直接访问目标网站，不读取爬虫原始文件，只消费统一归一化后的数据。

## 2. 第一版范围

纳入：

- 招投标公告关键词检索和组合筛选。
- 公告详情、原文附件和来源跳转。
- 公告变更记录和重复提示。
- 数据来源、同步任务、失败重试和采集日志。
- 关注、忽略、备注和人工处理状态。
- 按当前筛选结果导出 XLSX。

不纳入：

- 报名、投标、保证金和标书管理。
- 开标、评标、中标结果和履约管理。
- 自动创建客户、商机或推进商机阶段。
- 关联客户和商机。第一版只预留页面位置和后续接口边界。
- UI 直接编辑爬虫原文或原始字段。

## 3. 页面与窗口

### 3.1 线索管理

路径：`/leads`

原型：`screenshots/54-lead-management.png`

页面结构：

- 六项指标：线索总量、今日新增、待跟进线索、即将截止、重点线索、来源异常。
- 左侧筛选：关键词、来源、区域、行业、采购方式、预算、发布时间、截止时间和处理状态。
- 中间结果：线索标题、采购单位、区域、预算、发布时间、截止时间、处理状态和线索状态。
- 右侧预览：选中线索摘要、来源、预算、截止时间和快捷动作。

主要动作：

- 同步刷新。
- 打开线索详情。
- 关注线索。
- 忽略线索。
- 导出当前检索结果。

### 3.2 线索详情

路径：`/leads/:id`

原型：`screenshots/55-lead-detail.png`

页签：

- 线索详情。
- 原文附件。
- 变更记录。
- 后续关联（预留，不可操作）。

右侧固定展示：

- 关键时间节点。
- 采购单位和代理机构。
- 后续客户与商机关联预留位置。
- 数据来源、抓取时间、内容哈希和最近校验时间。
- 关注、关联和忽略动作。

### 3.3 数据来源与采集

路径：`/lead-sources`

原型：`screenshots/56-lead-sources.png`

页面结构：

- 来源列表：来源名称、类型、覆盖区域、采集频率、最近同步时间和状态。
- 本次结果：新增、更新、失败和耗时。
- 异常提示：连续失败、超时、页面结构变化和来源暂停。
- 最近任务：执行时间、结果和重试记录。

主要动作：

- 立即采集。
- 暂停或恢复来源。
- 重试失败任务。
- 查看采集日志。

## 4. 状态口径

采集来源状态：

- `enabled`：启用。
- `paused`：暂停。
- `running`：执行中。
- `partial_failed`：部分失败。
- `failed`：失败。

公告生命周期状态由时间字段和变更记录派生：

- 新发布。
- 即将截止。
- 已截止。
- 已变更。
- 已取消。

业务处理状态：

- 未处理。
- 已关注。
- 已关联。
- 已忽略。

三类状态必须分开存储和展示，不能压成一个状态字段。

## 5. 数据字段

来源字段：

- `sourceCode`、`sourceName`、`sourceType`。
- `regions`、`frequency`、`status`。
- `lastSuccessAt`、`lastRunAt`、`lastError`。

公告字段：

- `id`、`sourceCode`、`externalId`、`sourceUrl`。
- `title`、`noticeNo`、`noticeType`。
- `purchaserName`、`purchaserCreditCode`、`agencyName`。
- `regionCode`、`cityCode`、`industryCode`。
- `budgetAmount`、`currency`、`procurementMode`。
- `publishAt`、`registrationDeadline`、`bidDeadline`、`openingAt`。
- `contentHtml`、`contentText`、`attachments`。
- `contentHash`、`fetchedAt`、`updatedAt`、`verifiedAt`。
- `changeType`、`changeSummary`、`duplicateGroupId`。
- `matchedLeadId`、`matchedCustomerId`、`matchedOpportunityId`。三个字段仅作为后续版本预留，第一版不写入。

## 6. 权限

| 角色           | 检索         | 详情         | 关注 / 忽略 | 后续关联（预留） | 来源管理 |
| -------------- | ------------ | ------------ | ----------- | ---------------- | -------- |
| 超级管理员     | 全量         | 全量         | 允许        | 后续版本开放     | 允许     |
| 区域管理员     | 绑定区域     | 绑定区域     | 允许        | 后续版本开放     | 只读     |
| 普通管理员     | 按权限和范围 | 按权限和范围 | 按权限      | 后续版本开放     | 不允许   |
| 渠道企业管理员 | 授权范围     | 授权范围     | 允许        | 后续版本开放     | 隐藏     |
| 渠道员工       | 按权限       | 按权限       | 按权限      | 后续版本开放     | 隐藏     |

原文、附件和联系方式按字段权限返回。跨区域和跨渠道对象由服务端返回保护性 `404`。

## 7. 建议接口边界

```text
GET  /api/leads
GET  /api/leads/:id
GET  /api/leads/:id/changes
PUT  /api/leads/:id/follow-state
GET  /api/lead-sources
POST /api/lead-sources/:code/run
PUT  /api/lead-sources/:code/status
GET  /api/lead-source-runs
GET  /api/lead-source-runs/:id/logs
```

第一版不提供关联接口。关注、忽略和立即采集必须使用幂等键。来源启停和重试必须记录操作人和审计。

后续版本建议接口：

```text
POST /api/leads/:id/associations
```

## 8. 验收标准

- 检索页可按来源、区域、行业、时间和状态筛选。
- 线索详情能打开原文、下载附件并查看变化记录。
- 来源页面能显示最近同步、失败数量、错误摘要和任务日志。
- 客户和商机关联只显示预留入口，第一版不能执行正式关联。
- 关注和忽略动作可恢复或审计。
- 采集失败不影响公告历史数据，也不改变业务关联关系。
- 页面保持 1440px 固定画板，不因浏览器宽度变化自动换行或折叠列。
