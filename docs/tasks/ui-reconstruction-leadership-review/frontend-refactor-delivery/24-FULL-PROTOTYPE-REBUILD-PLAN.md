# 全量原型一致性重构方案（r13 起）

更新日期：2026-09-24

需求负责人决策：以交互原型为唯一实现基线，**全量页面**改造；KPI 与业务数据使用真实数据，并保证升级数据兼容。

## 1. 术语与现状（更正）

- 当前系统是 **V3 工程化应用底座**：前端 `apps/web`（Vue 3 + Vue Router + Pinia + Element Plus），后端 `apps/api`，任务进程 `apps/worker`，受控只读服务 `apps/mcp`，单机部署 `deploy/single-server`。
- 根目录历史 V2 静态目录与旧后端已在 V3 主线清理，不再维护。
- 本次要改的不是「V2 系统」，而是 **V3 底座上仍沿用迁移期表格版式的页面**：这些页面由 `apps/web/src/pages/BusinessWorkspacePage.vue` 与部分独立页面组件渲染，视觉与交互未对齐 `ui-demo` 原型。
- 因此本文档统一使用「V3 页面」「迁移期表格版式」表述，不再使用「V2 版本」描述当前系统。

## 2. 实现基线

| 项目 | 基线 |
| --- | --- |
| 目标视觉 | `visual-designs/screenshots/02-war-full.png` |
| 设计系统 | `visual-designs/assets/visual-ui.css`（1808 行，含色彩令牌与作战室组件） |
| 页面骨架 | 六指标 `war-kpis` + 三栏 `war-layout`（左列表 / 中详情 / 右快照） |
| 列表形态 | `war-record` 卡片（标题、状态徽标、标签、负责人、金额、风险提示） |
| 交互原型 | `ui-demo/index.html`（56 个页面、96 个关键窗口） |
| 原型样式参考 | `ui-demo/demo.css` + `visual-designs/assets/visual-ui.css` |

实现方式：把 `visual-ui.css` 作为设计系统移植进 `apps/web/src/styles/`（作用域隔离，避免污染现有页面），抽出共享组件后逐页替换，**不保留迁移期表格版式作为主导航页面形态**；表格仅保留给导入导出、批量核对等确需表格的场景。

## 4. 真实数据与升级兼容

### 4.1 原则

1. 不为了 UI 改表结构；KPI 与派生值优先在前端按现有接口聚合，确认必须由服务端聚合的再按新增兼容接口的方式补。
2. 所有新增前端读取必须保留旧字段兼容层，升级后历史数据仍可展示。
3. 未知状态码、未知等级、空值一律兜底展示，不允许出现 `none`、`undefined`、`null`、空白列。

### 4.2 字段兼容映射（示例）

| 场景 | 兼容策略 |
| --- | --- |
| 渠道商级别 `level` | `primary/secondary/gold/silver/lep/none` → 一级/二级/金牌/银牌/核心/未分级；未知值原样展示并加灰色标签 |
| 渠道商联系人 | `contact` → `bossName` → 「未维护」 |
| 渠道商电话 | `phone` → `bossPhone` → 「未维护」 |
| 渠道商成员数 | `staff` 数组长度；为空时显示「未维护成员」而不是 `0 人` |
| 客户行业/区域 | `industry`、`region`，空值时显示「未填写」 |
| 订单状态 | 现有状态码 → 中文；未知状态原样展示并标注「未知状态」 |
| 报价状态 | `draft/submitted/approved/converted/...` → 中文；未知值原样展示 |
| 时间字段 | `createdAt/updatedAt/approvedAt`，空值显示 `—` |
| 金额 | `金额/amount/total`，空值显示 `—`，统一千分位与币种 |

### 4.3 KPI 口径（先按现有接口聚合，标注口径）

| KPI | 口径 |
| --- | --- |
| 客户总数 | 当前数据范围内的客户报备总数 |
| 本月新增 | `createdAt` 落在本自然月的记录数 |
| 待处理 | 状态属于待审核/待审批的记录数 |
| 风险/逾期 | 距上次跟进或到期日超过阈值（先按 7/30 天） |
| 订单状态指标 | 按订单状态码计数（如 `pending_primary_confirm`、`pending_superadmin_confirm`） |
| 渠道成员/证书 | 渠道商 `staff` 与证书记录聚合 |

页面必须在 KPI 卡片脚注标注口径来源（例如「本月新增」），口径最终由业务确认后固化为接口。

### 已定位结论：订单编号切换规则（原「接口编号与库中不一致」）

结论：不是编号错乱，是设计内的 V2 兼容编号规则，已通过数据库证据确认。

| 阶段 | 编号字段 | 示例 |
| --- | --- | --- |
| 报价转订单（创建） | `order_no` 初始为前置编号 | `LS-liulongfei-20260924-0008` |
| 区管确认 | `order_no` 切换为区管正式编号，原编号写入 `pre_region_order_no` | `leagsoft-smb-chenqinyu-0731-07`（前置 `LS-liulongfei-20260924-0008`） |

处理：订单中心列表与详情同时展示「订单编号」和「前置订单编号」，搜索同时匹配两者，保证跨阶段可追溯；验证脚本改为按客户名称检索后 4/4 通过。

## 6. 验收门禁

1. 结构一致：每页六项指标、三栏骨架、卡片字段、状态徽标、动作按钮与原型一致。
2. 数据真实：KPI 与列表值可追溯到接口字段，附聚合口径说明。
3. 兼容通过：用迁移后的历史数据抽样验证，无 `none`、空白、错位。
4. 视觉一致：1440 画板下与原型页并排比对，允许色差与内容差异，不允许版式差异。
5. 权限一致：超管 / 区管 / 渠道三类角色的可见范围与动作范围不变。
