## 2. 修复内容

### 2.1 渠道核心档案页（`ChannelProfilePage.vue`）

- 返回按钮对齐其他页面：`display: block` + `margin: 0 0 12px` + 蓝色 `#2f69ed` + `font-weight: 700`，放在页头卡片内第一行；「渠道核心档案」标签去掉底色芯片样式，与成员页「渠道成员维护」标签口径一致。
- 页头改为与成员 / 跟进 / 订单页一致的卡片（`padding: 22px 24px`、圆角 12、边框、渐变底），返回按钮坐标与成员页完全一致。
- 右上动作区对齐：`.档案按钮` 显式 `margin: 0`，抵掉全局 `.主按钮` 的 `margin-top: 18px`；「档案完整度」统一为圆角 pill（`min-height: 29px`，与「保护期」一致），三元素垂直中心线一致。
- 左侧分区可点性：全部分区按钮加边框与浅底色，激活项蓝框蓝底，悬停变深。

### 2.2 审批中心（`ApprovalCenterPage.vue`）

- 面板改为「审批任务」，头部右侧新增「待审批 / 已审批」页签（复用既有 `.tabs` / `.tab` 样式），切换时重置类型筛选与展开行。
- 口径：待审批 = 状态 `pending`（87 条）；已审批留存 = 其余状态 `approved / rejected / active`（175 条）。
  - `active` 为 V2 迁移的渠道商 / 账号审批状态，与老 UI（`admin-app.js`）一致显示为「已通过」（绿色），不再显示「待审核」。
- 已审批分区与待审批共用同一表格、类型分段（计数随分区联动）、关键词搜索与展开详情；操作列在已审批时为「查看业务 / 查看」，空状态文案分区区分。
- 修一个列表隐患：行键由 `target_id` 改为审批记录自身编号（`approvalId`），同一订单多级审批不再共用行键（此前已审批分区会多渲染 1 行、展开状态可能串行）。

### 2.3 审核中心独立一级入口（`admin-navigation.ts`）

- 一级导航在「订单」与「产品」之间新增「审核中心」（简称「审核」，`/admin/admin-review`，权限 `all_admin`）。
- 「配置」二级菜单的「审核与业务规则」保留跳转能力，但 `判断子项激活` 对其直接返回 `false`：审核页只高亮「审核」，不显示配置二级菜单条，不出现两个一级菜单同时高亮。
- 与 R30 遗留风险对应：区域管理员此前进入审核页顶部无高亮项，本轮起高亮「审核」。

## 5. 数据侧说明

- 本轮未改动数据库，未新增或修改接口，未写入测试数据。
- 审批口径取自既有 `/api/stage9/approvals` 全量返回：`pending` 87、`approved` 109、`rejected` 42、`active` 24（合计 262）。
- `active` 归入「已通过」的依据：V2 迁移数据中 `ops.approvals.status_code='active'` 表示渠道已激活（审批通过后的渠道状态）；老 UI `admin-app.js` 对 `status==='active'` 同样渲染「已通过」。

## 6. 风险与回退

- 风险：「已审批」收录主动作是跳业务页查看（订单处理 / 客户跟进），若后续要求对历史审批做只读详情页，需要在审核中心内新增详情路由。
- 风险：「审核」一级菜单对区域管理员全量可见；若后续收紧为超管专属，需同时调整路由 `允许角色` 与导航权限，并补回归。
- 回退：`cp compose/.env.bak-before-r31profileapprove compose/.env` 后执行
  `docker compose up -d --no-deps nginx api-1 api-2`，即回到本轮改动前的 protolign25 状态。
