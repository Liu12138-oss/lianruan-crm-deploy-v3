## 2. 修复内容

### 2.1 交付工作量规则可维护（`WorkloadConfigPage.vue`）

- 「工作量规则」表新增「操作」列：交付工作量规则显示「编辑」，实施工作量规则显示「只读」标记（与老 UI 工作量页口径一致）。
- 新增「编辑交付工作量规则」弹窗：规则名称（只读）、最小点数、最大点数（留空＝不设上限）、人天、组合项目加项（留空＝无加项）、状态（启用/停用）、说明。
- 保存调用既有正式接口 `PUT /api/workload/delivery-rules/:id`（后端 R32 前已实现并带审计，本轮未改后端）。前端对数字输入做归一化：清空一律按「留空」提交，`人天` 必须 ≥ 0，`最大点数` 不得小于 `最小点数`。
- 保存提示从映射面板内挪到页面级，映射保存与规则保存共用一条提示行。
- 实测：`EPP（仅DLP基础）· 1-100点` 人天 2.5 → 3 保存成功（接口返回 3，页面提示「已保存交付规则「EPP（仅DLP基础） · 1-100点」：3 人天。」），随后已还原为 2.5。

### 2.2 返回按钮胶囊化（`visual-ui.css`）

- `.返回按钮` 由无边框蓝色文字改为浅蓝底胶囊：`display: flex` + `width: fit-content`（独占一行，页面标签仍在其下方）、`min-height: 30px`、`padding: 0 12px`、`border: 1px solid #d5e5fb`、`border-radius: 8px`、`background: #f1f6ff`、11px / 700、悬停加深。
- 覆盖全部 11 处入口：订单处理、证书与风险、模块价格规则、渠道成员、渠道档案、客户跟进、工作量配置、新建客户、新建商机、新建报价。
- 实测四页（工作量配置、成员维护、新建报价）样式属性逐项一致，位置仍在页头卡片左上第一行。

### 2.3 页头按钮对齐根因修复（`theme.css` + `visual-ui.css`）

- `apps/web/src/styles/theme.css`：`.主按钮 { margin-top: 18px; … }` 收口为 `.状态页 .主按钮`，只服务 403 / 404 / 维护 / 会话失效四个状态页，不再泄漏给业务页。
- `apps/web/src/styles/visual-ui.css`：新增 `.主按钮、.次要按钮、.档案按钮 { display: inline-flex; align-items: center; justify-content: center; }`，让 `<button>` 与 `<RouterLink>`（`<a>`）在 38px 高度里文字都垂直居中。
- 实测成员维护页头：`核心档案` 与 `+ 新增成员` 均为 `上边 191 / 高 38 / 中心 210`，外边距 0，完全对齐。

### 2.4 订单中心中栏补齐（`OrderCenterPage.vue`）

- 中栏在「订单信息 / 订单明细」之后新增四个面板（客户中心同款两列网格）：
  - **合作伙伴与签单**：合作伙伴、一级渠道、渠道层级（一级/二级/内部直销）、签单人员、提报人、订单产品类型（按明细 `productRefType` 归纳为软件 / 硬件 / 手工服务）；
  - **区域与审批**（仅内部管理员可见）：所属区域、提交区域、负责区管、审批轮次、最近操作人、最近更新；
  - **交付与联系**：收货地址、联系人、电话区号、合同年度；
  - **关联单据**：关联报价单、关联商机、合同编号、报备编号、前置订单编号、正式订单编号。
- 复用 R32 的内部收益核算面板（`QuoteProfitPanel`），跨两列展示，仅 `superadmin` / `region_manager` 渲染，渠道端不返回内部金额。
- 字段口径与订单处理页一致：优先取订单原始数据字段，缺省显示「未填写 / —」。
