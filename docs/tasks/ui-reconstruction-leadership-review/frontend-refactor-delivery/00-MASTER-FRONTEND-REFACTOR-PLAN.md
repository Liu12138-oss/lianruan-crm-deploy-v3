# 联软渠道管理平台 V3 前端 UI 重构总方案

更新日期：2026-09-23

## 1. 文档定位

本文是前端 UI 重构的总入口，约束范围、架构、迁移方式、权限、分辨率、测试和交付顺序。各模块的页面、字段、动作和验收细节见本目录的模块落地文档。

本轮只做前端 UI 重构，不建设后端和业务主体。接口、数据库、爬虫、客户与商机关联、线索正式数据和外部集成由后续阶段另行实施。

## 2. 本轮范围

纳入：

- 现有管理端和渠道端正式业务页面。
- 工作台、客户报备、商机、报价、订单、渠道、产品、审核、消息和组织账号相关页面。
- 线索管理前端 UI：检索、详情、来源状态、关注、忽略、备注和导出。
- 统一设计系统、路由外壳、状态、权限展示和异常页面。
- 桌面端 13 / 14 / 15 英寸笔记本和 21 / 24 英寸显示器。

不纳入：

- 合同与协议、收款与应收、保证金、客户公海、AI 分析、备份恢复。
- MCP 管理、移动二期和未上线业务模块的正式 UI。
- 线索爬虫、数据接入、真实线索数据、来源调度和归一化服务。
- 客户与商机的正式关联动作。
- 订单、报价、渠道等后端业务规则重写。

未建设模块只从现有原型和导航中移除正式入口，不继续扩展视觉稿。

## 3. 核心目标

1. 一套视觉语言覆盖管理端和渠道端。
2. 一套阶段、状态、权限和错误码定义，禁止页面各自复制。
3. 新页面优先进入 Vue 工作区，旧静态页面逐步替换。
4. 13 至 24 英寸桌面设备在浏览器 100% 缩放时能够完整查看。
5. 页面缩放过程中不自动换行、不折叠列、不破坏主次关系。
6. 前端按角色隐藏、禁用或脱敏，服务端后续负责最终鉴权。
7. 每个模块独立开发、独立测试、独立回滚。

## 4. 推荐架构

采用“Vue 工作区承载新页面 + 旧页面兼容宿主”的渐进式迁移，不做大爆炸式重写。

```text
apps/web/public/*.html
  负责统一入口、会话接入和旧页面宿主

apps/web/src/
  design-system/
    tokens/
    layout/
    status/
    feedback/
    form/
  features/
    dashboard/
    customer/
    lead/
    opportunity/
    quote/
    order/
    channel/
    product/
    approval/
    message/
    organization/
  shared/
    permission/
    route/
    request/
    format/

packages/shared/src/
  阶段、状态、业务代码、错误码和公共契约
```

架构约束：

- 不新增第二套 UI 框架，继续使用 Vue 3、Pinia、Vue Router 和 Element Plus。
- 新页面不得继续加入 `apps/web/public/admin-app.js` 等大型静态入口。
- 页面组件只负责展示和交互，不在前端重新实现金额、审批、范围和后端状态机。
- 状态和阶段定义集中在共享字典中，不能在页面内部复制。
- 每个功能域拥有自己的 API 适配层，后端未完成时使用同形状 mock。
- 所有异步动作具有 loading、成功、失败、冲突和重复提交状态。

可参考的系统仅用于架构和排版借鉴，不直接复制依赖：

- Vben Admin：路由、菜单、权限和工作区分层。
- Soybean Admin：设计令牌、布局和主题一致性。
- Arco Design Pro Vue：高密度列表、表单和管理配置。
- Tabler：管理端表格、筛选和详情抽屉。

## 5. 页面承载策略

| 页面类型         | 目标承载                   | 迁移原则                  |
| ---------------- | -------------------------- | ------------------------- |
| 工作台与经营总览 | Vue 工作区                 | 优先替换                  |
| 客户与报备       | Vue 工作区                 | 保持原有状态和权限        |
| 线索管理         | Vue 工作区                 | 只做前端和 mock 数据      |
| 商机             | Vue 工作区                 | 先统一七阶段展示          |
| 报价             | Vue 工作区                 | 保持独立实体和报价快照    |
| 订单             | Vue 工作区                 | 保持审批和履约状态机      |
| 渠道与成员       | Vue 工作区                 | 核心档案和成员分开        |
| 产品与价格       | Vue 工作区                 | 价格由后续后端接口提供    |
| 审核与消息       | Vue 工作区                 | 与现有待办系统解耦展示    |
| 组织、账号和证书 | Vue 工作区，受功能开关约束 | 仅改造 UI，不开启后端能力 |
| 未建设模块       | 不进入本轮正式 UI          | 从原型和导航下线          |

## 6. 商机七阶段

前端统一展示：

| 顺序 | 阶段     | 进度    |
| ---- | -------- | ------- |
| 1    | 客户建联 | 10%     |
| 2    | 需求挖掘 | 20%-30% |
| 3    | 客户方案 | 40%     |
| 4    | POC 试用 | 50%     |
| 5    | 立项推进 | 60%-70% |
| 6    | 招投标   | 80%-90% |
| 7    | 成单     | 100%    |

输单和项目取消是终止结果，不计入七阶段进度。

本轮只做前端阶段字典和旧数据映射展示，不修改后端阶段代码。正式写入新阶段之前，必须等后端完成兼容映射。

## 7. 权限原则

权限分为五层：

1. 路由是否可进入。
2. 菜单和页签是否显示。
3. 页面动作是否显示。
4. 动作是否可执行或只读禁用。
5. 字段和敏感值是否可查看、脱敏或隐藏。

前端权限只负责界面控制，不能替代服务端鉴权。角色、区域、渠道和数据范围仍以服务端会话为准。

## 8. 桌面分辨率规范

默认面向电脑端，不以手机屏幕作为桌面页面的设计依据。

| 设备               | 常见物理分辨率                | 常见逻辑宽度           |
| ------------------ | ----------------------------- | ---------------------- |
| 13 / 14 英寸笔记本 | 1366×768、1440×900、1920×1080 | 1280、1366、1440、1536 |
| 15 英寸笔记本      | 1920×1080、2560×1440          | 1280、1536、1920       |
| 21 / 24 英寸显示器 | 1920×1080、2560×1440          | 1536、1920、2560       |

规则：

- 浏览器保持 100% 缩放。
- 逻辑宽度 `1280px` 为桌面页面最小完整展示宽度。
- `1280px` 至 `1439px` 压缩间距和次要列，不换行、不改变主结构。
- `1440px` 以上内容区域自适应铺满，超大屏限制最大内容宽度并居中。
- 低于 `1280px` 时保持逻辑最小宽度并启用组件内部横向滚动，不自动折行。
- 不通过缩小字体解决宽度问题。
- 表格、状态标签、按钮和操作列禁止自动换行。
- 图表、弹窗、抽屉和表单必须同步适配，不允许只优化页面头部。

## 9. 统一交互规则

- 页面详情使用右侧抽屉，跨模块动作使用弹窗。
- 筛选条件改变时不重置已选对象，除非对象不再属于结果集。
- 保存、审批、退回和状态变更必须显示处理结果。
- 高风险动作二次确认。
- 冲突状态显示服务端业务原因和刷新入口。
- 空状态、加载失败、无权限和维护状态分开设计。
- 线索的客户和商机关联只显示灰态预留，不提供可执行动作。

## 10. 迁移批次

### 批次 A：基础能力

- 设计令牌、布局、菜单、路由、权限元数据。
- 公共表格、状态、抽屉、弹窗、反馈和响应式规则。

### 批次 B：核心主链

- 工作台、客户、线索、商机、报价、订单。

### 批次 C：渠道与产品

- 渠道、成员、核心档案、产品、价格、工作量。

### 批次 D：协同与平台

- 审核、消息、组织、账号、证书及受开关约束的页面。

每个批次完成后必须做独立回归，不等待全部页面完成后统一测试。

## 11. 开发测试循环

每个模块按以下循环推进：

```text
开发
→ 组件和单元测试
→ mock 数据集成测试
→ 本地浏览器视觉检查
→ 开发修复
→ 回归测试
→ 测试环境核对
→ 问题修复
→ 最终验收
```

任何模块只有在前端、权限展示、状态、异常和视觉检查全部通过后，才允许标记为“开发完成”。

## 12. 交付物

每个模块必须提供：

- 模块落地文档。
- 页面和路由清单。
- 角色与字段权限矩阵。
- 动作和状态清单。
- mock 数据和接口适配说明。
- 单元、组件和浏览器测试。
- 截图证据。
- 已知限制和回滚方式。
