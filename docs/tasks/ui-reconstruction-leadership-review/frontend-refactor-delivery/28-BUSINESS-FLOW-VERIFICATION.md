## 3. 首轮暴露的业务规则守卫（均为正确拦截）

首轮 36 步中 4 步失败，逐个核对后确认全部是**业务规则生效**，不是缺陷：

| 现象 | 接口返回 | 规则结论 |
| --- | --- | --- |
| 商机改阶段未带原因 | `V3_STAGE9_OPPORTUNITY_CHANGE_REASON_REQUIRED` | 编辑商机必须填写变更原因 |
| 用渠道账号执行一级驳回 | `V3_ORDER_REGION_MANAGER_REQUIRED` | 确认/驳回/调价仅订单所属区域区管可执行 |
| 重提未带报价明细 | `V3_ORDER_RESUBMIT_CHANGE_REQUIRED` | 修订重提必须至少保留一项报价模块明细 |
| 向无任职关系账号颁发证书 | `ORG_CERTIFICATION_MEMBERSHIP_REQUIRED` | 只能为有有效任职或渠道成员关系的账号发证 |

另外在补齐脚本过程中又验证到三条规则：手机号在账号间唯一（重复返回 409）、停用账号不能颁发证书（409）、证书延期/撤销需要 `rowVersion` 乐观锁（缺失返回 400）。

## 4. 业务规则清单（按实测固化）

1. 客户报备：创建为 `pending`，区管可审核为 `approved`（带保护期）或 `rejected`。
2. 商机：必须从报备创建；阶段推进需带变更原因；阶段为七阶段模型。
3. 报价：草稿 → 提交 → 区管确认 → 可转订单；区管可驳回；同一报价只能转一次订单（重复返回 409 并提示已有订单号）。
4. 订单：报价转订单后进入审批链，确认/驳回/调价仅属地管，终审由超管；支持超管退回、渠道修订重提；履约状态流转 处理中 → 已发货 → 已完成。
5. 渠道成员：同一手机号只能绑定一个账号；成员可停用。
6. 证书：只能发给有效任职或渠道成员关系的启用账号；延期与撤销使用 `rowVersion` 乐观锁。
7. 消息：支持一键全部标记已读。
8. 权限：渠道账号不进入管理端内部数据；区管数据范围受区域限制。
