# UI 重构风险登记册

## P0 风险

| 风险                              | 影响                             | 处理方式                                         |
| --------------------------------- | -------------------------------- | ------------------------------------------------ |
| 七阶段与旧十阶段代码并存          | 阶段显示、筛选和写入不一致       | 前端先统一展示字典；后端迁移完成后才切换正式写入 |
| 线索管理没有正式路由和 Repository | 页面可能直接依赖 mock 或空白数据 | 先定义 Repository 和 mock，后端完成后再替换      |
| 页面范围包含未建设模块            | 研发资源被占位页面消耗           | 本轮只实施明确上线模块                           |
| 权限仅在前端判断                  | 数据泄露和越权                   | 页面仅做展示控制，后续接口必须服务端鉴权         |
| 客户与商机关联误开放              | 产生错误归属和数据污染           | 第一版无候选对象、无写接口、无可用按钮           |

## P1 风险

| 风险                   | 影响                   | 处理方式                                     |
| ---------------------- | ---------------------- | -------------------------------------------- |
| 新旧前端双维护         | 状态和样式重复实现     | 新页面只进入 Vue feature，旧页面逐步退出     |
| 分辨率适配只做页面外壳 | 表格、弹窗和抽屉溢出   | 所有公共组件一起做视觉回归                   |
| 实时数据和 mock 混用   | 演示数据进入生产       | mock 只能位于测试和开发构建                  |
| 大批量数据查询未定义   | 列表卡顿、导出超时     | 后端阶段再补分页、索引和异步任务             |
| 测试覆盖不足           | 交付后期集中爆雷       | 每个模块独立完成单元、组件、浏览器和权限测试 |
| 术语漂移               | 页面名称和领域概念混乱 | 以 `docs/CONTEXT.md` 和本目录术语为准        |
