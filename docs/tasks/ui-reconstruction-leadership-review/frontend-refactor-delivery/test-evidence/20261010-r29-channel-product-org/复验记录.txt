## 1. 渠道档案扩展字段覆盖

### 1.1 详情面板「有效展示覆盖」（核心档案优先、渠道主档回退，分母 227 家渠道）
数据来源：测试环境 PostgreSQL 直查（只读 SQL）

| 字段 | 已维护家数 | 占比 |
| --- | --- | --- |
| 成立时间 establishedAt | 87 | 38.3% |
| 注册资本 registeredCapital | 65 | 28.6% |
| 统一社会信用代码 unifiedSocialCreditCode | 65 | 28.6% |
| 合作背景 cooperationBackground | 21 | 9.3% |
| 业务范围 businessScope | 65 | 28.6% |
| 典型客户 typicalCustomers | 205 | 90.3% |

核对 SQL（节选）：
```sql
WITH 合并 AS (
  SELECT p.id, p.extra_json AS b, COALESCE(pp.extra_json, '{}'::jsonb) AS pp
  FROM channel.partners p
  LEFT JOIN LATERAL (
    SELECT extra_json FROM channel.partner_profiles
    WHERE partner_id = p.id AND status_code = 'active' ORDER BY id LIMIT 1
  ) pp ON true
)
SELECT count(*) FILTER (WHERE COALESCE(NULLIF(pp->>'establishedAt',''), NULLIF(b->>'establishedAt',''), '') <> '') AS 成立时间,
       count(*) AS 渠道总数
FROM 合并;
```

备注：列表接口 `/api/partners` 返回行的 `原始数据` 仅来自 `channel.partners.extra_json`（成立时间 23 / 注册资本 22 / 信用代码 22 / 合作背景 0），
详情面板会再叠加 `/api/v2/partners/:id/profile` 的核心档案，因此以「有效展示覆盖」为准。
未维护的记录在界面上统一显示「未维护」，属数据现状而非功能缺失。
