## 2. 实现内容

### 2.1 工作台面板换位与角色收敛（`DashboardPage.vue`）

- 「我的待办」面板移到 `.grid-2` 第一位（左侧），「业务趋势」移到第二位（右侧），面板内容与卡片结构不变。
- 「进入审核中心」按钮改为仅内部管理员（superadmin / region_manager）可见；「查看操作日志」按钮改为仅超级管理员可见（审计日志路由仅允许 superadmin）。
- 待办条目跳转改用 `use外壳前缀()`：渠道端跳 `/partner/registration/:id/followup`、`/partner/order/:id/actions`，管理端保持 `/admin/...`，不再把渠道用户送到管理端地址。

### 2.2 渠道端产品目录收口（`ProductCatalogPage.vue`）

- 新增 `内部管理员 = 是内部管理员(会话.user)`（superadmin / region_manager）。
- 头部「价格规则」入口与「刷新」按钮改为仅内部管理员可见；渠道端不再出现。
- 头部说明按角色分流：内部管理员沿用「对外报价与内部成本双重职责…」；渠道端改为「浏览在售软件功能、硬件与套餐，可在报价单中直接选型并使用系统计价。」
- KPI 中的「价格规则」「待发布」两项仅内部管理员展示；渠道端保留 软件功能 / 硬件产品 / 产品套餐 / 产品大类·模块 四项。
- 渠道端「产品目录」下钻（大类 → 模块 → 功能）与「推荐套餐」结构不变。

## 4. 发布与回退

- 发布方式：`apps/web` 执行 `npm run build` → 上传 `dist-web-protolign36` → 基于 `Dockerfile.nginx-protolign36`（`FROM nginx:1.27-alpine` + `COPY . /usr/share/nginx/html`）构建 `lianruan-crm-v3-nginx:3.0.0-stage10.20261014-protolign36` → 切换 `compose/.env` 的 `V3_IMAGE_TAG` → `docker compose up -d --no-deps nginx`；api / worker 镜像同步打同名标签，保证 compose 口径一致。
- 回退：`cd /opt/lianruan-crm-v3/compose && cp .env.bak-before-r39-protolign36 .env && docker compose up -d --no-deps nginx`，即回到 R38 的 protolign35。

## 5. 待确认事项（本轮未改）

1. 渠道端功能卡片仍展示「N 档阶梯价 / N 个区域覆盖」标签与阶梯价金额。渠道报价依赖系统按等级与区域自动计价，目录价格是否也要对渠道端隐藏，需要业务确认。
2. 「他看的功能和模块也没有」的准确含义待确认，候选解释：
   - 甲：渠道端「推荐套餐」只能看到套餐内模块 / 功能 / 硬件的数量，看不到具体名称；希望像老 UI 一样提供只读「查看套餐详情」。
   - 乙：某些产品大类本身没有配置模块与功能（如测试环境「联软异常流量分析系统V3.0」为 0 模块 0 功能），属产品目录数据未配置，需要维护数据而非改 UI。
