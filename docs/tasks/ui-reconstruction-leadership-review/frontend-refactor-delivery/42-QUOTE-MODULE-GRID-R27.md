## 1. 用户反馈与结论

| # | 反馈 | 结论 |
| --- | --- | --- |
| 1 | 报价页中间模块展示不如 V2 那种「一小块一小块的圆方格」 | 成立。R24 把中间栏做成了表格（产品模块 / 数量 / 标准价 / 区域覆盖 / 渠道比例 / 最终单价 / 小计），信息虽全但观感偏表格化。已改为圆角方格卡片。 |

## 2. 中间栏模块方格

- 每个模块一块圆角方格（`2px` 边框 + `12px` 圆角，hover 变主色并轻投影），与老 UI 的 `supplement-card` / `feature-chip` / `hardware-card` 同一套视觉语言。
- 方格内容：模块名称、`−/＋` 数量步进 + 数量输入、最终单价（主色大字）、标准价 / 区域覆盖 / 渠道比例构成、小计；套餐内模块右上角显示「套餐内」角标，自选模块显示可点击的移除按钮。
- 可选模块区同步改为带勾选角标的方格（未选 `＋` / 已选 `✓`），硬件与服务同样用方格（橙色角标区分硬件）。
- 数量调整仍走服务端重新取价：整单 120 端点时点「＋」→ 数量 121、小计由 ¥2,640.00 变为 ¥2,662.00（22.00 × 121）。

## 3. 渠道端统一

| 路由 | 改造前 | 改造后 |
| --- | --- | --- |
| `/partner/quote/new` | 落到 V2 兼容工作区页（`BusinessWorkspacePage`），按钮为「生成报价单」且无提交入口 | 新 UI 报价构建器（`QuoteCreatePage`），与管理端完全同构 |
| `/partner/quote/edit/:id` | 同上 | 新 UI 报价构建器编辑态 |

路由实现：在 `渠道端专项路由` 中新增两条与 `quote/new`、`quote/edit/:id` 同路径的专项路由，
按仓库既有规则「专项路由优先」，同路径的通用 V2 兼容路由会自动被移除，管理端与渠道端共用同一组件。
页面内所有跳转沿用 R25 引入的 `use外壳前缀`，渠道账号不会跳到 `/admin`。

## 6. 风险与回退

- 风险：方格内同时展示「最终单价」与价格构成，卡片高度略高于原表格行；模块很多时以多列自适应网格排布（`minmax(236px, 1fr)`），不会挤压信息。
- 风险：渠道端报价创建从 V2 兼容页切到新 UI，渠道账号的报价习惯变化；报价接口与取价逻辑未变（仍走 `POST /api/quotes` 与 `试算报价`）。
- 回退：改回 `compose/.env` 的 `V3_IMAGE_TAG=3.0.0-stage10.20261008-protolign16` 后执行
  `docker compose up -d --no-deps nginx`，即回到 R26 交付态。
