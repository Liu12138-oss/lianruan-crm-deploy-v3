## 2. 现有 UI 能力（接入后保持不变）

- 检索筛选：关键词、区域、行业、数据来源、处理状态、预算范围。
- 线索列表：卡片式记录，含标题、公告编号、采购单位、区域、行业、预算、发布时间、截止时间、来源、状态、重点标记。
- 线索详情：公告详情、摘要、联系人、原文/附件跳转、变更与重复提示位置。
- 轻量处理：关注、取消关注、忽略、备注。
- 数据来源页：来源总数、正常同步、今日新增、失败任务；来源状态表与采集任务日志；失败重试入口。
- 权限：超级管理员、区域管理员可见；渠道账号不可见（当前路由已按此控制）。

## 3. 建议接口契约

统一响应沿用 V3 现有格式：`{ success, data, error, meta }`。

### 3.2 线索详情

```http
GET /api/leads/:id
```

额外返回：附件列表、变更记录（`changes[]`）、重复线索提示（`duplicates[]`）、备注历史（`notes[]`）。

### 3.3 线索状态与备注

```http
POST /api/leads/:id/status   { "status": "未处理 | 已关注 | 已忽略" }
POST /api/leads/:id/notes    { "content": "..." }
```

要求：幂等（同状态重复提交不报错）、写入操作人、写审计。

### 3.4 数据来源与采集任务

```http
GET  /api/lead-sources
POST /api/lead-sources/:id/retry
GET  /api/lead-tasks?sourceId=&status=&page=&pageSize=
```

来源字段：`名称、类型、覆盖范围、采集频率、最近成功时间、状态（正常/部分失败/暂停）、今日新增、今日更新、失败数`。

## 4. 字段与状态约定

| 字段 | 规则 |
| --- | --- |
| 线索状态 | `未处理` / `已关注` / `已忽略`，前端按此三态展示，未知状态原样展示并标注 |
| 区域 | 复用组织区域字典，保证与客户/商机区域口径一致 |
| 行业 | 复用客户报备行业枚举，空值显示"未填写" |
| 预算 | 单位万元；空值显示"—"，不显示 0 |
| 时间 | ISO 字符串；前端统一格式化，空值显示"—" |
| 来源 | 采集模块的归一化来源名，前端只展示不解析 |

## 5. 接入顺序建议

1. 采集模块产出归一化线索并落库（含原始快照与去重键）。
2. 后端实现 3.1–3.4 接口，先只读后写入。
3. 前端把 `LeadManagementPage` 的内置演示数据替换为接口调用（改动集中在数据层，页面结构不动）。
4. 联动客户/商机：第二版再开放，需先定义归属冲突与保护期规则。

## 6. 权限与边界

- 可见角色：超级管理员（全部区域）、区域管理员（本区域）。渠道账号不提供入口。
- 第一版不提供投标过程管理，不建立客户/商机正式联动。
- UI 不直接访问目标网站，不读取爬虫原始文件，只消费归一化数据。
