# 原型一致性审计与改造方案（r13 前置）

审计日期：2026-09-24

审计对象：测试环境 `http://10.9.86.66` 当前实现 vs 交互原型 `docs/tasks/ui-reconstruction-leadership-review/ui-demo/index.html`

目标视觉模型：`visual-designs/screenshots/02-war-full.png`，设计系统样式：`visual-designs/assets/visual-ui.css`

## 1. 结论

需求负责人反馈「几乎所有 UI 页面和原型图都对不上」属实。当前实现与原型是两套不同的设计语言：

| 维度 | 原型（ui-demo） | 当前实现 |
| --- | --- | --- |
| 页面骨架 | 六项指标卡 `war-kpis` + 三栏作战室 `war-layout`（左侧列表 / 中间详情 / 右侧快照） | 顶部标题 + 搜索 + 单张宽表格 |
| 列表形态 | 卡片式业务记录（标题、标签、负责人、金额、状态徽标、风险标签） | 传统表格行（编号、名称、字段列） |
| 指标 | 每页固定六项业务指标（总数、本月新增、待处理、风险等） | 大部分页面没有指标区 |
| 详情 | 中间栏内联展示生命周期、档案、业务快照、健康度、时间线 | 需要点进独立详情页或弹窗 |
| 样式来源 | `visual-designs/assets/visual-ui.css`（1808 行设计系统） | `theme.css` + `BusinessWorkspacePage.vue` 内嵌 V2 样式（165 个 `v2-` 类名） |

## 2. 根因

1. 路由中大量业务页面仍由 `apps/web/src/pages/BusinessWorkspacePage.vue`（5541 行、V2 移植版）统一渲染，见 `apps/web/src/router/index.ts:628`。该组件在视觉上只做了主题色替换，版式仍是 V2 表格。
2. 后来新建的独立页面（线索、消息、渠道成员、订单处理、价格规则、证书、平台配置、组织）虽然脱离了通用工作区，但没有按 `war-kpis + war-layout` 原型骨架实现，因此仍然「对不上」。
3. 原型的设计系统 `visual-designs/assets/visual-ui.css` 从未被引入 Vue 应用，页面各自重写了样式，导致同一页面在原型与实现中宽度、间距、圆角、指标列数、标签样式都不一致。
4. 数据层按「表格字段」而不是「作战室卡片字段」组织：原型需要的派生指标（本月新增、待处理、风险数、证书数、成员数、健康度）没有聚合来源或没有做映射，部分字段直接展示原始值（例如渠道商级别显示 `none`）。

## 4. 数据不一致清单（示例，已核对接口）

| 现象 | 位置 | 原因 | 处理方向 |
| --- | --- | --- | --- |
| 渠道商「级别」显示 `none` | 渠道商列表 | 接口 `原始数据.level = "none"` 直接透传 | 映射为「未分级/银牌/金牌/核心」，并补 `partnerLevel` 取值 |
| 渠道商「联系人/电话」为空或异常 | 渠道商列表 | 列表取 `原始数据.contact`，大量记录为空，真实联系人在 `bossName/bossPhone` | 按 `contact → bossName` 回退，电话同理 |
| 渠道商「销售人数 0 人」 | 渠道商列表 | 列表读 `原始数据.staff`，导入数据为空数组，真实成员在渠道成员接口 | 改为读成员聚合数 |
| 渠道商「报价/订单 0/0」 | 渠道商列表 | 列表没有按渠道商聚合报价与订单 | 增加按渠道商聚合 |
| 工作台/各模块缺 KPI | 全部列表页 | 原型要求的派生指标没有接口或没有聚合 | 前端聚合 + 缺失的由后端补聚合接口 |
| 订单列表无审批状态统计 | 订单中心 | 原型要求按 `pending_primary_confirm` 等状态计数 | 前端按状态聚合现有订单数据 |
| 消息中心未读数与原型不一致 | 消息中心 | 原型为演示值（5 条），线上为真实值（22 条） | 保留真实值，属于原型演示数据差异 |

## 5. 改造方案

### 5.1 设计系统先行

1. 把 `visual-designs/assets/visual-ui.css` 作为原型设计系统移植进 Vue 应用（建议 `apps/web/src/styles/visual-ui.css`），并做作用域隔离，避免与现有 `theme.css`、Element Plus 冲突。
2. 抽出三个共享 Vue 组件：`WarKpis`（六项指标）、`WarLayout`（三栏作战室）、`WarRecordCard`（业务记录卡片）。
3. 列表页统一按「六指标 + 左列表 / 中详情 / 右快照」重建，表格保留为可选视图（仅用于导入导出等场景）。

### 5.2 分批改造

| 批次 | 页面 | 说明 |
| --- | --- | --- |
| 批次 1 | 工作台、客户报备、线索管理、渠道商、订单中心、消息中心、组织架构 | 与需求负责人截图的 7 个页面一一对应，先出样板验收 |
| 批次 2 | 商机作战、报价管理、产品目录、审核中心、证书与风险 | 核心销售链路 |
| 批次 3 | 渠道核心档案、渠道成员、订单处理、价格规则、消息渠道与规则、账号管理、开放接口、审计日志、工作量配置、渠道报表 | 运营与平台模块 |
| 批次 4 | 渠道端工作台与各列表、渠道端订单处理 | 渠道端对齐 |

### 5.3 验收方式

每批交付时必须提供：

- 原型页与实现页同分辨率（1440×900）并排截图。
- 结构一致性检查：`war-kpis` 指标数量、三栏骨架、卡片字段、状态徽标、动作按钮一致。
- 数据一致性检查：KPI 与实际接口聚合值逐项核对。
- 测试环境发布与角色回归（超管 / 区管 / 渠道）。
