## 2. 修复内容

### 2.1 渠道管理详情（`ChannelListPage.vue`）

- 选中渠道时并发加载「渠道核心档案」与「渠道经营摘要」，失败各自降级为空，不影响主档渲染。
- 「工商主体」面板改为：统一社会信用代码、成立时间、注册资本、实缴资本、法定代表人、经营状态、工商认证、编号。
- 「经营与能力」面板改为：代理品牌、服务区域、年营收、员工人数、参保人数、开票能力、授权产品、资质证书。
- 新增「合作背景」面板：协议编号、合作起始、负责人、电话，以及合作背景 / 业务范围 / 典型客户 / 客户行业四段长文本。
- 新增「合作经营摘要」面板：客户 / 商机 / 报价单 / 订单四宫格，卡片数值 23px，消除原先中下部的大块留白。
- 字段缺失时统一显示「未维护」，区分「功能没做」与「数据没录」。

### 2.2 合作经营摘要数据口径

- `查询渠道经营摘要(渠道编号)` 复用正式列表接口，不新增统计接口、不新增统计表，口径与各业务模块一致：
  - `/api/stage9/registrations?partnerId=<UUID>&pageSize=1` → `分页.总数`
  - 商机、报价单、订单同法。
- `查询阶段9列表` 新增 `partnerId` 查询参数，服务端按当前账号的数据范围过滤，因此渠道账号只会统计到自己渠道的数据。

### 2.3 产品目录维护（`ProductCatalogPage.vue` + 新建 `product-catalog-client.ts`）

- 客户端封装 `/api/v2/categories|modules|features|hardware|packages` 的查询与保存，以及 `PATCH publish`（发布 / 下架）、`DELETE`（归档），与老 UI 使用同一套数据与字段口径，避免新 UI 另起一套产品模型导致报价取价不一致。
- 顶部新增操作：工作量配置（跳工作量页）、新建大类、新建模块、新建功能产品、新建硬件、新建套餐；工具区新增「价格规则」与「刷新」。
- 五类弹窗：功能产品（价格类型、固定价、一级 / 二级比例、必选标记、阶梯档位增删、区域覆盖编辑含区域阶梯）、硬件产品、产品套餐（勾选模块 / 功能 / 硬件）、产品大类、产品模块。
- 行内操作：查看、编辑、下架 / 发布、归档（归档二次确认）。
- 新增「产品结构」面板，展示大类 × 模块的组织关系。
- 权限：仅超级管理员（`是超级管理员(会话.user)`）显示写操作，非超管只读。

### 2.4 组织架构与账号维护

- `organization-client.ts` 的 `创建用户` / `更新用户` / `更新用户状态` / `重置用户密码` 由 `/api/users*` 改为 `/api/v2/users*`。
  - 原因：V3 主线未提供 `POST /api/users`，实测返回 404；老 UI 一直走 `/api/v2`，改回后与老 UI 同源。
- `GenericWarModulePage.vue` 新增 `维护入口`：模块配置可声明「文案 + 路径」，中心区渲染跳转按钮，用于只读核对页指向真正可写的模块。
- `AccountManagePage.vue` 配置 `维护入口` 指向 `/admin/organization`，并加强说明文案，用户从账号管理页一步进入组织与账号工作区。

### 2.5 审计日志导航

- `admin-navigation.ts` 顶部导航新增「审计日志」→ `/admin/audit-logs`（`superadmin` 权限）。
- 原先 `/admin/platform-admin` 的激活判断把 `audit-logs` 也算作自己，导致审计页高亮错项；已把 `audit-logs` 从该判断中移除。
- 审计数据源 `audit.audit_logs` 当前 2093 条记录。

## 5. 数据侧说明

- 渠道工商与合作背景字段属历史数据现状：227 家渠道中成立时间 87 家、注册资本 65 家、统一社会信用代码 65 家、合作背景 21 家已维护，其余在界面显示「未维护」。这些字段取自渠道核心档案（`channel.partner_profiles.extra_json`，渠道主档 `channel.partners.extra_json` 作为回退），如需补录可在渠道档案维护入口按渠道补录，无需改代码。
- 列表接口 `/api/partners` 返回行的 `原始数据` 只来自 `channel.partners.extra_json`，不含核心档案；详情面板会叠加核心档案，因此以详情面板显示为准。
- 本轮产品目录、组织账号的验证数据已全部 SQL 清理（功能产品 / 模块 / 大类 / 测试账号 / 任职记录复查均为 0），未污染测试环境业务数据。
- 组织「离职交接 / 账号停用」开关 `V3_ORGANIZATION_OFFBOARDING_ENABLED` 未在测试环境配置，默认关闭，本轮未开启。

## 6. 风险与回退

- 风险：账号写入改走 `/api/v2/users*` 后与老 UI 同源，若后续 V3 主线另行提供 `/api/users`，需要同步迁移并补回归测试，避免两套入口并存。
- 风险：合作经营摘要为实时统计（每次选中渠道并发 4 个列表请求），渠道数据量继续增长时若出现明显卡顿，可改为服务端单接口聚合，本次先以「零新增后端接口」优先。
- 风险：产品目录写操作仅超管可见；如后续需要区域管理员维护产品，需在权限口径中单独开放并补测试。
- 回退：把 `compose/.env` 的 `V3_IMAGE_TAG` 改回 `3.0.0-stage10.20261008-protolign21`（或直接 `cp compose/.env.bak-before-r29channel compose/.env`），再执行
  `docker compose up -d --no-deps api-1 api-2 nginx`，即回到本轮改动前的状态。
