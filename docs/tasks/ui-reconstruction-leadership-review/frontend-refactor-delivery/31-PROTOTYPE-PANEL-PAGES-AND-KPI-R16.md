## 2. 骨架改造（7 页）

原型这几页不属于三栏作战室，而是"六项指标 + 通栏面板（或两列网格）"。为保持画板概念一致，
新增画板变体 `.war-artboard-flow`（`apps/web/src/styles/war-artboard.css`）：

- 画板固定 `1440 × 742`，内容超出时在画板内部滚动；
- 六项指标绝对定位在画板顶部 73px（与原型一致）；
- 其余内容按原型的 180px 顶部内边距自上而下排列；
- 通栏面板 / 两列网格在画板内平分剩余高度，`panel-body.flush` 内工具栏与表头固定、表格区域独立滚动。

## 7. 已知问题（测试环境既有，本轮未修）

**`GET /api/messages/platform/channels` 返回 500**

- 现象：所有账号打开「消息渠道配置」都返回 `V3_INTERNAL_ERROR`，页面因此显示"渠道配置接口当前不可用"。
- 定位：接口把 `message.channel_accounts.cipher_text` 用当前 `MESSAGE_CHANNEL_CONFIG_ENCRYPTION_KEY` 解密，
  密文保存于 2026-09-07，而测试环境密钥在 2026-09-18 之后重新生成，导致 `aes-256-gcm` 认证失败。
  数据库记录与接口 SQL 本身都正常（已用 `psql` 直接验证）。
- 影响：仅影响渠道配置读取；投递记录、提醒规则、消息模板、任务模板全部正常。
- 处理建议（需授权，未执行）：
  1. 用原始企微/短信/SMTP 凭据重新保存一次通道配置，让密文用当前密钥重新加密；或
  2. 在接口层做兜底——解密失败时把该通道标记为"未就绪"而不是整表 500（需要重建 api 镜像）。
- 本轮页面已做降级：接口不可用时展示 4 类通道清单占位并明确提示，不出现空白页。
