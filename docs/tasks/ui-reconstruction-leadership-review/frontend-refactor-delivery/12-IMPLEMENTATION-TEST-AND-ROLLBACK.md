# 前端实施、测试与回退方案

## 1. 实施原则

- 先建公共能力，再迁移业务页面。
- 一个模块完成后立即测试和回归，不等待全量页面完成。
- 新页面和旧页面在同一迁移周期内只能有一套事实来源。
- 高风险动作先完成契约和原型，再替换正式页面。

## 2. 开发流程

每个模块执行：

```text
页面结构开发
→ 状态和权限接入
→ mock repository
→ 单元 / 组件测试
→ 本地浏览器测试
→ 开发修复
→ 回归测试
→ 测试环境核对
→ UAT
```

## 3. 测试分层

### 单元测试

- 状态映射。
- 权限判断。
- 字段格式化。
- 数据范围展示。
- 错误码转换。

### 组件测试

- 表格、筛选、表单、抽屉和弹窗。
- loading、empty、error、forbidden。
- 动作显示、禁用和二次确认。

### 浏览器测试

- 角色切换。
- 路由和菜单。
- 主业务链路。
- 页面状态恢复。
- 弹窗打开、关闭和提交。

### 视觉回归

- 1366、1440、1600、1920 四组宽度。
- 浏览器缩放 100% 和 125%。
- 超管、区域管理员和渠道用户。

## 4. 测试环境

测试环境：`http://10.9.86.66`。

只在用户授权的测试环境执行验证。不得对生产环境执行实验性操作。

测试环境确认内容：

- 登录和统一入口。
- 角色和菜单。
- 数据范围。
- 页面字段。
- 状态和动作。
- 与原型视觉差异。

## 5. 模块回退

| 模块       | 回退动作               | 数据影响           |
| ---------- | ---------------------- | ------------------ |
| 公共外壳   | 恢复旧资源或旧路由入口 | 不改业务数据       |
| 客户       | 关闭新入口，恢复旧页面 | 保留客户和报备事实 |
| 线索       | 关闭前端入口           | 不涉及真实线索数据 |
| 商机       | 恢复前端旧展示逻辑     | 不修改后端状态     |
| 报价       | 关闭新报价入口         | 保留报价和快照     |
| 订单       | 回退旧订单页面         | 保留审批和状态历史 |
| 渠道       | 关闭新档案入口         | 保留主档和成员关系 |
| 产品       | 关闭新价格入口         | 保留规则和版本     |
| 消息与组织 | 关闭 UI 新入口         | 保留原业务事实     |

## 6. 交付门禁

每个模块交付前必须满足：

- 类型检查通过。
- 单元和组件测试通过。
- 浏览器测试通过。
- 角色权限测试通过。
- 4 组分辨率截图通过。
- 无自动换行和横向页面溢出。
- 无控制台错误和缺失资源。
- 已知限制和回退步骤已记录。
