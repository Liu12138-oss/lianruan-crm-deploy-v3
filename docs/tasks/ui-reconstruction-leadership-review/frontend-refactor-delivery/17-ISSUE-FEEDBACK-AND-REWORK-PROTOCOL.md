# 问题反馈、测试验证与返工闭环

## 1. 目标

确保其他 Agent 发现问题后能够定位、复现、修复、回归和留下证据，而不是只提交一句“页面有问题”。

## 2. 问题等级

| 等级 | 定义                                         | 处理时限               |
| ---- | -------------------------------------------- | ---------------------- |
| P0   | 数据泄露、权限越界、关键页面不可用、状态错误 | 立即停止合并，当天修复 |
| P1   | 主流程受阻、字段错误、视觉严重错位、测试失败 | 当前迭代内修复         |
| P2   | 非主流程问题、局部视觉问题和文案不一致       | 排入当前或下一迭代     |
| P3   | 优化建议、不影响交付的一致性建议             | 记录后排期             |

## 3. 问题单格式

必须包含：

- 问题编号。
- 模块和任务 ID。
- 页面、路由和角色。
- 设备宽度、浏览器缩放。
- 前置数据和 mock 版本。
- 复现步骤。
- 期望结果。
- 实际结果。
- 控制台错误。
- 截图或录屏证据。
- 影响范围和严重等级。
- 建议处理方式。

使用 `templates/ISSUE-REPORT.md`。

## 4. 修复流程

```text
接收问题
→ 复现
→ 确认根因
→ 判断范围和回滚风险
→ 修复
→ 增加回归用例
→ 重跑单元 / 组件 / 浏览器测试
→ 更新截图证据
→ 提交返工记录
→ 复审
```

## 5. 返工闭环

返工记录必须关联原问题编号，并说明：

- 根因。
- 修改文件。
- 设计或文档是否同步更新。
- 新增或更新的测试。
- 回归范围。
- 未解决问题和风险。
- 最终验证结论。

使用 `templates/REWORK-RECORD.md`。

## 6. 不得关闭问题的情况

- 只在本地页面隐藏问题，服务端仍越权。
- 测试未复现但没有证据。
- 修改视觉但没有更新基线截图。
- 修复一个角色但未验证其他角色。
- 修改共享组件但未跑全量回归。

## 7. 最终反馈

每个迭代结束后汇总：

- 完成任务 ID。
- 修改范围。
- 自动化测试结果。
- 浏览器测试结果。
- 截图差异。
- 阻塞问题。
- 已知风险。
- 下一轮建议。
