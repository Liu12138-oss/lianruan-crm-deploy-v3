UI 重构方案

构建专业、统一、高效的业务协同体验

以联软 ESPP 产品的明亮科技蓝为品牌基准，结合企业级数据管理场景，统一桌面端与移动端视觉体系，并通过渐进迁移降低业务回归风险。

领导评审概念稿 · 2026 年 9 月

为什么要重构

这不是一次简单换色，而是统一设计体系与前端工程化能力。

01
◇

当前问题

  • 正式页面与工程化页面并存
  • 样式规则分散、视觉不统一
  • 超长脚本导致维护和迭代成本高
◎

重构目标

  • 建立联软品牌化设计体系
  • 统一表格、表单、详情和状态表达
  • 逐页迁入 Vue 3 工程化结构
✓

保持不变

  • 登录、角色、权限与数据范围
  • 既有业务字段、状态机与接口契约
  • 四个正式入口和设备分流规则
实施原则先确认设计系统和代表性页面，再分模块迁移；每个页面均保留可回退能力，不一次性整体切换。

ESPP 同源视觉体系

从现有优秀产品提取品牌语言，再适配 CRM 高密度业务场景。

02
◐

色彩策略

白色内容区和浅蓝页面背景为主，科技蓝用于主操作与选中态，绿色与金色用于业务状态，避免大面积深色带来的压迫感。

科技蓝#2F69ED
亮蓝#55BDF2

▦

界面策略

  • 左侧导航保持稳定，内容区采用清晰的信息层级
  • 列表页面统一为页头、筛选区、状态标签和数据表格
  • 详情优先使用抽屉，减少页面跳转和上下文丢失
  • 桌面端面向数据效率，移动端面向查询与关键动作
  • 采用 Ant Design Vue 的交互模式，并进行联软主题定制

建议实施路线

先试点、再固化、后迁移，确保视觉升级不影响业务连续性。

09
1基线冻结盘点页面、字段、权限、接口和关键流程
2设计系统确认品牌色、组件规范、布局和状态表达
3试点开发登录、工作台、渠道商、报备、订单
4分批迁移管理端、渠道端、移动端按模块切换
5灰度验收权限、业务、视觉、性能和回退验证
本次建议只确认设计方向和试点范围确认后再形成正式设计规范、迁移清单、任务拆分与排期；当前原型中的数据均为演示数据，不代表业务口径调整。
