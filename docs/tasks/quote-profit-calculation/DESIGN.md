# 微盾＋硬件报价收益核算落地设计

## 1. 目标与交付边界

本任务把现有 V3 报价功能中的“模块报价、硬件报价、维保/服务报价”转换为可审计的微盾＋硬件收益核算表。核算结果先作为报价详情中的实时预估，订单经过超管确认后生成不可覆盖的正式收益快照。

本期只支持微盾产品线及其配套硬件，明确不支持 XCAD，也不把收益数据暴露给渠道端、普通管理员、OpenAPI 或 MCP。

本设计是交给其他代理直接实施的执行基线。QPC-00 至 QPC-09 已按本设计完成本地开发与验证；生产迁移、生产配置、升级包、发布和历史回填尚未执行，必须另行取得明确授权。详细验证证据见 `docs/VERIFICATION-RECORD.md`。

## 2. 已确认业务口径

1. 只做“微盾＋硬件”，XCAD 不进入本核算域。
2. 区管、超管可以在报价详情查看实时收益预估；区管可以查看本人一个或多个正式绑定区域的数据，超管查看全部。
3. 区管可以填写质保年限、采购维保年限，但不能维护内部成本。
4. 超管在现有“产品目录 → 硬件管理”中维护版本化的硬件内部销售成本和年度质保/维保成本；页面入口合并，成本数据与对外报价数据分表保存。
5. 初始硬件成本按完整 Excel 导入。`LV-7050A` 年度质保成本尚未确定，命中时允许保存草稿，但不能冻结正式收益。
6. 现有报价的硬件选择需要补充同型号硬件正整数数量；旧格式 `hardwareIds` 继续兼容，旧数据按每个型号 1 台处理。
7. 首版不增加“大区负责人、营销总裁”审批流，继续复用现有订单审批状态机。
8. 默认质保年限为 3 年，默认采购维保年限为 0 年；用户填写后以报价级配置为准。
9. 采购维保成本只展示，不从“项目收益”中再次扣减，避免重复扣减。
10. 业务事实和初始成本以权威文件 `微盾+硬件+渠道XCAD收益核算表-2026-05-to+龙海.xlsx` 为准，SHA256 固定为 `236e3b588e169894509d1e1982e97b5e001ffbc742b5f4262b42ca2033a5e015`。

## 3. Excel 与系统计算公式

所有金额由服务端计算，前端只提交输入并展示结果。原始报价和成本金额使用 PostgreSQL `numeric(18,2)`；百分比计算的中间值和结果使用 `numeric(24,6)`，不得在公式中间提前按分取整。接口展示时再按人民币分四舍五入，计算快照保留 6 位小数，禁止在累计过程中直接使用 JavaScript 浮点数。

### 3.1 输入定义

- 软件折后价：报价预估阶段取微盾软件销售明细合计；正式冻结阶段以订单最终总额为合同口径，按“订单总额 - 硬件销售明细 - 服务销售明细”反算软件折后价。当前订单总价调价没有分摊字段，V1 明确把总额差异归入软件折后价，不改变硬件和服务明细；反算结果小于 0 时标记不完整，不能冻结。
- 软件公开报价：同一软件项按报价时数量、区域覆盖和公开阶梯规则计算出的“未应用渠道级价格比例/渠道专属价”的原价，不使用渠道折后价；必须在计算输入快照中固化目录版本、命中阶梯、单价、数量和金额。
- 硬件报价：报价明细中硬件销售单价乘以数量。
- 维保及服务报价：报价明细中明确归类为服务的项目金额；标准质保赠送项金额为 0，不计入服务合同额。
- 硬件内部成本：每个硬件型号的内部销售成本乘以数量。
- 硬件年度质保/维保成本：每个硬件型号的同一年度成本基准乘以数量，分别供质保公式和采购维保公式使用；成本规则缺失时为不完整。
- 质保年限：整数，V1 允许 1 至 20，默认 3。
- 采购维保年限：整数，V1 允许 0 至 20，默认 0。

### 3.2 公式

```text
合同额（产品） = 软件折后价 + 硬件报价
合同额（服务） = 维保及服务报价
硬件内部成本 = Σ（硬件型号数量 × 内部销售成本）
产品税费 =（合同额（产品）- 硬件内部成本）× 5%
服务税费 = 合同额（服务）× 7%
质保成本 =（硬件年度质保成本合计 + 软件公开报价 × 0.5%）×（质保年限 - 1）
采购维保成本 =（硬件年度维保成本合计 + 软件公开报价 × 0.5%）× 采购维保年限
合同有效收入 =（合同额（产品）- 硬件内部成本）× 95% + 合同额（服务）× 93%
项目收益 = 合同有效收入 - 质保成本
```

说明：

- 产品税费、服务税费必须保存明细，便于与 Excel 对账；“合同有效收入”按 Excel 公式计算，不再额外减税费，避免将税费重复扣除。
- 采购维保成本保存并展示，但不从项目收益再次扣除。
- 当质保年限为 1 年时，质保成本为 0；当采购维保年限为 0 年时，采购维保成本为 0。
- 不对公式结果静默取绝对值、归零或封顶。当产品合同额低于硬件内部成本时，产品税费、合同有效收入或项目收益可以为负，页面应按实际结果展示风险提示。

### 3.3 手工验算基准

以下数据用于锁定公式，不代表真实客户报价：

```text
软件公开报价 = 100000.00
软件折后价 = 80000.00
LV-7050 数量 = 2
硬件报价 = 40000.00
单台内部销售成本 = 13000.00
单台年度质保/维保成本 = 500.00
服务合同额 = 12000.00
质保年限 = 3
采购维保年限 = 1
```

预期结果：

```text
产品合同额 = 120000.00
硬件内部成本 = 26000.00
产品税费 = 4700.00
服务税费 = 840.00
质保成本 = 3000.00
采购维保成本 = 1500.00
合同有效收入 = 100460.00
项目收益 = 97460.00
```

其中采购维保成本 1500.00 只展示，不从项目收益 97460.00 中再次扣除。

### 3.4 产品和服务归类

归类必须优先使用目录中的结构化字段，不得只依赖名称正则：

1. `catalog.hardware_products` 明确归类为硬件。
2. `catalog.product_features` 通过所属 `catalog.product_categories.product_type_code` 归类为软件或服务。
3. 套餐按 `catalog.package_items` 展开后分别归类；本期只允许展开为微盾软件和配套硬件。
4. 报价明细中的手工项目必须携带明确的 `itemTypeCode`（`software`、`hardware`、`service`）；没有明确归类的项目标记为“核算不完整”，不得用名称猜测。
5. “标准质保服务（赠送1年）”是系统赠送服务项，固定金额 0，不计入服务合同额；它不能替代用户填写的质保年限。
6. 产品范围采用结构化产品线标识。为 `catalog.product_categories` 和 `catalog.hardware_products` 增加 `profit_scope_code`（`weidun`、`xcad`、`unclassified`），运行时只接受 `weidun`；XCAD 或未分类产品不得进入微盾收益核算。首个启用迁移需按稳定分类编码/硬件型号补齐现有微盾、XCAD 目录，禁止运行时按名称猜测。
7. 同一报价同时包含微盾和 XCAD/未分类软件时，整张报价标记 `not_applicable`，不能只计算其中一部分后给出误导性收益；纯硬件报价只在所有硬件均有明确目录引用时允许计算。

## 4. 业务流程与状态机

```text
报价保存/编辑并固化价格依据
      ↓
区管/超管打开报价详情 → 服务端只读实时预估 → 查看缺失规则或金额明细
      ↓
区管/超管保存年限 → 生成或更新收益草稿
      ↓
订单沿用既有审批状态机
      ↓
超管确认订单（产生 crm.order.confirmed 事件）
      ↓
ops.outbox_events 幂等投递收益冻结请求
      ↓
Worker 重新读取订单、报价、成本规则并冻结正式快照
      ├─规则齐全：status_code=frozen
      └─规则缺失：status_code=incomplete，订单主链保持已确认
```

收益记录状态：

| 状态             | 含义                                    | 是否允许编辑                 | 是否允许作为正式收益 |
| ---------------- | --------------------------------------- | ---------------------------- | -------------------- |
| `draft`          | 已生成草稿，输入尚未全部确认            | 允许区管修改年限，服务端重算 | 否                   |
| `incomplete`     | 缺少成本规则、产品公开价或明确归类      | 允许补齐后重算               | 否                   |
| `frozen`         | 订单超管确认后固化的正式快照            | 不允许覆盖                   | 是                   |
| `void`           | 因报价重新修订而废弃的旧草稿/未冻结版本 | 不允许                       | 否                   |
| `not_applicable` | 非微盾范围报价，仅供内部诊断            | 不允许                       | 否                   |

`estimated` 仅是接口响应的展示状态，不写入数据库：当没有草稿或草稿的 `quote_row_version` 已落后于当前报价时，GET 接口只读计算实时预估。只有保存参数、主动重算或冻结任务才写收益表，避免收益附属功能阻断报价保存。

冻结规则：

- 冻结输入必须来自服务端当前订单和报价明细，不能信任前端传入的总额、单价或收益。
- 正式冻结以订单 `total_amount` 为最终合同总额，硬件和服务金额取当前订单明细，软件折后价取剩余金额；三类金额相加必须与订单总额一致。这样可兼容现有“只调整订单总额”的流程，又不擅自改写硬件、服务销售价。
- 实时预估和草稿按当前时间选择成本规则；正式冻结按订单进入 `confirmed` 的事件时间选择有效成本规则，不能因 Worker 延迟或之后改价改变正式结果。
- 冻结时只从最新草稿复制质保年限和采购维保年限，不复制草稿金额；没有草稿时使用 3 年和 0 年默认值，然后重新读取全部金额和成本。
- `frozen` 记录只允许查询，永不标记 `void`。订单发生受控修订后按新的 `approval_round`/`revision_no` 产生新计算版本；新一轮超管确认后冻结新快照，上一轮正式快照作为历史保留。
- 缺失成本规则时不阻断订单状态更新。Worker 记录 `incomplete` 并写审计；超管补齐规则后可以手动重算冻结，或由成本规则变更事件触发重试。
- 成本规则补齐后自动重试受影响的已确认但未冻结订单；已冻结快照不参与重算。V1 成本规则只允许立即或过去时间生效，不开放未来生效调度。
- 收益冻结失败不得回滚订单确认事务；收益属于订单确认后的异步附属事实。

## 5. 数据模型与迁移要求

### 5.1 硬件收益成本规则

成本维护采用“页面合并、数据分离”原则：操作上不新增独立的成本管理菜单，直接在现有硬件管理列表的每个型号上增加“成本配置”操作；数据上不把内部成本写入 `catalog.hardware_products.list_price` 或对外硬件接口返回对象，而是写入下方独立的版本化规则表。这样超管可以在维护硬件型号时一并维护成本，渠道报价仍只能读取对外销售价格。

新增 `catalog.hardware_profit_cost_rules`：

| 字段                               | 类型/约束                | 说明                                            |
| ---------------------------------- | ------------------------ | ----------------------------------------------- |
| `id`                               | `uuid` 主键              | 规则编号                                        |
| `hardware_product_id`              | `uuid` 外键              | 关联 `catalog.hardware_products`                |
| `internal_sale_cost`               | `numeric(18,2)` 非负     | 内部销售成本                                    |
| `annual_warranty_maintenance_cost` | `numeric(18,2)` 可空非负 | Excel 中同一年度质保/维保成本基准，空值表示未知 |
| `version_no`                       | `integer` 正数           | 同型号规则版本                                  |
| `effective_from`                   | `timestamptz`            | 生效时间                                        |
| `effective_to`                     | `timestamptz` 可空       | 失效时间，必须大于生效时间                      |
| `status_code`                      | `active/disabled`        | 规则状态                                        |
| `source_code`                      | `excel/manual`           | 初始导入或超管维护                              |
| `source_reference`                 | `text`                   | 文件名、工作表、行号或维护说明                  |
| `created_by_user_id`               | `uuid`                   | 创建人                                          |
| `created_at`                       | `timestamptz`            | 创建时间                                        |
| `row_version`                      | `bigint`                 | 乐观锁版本                                      |

约束与索引：

- 同一型号同一生效区间只能有一条有效规则；新增版本先关闭旧版本，再插入新版本，历史行禁止覆盖。
- 查询规则必须按“计算时点 + `status_code=active` + 生效区间”取唯一版本。
- `LV-7050A` 的 `annual_warranty_maintenance_cost` 初始为空，不能用 0 代替。
- 超管成本规则写入、修改、停用均记录前后值、来源和审计日志；区管接口返回 403。

### 5.2 产品收益范围

为 `catalog.product_categories` 和 `catalog.hardware_products` 增加：

```text
profit_scope_code text NOT NULL DEFAULT 'unclassified'
CHECK (profit_scope_code IN ('weidun','xcad','unclassified'))
```

- 产品分类只按稳定 `category_code`/`v2_source_id` 映射，硬件只按稳定 `hardware_code`/`v2_source_id` 映射，禁止用名称模糊匹配。
- 新增产品分类或硬件时默认 `unclassified`，未经超管明确归类不能进入收益核算。
- 套餐展开后只要包含 `xcad` 或 `unclassified` 软件项，整张报价不适用本期收益核算。
- 本期不新增产品范围维护页面；映射作为上线前受控基础数据，后续如需开放维护必须另行评审。

### 5.3 报价明细补充

在 `crm.quote_items` 增加以下兼容字段：

- `item_type_code text NOT NULL DEFAULT 'unknown' CHECK (item_type_code IN ('software','hardware','service','unknown'))`：服务端根据目录结构化归类；手工项由请求明确指定。
- `extra_json jsonb NOT NULL DEFAULT '{}'::jsonb`：保存公开价来源、套餐展开关系和兼容标记。
- 增加检查：`product_ref_type <> 'hardware' OR quantity = trunc(quantity)`，硬件数量只能为正整数。

现有 `quantity` 保持 `numeric(18,4)`，软件点数和服务月数不受影响。新请求使用：

```json
{
  "hardwareItems": [{ "productId": "硬件产品编号", "quantity": 2 }]
}
```

旧请求中的 `hardwareIds: ["型号A", "型号B"]` 转换为每项数量 1。相同型号在同一次请求中不得重复，重复返回中文参数错误，避免数量含义不清。

#### 报价调整边界

- 报价价格规则不变：软件阶梯价、区域价格覆盖、渠道价格比例、渠道专属价、服务报价和优惠计算仍沿用现有规则。
- 报价硬件选择、请求结构和明细持久化必须调整：`string[]` 不能表达同一型号多台，现有页面和接口必须改为 `hardwareItems: [{productId, quantity}]`。
- 新报价、编辑报价、快速报价、套餐加配、订单明细、正式报价 PDF 和收益输入必须使用同一份规范化硬件数量。套餐自带硬件与手工加配同型号时先合并数量，再参与金额、内部成本和年度质保/维保成本计算，不能生成两条同型号明细。
- 收益是报价和订单的只读派生事实，不能让收益功能改写报价价格、订单审批或硬件报价单价。收益功能可以要求报价补齐数量和价格依据，但不能用报价总额百分比代替结构化硬件成本。
- 同一型号两台已验证为真实业务场景。`quantity=2` 时，硬件报价、硬件内部成本以及年度质保/维保成本都必须按 2 倍计算；不得只按型号命中一次处理。

| `product_tax_amount`                        | `numeric(24,6)`                               | 产品税费                                                                  |
| `service_tax_amount`                        | `numeric(24,6)`                               | 服务税费                                                                  |
| `warranty_cost`                             | `numeric(24,6)`                               | 质保成本                                                                  |
| `procurement_maintenance_cost`              | `numeric(24,6)`                               | 采购维保成本，仅展示                                                      |
| `effective_contract_income`                 | `numeric(24,6)`                               | 合同有效收入                                                              |
| `project_profit`                            | `numeric(24,6)`                               | 项目收益，可为负                                                          |
| `missing_rules_json`                        | `jsonb`                                       | 缺失规则和不完整原因                                                      |
| `input_snapshot_json`                       | `jsonb`                                       | 报价、公开价、成本规则、区域和年限输入快照                                |
| `calculation_snapshot_json`                 | `jsonb`                                       | 公式中间值和最终结果                                                      |
| `input_hash`                                | `text`                                        | 输入指纹，幂等与漂移检测                                                  |
| `created_by_user_id` / `updated_by_user_id` | `uuid`                                        | 操作人                                                                    |
| `frozen_by_user_id`                         | `uuid` 可空                                   | 冻结人；自动冻结时可为系统账号                                            |
| `frozen_at`                                 | `timestamptz` 可空                            | 冻结时间                                                                  |
| `created_at` / `updated_at`                 | `timestamptz`                                 | 时间                                                                      |
| `row_version`                               | `bigint`                                      | 乐观锁版本                                                                |

建议约束：

- 同一 `quote_id` 只能有一条当前草稿/不完整记录；历史版本保留。同一订单、审批轮次和公式版本只能有一条冻结记录。
- 纯计算函数的 `complete` 只表示本次计算完整；持久化时映射为 `draft`。`estimated` 是接口响应态，`complete` 和 `estimated` 均不得写入数据库状态列。
- 金额列允许在 `incomplete`、`not_applicable` 时为空：缺少某项输入时，所有依赖该输入的结果保存为 `NULL`，接口返回 `null`，页面显示“--”，严禁用 0 冒充已计算结果。
- `status_code='frozen'` 时全部公式输入和结果金额必须非空，并且必须有 `input_snapshot_json`、`calculation_snapshot_json`、`formula_version`、`frozen_at` 和 `input_hash`。
- 数据库触发器禁止对 `frozen` 行执行金额、输入、年限、状态和规则来源更新；如需重新报价必须新建审批轮次和计算版本。
- `region_id` 为空时只能标记不完整，区管不可通过名称兜底访问。

### 5.5 区域归属

现有报价表没有正式 `region_id` 时，迁移中为 `crm.quotes` 增加可空 `region_id` 外键并按以下顺序补齐：

1. 已有正式商机 `crm.opportunities.region_id`；
2. 绑定渠道商的正式 `channel.partners.region_id`；
3. 两者冲突或无法唯一确定时保持空值并标记收益不完整，不按名称或固定优先级猜测。

新建或编辑报价必须写入正式区域编号。区域名称只用于展示，禁止作为权限判断和越权兜底依据。

区管收益权限采用现有 `iam.data_scope_bindings` 的角色级正式区域绑定，可以绑定一个或多个 `scope_type='region'` 的范围。运行时先确认账号启用状态和有效角色，再合并有效区域绑定；存在正式区域绑定集合时以绑定集合为准，绑定为空时才兼容读取 `iam.users.region_id`。报价区域命中绑定集合中任一区域即可访问，否则返回保护性 404。若商机区域与渠道区域冲突，创建或编辑报价必须拒绝并提示用户处理正式区域，不能自动选择。

## 6. 服务端接口契约

建议新建独立的 `quote-profit-routes.ts` 与 `quote-profit-store.ts`，在 `create-app.ts` 挂载，避免继续膨胀 `business-routes.ts` 和 `business-store.ts`。

### 6.1 收益核算接口

接口金额和状态必须区分计算层与持久化层：纯计算返回 `complete/incomplete/not_applicable`，持久化状态使用 `draft/incomplete/frozen/void/not_applicable`，接口展示态可使用 `estimated`。计算完整且未保存草稿时响应 `estimated`，保存成功后响应 `draft`。

#### `GET /api/quotes/:quoteId/profit-calculation`

- 仅 `superadmin`、`region_manager` 可访问。
- 每次请求实时复核数据库中的启用角色，并从 `iam.data_scope_bindings` 计算本人一个或多个正式区域。
- 超管返回当前草稿、最新不完整记录或冻结快照及成本明细。
- 区管只允许访问 `crm.quotes.region_id` 命中本人正式区域绑定集合的报价；无权对象返回保护性 404，不泄露对象存在性。
- 渠道端、普通管理员等已登录但角色不允许的调用返回 403；区管跨区域对象返回保护性 404。OpenAPI、MCP 不注册该能力，不能通过前端隐藏代替后端防护。

返回结构至少包含：

```json
{
  "quoteId": "...",
  "orderId": "...",
  "scopeCode": "weidun",
  "statusCode": "draft",
  "statusName": "草稿",
  "warrantyYears": 3,
  "procurementMaintenanceYears": 0,
  "summary": {
    "productContractAmount": "0.00",
    "serviceContractAmount": "0.00",
    "effectiveContractIncome": "0.00",
    "projectProfit": "0.00"
  },
  "details": {
    "softwareDiscountedAmount": "0.00",
    "softwarePublicAmount": "0.00",
    "hardwareQuoteAmount": "0.00",
    "hardwareInternalCost": "0.00",
    "productTaxAmount": "0.00",
    "serviceTaxAmount": "0.00",
    "warrantyCost": "0.00",
    "procurementMaintenanceCost": "0.00"
  },
  "hardwareLines": [],
  "missingRules": []
}
```

上例表示完整的零金额草稿。对于不完整结果，受缺失输入影响的字段必须返回 `null`，不能返回字符串 `"0.00"`。

#### `PUT /api/quotes/:quoteId/profit-calculation/draft`

- 仅区管、超管；区管必须拥有报价正式区域绑定的一个或多个区域。
- 请求只允许提交 `warrantyYears`、`procurementMaintenanceYears` 及可选 `expectedRowVersion`。
- 服务端锁定报价读取明细和成本规则，校验输入范围后计算并保存新草稿版本。
- 不接受前端金额字段；传入金额字段直接报参数错误。
- 已冻结记录不能覆盖，返回 `V3_QUOTE_PROFIT_FROZEN_READ_ONLY`。

#### `POST /api/quotes/:quoteId/profit-calculation/recalculate`

- 仅区管、超管；重新从当前报价、目录、价格规则和硬件成本规则读取数据。
- 若当前订单审批轮次已有 `frozen`，只返回正式快照，不能再生成同轮草稿。只有订单进入新的受控修订/审批轮次后，才允许产生新的草稿并等待下一次超管确认。
- 可选请求头 `Idempotency-Key`；相同报价、相同输入指纹只返回已有结果。
- 对已确认但仍为 `incomplete` 的订单，超管重算完整后可重新投递专用冻结事件；区管只能更新草稿/不完整记录，永远不能投递冻结事件。

#### `POST /api/quotes/:quoteId/profit-calculation/freeze`

- 仅超管；报价必须已转订单且订单处于 `confirmed`、`processing`、`shipped` 或 `completed`，并且当前审批轮次没有正式冻结记录。
- 服务端重新计算并校验所有输入，完整时写入幂等冻结请求事件；缺失输入返回 `V3_QUOTE_PROFIT_INCOMPLETE`，不创建伪造快照。
- 该接口只负责受控投递冻结请求，实际冻结仍由 Worker 完成；重复调用返回已有事件或正式快照。

#### `GET /api/quote-profit/hardware-cost-rules`

- 仅超管；支持型号、状态、生效时间筛选。
- 返回当前有效版本及历史版本摘要，不返回给区管和其他角色。

#### `POST /api/quote-profit/hardware-cost-rules`

- 仅超管；新建型号规则版本，不允许覆盖历史行。
- 必填 `hardwareProductId`、`internalSaleCost`；年度质保/维保成本可空但会影响冻结资格。
- 必填来源说明；导入 Excel 时来源写文件名、工作表和行号。
- 成功后写 `audit.audit_logs`，并投递成本规则变更事件，供不完整确认订单重试。

### 6.2 订单确认事件

在现有订单状态机从 `pending_superadmin_confirm` 进入 `confirmed` 的同一事务中，直接新增一条专用收益冻结请求事件 `crm.quote.profit.freeze.requested`，不由前端另行投递，也不要求再消费 `crm.order.confirmed` 做二次转换。载荷至少包括：

```json
{
  "orderId": "...",
  "quoteId": "...",
  "orderRowVersion": 12,
  "approvalRound": 1,
  "orderRevisionNo": 0,
  "confirmedAt": "2026-09-15T10:00:00+08:00",
  "eventCode": "profit_freeze_requested",
  "formulaVersion": "weidun-v1"
}
```

事件消费必须使用 `ops.outbox_events` 的数据库租约和唯一幂等键。Worker 只写收益表和审计表，不回写订单状态；失败可重试，超过重试阈值进入失败告警，但不得撤销已确认订单。首版并入现有主 Worker 生命周期，通过 `QUOTE_PROFIT_WORKER_ENABLED` 和 `QUOTE_PROFIT_EVENT_CUTOVER_AT` 灰度启用，不新增外部队列依赖。

## 7. 权限、数据范围与审计

### 7.1 角色规则

- `superadmin`：全部微盾收益、成本规则和冻结操作。
- `region_manager`：只读查看和填写年限，只能访问本人一个或多个正式区域绑定内的报价；不能维护成本规则，不能替他区冻结。
- `admin`：正式绑定区域的账号按历史区管别名兼容；无正式区域绑定的 `admin` 不授予收益权限。后端必须同时复核有效区域绑定，不能因页面展示角色为 `admin` 就无条件放行。
- `partner_admin`、`staff`：默认不显示收益接口和页面，不授予收益权限。
- 会话中的角色摘要只用于菜单初始显示，后端每次从 `iam.users`、`iam.user_roles`、`iam.roles` 复核有效账号和角色；角色查询异常返回 503，禁止失效开放。

### 7.2 审计动作

统一写入 `audit.audit_logs`，模块建议为 `quote_profit`，动作至少包括：

- `draft_calculated`：生成/更新草稿；
- `recalculated`：手动或规则变更重算；
- `freeze_requested`：投递冻结事件；
- `frozen`：正式快照冻结；
- `freeze_incomplete`：因缺失规则未冻结；
- `cost_rule_created`、`cost_rule_disabled`：成本规则维护；
- `access_denied`：收益越权访问。

审计前后值只记录必要金额、版本、缺失规则和操作者，禁止写入渠道端不应看到的敏感凭据。

## 8. 管理端展示方案

首版直接扩展 `apps/web/public/admin-app.js` 的报价详情，不新增独立收益审批页。

### 8.1 报价详情“内部收益核算”区块

仅区管和超管渲染，进入详情后调用收益接口：

1. 状态条：实时预估、草稿、核算不完整、已冻结；显示计算时间、公式版本和报价行版本。
2. 基本信息：报价编号、订单编号、渠道商、客户、正式区域，只读。
3. 参数区：质保年限、采购维保年限。区管和超管可编辑草稿；已冻结全部只读。
4. 汇总卡：产品合同额、服务合同额、合同有效收入、项目收益。
5. 核算明细表：软件折后价、软件公开报价、硬件报价、硬件内部成本、产品税费、服务税费、质保成本、采购维保成本。
6. 硬件成本明细：型号、数量、单台内部销售成本、内部成本小计、单台年度质保/维保成本、年度成本小计。计算快照内的质保与采购维保年度汇总在 V1 中使用该同一基准。
7. 缺失规则提示：使用中文列出“型号、缺少字段、影响结果、处理动作”。`LV-7050A` 明确显示“年度质保成本未配置，允许保存草稿，不允许正式冻结”。
8. 超管在现有“产品目录 → 硬件管理”中使用每个型号的“成本配置”弹窗维护版本、查看历史；硬件卡片显示“成本完整/缺少年度成本/未配置”状态，列表支持只看缺失成本。不新增独立成本菜单，不提供直接编辑历史行。年度“质保/维保成本”V1 使用权威 Excel 中的单一字段，同时供质保和采购维保公式使用；如后续要求拆分，必须另行变更公式和数据模型。Excel 初始数据由受控迁移导入，不在首版页面提供批量导入。区管可以看到硬件产品和对外报价，但不显示成本状态、成本金额和“成本配置”操作，也不能读取成本规则接口。
9. 已冻结记录增加“正式快照”标识、冻结人、冻结时间和输入指纹，不提供编辑按钮。

### 8.2 交互与异常

- 收益接口加载失败只影响收益区块，报价详情和订单主链仍可用；页面显示“收益暂时无法读取”，不伪造 0 元。
- 保存年限前做整数和范围校验，接口再次校验。
- 非微盾报价不显示收益区块；接口不返回 XCAD 的任何金额。
- 首版不增加导出、打印或渠道端收益列；如后续要导出，必须单独评审脱敏和权限。

## 10. 兼容、回退与风险控制

- 旧报价继续接受 `hardwareIds`；服务端规范化为数量 1，并在输入快照中记录 `legacyHardwareIds=true`。
- 既有报价、订单、审批、OA、企微和渠道端接口不改语义；收益事件失败不改变订单状态。
- 不新增 V2 路由，不把收益字段加入 OpenAPI 或 MCP 只读白名单。
- 价格、公开报价、成本规则必须由服务端重算；前端传入的 `total`、`lineAmount`、`projectProfit` 不能作为可信输入。
- 公开价历史缺失、产品范围未标记、区域为空、服务归类未知、硬件成本为空，均进入 `incomplete`，不能以 0 代替。
- 主要回退路径：先停止收益 Worker，再回退 API/前端镜像；若已执行迁移，先执行本任务回退 SQL，保留报价、订单和原有审批表。未冻结收益记录可标记 `void`；已冻结快照和审计记录不得删除。

## 11. 验收门禁

1. 给定 Excel 样例，服务端计算结果与 Excel 逐项一致，包含 5%、7%、0.5%、95%、93% 和年限公式。
2. 只选择硬件、只选择软件、同时选择软件硬件、含服务、含套餐展开、含未知成本规则均有明确结果。
3. `LV-7050A` 缺年度质保成本时可保存草稿，冻结接口明确拒绝并返回中文原因。
4. 同型号硬件数量只能为正整数；旧 `hardwareIds` 数据按 1 台兼容。
5. 超管可看全部、维护成本和冻结；区管只能看正式绑定区域、只能改年限；其他角色和渠道端无法获取收益金额。
6. 区域名称变化、会话角色摘要过期或区域为空时，后端仍不能越权。
7. 同一订单重复确认、Worker 重试、并发冻结只产生一个正式快照，且冻结后数据不可覆盖。
8. 收益冻结失败或不完整不回滚订单确认，订单状态和审批待办回归通过。
9. 页面收益区块、缺失提示、冻结只读状态以及嵌入硬件管理的“成本配置”操作符合权限；接口异常不影响报价详情主页面。
10. 通过 API/Worker/前端类型检查、单元测试、集成测试、迁移检查、`git diff --check` 和升级包等价自检。
