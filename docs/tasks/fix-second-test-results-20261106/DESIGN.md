# 第二轮测试 17 项失败修复设计

## 问题陈述

第二轮测试共 17 条未通过：`AUD-07、AUTH-06、AUTH-08、ORD-27、APR-09、CHN-18、CHN-19、AUD-12、SEC-08、SUP-01、SUP-02、STAFF-09、STAFF-10、STAFF-22、XROLE-06、XROLE-17、UNAUTH-07`。问题集中在会话一致性、订单调价留痕、审批定位、渠道统计与筛选、审计可检索性、组织维护、商机跟进附件与阶段状态机、成员申请及账号停用入口。

## 方案

1. 会话与账号：统一 401 出口；完善登录限流与审计；接入自助改密；停用账号登录提示和旧会话校验保持同源。
2. 订单与审批：调价写前后金额、原因、操作人、时间和调价记录；客户端提交 `rowVersion`；审批记录编号与业务编号都定位到同一对象。
3. 渠道：摘要统一有效口径并去重客户；报价排除草稿；增加区域、等级、关键词组合筛选。
4. 审计：动作列完整展示；详情展示业务编号、操作人、时间、前后值；关键词检索覆盖业务编号和前后值。
5. 组织与成员：部门编辑、启停、下级新建、引用校验；渠道管理员成员申请入口与审批链；用户列表提供停用/启用。
6. 商机：跟进附件落库并可下载；阶段推进增加服务端状态机校验。
7. 加载态：KPI 未加载完成显示“—”，避免刷新短暂显示伪 0。

## 兼容性与回归

- 仅修改 V3 `apps/web`、`apps/api`、`apps/worker`，不改老 UI/V2 页面。
- 保留既有接口路径和响应结构，新增字段为向后兼容字段。
- 关键回归：登录/退出、客户报备、商机创建与跟进、报价转订单、订单三级审批、渠道档案、组织账号、审计分页。
