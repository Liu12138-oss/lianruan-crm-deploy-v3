还原脚本的默认保护（已读源码确认）：

1. 默认先自动创建"还原前备份"（类型 `restore-pre`），除非显式传 `--skip-pre-restore-backup`；

## 五、风险与注意事项

1. 备份目录含生产密钥（数据库口令、会话密钥、渠道加密密钥），权限已限制为 700（仅 root 可读），请勿外发或降低权限。
2. 镜像对账状态为"存在不一致"：Compose 文件声明 api/worker 使用 `...kb027` 标签，但实际运行容器仍为 `...quotefix1` 镜像（KB-20261012-027 升级仅替换 nginx，未重建 api/worker）。属已知状态；备份已记录实际镜像并生成 `metadata/actual-images.override.yml`，同机还原直接启动原容器，跨机还原按实际镜像启动，不需要拉取镜像。
3. 备份与系统同盘（`/home` 与 `/` 同属本机磁盘）。如需防整机故障，建议另行复制一份离线副本到其他介质。
4. 历史备份累计 26 个目录共 19G（最近一次此前为 2026-09-23），`/home` 剩余 188G 充足；如无保留价值可定期清理旧备份。
5. 备份过程中发现一个既有脚本的自愈行为（非本次新问题）：恢复阶段 nginx 排在同批第一个启动时，会因 api-1 尚未就绪产生一次 `[emerg] host not found in upstream "api-1:3100"`，Docker 重启策略在约 0.5 秒后自动拉起并成功。实际影响可忽略（nginx 已 healthy，服务核验正常），留档备查。
