# 泛微身份并发版本号规范化

## 目标

确保泛微 OA 身份候选的确认、修改、驳回，以及正式身份停用等操作始终提交数字类型的并发版本号；同时让账号管理创建的内部管理员自动进入组织架构，并在两个内部用户创建入口安全维护外部身份。

## 实施范围

- `apps/api/src/org-store.ts`：泛微身份详情查询的行版本类型规范化。
- `apps/web/public/admin-app.js`：正式管理员页面写入前数字化行版本。
- 对应真实 PostgreSQL 回归测试和正式页面静态断言。
- `apps/api/src/v2-compat-routes.ts`：账号管理创建内部管理员时同步建立组织任职；创建内部用户时写入泛微待核验候选或有效企业微信身份。
- `apps/web/public/admin-app.js`：账号管理与组织成员新建用户入口增加外部身份字段和前置校验。

## 不做事项

- 不降低后端的版本校验要求。
- 不自动确认泛微候选。
- 不改变既有身份归属、审批、订单或外部调用。
- 不向渠道商员工创建入口增加外部身份字段。
- 不自动确认泛微候选，也不覆盖已被其他账号占用的泛微或企业微信身份。
