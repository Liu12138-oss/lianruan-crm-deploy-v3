# 决策记录：泛微身份并发版本号规范化

## 已确认事实

- 泛微身份候选记录的 `row_version` 是 PostgreSQL `bigint`。
- Node PostgreSQL 驱动默认将 `bigint` 读取为字符串。
- 正式管理员页面会把候选记录的 `rowVersion` 回传；后端为并发控制要求该字段是整数，导致确认、修改和驳回出现“rowVersion必须为整数”。

## 采用方案

- 查询泛微正式身份、候选身份和企业微信身份时，将 `row_version` 显式转换为整数返回。
- 正式管理员页面提交候选确认、修改和驳回时再显式转换一次，兼容旧缓存或历史接口响应。
- 保持后端写入接口的整数校验，不放宽并发控制规则。

## 数据与回退

- 不修改候选、正式身份、用户或业务数据。
- 不新增数据库迁移。
- 回退只需回退应用代码版本。

## 新建内部用户外部身份与组织归集

- 账号管理与组织成员两个入口仅服务联软内部人员；渠道商员工不纳入本次改动。
- 泛微 OA userid 必须同时带泛微姓名或登录名，创建后只形成待核验候选；管理员确认前不能作为 OA 流程发起人。
- 企业微信 userid 通过有效映射唯一性校验后直接生效；发生冲突时整体回滚创建，不覆盖既有映射。
- 账号管理新建超管或区管时在同一事务内建立组织任职。区管按 `iam.users.region_id` 归入对应区域组织；组织根节点缺失时创建失败并回滚，避免账号已创建但组织未同步。
