# 决策日志

## 2026-09-04

### 已确认

- 用户要求优化全量备份，之后由用户把脚本或文件上传到生产执行。
- 生产无国际网络，因此备份和恢复不得依赖 Docker Hub 或其他外网镜像仓库。
- 生产当前 API/Nginx 与 Worker 版本标签不一致，不能把 Worker 强行改成 API 标签。
- 本轮只修改本地 V3 备份脚本与配套说明、测试，不操作生产。

### 采用方案

以运行容器实际镜像为恢复事实来源；备份格式升级为 v2，写入容器快照和实际镜像覆盖文件。原机优先启动原容器，跨机器使用 `--pull never`，并按备份时运行状态启动服务。

### 否决方案

- 继续使用 `docker compose up`：会重新解析错误标签，在无外网生产触发拉取。
- 给旧 Worker 镜像追加新标签：会掩盖版本不一致，无法保证镜像内容与标签语义一致。
- 调用 `start.sh` 完成还原：会读取 `config/deploy.env`，在生产配置冲突时可能重建错误版本容器。

### 待生产执行时核对

- 上传脚本的 SHA-256 与本地文件一致。
- 备份目录完整生成 `BACKUP_INFO`、`SHA256SUMS`、`docker-images.tar`、容器快照和实际镜像覆盖文件。
- `BACKUP_INFO` 中的镜像对账状态与生产实际情况一致；若为“存在不一致”，按实际镜像恢复，不做手工改标签。
