# 区管正式区域绑定一致性修复设计

## 问题

区管账号的扩展信息可能保存了区域名称，但 `iam.users.region_id` 为空。业务列表查询允许使用区域名称兜底，因此账号可以查看区域业务；订单确认和调价使用正式区域编号严格校验，导致出现“看得到但不能确认”。

## 目标

1. 区管账号创建或编辑时，根据区域名称精确解析并写入 `iam.users.region_id`。
2. 超级管理员不绑定区域；普通渠道账号不改变现有行为。
3. 对已有启用的区域管理员，仅在区域名称与唯一有效区域精确匹配时补齐正式区域编号，无法唯一匹配时保持不变并可审计。
4. 保持订单跨区域确认拒绝规则不变。

## 方案与边界

- 只修改 V3 的 V2 兼容账号保存入口及新增增量迁移。
- 区域匹配限定 `org.regions.status_code='active'`、`region_level='region'` 和精确名称。
- 创建或编辑区域管理员时，区域名称缺失或无法唯一匹配直接返回中文错误，不写入半成品账号。
- 编辑未提交区域字段时沿用已有正式区域或已有展示区域；若展示区域明确为空，清空正式区域。
- 不放宽 `校验订单所属区域区管`，不改变订单状态机、渠道商、商机和报价权限。

## 验收

- 新建和编辑区域管理员后，`iam.users.region_id` 与 `org.regions.id` 一致。
- 缺失或歧义区域保存失败且数据库不产生部分更新。
- 迁移只补齐精确唯一匹配账号，重复区域名称不修改。
- 区管可确认所属区域订单，跨区域账号仍返回 403。
- 账号联系电话、登录、停用恢复和渠道员工保存回归通过。

## 回退

代码回退使用上一版本镜像；数据迁移提供反向脚本，仅回退本次迁移标记的账号区域绑定，不覆盖之后人工修改的区域。
