# 产品/维保业务、客户档案与报价界面重构方案

> 由 hgrill-feature 访谈生成，来源：`docs/tasks/product-maintenance-business-refactor/docs/DECISION-LOG.md`。术语见 `docs/CONTEXT.md`。

## Problem Statement（问题陈述）

当前新 UI 将产品与维保混在商机、报价和订单的同一条业务链中，客户列表无法区分两类订单，客户档案和联系人信息分散，商机列表仍展示即将取消的下次跟进时间，报价构建器的操作顺序与老 UI 不一致，收益表入口和内容也不完整。需要在不改动老 UI、不接触生产环境的前提下，把产品与维保业务的边界落实到数据库、接口和页面。

## Solution（解决方案）

1. 客户全生命周期第七步固定为“持续运营”，在保/断保作为客户档案和订单条目的状态展示。客户档案合并客户主体与主联系人字段，移除客户级质保日期和审核说明，移除客户跟进入口。
2. 客户业务概况的订单条目分为产品订单、维保订单两组。产品订单按质保到期日、维保订单按维保到期日计算颜色：30 个自然日内黄色，已过期红色，无日期不着色。订单总数和总金额仍合计两类订单。
3. 商机新增产品/维保类型。产品商机用于产品报价和产品订单；维保商机必须关联至少一个同客户的产品订单，可关联多个，不要求同区域或渠道。商机列表移除快速跟进和下次跟进时间展示，跟进表单保留沟通内容、下一步计划并增加需求挖掘提示，不再写入下次跟进时间。
4. 报价新增产品/维保类型，报价创建和编辑从商机继承类型；维保报价只允许维保服务项。报价构建器改为上方先选报价方式，下方选择功能模块并展示具体功能和点数，保留套餐、补充功能、自定义三种模式和现有价格计算规则。
5. 订单新增产品/维保类型，由报价类型决定。产品报价只能生成产品订单，维保报价只能生成维保订单；维保订单必须关联至少一个同客户的产品订单，且关联产品订单必须处于已确认或已完成状态。产品订单和维保订单不得在同一张报价或订单中混合。
6. 报价收益表复用现有内部收益核算能力，只对超级管理员和区管展示；渠道用户不渲染、不请求、不返回内部成本和收益字段。

## 涉及模块（Implementation Impact）

- 数据层：商机、报价、订单新增业务类型字段；新增维保商机关联产品订单、维保订单关联产品订单两张关系表；历史数据默认回填为产品类型；停用商机下次跟进到期提醒模板。
- 接口层：商机创建/编辑、报价创建/编辑、报价转订单增加类型和关联参数；服务端增加同客户、状态、至少一条关联和混单拦截；查询结果透出业务类型和关联订单摘要。
- 前端：客户管理、客户档案、客户跟进路由、商机列表与跟进、商机创建/编辑、报价构建器、订单中心、审核/打印入口和收益面板。
- 逻辑：类型从商机到报价再到订单单向继承；维保关联在商机保存和订单创建时均复核；历史记录不能被静默改写；报价价格、区域覆盖、分销等级和收益公式继续由服务端计算。

## Compatibility（兼容性分析）

- 存量商机、报价、订单默认回填为产品类型；历史维保数据没有可靠标识，不能按名称自动猜测，需在报告中保留人工校正说明。
- 存量客户、联系人和订单质保数据保留；客户档案只调整展示和编辑入口，不删除底层历史字段。
- 存量商机跟进历史保留只读；下次跟进字段不再新增，已有字段可保留用于历史展示或迁移分析，但不再产生新的到期提醒。
- 现有报价转订单、订单审批、OA 预审、打印、收益核算和审计接口保持原路径；新增字段为向后兼容扩展，旧调用未传类型时按产品处理。
- 渠道账号继续受数据范围和内部收益字段脱敏约束，新增报价和订单类型不得扩大可见范围。

## Acceptance Criteria（验收标准）

- [ ] 生命周期第七步固定显示“持续运营”；在保/断保状态仍可在客户档案和订单条目查看。
- [ ] 客户档案不再展示客户级质保起止日和审核说明；主联系人四项并入客户档案，联系人独立面板消失；客户跟进入口和直达路由不可用。
- [ ] 客户业务概况分别展示产品订单、维保订单；30 天内到期黄色、已过期红色，产品订单使用质保到期日，维保订单使用维保到期日。
- [ ] 新建商机可选产品/维保；维保商机保存时至少关联一个同客户的产品订单，可关联多个；跨客户关联被接口拒绝。
- [ ] 商机列表无快速跟进和下次跟进时间；跟进表单无下次跟进字段，沟通内容有需求挖掘提示；历史跟进仍可只读查看。
- [ ] 报价构建器上方展示报价方式，下方展示功能模块和逐项点数；套餐、补充功能、自定义模式与现有价格规则回归通过。
- [ ] 内部用户在报价详情可看到完整收益表；渠道用户看不到收益、内部成本或价格规则。
- [ ] 产品报价转产品订单、维保报价转维保订单；维保订单没有有效产品订单关联时被拒绝，混入新产品或硬件的维保报价不能被转单。
- [ ] 历史商机、报价、订单有明确默认类型，旧数据仍可查询、打印、审批和查看审计。
- [ ] 单元测试、接口测试、页面回归、构建和测试环境全链路验证通过。

## Regression Scope（回归范围）

- 客户列表、客户编辑、客户报备审核、客户业务概况、订单摘要、质保维护和生命周期。
- 商机新建、编辑、阶段推进、跟进、报价入口和列表筛选。
- 报价新建、编辑、套餐/补充/自定义切换、点数、区域覆盖、分销等级、打印、转订单和收益计算。
- 订单创建、审批、退回、重提、质保维护、OA 预审、订单明细、客户数颜色标记和审计。
- 渠道管理员与内部管理员的可见字段、数据范围和接口 403/404 行为。
- 历史 V2 兼容报价和订单读取。

## Rollback Plan（回滚方案）

代码回滚到本任务前的 Web/API/Worker 镜像；数据库保留新增类型字段和关联表，避免破坏已写入的审计与关联数据，新增字段默认产品，不删除业务事实。若必须回退数据库，使用对应迁移的 rollback 文件，并先确认没有新增维保关联。停用的商机下次跟进提醒模板在回滚时恢复为启用。

## Out of Scope（范围外）

- 不修改老 UI。
- 不连接或修改生产环境。
- 不重构收益公式本身，只补齐入口和展示。
- 不建立多联系人表，只保留一个主联系人。
- 不自动把历史订单按名称拆分为产品/维保，不做无法证明的历史数据补写。
- 不改变客户报备、订单审批和 OA 的既有状态机语义。

## 待确认（Open Questions）

- 无。用户已确认总体业务口径；实施中发现数据级冲突时按“保留真实数据、默认产品类型、记录人工校正”的原则处理。

## Further Notes（补充说明）

- 现有数据模型没有商机/报价/订单业务类型和维保关联表，必须通过迁移完成，不能用备注或页面局部状态替代。
- 订单类型的唯一权威来源是报价类型，报价类型从商机继承；维保关联在商机保存和转订单时都要复核。
- 收益面板只属于内部管理员，报价打印和 PDF 不包含内部收益字段。
