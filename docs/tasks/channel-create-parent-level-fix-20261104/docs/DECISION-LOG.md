# 新建渠道商、一级渠道选择与分销层级保存决策日志

## 2026-11-04 — 三种失败现象合并定位

- 问了什么：用户明确要求修复新建渠道无原因提示、江苏区一级渠道缺失、分销层级保存失败。
- 定了什么：
  1. 服务端字符串错误必须原样展示给用户。
  2. 一级渠道判断以有效上下级关系和显式层级字段共同为准，优先使用有效下级关系修正历史数据。
  3. 候选只允许生效中且同区域的渠道。
  4. 历史渠道存在有效下级但主档层级为 `none` 时，接口返回有效一级，保存时写回 `primary`。
  5. 后端上级校验接受“生效中且存在有效下级”的历史一级渠道。
  6. 已归档渠道不计入有效上下级关系。
- 否了什么：
  - 不批量直接改测试环境历史渠道字段。
  - 不把仍有下级的渠道静默降级为二级或未设置。
  - 不修改老 UI/V2 页面，不操作生产环境。
- 权衡了什么：
  - 关系表比单个历史展示字段更可信，因此以关系事实修正有效层级；同时保留显式字段兼容，避免只依赖关系表。
  - 对仍有下级但主档为 none 的渠道，读取为一级并允许保存写回，解决死循环；直接降级仍由后端明确拒绝。

## 待确认项

- 无。用户已明确要求修复三项问题，本轮按现有“二级必须绑定同区域生效一级”的业务规则执行。
