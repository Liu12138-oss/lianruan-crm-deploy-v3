# 新建渠道商、一级渠道选择与分销层级保存修复方案

## 问题陈述

测试环境新 UI 存在三个相互关联的问题：

1. 新建渠道商失败时只显示“新建渠道商失败。”，没有展示服务端返回的具体原因。
2. 新建江苏区二级渠道商时，一级渠道下拉没有江苏汇鸿中天科技有限公司（P175）。
3. 打开仍绑定有效下级渠道的渠道档案后保存分销层级会失败。

## 根因

1. V2 兼容接口失败时返回 `error` 字符串，前端渠道客户端只读取 `error.message`，因此真实原因被统一回退文案覆盖。
2. 一级渠道候选仅按 `原始数据.partnerLevel === "primary"` 判断。P175 的历史 `partnerLevel` 为 `none`，但其 `level` 为 `primary`，且存在有效下级关系；同时候选未过滤停用、归档和无同区域记录，导致有效一级缺少、无效一级混入。
3. P066 等历史渠道存在有效下级，但 `partner_level_code` 为 `none`。档案接口返回“未设置”，页面保存时提交 `none`，后端按“仍有下级不能改为非一级”拒绝，形成无法保存的循环。

## 修复方案

1. 渠道客户端统一解析字符串和对象两类错误，页面展示服务端具体原因；网络或响应解析失败时保留可理解的兜底文案。
2. 前端新增统一的渠道层级判断：
   - 有效下级关系存在时，视为一级渠道；
   - 显式 `partnerLevel` 与历史兼容字段 `level` 均作为判断来源；
   - 一级上级候选必须为生效中渠道，且区域与新渠道完全一致；
   - 区域变化时清理不再有效已选上级。
3. 后端档案查询对“`partner_level_code` 非一级但仍有有效下级”的历史渠道返回有效一级；页面据此提交 `primary`，可正常保存并修复主档字段。
4. 后端保存二级渠道关系时，上级为生效中且存在有效下级关系的渠道同样视为有效一级，避免历史展示字段不一致阻断正确业务关系。
5. 关系列表统计排除已归档渠道，防止已归档测试渠道继续出现在上下级关系与候选判断中。

## 验收标准

- [x] 服务端返回字符串错误时，新建渠道商和保存层级页面显示具体原因，不再只显示通用失败文案。
- [x] 新建江苏区二级渠道商时，下拉展示生效中的 P175，并排除停用、归档、跨区域渠道。
- [x] 使用 P175 创建江苏区二级渠道商成功，保存后层级和上级关系正确。
- [x] P066 等仍绑定有效下级的历史渠道，档案展示为一级渠道；不修改层级直接保存也能成功。
- [x] 后端仍拒绝将仍有下级的渠道改为二级或未设置，并返回明确原因。
- [x] 新建、档案保存、区域切换和上下级关系查询回归通过。

## 回归范围

- 渠道列表新建弹窗的必填校验、区域切换、分销层级与上级选择。
- 渠道核心档案加载、档案保存、层级保存、年度目标与成员入口。

## 回滚方案

本轮无数据库迁移。若出现异常，仅切换回上一版 API、Worker、Nginx 镜像，并保留数据库当前值；不执行批量数据修复。

## 范围外

- 不批量改写历史渠道的 `partner_level_code`。
- 不改变合作级别、报价取价、订单审批和其它渠道业务规则。
- 不修改老 UI/V2 交互，不操作生产环境。
