# 报价免审批直接转订单决策日志

## 2026-11-04 — 用户确认最终口径

- 问了什么：确认新 UI 报价是否取消审批，以及标准产品和渠道分销产品分别如何定价、如何转订单。
- 定了什么：
  1. 渠道员工创建标准产品报价不再等待报价审批，报价金额直接为 0。
  2. 标准产品报价可直接提交订单，订单进入区管流程，由区管在审批环节补充最终订单价格。
  3. 渠道分销产品报价由服务端自动取价，也不需要等待报价审批。
  4. 草稿、历史提交、历史通过、历史驳回报价均可直接转订单。
  5. 已转订单、已取消、已过期报价不可转单。
  6. 只修改新 UI，老 UI/V2 保持原样；只操作测试环境，不接触生产。
- 否了什么：
  - 不在新 UI 保留报价提交、确认、驳回、重新提交和撤回操作。
  - 不删除报价状态兼容接口和历史报价审批数据。
  - 不修改老 UI/V2，不修改生产环境。
- 权衡了什么：
  - 标准报价金额为 0 会让订单初始金额无法直接作为成交价，因此区管补价必须成为标准订单提交超管前的硬门禁。
  - 保留历史状态直接转单可避免存量在途报价被新流程阻断，但需要在服务端明确拦截已转单和关闭状态。
  - 审核中心隐藏历史报价审批，可以避免产生无入口处理的僵尸待办，同时保留数据库记录供审计追溯。

## 2026-11-04 — 实施与验证口径

- 问了什么：无需再次确认，沿用用户“可以，确认修改”的明确授权执行。
- 定了什么：
  1. 服务端转单门禁允许 `draft`、`submitted`、`approved`、`rejected`。
  2. 服务端转单门禁拒绝 `converted`、`cancelled`、`expired`。
  3. 重复转单检查必须先于状态门禁，返回已有订单提示。
  4. API 自动化测试覆盖草稿、历史提交、历史通过、历史驳回、已取消和重复转单。
  5. Web 自动化测试覆盖报价中心、商机报价弹窗和审核中心不出现报价审批动作。
  6. 真实环境验收覆盖渠道标准报价、渠道分销报价、区管补价、附件、取消订单和角色权限。
- 否了什么：
  - 不修改移动端报价页面。
  - 不改变渠道分销价格计算规则。
  - 不新增数据库迁移。
- 权衡了什么：
  - 真实验收使用独立测试前缀和临时数据，完成后清理报价、订单、附件、通知、待办和审计；存在历史数据时只删除本轮明确编号的数据，不做模糊批量清理。
  - 测试环境发布前保留当前版本作为回退点，本轮无迁移，回退只需恢复镜像标签。
