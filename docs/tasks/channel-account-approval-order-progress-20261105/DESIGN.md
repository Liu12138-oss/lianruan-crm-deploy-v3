# 订单进度、业务全景、组织页、技术服务商与渠道账号两级审批修复方案

## 问题与目标

新 UI 本轮需要同时解决以下六项问题：

1. 订单顶部审批进度写死为第 1 步，已完成订单仍显示“待一级确认”。
2. 企业管理员可在渠道端新建员工账号，但需要经过区管初审、超管终审。
3. “业务全景”仅允许超级管理员访问，区管与渠道用户不展示入口。
4. 组织与岗位页顶部重复的“检索任意内部账号”输入框需要移除。
5. 渠道管理当前渠道标题区增加技术服务商类型：签约技术服务商、提名技术服务商、非技术服务商。
6. 区管可维护本区域渠道成员账号，企业管理员可维护本渠道员工账号。

## 实施方案

- 订单进度：新增纯函数状态映射，按真实订单状态计算当前步骤；退回、取消、替换、驳回使用异常状态轨道，不再套用正常审批进度。
- 账号审批：同一 `ops.approvals` 记录内增加 `approvalStage`。企业管理员提交后为 `region_review`；区管通过后仍保持待审批并推进到 `superadmin_review`；超管通过后账号启用。任一阶段驳回即结束并停用账号。
- 角色边界：超管处理所有区域；区管只处理本区域账号审批；企业管理员只能维护本渠道成员，且不能创建或提权为企业管理员。
- 渠道成员权限：区管可在本区域新增、编辑、启停和重置成员密码；企业管理员可维护本渠道员工；删除仍仅超管可用。
- 业务全景：导航入口权限改为 `superadmin`，与既有路由权限一致。
- 组织页：删除顶部重复账号检索框及其仅服务该输入框的状态、方法和样式，保留部门树搜索和右侧成员搜索。
- 技术服务商：渠道列表标题区按档案字段展示中文类型，空值显示“非技术服务商”。

## 验收标准

- [x] 已完成订单顶部显示全部审批步骤完成；处理中、已确认、退回、取消等状态均与订单真实状态一致。
- [x] 企业管理员从渠道端新建员工，账号状态为待审批，审批单先进入区管初审，再进入超管终审。
- [x] 区管可处理本区域账号初审，跨区域操作返回 403；超管不能跳过区管初审。
- [x] 超管通过终审后账号可登录；任一级驳回后账号不可登录并保留驳回原因。
- [x] 区管账号看不到“业务全景”，直接访问仍返回 403；超管正常访问。
- [x] 组织与岗位页顶部不再显示重复账号检索框。
- [x] 渠道标题区展示技术服务商类型，空值为“非技术服务商”。
- [x] API、Web 测试、类型检查和生产构建通过；测试环境真实账号验收通过。

## 实施结果

- 订单顶部进度改为按真实状态计算，已完成订单显示 5 个步骤全部完成，取消订单只显示“订单已取消”异常节点。
- 企业管理员新建员工进入区管初审，区管通过后进入超管终审；超管终审后账号启用。区管自建成员直接进入超管终审，避免自审。
- 审核中心状态列对账号待办显示“待区管初审 / 待超管终审”，不再使用笼统的“待审核”。
- “业务全景”导航仅超级管理员可见，区管直达返回 403。
- 组织与岗位页删除顶部重复账号检索框，保留部门树与右侧成员搜索。
- 渠道标题区展示“技术服务商：签约技术服务商 / 提名技术服务商 / 非技术服务商”。
- 区管可进入本区域渠道成员维护；企业管理员可维护本渠道员工，`/partner/members` 直达与刷新均正常。
