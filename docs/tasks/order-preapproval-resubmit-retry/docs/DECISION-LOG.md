# 决策记录

## 2026-09-09：订单预审退回重提后的重试边界

### 已知事实

- 订单预审请求目前按订单唯一，旧的明确失败记录会阻止退回修改后的新确认轮次创建请求。
- 当前订单已出现“首次失败、退回修改、再次确认但没有新事件”的生产现象。
- Worker 只消费 `crm.order.preapproval.requested` 发件箱事件，因此没有新请求就不会产生 OA 和企微调用日志。

### 用户确认的业务选择

- 按建议修复，不影响主体业务。
- 明确失败且没有泛微流程编号的旧轮次允许在真实退回修改后进入新审批轮次并自动重试。
- 已受理或结果不确定的旧轮次不得自动重发，避免外部审批重复；这类情况保留人工受控处理。

### 采用方案

- 幂等键改为订单＋审批轮次。
- 轮次由服务端根据订单和历史预审请求计算，禁止客户端覆盖。
- 新轮次固化新的报价、模块、金额、区域和区管信息；旧轮次只读保留。
- 门禁跳过时写审计，不静默吞掉原因。

### 未授权事项

- 不修改生产数据库、不重发当前生产订单、不调用真实泛微或企微写接口。
- 不修改订单权限、状态节点、价格计算、成员映射和外部字段契约。
