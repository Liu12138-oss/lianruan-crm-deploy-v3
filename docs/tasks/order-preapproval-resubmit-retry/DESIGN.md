# 订单预审退回重提后可重试缺陷修复设计

## 1. 缺陷与范围

当前订单预审请求在 `integration.order_preapproval_requests.order_id` 上使用单列唯一约束。订单首次预审明确失败后，审批退回、修改并重新确认时，状态机再次尝试创建预审请求会被旧记录静默拦截，因此没有新的发件箱事件，Worker 不会再次调用泛微 OA，也不会创建企微群。

本次只修复 V3 订单预审的审批轮次幂等和重提触发，不改变订单权限、渠道价格计算、订单状态机节点、OA 字段、企微成员规则或其他 CRM 主链路。

## 2. 已确认业务规则

1. 幂等范围从“订单”调整为“订单＋审批轮次”。同一轮并发确认只能有一条预审请求，历史轮次完整保留。
2. 首次明确失败且没有泛微流程编号的旧轮次，在订单真实退回修改并进入新审批轮次后，允许自动创建新预审请求。
3. 已取得泛微流程编号、已受理，或结果不确定并进入 `manual_confirmation_required` 的旧轮次，不允许自动创建新 OA。需要先人工确认外部流程已撤回或终止，再走受控人工处理。
4. 旧轮次只有在状态为 `failed` 且没有外部流程编号时，才允许后续真实新轮次自动发起；`stopped` 仍保留人工核验，避免扩大自动重试边界。
5. 被重发门禁拦截时写入审计，说明阻断原因，禁止静默忽略。
6. 新轮次继续使用服务端重新读取的报价、订单明细、区域和身份映射快照；旧轮次的请求快照、附件和调用记录不被覆盖。

## 3. 技术方案

### 3.1 数据模型

- 为 `integration.order_preapproval_requests` 增加正整数 `approval_round`，存量记录回填为 `1`。
- 删除该表的 `UNIQUE(order_id)`，增加 `UNIQUE(order_id, approval_round)`；`idempotency_key` 继续保持全局唯一。
- 新幂等键格式为 `order-preapproval:<orderId>:round-<approvalRound>:<templateVersion>`。
- 请求快照增加 `approvalRound`，便于审计和现场对账。
- `integration.order_preapproval_groups` 继续按 `request_id` 唯一，每个轮次独立建群事实。

### 3.2 状态机与门禁

- 初次触发时订单 `extra_json.approvalRound` 为空或为 `0`，预审请求使用轮次 `1`；订单每次真实退回修改并重新提交后，服务端把订单轮次更新为“当前订单轮次与历史预审最大轮次的较大值加一”，后续预审请求使用该订单轮次。
- 发起新轮次前查询旧轮次：只要存在 `external_request_id`，或状态为 `accepted`、`manual_confirmation_required`，就只写审计并跳过自动发起。
- 只有无外部流程编号的 `failed` 旧轮次不会阻断新轮次。
- 同一轮次使用数据库唯一约束和 `RETURNING` 结果判断并发幂等；插入未成功时写明“已有同轮请求”，不能当作新请求继续投递。

### 3.3 兼容与回退

- 存量订单和存量请求无需业务数据回填；迁移只增加字段、调整约束并回填轮次 `1`。
- 旧请求的调用记录、附件和外部流程编号全部保留。
- 代码回退前不得删除已产生的新轮次事实；数据库回退脚本在存在轮次大于 `1` 时明确阻断，避免丢失追溯数据。
- 不对生产订单手工删除请求、重置状态或补发外部流程。

## 4. 主业务保护

- 不修改订单主体金额、模块定价和渠道等级计算。
- 不修改订单审批节点的权限校验和退回目标规则。
- 不回写订单状态；Worker 仍只维护 `integration` 和受控附件事实。
- 预审连接器默认开关、企微成员映射、泛微字段映射和现有成功流程保持不变。

## 5. 验收口径

1. 首次预审成功后，同一轮重复确认不产生第二条请求或第二个 OA 流程。
2. 首次明确失败且无流程编号，订单退回修改、重新提交并再次确认后产生第二轮请求和一条新的发件箱事件；旧失败请求仍保留。
3. 旧轮次存在流程编号、状态为 `accepted` 或 `manual_confirmation_required` 时，重新提交后不产生新 OA 请求，并有可查询审计说明。
4. 两个并发确认最多产生一条同轮请求和一条同轮发件箱事件。
5. 新请求的 `approval_round`、幂等键和报价/模块快照对应重新提交后的版本。
6. 既有报价转订单、订单审批、价格恢复、区域范围、V2 兼容和 Worker 默认关闭测试全部通过。
