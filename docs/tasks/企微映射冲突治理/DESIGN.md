# 企微映射冲突治理设计

## 目标

补齐企业微信身份映射导入的阻断定位与受控纠正能力，并为同名不同登录账号提供可识别入口。使超级管理员能在不改写订单、OA、自动拉群、角色、区域和历史事实的前提下，定位冲突对象、明确选择处理目标并完成校正。

## 已确认规则

1. V3 登录账号全局唯一；本任务识别的是同名不同登录账号，不把同名视为同一人员。
2. 同名不同登录账号仅列入疑似重复清单。超级管理员必须明确选择来源账号和保留账号，仍复用既有“交接当前业务并停用来源账号”流程。
3. 企业微信 `UserId` 的纠正仅由超级管理员操作，必须填写原因、输入目标登录账号二次确认，并带入预览返回的映射行版本。
4. 身份校正使用“停用冲突的有效映射，再新增目标账号的有效映射”的同一数据库事务；不物理删除映射，不改写历史业务、审批、审计或已创建的群记录。
5. 身份校正只影响后续需要读取企业微信身份的投递和拉群任务；不改变泛微 OA 映射。
6. 文件自身的空值、格式错误、重复姓名、重复 `UserId` 必须由维护人修改源文件，页面只给出准确的源行和说明，不自动猜测修正。

## 接口与状态

1. `GET /api/org/account-conflicts`：只读返回启用账号中同名不同登录账号清单及成员摘要，供人工打开账号、查看现有归并预览。
2. 企业微信导入预览的阻断行补充关联账号、关联映射编号和行版本。前端可筛选“仅阻断”，并从行内发起校正。
3. `POST /api/org/wecom-identities/correct`：在可串行化事务中锁定目标账号与当前冲突映射；校验预期映射编号和行版本未变化后，停用冲突有效映射并新增目标有效映射，最后写组织审计。
4. 校正成功后前端重新预览原文件。只有文件自身阻断项全部消除后，才允许确认整批导入。

## 权限、并发与回退

- 两个接口都要求组织功能与超级管理员签名 Cookie 会话；写入另要求 `V3_ORGANIZATION_WRITE_ENABLED=true` 和幂等键。
- 写入使用可串行化事务、`FOR UPDATE`、映射 `row_version` 与幂等记录；并发或预览过期返回冲突，不做覆盖。
- 数据库迁移仅放开企业微信身份的逻辑停用状态，不删除或回填任何已有数据。
- 回退只下线入口和接口，不自动撤回已经完成的身份校正或账号交接；数据库中的停用映射和审计继续保留。

## 验收与回归

- 同名启用账号能在冲突清单中同时展示，且仍需人工选定保留账号才能归并。
- 导入预览的“账号已有不同 UserId”“UserId 已被其他账号占用”能显示关联账号和可校正入口。
- 校正必须校验超管、开关、幂等键、原因、二次确认、映射版本和目标账号状态；失败不写任何映射。
- 成功校正后旧映射停用、新映射有效、审计完整，重新预览显示“已一致”。
- 回归组织路由、账号归并、企微导入、订单、报备、报价、渠道成员和会话状态测试。
