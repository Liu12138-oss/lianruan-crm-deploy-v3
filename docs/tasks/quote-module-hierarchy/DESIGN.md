# 新 UI 报价方式三级结构设计

## 问题陈述

当前新建 / 编辑报价页把报价方式、产品套餐、已选功能和可选功能平铺在同一页面。套餐卡片过小，产品目录没有体现“大类 → 模块 → 功能”的关系；可选功能又出现在软件模块区域，导致用户无法区分“正在选择”和“已经入单”的内容。

## 解决方案

1. 报价方式区域采用三张方式卡片：套餐报价、补充功能、自定义报价。
2. 套餐报价与补充功能先展示产品套餐卡片，点击套餐选中，点击“查看详情”在报价方式区域内展开套餐包含的功能。
3. 自定义报价展示产品大类卡片；点击大类，在下方按产品模块分组展示具体功能胶囊，可逐项勾选。
4. 补充功能展示套餐未包含的产品大类，并按相同方式展开模块与功能。
5. 维保报价沿用同一套大类、模块、功能选择结构，只展示维保服务项。
6. 软件模块区域仅展示已入单功能，并按产品模块分组；数量、价格构成、越档提示和移除能力保持不变。
7. 可选功能搜索框移动至报价方式区域，只影响当前可选目录。

## 数据来源

- 报价试算、价格和已选产品仍以 `GET /api/stage9/products` 与现有报价接口为准。
- 产品大类、模块和功能的显示顺序与图标优先读取只读 `GET /api/v2/product-tree`。
- 产品树不可用时，按阶段九产品自带的 `categoryName`、`moduleName` 分组回退。
- 选择值仍使用阶段九产品 `id`，不改变保存和试算载荷。

## 兼容性

- 不新增数据库迁移，不改变报价接口契约。
- 编辑历史报价继续按原 `quoteMode`、`packageId` 和 `productIds` 回填。
- 历史明细无法匹配产品目录时，归入“其他功能”分组，不丢失数量和金额。
- 渠道用户沿用现有价格脱敏逻辑，功能胶囊不展示价格或价格规则。

## 验收标准

- 套餐报价下可见产品套餐卡片，选中状态清晰；点击“查看详情”可在报价方式区域内看到套餐功能。
- 自定义报价下可见产品大类卡片；点击大类后按产品模块分组展示具体功能，点击功能可勾选或取消。
- 补充功能只展示套餐未包含的功能；自定义报价可选全部非维保功能。
- 软件模块区域不再出现可选功能搜索和可选模块网格，只展示已入单功能，并按产品模块分组。
- 编辑报价时原选择可回填；数量调整、移除、试算、保存和返回商机不回归。
- 维保报价不出现普通软件功能。
- 渠道用户不因本次调整看到价格规则或内部成本说明。

## 回归范围

- 产品报价新建与编辑。
- 维保报价新建与编辑。
- 套餐切换、补充功能勾选、自定义勾选、功能数量调整和重新试算。
- 渠道端报价创建入口与管理端共用组件。

## 回滚方案

本次只修改报价页组件、报价目录分组辅助函数和产品目录客户端。回滚时恢复对应前端文件并重新构建静态资源即可，不涉及数据库回滚。

## 范围外

- 移动端报价表单结构。
- 产品目录维护页。
- 报价价格算法、渠道等级价、区域覆盖价和收益表。
- 老 UI/V2 页面。
