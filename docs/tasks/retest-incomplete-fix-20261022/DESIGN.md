# 全业务链全员复测非通过项修复方案

## 问题陈述

2026-10-22 复测表共 209 条用例，其中 5 条非完全通过：`QTE-16`、`APR-02`、`ORG-12`、`ERR-07`、`VIS-02`。其中证书两项为同一前端版本号缺陷，字号一项为样式锁作用域遗漏；历史报价和审核数量需要先区分代码缺陷与测试数据边界。

## 修复方案

1. 在组织接口客户端规范化成员证书的 `rowVersion`，查询、颁发、延期和撤销响应均向页面返回数值；证书页提交时继续使用该数值版本，保留后端 400/409 乐观锁语义。
2. 将新 UI 一级导航统一为 11px，并把 403、404、维护、会话失效状态页纳入同一字体族和 22/16/23/11px 字号口径。
3. 审核中心只通过数据库和接口核对待审批事项与目标业务状态，确认是否存在终态幽灵待办；数量变化不修改代码或测试数据。
4. 历史报价核验原始字段和报价快照；无原始价格时不补造明细，保留总额与“历史未记录”业务提示。

## 兼容性与回归

- 接口契约不变，只修正前端对 `bigint` 字符串版本号的读取。
- 后端证书乐观锁、权限和审计逻辑不改。
- 字号只影响新 UI；老 UI、登录页和移动端不在本次范围。
- 回归范围覆盖证书颁发、延期、撤销、重复提交、审核中心待办、报价历史展示和至少 5 个页面的计算字号。

## 验收标准

- 证书页面延期、撤销首次提交成功，请求体 `rowVersion` 为数字；重复提交返回 409。
- 新 UI 抽查页面可见正文只出现 11、16、22、23px 四档；状态页为 22px 一级标题和 11px 正文/按钮。
- 待审批清单每一条均对应真实 pending 业务记录，不存在终态残留。
- 历史报价总额保持 16,764.00，缺失明细继续明确提示“历史未记录”。
- Web 测试、类型检查、构建、格式检查和测试环境复测通过。

## 回滚方案

保留测试环境发布前镜像标签和配置快照；如页面回归失败，将 `compose/.env` 的 `V3_IMAGE_TAG` 切回上一版本并重建 Web/Nginx，不改数据库。

## 范围外

- 不修改生产环境。
- 不修改老 UI。
- 不补造历史报价明细。
- 不调整审核中心测试数据或验收基线。
