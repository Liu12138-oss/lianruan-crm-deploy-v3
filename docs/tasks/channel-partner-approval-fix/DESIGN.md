# 渠道商创建审批缺陷修复设计

## 实现切片

1. 数据库：允许 `channel.partners.status_code=pending`，提供迁移及回退。
2. API：保留待审批状态，写入审批待办；审批任务处理同步更新渠道商状态；区域列表范围兼容 `region_id` 和区域扩展字段。
3. 前端：创建渠道商显式传递状态；审批列表保留审批编号并调用审批任务接口。
4. 测试：覆盖创建、待办可见、通过/驳回状态回写和区域列表范围。

## 验收标准

- 区域管理员创建后，服务端强制将渠道商保存为 `pending`，存在一条 `channel.partner.approval.pending` 发件箱事件和一条待审批任务。
- 超级管理员在 `/pending-approvals` 可看到渠道商审批任务。
- 区域管理员和超级管理员在 `/partners` 可看到该渠道商；渠道商未审批通过前不会被当作生效渠道使用。
- 超级管理员通过或驳回后，审批任务与渠道商主档状态一致，重复处理返回冲突。
- 其他渠道、报备、商机、报价、订单和账号功能测试不受影响。
