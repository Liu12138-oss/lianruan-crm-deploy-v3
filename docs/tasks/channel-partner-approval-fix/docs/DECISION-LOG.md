# 渠道商创建审批缺陷修复决策记录

## 共识摘要

- 目标：修复区域管理员创建渠道商后，超级管理员无审批待办、双方列表不可见的问题。
- 范围：仅涉及渠道商创建、待审批状态、审批中心展示、审批通过/驳回和区域数据范围。
- 状态机：`pending → active`（通过）；`pending → rejected`（驳回）；`rejected → pending`（重新提交）。
- 数据规则：区域管理员可查看本区域渠道商的 `pending`、`rejected`、`active` 记录；超级管理员可查看全部记录。
- 安全规则：待审批渠道商不得被视为已生效渠道商，不改变其他业务模块的既有状态机。
- 回退：代码可回退；数据库迁移提供对应回退脚本，回退前须确认不存在 `pending` 渠道商记录。

## 已确认事项

1. 增加渠道商主档 `pending` 状态，保留审批记录作为审批事实和审计依据。
2. 前端会显式提交 `status=pending`，且服务端以已登录角色为准：区域管理员新建强制为 `pending`，超级管理员新建强制为 `active`，防止客户端参数绕过审批。
3. 审批中心通过审批任务接口处理渠道商，不再只修改渠道商主档状态。
4. 兼容接口继续作为正式页面的后端入口，不改动 V2 历史目录。

## 风险与验证

- 风险：已有数据库若存在 `pending` 数据，回退迁移不能直接移除状态约束；交付前通过查询确认。
- 验证：执行渠道商审批相关 API 测试、类型检查和前端脚本语法检查；并回归现有 V2 兼容审批测试。
