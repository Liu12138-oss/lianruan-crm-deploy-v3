# 账号停用归并与恢复设计

## 已确认共识

- 账号停用后，客户、报备、商机、报价和未结束订单的当前负责人交接给接收人；历史申请人、审批人、操作记录和外部身份历史不得改写。
- 历史账号不得物理删除，也不得把已停用账号的登录名直接分配给另一名人员。
- 同一人员回岗或调整权限，应恢复原账号并重新授权；旧会话不得恢复，已交接的业务负责人不得回滚。
- 同名不同登录账号的清理采用“选择保留账号、交接并停用重复账号”，不自动按姓名猜测。

## 实现范围

1. 角色成员列表默认只统计和展示启用账号，可显式查看停用历史。
2. 增加受控的账号恢复接口和页面入口：仅超级管理员可操作，要求已完成交接、重新指定当前角色和内部任职，并记录审计。
3. 增加重复账号归并预览和执行：操作者明确选择来源与保留账号；执行复用现有停用交接，不物理删除来源账号。
4. 新建账号遇到已归档登录名时，拒绝静默更新旧记录，并提示使用恢复账号或新登录名。

## 回退与验收

- 回退只下线新入口和接口；已完成的交接、恢复和审计不自动反转。
- 验证停用账号不再出现在默认角色成员列表；显示历史时可见状态。
- 验证恢复后旧会话仍失效，当前业务负责人保持交接结果。
- 验证归并必须二次确认且不允许来源与保留账号相同。
