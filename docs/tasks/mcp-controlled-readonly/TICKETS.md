# V3 受控只读 MCP 实施任务单

## 1. 执行规则

- 所有任务按编号和依赖顺序执行，不得跳过安全、权限、审计、迁移或回退任务。
- `MCP-00` 完成后必须先取得用户对设计和任务单的确认，再开始编码。
- P0 身份权限修复必须独立提交、独立测试、独立发布，不得与 MCP 业务工具混为一个升级包。
- 每完成一个任务，执行验证命令并记录证据；未通过不得开始依赖任务。
- 数据库、生产配置、证书、生产容器和生产发布均属于高风险动作，需另行明确授权。
- 实现与本设计不一致时，先更新任务决策日志并取得确认，禁止在代码中静默改变协议、权限或数据边界。

### P0-A：身份、权限与数据范围前置修复

5. OpenAPI 资源未配置时不再回退为 `*`，完成存量客户端影响核查。
6. 补齐内部、渠道、区域、本人和跨范围负向测试。

验收标准：

- 空身份、停用账号、伪造身份、跨范围访问全部拒绝。
- 现有四套正式页面、业务 API、Worker 和 OpenAPI 合法调用回归通过。
- 修复作为独立提交、独立升级包和独立发布记录处理。
- P0-A 未完成时不得注册真实 MCP 工具。

回退：按独立修复任务自身回退，不使用 MCP 开关代替业务修复。

实施证据：

- OpenAPI 查询传入绑定用户上下文，未绑定用户的资源访问被拒绝。

## 4. 强制停止条件

出现任一情况立即停止对应阶段：

1. P0-A 未完成或回归失败。
2. 赤兔实际不支持 MCP `2026-07-28` 且没有批准的兼容方案。
3. 外部入口没有 HTTPS。
4. 出现越权、字段泄露、凭据泄露或未审计调用。
5. MCP 导致主业务性能超过确认阈值。
6. 审计、身份映射或客户端撤权失效。
