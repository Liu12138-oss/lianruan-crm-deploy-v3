# 客户报备查重临时放行设计

## 目标

历史重复客户尚未完成合并清理期间，允许客户报备继续提交，不再因名称或统一社会信用代码重复直接返回 409；同时保留查重识别、冲突审计和后续恢复拦截的能力。

## 业务规则

- 默认规则不变：`V3_CUSTOMER_DUPLICATE_BLOCK_ENABLED=true`，重复报备仍返回 `V3_CUSTOMER_DUPLICATE_CONFLICT`。
- 临时放行：设为 `false` 时，重复报备正常提交，并写入 `warning` 审计。
- 审计沿用 `registration / customer_duplicate_conflict`，通过 `extra_json.duplicatePolicy=warn_only` 区分放行记录。
- 查重周报继续统计放行冲突，不因关闭拦截而丢失统计口径。
- 新建、驳回后修改两条报备路径均接入同一开关。

## 非目标

- 不删除查重能力，不自动合并历史重复客户。
- 不修改老 UI/V2。
- 不清理生产数据。

## 验收标准

- 默认配置下，重复名称或信用代码仍返回 409。
- 开关关闭时，重复名称、重复信用代码和驳回后修改均可成功，审计结果为 `warning`。
- 查重周报能查询到放行记录。
- 测试环境健康检查通过，生产环境未连接、未修改。
