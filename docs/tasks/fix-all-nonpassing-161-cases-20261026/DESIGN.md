# 新增 161 项非通过用例统一修复方案

## 问题陈述

2026-10-23 的新增 161 项测试中，76 项通过，其余 85 项由 60 项部分通过、10 项失败、9 项有条件通过和 6 项阻塞组成。非通过原因既有真实代码缺口，也有验收口径滞后、测试数据不足和外部联调环境缺失。本轮目标是把可闭环的缺陷全部修复，把不能闭环的环境前置条件单独列出，并保证结论可追溯。

## 范围

### 代码与配置

- 报价价格有效期、区域价、端点校验、版本冲突和并发转单幂等。
- 产品目录写权限、套餐组合约束、价格档位冲突、工作量映射 CRUD。
- 订单质保保存后的页面回显与客户业务概况一致性。
- 审批详情路由、驳回原因校验、待办终态清理、计数刷新。
- 客户报备查重审计、附件内容识别与文件名安全。
- 渠道成员规范化唯一、审批状态、成员口径和中文等级。
- 组织账号停用会话撤销、证书边界、导入预览与错误报告。
- 消息偏好字段兼容、已读幂等、渠道状态中文与 Worker 关闭态说明。
- 操作审计导出、完整性校验、长文本与敏感内容展示。
- 客户/渠道/员工导入的逐行错误、同文件重复、批次幂等、编码与失败返回码。
- 移动端客户搜索、商机跟进时间线、报价试算、订单审批动作、触控尺寸。
- CSRF 防护、上传 MIME/Magic Number、登录限流、审计与存储型 XSS 复核。
- 全业务链中的渠道等级展示和订单打印入口。

### 测试与文档

- 修正与当前统一入口架构冲突的过期验收文本：`AUTH-02`、`AUTH-03`、`MOB-01`。
- 对外部 IAM、OA、企微、消息 Worker 和隔离迁移库项目保留阻塞说明。
- 增加/更新自动化回归测试，部署测试环境后只复跑受影响脚本。
- 重新生成 Markdown、HTML 报告和结果明细，不覆盖历史原始结果。

## 非目标

- 不修改老 UI/V2。
- 不连接或修改生产环境。
- 不在现有测试库执行破坏性迁移回滚。
- 不伪造外部系统投递、OA 回调、企微建群和真实 IAM 票据验证。

## 统一处理原则

1. 服务端做最终校验，前端只负责提示与防重。
2. 金额、权限、状态机、数据范围和审计必须在同一数据库事务内完成。
3. 并发写请求：同一资源使用锁或版本条件，冲突返回 409，不能返回 500。
4. 导入按批次和行级返回结果；全失败批次必须是非成功业务结果，并给出可下载错误报告。
5. 审计详情按纯文本展示；导出结果必须与筛选总数一致。
6. 移动端与桌面端共享同一业务接口，不建立第二套状态机。
7. 环境阻塞项必须保留真实原因和下一步授权条件，不能标记通过。

## 验收标准

- 每个非通过编号在修复矩阵中有明确归属：已修复待复测、验收口径修订、环境阻塞或保持有条件通过及原因。
- 已修复项必须有本地自动化测试和测试环境真实接口/页面证据。
- 161 项复测结果只增不减；任何无法验证的项不得写成“通过”。
- 测试环境健康检查通过，API、Worker 版本信息可核对，关键回归链路无 500。
- 报告包含变更文件、版本、复测命令、数据范围、回滚方式和剩余阻塞。

## 回归范围

- 登录与统一入口、客户报备、商机、报价、订单、审批、渠道、产品目录、组织账号、消息、审计、导入导出、移动端、安全权限和并发路径。
- 桌面 UI：客户列表/档案、商机详情、报价编辑、订单详情、渠道详情、产品维护、审批中心、消息中心、操作审计。

## 回滚方案

- 代码：保留测试环境发布前镜像标签与源码快照，出现回归时切回上一镜像标签。
- 数据：本轮不执行破坏性迁移回滚；测试数据统一使用新前缀并按引用关系清理。
- 配置：外部 Worker 继续保持关闭，不在缺少凭据时开启真实外发。

## 决策缺口

- 真实 IAM/UniSDP 回调、OA 回调、企微建群和消息外发需要测试环境凭据、可恢复 Worker 与明确授权。
- 迁移失败回滚需要隔离迁移库、备份恢复窗口和专项授权。
- 压力基线需要在测试库构造并清理 100/500/1000 条临时数据，具体执行前需确认数据窗口。
