# 决策日志

## 2026-10-23

### D01 范围

- 用户目标：修复工作台待办超长、客户列表报备商机报错，并检查渠道管理、产品目录、消息中心等管理员业务及全业务链。
- 约束：只改新 UI/V3；老 UI 和生产环境不动；只在测试环境部署和写入数据。
- 结论：按最小修改原则处理两个已确认缺陷，其余模块先检查后决定是否修复。

### D02 报备商机端点数量

- 事实：字段为数字输入，提交代码调用 `.trim()`，已在测试环境复现前端异常且未发出创建请求。
- 决策：按数值提交，空值按 `0` 处理；不改变后端接口契约。

### D03 工作台待办布局

- 事实：长标题使卡片实际宽度超过左侧面板；页面自身未出现横向滚动是因为外层隐藏溢出。
- 决策：只调整工作台待办卡片作用域内的弹性收缩和省略规则，不做全局 UI 重排。

### D04 测试数据

- 决策：全业务链验收产生的临时记录在验收完成后清理；保留测试环境原有基线数据。
- 回滚：保留发布前镜像标签和配置备份，回滚不涉及生产环境。

### D05 渠道等级中文口径

- 事实：渠道列表、经营报表和渠道档案存在直接展示 `diamond` 等等级代码的路径。
- 决策：统一由共享格式化函数转换，`diamond` 展示“钻石”，未知代码展示“其他渠道”，不在各页面重复维护映射。

### D06 区管姓名与账号目录权限

- 事实：区管订单页为补齐负责区管姓名请求 `/api/users`，该接口仅允许超级管理员，导致正常业务页面出现 403。
- 决策：订单查询由服务端返回 `regionConfirmedByName`，前端优先展示姓名；不扩大 `/api/users` 权限，避免普通账号读取管理目录。

### D07 验收数据清理与审计保留

- 事实：全业务链产生两轮商机、报价和订单，相关明细与状态历史均可按业务编号定位。
- 决策：清理临时业务数据及从属记录，保留审计日志作为可追溯证据；清理前生成快照，不使用数据库整体回滚。
- 结果：临时业务残留为 0，审计记录 2083 条，迁移版本 73，既有客户报备保留。
