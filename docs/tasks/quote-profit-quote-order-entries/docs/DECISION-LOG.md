# 决策记录：收益核算报价与订单入口完善

## 1. 任务信息

- 任务标识：`quote-profit-quote-order-entries`
- 起始日期：2026-09-18
- 使用技能：仓库要求使用 `hgrill-feature`，当前环境未提供该技能文件；本轮按仓库 `AGENTS.md` 的等价要求人工完成预检、决策记录、设计、任务单和验收门禁。
- 冲突处理：不按 hgrill 默认规则覆盖根目录 `AGENTS.md`，所有本轮产物仅写入任务目录。

## 2. 用户明确决定

用户原话摘要：

1. “收益表应该要在报价单和订单内能看到吧？区管和超管。”
2. “你帮忙完善一下，做好功能测试。按推荐来。”

确认后的方案：

- 报价单详情：区管和超管可见；冻结前可维护年限、保存草稿和重新计算。
- 订单详情：区管和超管可见；默认只读。
- 订单冻结前：展示最新实时预估、草稿或不完整结果，并明确标注非正式。
- 订单冻结后：展示正式收益快照，只读。
- 渠道端、普通管理员、员工、OpenAPI 和 MCP 不新增入口。

## 3. 事实核查

- 现有后端收益接口已经支持按报价编号读取，并复核数据库角色和区域。
- 现有前端只在商机关联报价详情中内联收益面板。
- 报价管理详情和订单详情目前没有收益入口。
- 管理员页面恢复登录时只读取 `localStorage`，历史缓存可能缺少数据库已经补齐的区域信息。
- 现有结算公式、冻结状态和后端权限无需修改。

## 4. 方案取舍

采用共享组件方案：

- 三处入口复用同一收益加载、状态和操作逻辑，减少行为漂移。
- 订单只读模式使用同一接口，不新增后端契约。
- 保持报价打印区域隔离，避免内部收益进入客户侧 PDF 或浏览器打印。
- 页面启动后使用现有 `/api/v2/auth/me` 静默刷新用户资料，修复旧缓存但不增加新的认证接口。

未采用：

- 在订单详情复制一份可编辑收益面板：会造成报价与订单双入口修改冲突。
- 新增独立收益页面：超出本轮明确需求，并改变既有操作路径。
- 修改后端接口：当前接口已满足入口扩展需求，新增接口只会扩大回归面。

## 5. 风险与回退

- 风险：订单关联报价编号缺失时收益面板不能加载；页面必须仅降级收益区，不影响订单主链。
- 风险：静态管理员脚本体积较大，修改需通过 Source 级测试和 Playwright 入口测试防止模板破坏。
- 回退：撤回前端组件接入，保留后端收益数据和正式快照。
