# 收益核算在报价管理与订单详情中的入口完善设计

## 1. 目标与范围

本轮补齐“微盾＋硬件报价收益核算”在管理端的业务入口，使区管和超级管理员不仅能在商机关联报价中查看收益，也能从正式的“报价管理”和“订单管理”页面查看。

- 报价管理详情：区管和超管可查看实时预估、草稿、不完整和正式快照；未冻结时仍可保存年限或重新计算。
- 订单详情：区管所属区域订单和超管全部订单可查看；订单详情为只读视图，不维护年限、不直接重算或冻结。
- 权限、数据范围和金额计算继续由现有后端接口控制。
- 渠道账号、普通管理员、员工、OpenAPI 和 MCP 不新增收益入口。

## 2. 已确认业务口径

1. 用户明确确认采用推荐方案：订单详情冻结前显示最新实时预估、草稿或不完整结果，并明确标注“非正式快照”；超管确认订单并完成异步冻结后显示只读正式收益快照。
2. 报价管理详情保持与商机关联报价一致的操作能力：区管和超管可维护质保年限、采购维保年限并保存草稿或重新计算；正式冻结后只读。
3. 订单详情不提供年限编辑、保存草稿、重算和冻结按钮，避免同一报价在不同入口出现两套修改语义。
4. 区管仅能访问报价正式区域命中本人有效区域的数据；超管可访问全部。跨区访问继续由后端返回保护性 404。
5. 非微盾或未明确归类报价继续显示“不适用”，不展示部分收益。

## 3. 技术方案

新增共享 `QuoteProfitPanel` Vue 组件，封装收益状态、接口加载、错误降级、状态展示、参数维护和冻结只读逻辑。

- `QuoteProfitPanel` 接受 `quoteId`、`readonly` 和 `context` 属性。
- 报价管理和商机关联报价使用可编辑模式；订单详情使用只读模式。
- 组件只在当前账号满足超管或区管条件时渲染；实际权限仍由 `GET /api/quotes/:quoteId/profit-calculation` 复核。
- 订单只读模式在冻结前显示“非正式快照”提示，冻结后显示“正式快照”提示，始终不展示编辑控件。
- 原商机报价详情改为复用同一组件，移除重复状态与函数，避免未来行为漂移。
- 报价管理的收益面板放在打印区域之外，不进入浏览器打印预览和报价单 PDF。
- 管理员页面启动后静默调用 `/api/v2/auth/me` 刷新本地用户资料，修复历史缓存缺少区管区域信息导致收益面板被隐藏的问题；刷新失败时继续使用现有可验证会话。

## 4. 状态与异常

- `estimated`：实时预估，非正式。
- `draft`：已保存草稿，非正式。
- `incomplete`：输入不完整，非正式，展示缺失原因。
- `frozen`：正式快照，只读。
- `not_applicable`：非微盾范围，不输出部分收益。
- 接口 404、403、5xx 或网络异常只影响收益面板，不阻断报价和订单主链。

## 5. 验收标准

1. 超管从“报价管理”打开报价详情可看到内部收益核算，并可保存草稿、重新计算。
2. 所属区域区管从“报价管理”打开本区域报价详情可看到内部收益核算；跨区域报价不可访问。
3. 区管和超管从“订单管理”打开对应订单详情可看到收益；冻结前明确显示非正式状态，冻结后显示正式快照。
4. 订单详情没有任何年限输入、保存、重算或冻结操作。
5. 普通管理员、渠道账号和员工页面不渲染收益面板。
6. 报价打印区域和 PDF 不包含收益金额或内部成本。
7. 现有商机关联报价入口保持可用且复用同一组件。
8. 旧区管登录缓存刷新后能够恢复区域信息并看到收益面板。
9. Web 单元测试、静态入口测试、Playwright 入口测试、类型检查和构建通过。

## 6. 回归与回退

- 回归报价列表、报价详情、打印、转订单、订单详情、订单状态操作和商机报价详情。
- 不改后端接口、数据库和收益公式。
- 回退时移除三个页面的组件接入并恢复原商机报价内联区块；数据库和已冻结快照不受影响。
