# 渠道商维护能力补齐决策记录

## 2026-10-29 — 预检与现状核查

- 问了什么：新 UI 中新建渠道商、经营与地址、合作背景、渠道分销层级为何无法维护。
- 已核查事实：
  - `/admin/partners` 当前没有“新建渠道商”入口，列表与详情只有查看档案、成员维护和渠道资质审核。
  - 核心档案已有“工商主体、经营与地址、联系人与合作信息、产品能力与提醒”四组字段，但入口不够直观，且缺少代理品牌、典型客户、客户行业等已展示字段的编辑项。
  - 后端已有 `POST /api/v2/partners`、`PUT /api/v2/partners/:id/profile`、`PUT /api/v2/partners/:id/level`。
  - 当前管理配置写接口统一只允许超级管理员；该规则与历史渠道商审批方案中“区域管理员创建后待审批”的口径冲突。
  - 渠道分销层级与渠道合作级别是两个不同字段：前者为一级、二级或未设置，后者为核心、金牌、银牌、钻石或 LEP。
- 定了什么：本次仅修改 V3 新 UI 及其后端兼容接口，不动老 UI，不接触生产数据。
- 否了什么：未确认前不修改权限、不开放新的数据范围。
- 权衡了什么：需要在“仅超管维护”的现状安全边界与“区域管理员维护本区域渠道商”的历史业务方案之间做选择。
- 待确认：
  1. 新建及维护权限是否恢复为“超级管理员可直接维护；区域管理员仅能维护本区域，且新建进入待审批”。
  2. 是否同时提供“渠道分销层级”和“渠道合作级别”两个独立维护项。
  3. 二级渠道是否继续允许绑定多个同区域一级渠道。
  4. 经营能力是否开放代理品牌、典型客户、客户行业及其他现有展示字段的编辑。

## 2026-10-29 — 用户确认执行口径

- 问了什么：是否按“超管全量、区管本区域且新建待审批”的权限方案执行。
- 定了什么：用户明确同意该方案，并要求只操作测试环境、不得改动生产。
- 权限：超级管理员可新建和维护全部渠道商；区域管理员只能新建本区域渠道商并进入待审批，只能维护本区域渠道商档案和分销层级。
- 等级：合作级别与分销层级分开维护；分销层级支持未设置、一级和二级。
- 关系：二级渠道可绑定多个同区域一级渠道，禁止自绑、跨区域和循环关系。
- 档案：开放经营与地址、合作背景、代理品牌、典型客户、客户行业及现有能力字段维护。
- 否了什么：不采用“渠道商所有写操作仅超管可执行”的当前临时限制，不把渠道用户纳入维护范围。
- 权衡了什么：放宽管理配置中间件会扩大写权限，因此必须逐接口执行服务端角色、区域、关系和审计校验，不能仅依赖前端隐藏。

## 2026-10-29 — r2 渠道列表与核心档案交互收口

- 问了什么：技术服务商类型是否只保留签约和提名两种；保存核心档案是否需要反馈；渠道列表卡片是否移除重复的查看档案和成员维护。
- 用户原话：技术服务商类型只可能是“签约技术服务时”“提名技术服务商”；保存渠道商核心档案时给反馈；渠道列表不需要展示查看档案和成员维护，因为上方已有维护按钮。
- 已核查事实：
  - 原页面技术服务商下拉包含全能力、交付、集成、发展中等等价或历史类型，容易造成业务口径不一致。
  - 原保存成功后仅刷新数据，没有明确的成功提示。
  - 渠道列表卡片既有查看档案、成员维护动作，上方又有渠道核心档案、成员维护按钮，形成重复入口。
- 定了什么：
  - 下拉保留“请选择”占位，业务值仅保留 `full`（签约技术服务商）和 `developing`（提名技术服务商）；“请选择”不作为业务类型。
  - 服务端同步校验 `none/full/developing`，其他值返回 400；历史无效值按未选择处理。
  - 保存成功后显示“渠道核心档案已保存。”。
  - 列表卡片移除查看档案和成员维护，只保留上方统一维护入口。
- 否了什么：不改老 UI/V2；不新增数据库迁移；不删除存量渠道数据；不连接生产环境。
- 验证结果：
  - 测试环境切换到 `3.0.0-stage10.20261029-channelmaintenance-r2`，页面定向验收 8/8 通过。
  - `delivery` 返回 400，提示“技术服务商类型仅支持签约技术服务商或提名技术服务商。”，回读原值仍为 `full`。
  - 列表 20 个卡片均不含查看档案、成员维护；上方两个统一按钮各 1 个。
  - 保存反馈可见，刷新后仍为签约技术服务商。
- 权衡了什么：保留“请选择”用于表达未设置，不把它当成第三种业务类型；验收临时渠道归档而不物理删除，以保留审计链路。
