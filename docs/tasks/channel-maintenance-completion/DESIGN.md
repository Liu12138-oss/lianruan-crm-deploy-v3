# 渠道商维护能力补齐修改方案

> 由 hgrill-feature 访谈生成，来源：docs/tasks/channel-maintenance-completion/docs/DECISION-LOG.md。术语表见仓库 docs/CONTEXT.md。

## Problem Statement（问题陈述）

新 UI 的渠道商列表没有新建入口，核心档案虽有经营与地址、合作背景字段，但用户难以发现和维护，且代理品牌、典型客户、客户行业只展示不可编辑。渠道分销层级和合作级别没有维护界面，二级渠道无法绑定同区域一级渠道。区域管理员本应维护本区域渠道商，但当前所有渠道商写接口只允许超级管理员，导致页面出现可编辑假象并最终返回 403。

## Solution（解决方案）

- 渠道商列表增加“新建渠道商”入口，表单覆盖名称、区域、城市、联系方式、合作级别、分销层级、经营地址和合作背景。
- 超级管理员新建后立即生效；区域管理员新建强制绑定服务端确认的本区域，并进入待审批，不信任前端提交的区域和状态。
- 渠道详情增加经营与地址、合作背景、经营能力、合作级别和分销层级的明确维护入口或动作。
- 核心档案补齐代理品牌、典型客户、客户行业等字段，并让现有经营与能力字段可保存。
- 分销层级使用“未设置、一级、二级”；二级必须绑定一个或多个同区域一级渠道，禁止自绑、跨区域、重复和循环关系。
- 合作级别单独维护为核心、钻石、金牌、银牌、铜牌或未设置。
- 技术服务商类型只保留“签约技术服务商”和“提名技术服务商”两个业务选项，历史无效值按未选择处理，服务端拒绝其他枚举值。
- 渠道列表卡片不再重复提供“查看档案”和“成员维护”，统一使用列表上方的档案维护动作。
- 渠道核心档案保存成功后给出明确前端反馈，并支持刷新后回显。
- 服务端逐接口校验角色、区域、目标渠道和上级关系，写入操作审计；前端仅展示当前账号允许的动作。

## 涉及模块（Implementation Impact）

- 数据层：沿用现有渠道主档、画像和渠道关系表，不新增数据库迁移；合作级别保存在渠道扩展信息，分销层级保存在渠道主档级别字段。
- 接口层：调整渠道商新建、核心档案读取与保存、分销层级保存接口；兼容现有字段和历史数据，新增合作级别与关系校验。
- 前端：渠道商列表增加新建和维护入口；核心档案增加经营能力、合作背景和层级维护。
- 逻辑：增加服务端角色与区域范围校验、待审批状态约束、分销关系合法性校验和审计记录。

## Compatibility（兼容性分析）

- 存量渠道商字段保持兼容，未设置合作级别或分销层级的记录继续显示“未设置”。
- 历史一级、二级及多上级关系保留；保存时只校验新的合法关系。
- 原有只读列表、成员维护、资质审核和订单审批接口不变。
- 渠道用户仍不可访问渠道商维护接口；跨区域区域管理员返回 403。
