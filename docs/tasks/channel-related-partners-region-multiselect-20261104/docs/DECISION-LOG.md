# 渠道上下级可见性与区域价格多选决策日志

## 2026-11-04 — 需求理解与默认口径

- 问了什么：用户要求删除渠道列表红框内容、修复一级与二级渠道互相不可见的问题、将区域价格覆盖改为支持单选和多选。
- 定了什么：
  1. 红框内“档案维护入口、经营与地址、合作背景、合作与分销层级”整块删除，顶部核心档案入口保留。
  2. 渠道上下级只开放直属关系：自身、直属一级、直属二级；不开放兄弟渠道和无限层级递归。
  3. 上下级关系以有效 `primary_secondary` 关系为准，不依赖可能不准确的渠道层级字段。
  4. 上下级档案只读，不允许编辑档案、层级、成员或目标，也不展示经营摘要和年度目标。
  5. 区域价格覆盖采用与老 UI 一致的多选逻辑，同一覆盖项支持一个或多个区域，保存时去重并同步 `region=regions[0]`。
  6. 老 UI 与生产环境不修改，只更新 V3 新 UI 和测试环境。
- 否了什么：
  - 不扩展完整下级树、不展示兄弟渠道。
  - 不授予一级渠道编辑或管理二级渠道的权限。
  - 不改变区域价格优先级、渠道等级价和报价计算方式。
  - 不批量修改测试环境历史渠道层级字段。
- 权衡了什么：
  - 一级渠道需要看到直属二级渠道，但不应获得其经营和订单目标等敏感数据，因此采用关系可见、档案只读、敏感区块隐藏的最小权限方案。
  - 区域多选需要兼容老 UI 与历史单区域数据，因此保留 `region` 并新增/完善 `regions`，避免报价取价链路迁移风险。
