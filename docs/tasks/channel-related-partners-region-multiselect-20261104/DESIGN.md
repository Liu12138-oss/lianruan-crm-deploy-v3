# 渠道上下级可见性与区域价格多选修改方案

> 由 hgrill-feature 访谈自动生成，来源：docs/tasks/channel-related-partners-region-multiselect-20261104/docs/DECISION-LOG.md。术语表见仓库 docs/CONTEXT.md。

## Problem Statement（问题陈述）

新 UI 渠道管理当前存在三项问题：

1. 渠道列表顶部保留了“档案维护入口、经营与地址、合作背景、合作与分销层级”快捷区块，与页面已有维护入口重复，视觉上形成多余横条。
2. 渠道账号的数据范围只包含自身渠道，一级渠道无法在列表中看到直属二级渠道，二级渠道也无法确认自己所属的一级渠道。
3. 产品目录的区域价格覆盖仍为单选下拉框，无法像老 UI 一样让同一套区域价格规则覆盖多个区域；后续价格规则页面也只读取历史兼容字段 `region`，无法完整展示多区域规则。

## Solution（解决方案）

1. 删除渠道列表红框内的整个快捷区块及其无引用样式，保留顶部“渠道核心档案”按钮作为唯一档案入口。
2. 渠道账号可见范围扩展为自身、直属一级渠道和直属二级渠道，不扩展兄弟渠道或更远层级。上下级档案只读，不允许维护档案、层级、成员或年度目标；相关经营摘要和年度目标不对上下级账号展示。
3. 产品功能维护中的区域价格覆盖改为可筛选的多选控件，同一覆盖项可选择一个或多个正式组织区域。保存时去重，并以首个区域同步写入历史兼容字段 `region`，完整区域列表写入 `regions`。价格规则展示统一展示全部覆盖区域。

## 涉及模块（Implementation Impact）

- 数据层：不新增表、不修改既有表结构；继续使用渠道关系表识别有效上下级关系。
- 接口层：渠道列表数据范围增加直属上下级；渠道列表和渠道档案补充上下级编号、名称和数量；渠道档案增加读取关系类型和只读限制；区域价格校验兼容并校验 `regions` 数组。
- 前端：渠道列表删除快捷区块并展示上下级关系摘要；渠道档案展示所属一级渠道和直属二级渠道；产品目录区域覆盖改为多选；价格规则页面完整展示多区域。
- 逻辑：上下级关系以有效 `primary_secondary` 关系为唯一依据，不单独依赖渠道层级字段，兼容测试环境中的层级字段历史脏数据。

## Compatibility（兼容性分析）

- 存量区域价格规则只有 `region` 时继续有效，编辑时自动转换为单元素 `regions` 数组。
- 老 UI 同时写入 `region` 和 `regions`，V3 继续保留两套字段，报价取价逻辑无需迁移。
- 既有渠道列表接口字段保持兼容，只新增上下级关系字段；无关系渠道返回空数组或零数量。
- 超级管理员和区域管理员原有全量或本区域渠道范围不变。
- 渠道角色只增加直属上下级可见性，不获得任何写权限，不扩大到兄弟渠道或跨区域渠道。

## Acceptance Criteria（验收标准）

- [x] 渠道列表不再出现“档案维护入口 / 经营与地址 / 合作背景 / 合作与分销层级”快捷横条，顶部核心档案入口仍可正常使用。

- [x] 保存后 `regions` 保留去重后的全部区域，`region` 等于首个区域，重新编辑可完整回显。
- [x] 按任一覆盖区域报价时均命中同一套区域价格，价格规则页面展示全部区域。
