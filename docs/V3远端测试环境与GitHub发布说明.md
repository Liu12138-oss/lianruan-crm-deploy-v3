编写日期：2026-07-31  
适用项目：联软 CRM V3  
适用场景：V3 缺陷修复、功能迭代、远端生产同构测试环境验证、GitHub 同步发布。

## 一、核心约定

所有 V3 相关修复和迭代必须先基于当前 V3 项目结构完成，不再按 V2 老目录进行生产修复。

后续测试和发布默认流程：

```text
本地修复和验证
  -> 制作 V3 升级包或镜像
  -> 上传到生产同构测试服务器 10.20.3.10
  -> 自动备份、升级、健康检查、业务验收
  -> 验收通过后同步 GitHub
  -> 形成交付记录
```

## 四、远端测试更新规范

### 4.1 适用范围

以下工作完成后，应优先更新到 `10.20.3.10` 验证：

1. V3 后端接口修复。
2. V3 前端页面修复。
3. V3 保留旧入口静态资产修复。
4. 数据库迁移或数据修复。
5. Docker Compose、Nginx、部署脚本修复。
6. 登录、权限、报价、订单、迁移、OpenAPI 等核心流程修复。

### 4.2 推荐方式

一般修复推荐做成 V3 KB 升级包，遵循：

```text
docs/V3生产升级包制作规范.md
```

远端执行流程：

```bash
cd /tmp
sha256sum -c lianruan-crm-v3-kb-编号.zip.sha256
unzip -q lianruan-crm-v3-kb-编号.zip
cd lianruan-crm-v3-kb-编号
sudo bash scripts/precheck.sh /opt/lianruan-crm-v3
sudo bash scripts/upgrade.sh /opt/lianruan-crm-v3
sudo bash scripts/verify.sh /opt/lianruan-crm-v3
```

如果是完整离线包升级，遵循：

```text
docs/deployment/V3版本生产部署文档.md
deploy/single-server/README.md
```

### 4.3 必须自动完成的动作

远端测试更新不能只复制文件，必须至少完成：

1. 自动预检查。
2. 自动备份。
3. 保存升级前配置快照。
4. 停止受影响服务。
5. 应用修复。
6. 执行数据库迁移。
7. 启动受影响服务。
8. 健康检查。
9. 业务冒烟。
10. 输出升级日志、备份目录和回退命令。

### 4.4 欧拉环境注意事项

该远端环境按生产约束处理：

1. 升级包只使用 ZIP。
2. 解压只假设有 `unzip`。
3. 制包只假设有 `zip`。
4. 不依赖 `tar`、`python`、`jq`、`rsync`、`expect`。
5. 不使用交互式复杂脚本作为唯一升级方式。
6. 脚本必须使用 `bash`，并在开头设置 `set -euo pipefail`。

## 五、GitHub 同步规范

### 5.1 什么时候同步 GitHub

以下情况必须同步 GitHub：

1. V3 缺陷修复已经本地验证通过。
2. 修复已在 `10.20.3.10` 远端测试环境验证通过。
3. 新增或更新了 V3 升级包规范、部署脚本、迁移脚本、文档。
4. 做了功能迭代并完成测试验收。

### 5.2 同步前检查

推送前必须检查：

```bash
git status --short
git diff --stat
git remote -v
```

确认：

1. 没有提交密码、令牌、密钥、生产配置。
2. 没有提交 `tmp/`、`output/`、日志、数据库、备份包。
3. 没有误改 V2 旧目录作为 V3 修复。
4. 所有文档中的凭据均为占位或脱敏。
5. 远端仍指向 `Liu12138-oss/lianruan-crm-deploy-v3`。

### 5.3 推荐提交内容

每次修复建议至少包含：

1. 代码改动。
2. 测试或验证改动。
3. 必要数据库迁移。
4. 必要升级包说明。
5. 远端测试验证记录。

提交说明建议格式：

```text
fix: 修复 V3 某某问题

- 修复内容
- 影响范围
- 验证结果
- 远端测试环境：10.20.3.10
```

## 六、安全红线

任何情况下都不要做：

1. 不要把服务器密码写入文档。
2. 不要把 GitHub 密码或令牌写入文档。
3. 不要把密码拼进 Git 远端地址。
4. 不要把密码写进 `sshpass` 命令并提交。
5. 不要把生产 `v3.env` 提交到仓库。
6. 不要把 `/opt/lianruan-crm-v3/secrets/` 内容打包进 GitHub。
7. 不要把数据库备份、客户数据导出、迁移原始数据提交到 GitHub。
