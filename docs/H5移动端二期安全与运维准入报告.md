# H5 移动端二期安全与运维准入报告

> 审查日期：2026-07-14
>
> 审查范围：`backend/server.js`、`frontend/mobile-v2.html`、`frontend/mobile-v2-api.js`、`frontend/mobile-v2-app.js`、`frontend/mobile-v2.css`、`scripts/deploy.sh`、`scripts/start.sh`、`docs/DEPLOY.md`。
>
> 当前结论：**可继续隔离环境的受控只读联调；不具备生产开放或生产灰度准入条件。**

## 1. 审查边界与判定原则

本报告仅对已阅读的源码、脚本和文档作出结论。负载均衡器、反向代理、证书、域名、网络隔离、操作系统账号、日志平台、数据库备份、真实身份源和生产环境变量均不在工作区内；对这些项目统一标为“待部署侧核实”，不以猜测替代验证。

风险等级定义如下：

| 等级 | 含义 | 准入影响 |
|---|---|---|
| 阻断级 | 可导致令牌、账号、业务数据或生产边界被直接突破，或当前部署方式无法承载受保护移动服务。 | 禁止生产开放和生产灰度。 |
| 高风险 | 可明显降低鉴权、审计、可用性或数据保护能力，需要在生产前修复并回归。 | 禁止生产开放；仅可在隔离测试环境按限制使用。 |
| 中风险 | 当前只读范围内尚无直接利用链，但会阻碍后续写入、审计或运维可控性。 | 进入写入开发、试点或扩大灰度前必须关闭。 |
| 低风险 | 不直接影响当前安全边界，但应纳入版本质量与配置治理。 | 记录并按计划修复。 |

## 2. 准入结论

### 2.1 受控测试环境

在以下条件同时满足时，当前版本可作为受控只读联调候选：

1. 仅使用隔离数据库、脱敏测试数据和测试账号，入口不公开、不配置二维码、不接入真实渠道用户。
2. 二期仅开放现有查询接口和退出接口；不得增加或绕过任何业务写入路由。
3. 后端仅监听测试网络或本机，测试结束后撤销令牌、删除临时数据库与审计库。
4. 执行本报告第 8 节的语法、接口权限、基础安全和依赖检查；发现跨范围数据、令牌泄露或异常响应立即停止试用。

### 2.2 生产环境

当前**不准入**。阻断原因包括：二期仍接续一期浏览器令牌、当前本地登录令牌生成方式不可用于生产、现有部署脚本和部署文档直接使用 HTTP、跨域策略未收紧、后端端口无反向代理隔离，且没有生产级独立认证、刷新会话、限流和静态页面安全响应头的已验证证据。

## 4. 已确认风险与最小修复建议

### 4.1 阻断级

| 编号 | 风险 | 证据 | 影响 | 最小修复建议 |
|---|---|---|---|---|
| S-01 | 当前 V2 接续一期浏览器令牌，令牌可被页面脚本读取；本地登录分支使用时间戳构造令牌，不能作为生产会话凭证。 | `frontend/mobile-v2-api.js:30-53` 将令牌存入 `sessionStorage`；`136-145` 从一期 `localStorage` 接续；`backend/server.js:3196-3211` 的本地分支使用 `token_` 加时间戳。 | 一旦静态页面被跨站脚本、恶意浏览器扩展、共享设备或 HTTP 窃取，攻击者可复用 Bearer 令牌访问 V2 数据。 | 上线前实施独立移动认证：密码仅经 HTTPS 传输，短时访问令牌只驻留内存，刷新凭证使用 `HttpOnly`、`Secure`、`SameSite=Strict` Cookie，令牌使用密码学随机值并哈希保存，支持轮换、设备撤销、停用即时失效和再次验证。当前“接续一期登录态”入口必须在生产构建中移除或在网关层拒绝访问。 |
| S-02 | 当前部署脚本与部署指南均将服务暴露为 HTTP；脚本还直接以静态服务器提供页面。 | `scripts/start.sh:119-120`、`128`、`145-149`、`170-173`；`scripts/deploy.sh:91-93`、`120-124`、`153`；`docs/DEPLOY.md:11-29`、`58-80`。 | HTTP 下账号、令牌和业务数据可被网络旁路读取或篡改；静态服务器也无法提供完整生产安全头、同域反向代理与访问控制。 | 生产必须废弃上述脚本和文档中的 HTTP 路径：由受管反向代理提供 TLS，静态站点和 `/api/mobile/v2/` 同源发布，后端仅绑定本机或私网，公网仅开放 HTTPS。证书自动续期、HTTP 强制跳转、TLS 协议与密码套件由部署侧复验。 |
| S-03 | 现有部署脚本将整个安装目录设为全员可读，并复制后端目录；该目录通常包含数据库和审计库。 | `scripts/deploy.sh:72-75` 复制后端；`105-107` 执行 `chmod -R 755`。 | 同机低权限用户可能读取 CRM 数据、审计记录和源码配置；也不满足生产数据最小文件权限。 | 前端静态目录与后端数据目录分离；数据库、审计库、环境文件和上传目录归专用服务账号所有，目录权限不高于 `750`，数据文件不高于 `600`；部署前用非服务账号实际验证不可读。 |

### 4.2 高风险

| 编号 | 风险 | 证据 | 影响 | 最小修复建议 |
|---|---|---|---|---|
| S-04 | 全局跨域策略未限制来源。 | `backend/server.js:35` 使用无参数跨域中间件。 | 所有 API 路径继承宽松跨域响应；虽然 Bearer 令牌不会自动附带，但会扩大令牌被错误前端使用或后续 Cookie 迁移时的跨站风险。 | 在生产反向代理和应用层仅允许正式 H5 域名；V2 建议同源，拒绝未知 `Origin`，只允许必要方法与请求头，不启用跨站凭证。修改会影响一期，须作为整体跨域变更在回归环境实施，不能仅靠前端隐藏。 |
| S-05 | 登录和 V2 入口未见速率限制、来源限流或账户锁定控制。 | `backend/server.js:29-66` 中间件未配置限流；登录路由为 `3426-3515`。 | 可被口令猜测、枚举或资源耗尽；V2 当前继续依赖该登录体系。 | 在网关先配置基于来源、账号和路径的限流与告警；登录失败采用渐进延迟或短期锁定，V2 查询设置合理并发与响应大小限制。不得把客户端超时当作安全限流。 |
| S-06 | 审计来源地址直接信任任意 `X-Forwarded-For` 头。 | `backend/server.js:1191-1196`。 | 直接访问后端的调用者可伪造审计 IP，降低会话撤销和异常排查证据可信度。 | 后端仅接受受信反向代理流量；代理覆盖客户端伪造头，并按已知代理跳数配置框架的代理信任；无法确认代理拓扑前，审计中同时保留连接对端地址并标注来源可信度。 |
| S-07 | 静态 V2 页面没有可见的内容安全、反嵌入、引用来源和禁止缓存响应头配置；当前 API 头不能保护 HTML、脚本和样式文件。 | `frontend/mobile-v2.html:1-18` 无对应元标签；`scripts/start.sh:145-149` 使用简单静态服务器；`docs/DEPLOY.md:58-80` 的示例只配置静态缓存。 | 即使 V2 接口设置了安全头，静态页面仍缺少浏览器侧执行与嵌入约束；令牌驻留于浏览器存储时风险更高。 | 由生产反向代理为 `mobile-v2.html` 设置 `Cache-Control: no-store`、内容安全策略、`frame-ancestors`、`X-Content-Type-Options`、`Referrer-Policy` 和 `Permissions-Policy`；策略必须按实际静态资源、同源接口和后续构建产物联调后启用。 |
| S-08 | 依赖扫描发现直接依赖 `xlsx` 存在高风险已知漏洞；扫描还发现 `express` 依赖链的中风险问题。 | `backend/package.json:14-20`；2026-07-14 执行 `npm audit --omit=dev`，结果为高风险 1 项、中风险 3 项；`xlsx` 命中原型污染与正则拒绝服务公告，`express`/`body-parser` 经 `qs` 命中中风险公告。 | 当前 V2 不上传文件，但同一后端进程导入该依赖，后续导入、附件或其他路径可扩大攻击面。 | 生产前锁定受支持的安全替代版本或替代组件，完成导入兼容回归；无法修复时禁用受影响导入路径并提交书面风险接受。依赖升级不得与 V2 业务写入同批上线。 |
| S-09 | 当前脚本和文档含默认账号、默认密码或演示访问说明，且后端内存种子数据含明文演示密码。 | `backend/server.js:72-77`；`scripts/start.sh:170-176`；`scripts/deploy.sh:155` 后续默认账号说明；`docs/DEPLOY.md:110-128`。 | 若生产沿用初始数据或演示说明，可能被直接登录；明文密码也不满足生产凭据存储要求。 | 生产初始化强制创建首个管理员并要求首次改密；移除演示账号与明文密码；采用经验证的口令哈希方案、复杂度与重置流程。该项影响既有认证，需整体回归。 |

## 6. 生产环境必须项

以下项目必须全部完成、留存证据并通过复验后，才可申请生产只读灰度；任何业务写入还须额外完成业务规则、幂等、状态机、金额、再次验证和回退专项验收。

1. 完成 S-01 至 S-09 的修复或经安全负责人书面风险接受；阻断级项目不得通过风险接受绕过。
2. 使用独立移动认证，禁止 V2 读取一期 `localStorage` 令牌，禁止将长期 Bearer 令牌写入可由脚本读取的存储。
3. 部署同源 HTTPS 反向代理，后端不对公网暴露；静态页面与 V2 API 均设置经过验证的安全头和缓存策略。
4. 收紧跨域、请求体、查询参数、上传、速率限制和并发控制；登录、令牌刷新、再次验证和高风险写入分别设置更严格策略。
5. 删除演示账号与默认密码，完成生产数据初始化、口令哈希、密钥管理、最小文件权限、备份恢复和灾难演练。
6. 修复或隔离已知高风险依赖，使用锁定版本安装并保留依赖扫描结果；不得使用不受控网络安装替代生产制品。
7. 对四类角色执行认证、越权、跨区域、跨渠道、枚举、跨站脚本、跨域、缓存、弱网、重放、会话撤销、错误泄露、限流和回退测试。
8. 建立开关变更、会话撤销、鉴权失败和异常访问的审计与告警；校验请求编号能关联到应用日志、代理日志和审计记录。

## 7. 测试环境可接受项

下列条件仅可作为隔离测试便利措施，不能复制到生产：

1. 本机或隔离网络的 HTTP 静态服务，仅用于脱敏数据与短时测试；测试结束立即停止服务。
2. 现有一期会话接续，仅用于验证 V2 只读路由、字段脱敏和数据范围；不得向真实用户提供入口。
3. 默认关闭所有业务写入且不配置 `MOBILE_V2_FEATURE_FLAGS` 放开规则；未知 V2 写路径必须保持 `403`。
4. 宽松跨域只可在封闭测试网络临时使用；测试结束前记录并清理令牌、临时数据库、审计库和浏览器会话。
5. 使用 `scripts/test-mobile-v2-readonly.js` 和 `scripts/test-mobile-v2-foundation.js` 的隔离数据库流程；禁止指向工作库或生产库。

## 9. 最终判定

当前二期基础版本的“服务端数据范围隔离、只读默认关闭写入、敏感字段最小化、令牌撤销审计、统一错误结构”可以作为后续建设基线；它们不能替代生产认证和部署安全。

**最终判定：批准继续隔离环境只读联调；不批准生产灰度；不批准生产开放；不批准任何业务写入。**
