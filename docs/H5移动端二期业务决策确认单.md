## 1. 使用目的与确认规则

本确认单把二期中不能由研发自行推断的业务规则集中为可签署的最小决策项。签署后，产品、研发、测试和交付以本单为唯一业务基线实施；任何与本单不一致的页面、接口、状态迁移、权限或数据处理均不得上线。

1. 每个编号必须填写“最终选择”或“暂不开放”。只填写“同意建议”时，应在签署栏明确写明同意的具体建议条目；未签署前，所有“建议默认值”都不是已确认规则。
2. 选择“暂不开放”时，对应模块必须同时在移动入口、V2 接口和服务端功能开关中保持关闭，已有数据仅允许在已授权范围内查询。
3. 每项确认至少附一组真实或脱敏示例数据；价格、折扣、调价、退款还必须附可复算的金额样例。
4. 业务规则变更须新增版本号、变更原因、影响范围、回退方式和补充验收用例，并重新取得相关责任人确认。
5. 手机端不得以本单替代电脑端既有业务。二期只使用独立入口 `mobile-v2.html` 和 `/api/mobile/v2/*`；一期 H5、电脑端及历史接口继续保留为兼容和回退路径。

### 1.1 全局安全与交付约束

以下约束不是可选项，不因任何业务选择而取消：

| 约束 | 固定要求 |
|---|---|
| 授权 | 服务端仅从当前会话取得操作者、角色、区域和渠道商；请求中的用户、区域、渠道商等字段不得作为授权依据。 |
| 写入 | 每个写接口必须执行对象级权限校验、状态机校验、幂等校验、原子更新和审计留痕；幂等键相同但请求内容不同必须拒绝。 |
| 金额 | 单价、税额、折扣、总额、价格簿版本和订单快照只能由服务端计算及保存；前端传入金额不得直接写入。 |
| 高风险动作 | 调价、订单取消、账号审批等操作须再次验证、二次确认、功能开关和审计；再次验证有效期不得超过 5 分钟。 |
| 回退 | 关闭 V2 写入后，电脑端必须能继续查询和处理在途记录；不得修改历史主键或改变历史主状态含义。 |

### 1.3 已确认默认值的生效边界

1. “采用建议默认值”不等同于跳过参数配置。保护期、原因字典、状态映射和渠道关系必须由对应业务数据表提供；缺失参数的动作必须由服务端拒绝，而非猜测或回退到前端计算。价格簿、税率、币种、金额精度和折扣阈值继续由电脑端报价流程使用，手机端不直接使用这些规则新建报价。
2. D2-05 已确认“首批调价、取消和退款写入关闭”。这些能力只保留只读历史展示、接口契约和功能开关，不纳入本轮生产写入范围。
3. D2-06 未改变独立认证的技术选择门禁。密码登录、统一身份认证和短信再次验证的启用方式，仍须按《H5 移动端二期独立认证与会话实施说明》完成安全、账号和运维确认。
4. D2-01 至 D2-07 的确认不替代 P2-01 至 P2-07 生产门禁。独立认证、生产部署、数据迁移、真机性能、安全、灰度和回退证据完成前，生产入口和业务写入仍不得开放。

## 2. D2-01：报备保护与争议

### 2.1 必须确认的最小规则

| 决策点 | 必须填写的最终选择 | 建议默认值（未确认，不得直接实施） |
|---|---|---|
| 保护期起算与时长 | 明确从提交、审核通过或其他节点起算；填写保护期天数、是否允许续期、续期条件和最长保护期。 | 建议从“审核通过”起算；保护期、续期时长和上限由销售管理负责人在价格外的独立参数表中填写，未填参数不允许提交。 |
| 查重规则 | 明确统一社会信用代码、标准化客户名称、区域、联系人等字段的优先级；明确完全重复与疑似重复的判定方式。 | 建议统一社会信用代码完全相同直接判定重复；名称仅用于提示疑似重复；接口仅返回“可继续、需人工处理、不可提交”及下一步提示，不返回占用方、联系人或电话。 |
| 审核状态 | 明确是否使用 `reviewing`；明确 `pending`、`reviewing`、`approved`、`rejected`、`expired` 与历史状态的对应关系。 | 建议新单走“独立草稿 → `pending` → `reviewing` → `approved`”；审核可从 `pending` 或 `reviewing` 进入 `rejected`；历史 `expired` 仅只读。 |
| 撤回与驳回后处理 | 明确哪些状态允许撤回；明确驳回后是复制新草稿还是修订原记录；明确是否允许申诉。 | 建议草稿可直接删除；已提交记录不允许直接删除；驳回后仅复制为新草稿，不改写原记录；申诉和撤回申请在首批保持关闭。 |
| 跨渠道、跨区域争议 | 明确争议受理角色、归属判定依据、处理时限、升级路径和最终裁决人。 | 建议由归属区域销售管理负责人受理，跨区域争议由指定全局负责人裁决；移动端只展示处理结果和必要原因，不公开对方数据。 |
| 自动创建商机 | 明确审核通过后是否自动创建商机，以及失败、重复创建和撤销审核的处理方式。 | 建议首批由渠道账号主动从已通过报备创建商机；不自动创建，避免未确认的负责人、阶段和待办规则写入。 |

### 2.2 已确认默认规则下的关闭范围

报备草稿、查重、提交、审核、驳回后复制新草稿和时间线可进入受控开发；申诉、撤回申请、自动创建商机和争议处理写入继续关闭。保护期、查重和争议参数未配置时，服务端必须拒绝对应提交或审核，不得用前端隐藏按钮或人工调用接口绕过限制。

### 2.3 验收证据

1. 已签署的保护期、查重、争议处理和状态机图，附至少 10 组脱敏重复与争议样例。
2. 同一信用代码重复提交返回冲突，且响应不泄露其他渠道、区域或联系人信息。
3. 跨渠道、跨区域的查询、深链、审核和争议接口均被对象级权限拒绝。
4. 驳回无原因、非法状态迁移、并发审核和重复提交均不产生重复业务事件。
5. 移动端与电脑端对同一报备的状态、渠道、区域、创建人和事件时间线一致。

## 3. D2-02：商机状态与协作

### 3.1 必须确认的最小规则

| 决策点 | 必须填写的最终选择 | 建议默认值（未确认，不得直接实施） |
|---|---|---|
| 历史状态映射 | 为历史 `qualification`、`proposal`、`closing` 及其他实际状态逐项指定：映射到哪个展示状态、保持只读或允许继续推进。 | 建议历史状态先只读展示；仅新建商机使用已冻结的新状态，直到历史数据回放和双端对账通过后再开放迁移。 |
| 新商机阶段与跳转 | 明确每个阶段的允许前后关系、是否允许跳级、回退以及例外审批。 | 建议仅允许 `contacted → registered → quoted → budget → design → testing → negotiation → won` 的相邻推进；仅 `negotiation` 可进入 `lost` 或 `cancelled`；其他跳转默认拒绝。 |
| 结案原因 | 提供赢单、失单、取消的原因字典，并规定是否可补充说明及最小长度。 | 建议赢单、失单、取消均为必填原因；原因字典由销售管理负责人维护，首批不允许自由文本替代原因。 |
| 负责人及协作边界 | 明确谁可以新建、编辑、分配、转交和查看跟进；明确跨渠道、跨区域协作是否允许。 | 建议员工仅编辑本人商机；渠道管理员仅在本渠道商内分配；首批不允许跨渠道、跨区域转交或协作。 |
| 跟进与待办 | 明确下次跟进时间是否必填、到期起算时点、提醒频率、逾期处理人和关闭条件。 | 建议提交跟进时必须填写下次跟进时间；仅向当前负责人生成站内待办；具体催办频率待 D2-07 确认前不启用。 |

### 3.2 已确认默认规则下的关闭范围

从已审批报备创建商机、商机编辑、相邻阶段推进、渠道内分配、跟进和本人待办可进入受控开发；跨渠道、跨区域协作和转交继续关闭。历史与现有商机在完成状态映射和双端对账前仅允许授权范围查询，不得把未映射的历史状态作为手机端写入目标。

### 3.3 验收证据

1. 历史状态映射表、至少 30 条脱敏历史记录回放结果及电脑端对账结果。
2. 未审核通过的报备无法创建商机；创建人、渠道商、区域均由会话与关联报备确定。
3. 跳级、无原因结案、伪造负责人、跨渠道和跨区域转交均被服务端拒绝。
4. 并发阶段推进和重复跟进只产生一次有效状态或事件，并返回可识别冲突结果。
5. 到期待办只对授权人员可见；登录后深链恢复不会泄露无权商机内容。

## 4. D2-03：价格与折扣

### 4.1 必须确认的最小规则

| 决策点 | 必须填写的最终选择 | 建议默认值（未确认，不得直接实施） |
|---|---|---|
| 价格簿 | 明确唯一数据来源、版本编号、生效与失效时间、发布责任人、回滚方式及过期报价处理方式。 | 本轮手机端不做报价试算和提交；转订单只读取电脑端已确认报价中已经冻结的价格簿版本快照。 |
| 适用优先级 | 明确区域、合作级别、分销层级、产品、套餐、硬件、维保和点数等规则的优先级及冲突处理。 | 建议以书面优先级矩阵为唯一依据；任一维度缺失或冲突时不返回可提交价格，只提示补齐规则。 |
| 税费、币种与取整 | 明确报价是否含税、税率来源、币种、汇率来源、精度、舍入规则及展示格式。 | 建议首批仅启用业务确认的单一币种；金额精度和税率均由财务负责人签署的规则表提供；未提供时只允许目录查询，不允许试算或提交。 |
| 折扣阈值与审批 | 明确各产品、区域、合作级别的无审批阈值、审批层级、超限处理时限、驳回后的修改规则及替补审批人。 | 建议没有书面阈值时仅允许零折扣；任何非零折扣均不得提交或转订单。若启用审批，发起人与审批人不得为同一账号。 |
| 报价有效期与转订单 | 明确报价有效期、过期后处理、确认条件、是否允许修改和一次报价可转订单次数。 | 建议主状态仅使用 `draft → sent → confirmed → converted`，任意可用状态可进入 `expired`；未确认或已转单报价不得再次转单。 |

### 4.2 已确认默认规则下的关闭范围

手机端只允许读取电脑端已确认报价并发起转订单；服务端试算、报价草稿、报价提交、折扣审批、报价确认、报价打印和外部分享继续关闭。转订单时必须使用电脑端报价快照，若报价不是 `confirmed`、已转单、已过期、无权限或缺少可用快照，服务端必须拒绝。任何前端金额、税额、折扣、渠道等级或价格簿版本均不得直接写入业务记录。

### 4.3 验收证据

1. 手机端无新建报价、编辑报价、价格试算、折扣审批、报价确认、报价打印和外部分享入口。
2. 直接调用手机端相关报价写接口返回 `403 FEATURE_DISABLED`，且不产生业务数据、金额快照或审批事件。
3. 只有电脑端已确认、未转单、未过期且当前账号有权限的报价可以转订单。
4. 同一报价以相同幂等键转订单仅产生一张订单；同一报价再次转单返回冲突。
5. 报价、订单的产品项、金额、价格簿版本、审批结果和审计事件在电脑端、移动端及日对账结果中一致。

## 5. D2-04：多级渠道订单

### 5.1 必须确认的最小规则

| 决策点 | 必须填写的最终选择 | 建议默认值（未确认，不得直接实施） |
|---|---|---|

| 选择与改选时点 | 明确在报价、订单草稿、订单提交或一级确认前的哪个节点选定上级；明确能否改选、谁可改和改选后如何审计。 | 建议在订单草稿提交前选定；订单进入 `pending` 后禁止改选。若需改选，原订单保持不可修改并按书面流程创建新草稿。 |

| 履约责任 | 明确厂商、区域管理员、一级渠道、二级渠道在处理、发货、完成、异常及客户沟通中的职责和可操作状态。 | 建议首批由本区域管理员执行厂商处理、发货和完成；渠道端仅查看与参与其被授权的一级确认，不在手机端开放层级维护。 |

### 5.2 已确认默认规则下的关闭范围

二级渠道上级选择、订单创建、一级确认或驳回、履约状态推进及相关站内通知可进入受控开发；手机端渠道层级、绑定、解绑、改绑和创建二级渠道商继续关闭。电脑端既有关系配置不因移动端建设而改变。

### 5.3 验收证据

1. 已签署的一级、二级渠道关系示例、变更处置表和履约责任矩阵。
2. 二级渠道只能选择已绑定、同区域、有效的一级渠道；不存在有效上级时不能提交订单。
3. 非指定一级渠道、普通员工、跨区域管理员均不能确认或驳回订单；驳回缺少原因时被拒绝。
4. 非二级订单与二级订单均只能按确认状态机推进，重复确认、重复发货和非法跳转均不产生副作用。
5. 关系变更、关闭 V2 写入后，历史订单的报价快照、确认记录、金额和电脑端处理能力保持一致。

## 6. D2-05：订单调价与取消

### 6.1 必须确认的最小规则

| 决策点 | 必须填写的最终选择 | 建议默认值（未确认，不得直接实施） |

| 可调价状态与范围 | 明确哪些订单状态允许调价、按金额还是比例限制、是否允许增加与减少金额、可处理区域及例外范围。 | 建议在首批生产灰度中保持调价写入关闭；如后续开放，仅允许书面指定的未发货订单状态，金额上下限由财务参数表配置。 |
| 发起与复核 | 明确发起角色、复核角色、是否强制双人复核、超额升级路径和处理时限。 | 建议发起人与复核人必须不同；区域管理员仅处理本区域，超级管理员仅处理书面登记的全局例外。 |
| 再次验证与二次确认 | 明确使用密码重验、统一身份认证重验或短信验证；明确失败次数、有效期、设备变更及审计要求。 | 建议采用已获安全负责人批准的独立再次验证方式，有效期不超过 5 分钟；未通过再次验证不得创建调价申请。 |
| 快照与版本 | 明确调价后是新订单版本还是等价不可修改快照；明确报价快照、税额、审批、对账和电脑端展示处理。 | 建议每次调价保留不可修改的调前、调后快照及原因、操作者、复核者、时间和请求编号；调价不得改变订单主状态。 |
| 取消与退款 | 明确可取消状态、发起与审批角色、退款责任边界、金额计算、外部支付或发票影响和补偿流程。 | 建议首批移动端不开放取消与退款写入；仅展示历史状态，待财务、运营和法务共同签署后另行实施。 |

### 6.2 已确认默认规则下的关闭范围

调价申请、调价复核、调价生效、订单取消和退款写入在首批继续冻结；仅允许查看现有订单、报价快照和历史调价记录。对应服务端高风险写入开关必须保持关闭。

### 6.3 验收证据

1. 财务、运营、安全共同签署的可调价状态、限额、审批、再次验证、取消与退款流程，附正负金额及税费样例。
2. 开关关闭时所有调价、取消、退款写请求均被拒绝，且不修改订单或快照。
3. 无再次验证、再次验证过期、无原因、负金额、越限、越区、同人复核和非法状态均被拒绝。
4. 相同幂等键只产生一条调价事件；并发复核和重复提交不会形成重复版本或金额差异。
5. 调价前后金额、税额、报价快照、订单版本、审计和电脑端记录可逐笔对账；关闭写入后历史记录仍可查询。

### 7.2 已确认默认规则下的关闭范围

手机端账号审批、成员停用、角色变更、渠道商状态变更、账号恢复和在途单据移交写入继续关闭；仅实现当前会话状态校验、退出、授权范围查询、状态展示和会话撤销联动。独立认证、令牌撤销联动和生产门禁完成前，不得生产开放移动端写入。

### 7.3 验收证据

1. 经数据盘点确认的账号、渠道商状态映射表，以及在途单据与草稿处置矩阵。
2. 停用、驳回、密码重置、角色变更或渠道商停用后，旧令牌下一次请求均失效，草稿被清理且无敏感数据残留。
3. 用户不能通过请求字段、深链或缓存恢复旧角色、旧渠道商或旧区域的数据权限。
4. 账号审批和移交如获开放，必须具备再次验证、幂等、双人复核（如适用）、完整审计和电脑端一致性证据。
5. 恢复账号后只能以新登录会话访问恢复时被授予的数据范围，旧会话不得复活。

## 11. 当前结论

D2-01 至 D2-07 已按建议默认值确认，且本轮范围已收缩为：商机跟进可做，电脑端已确认报价转订单可做，手机端新建报价和报价制作相关能力关闭。二期可以进入受控的核心业务写入开发、接口契约、数据迁移准备和隔离验收。P2-01 至 P2-07 仍未形成生产准入签署记录；因此当前已发布版本继续只允许受控只读联调，尚不得开放生产入口、独立认证、报备提交、商机写入、转订单、审批、调价、取消、退款、账号处置或外部通知。
