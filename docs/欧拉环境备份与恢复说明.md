# 联软渠道管理平台欧拉/Ubuntu环境备份与恢复说明

## 一、文档目的

本文说明联软渠道管理平台在欧拉或 Ubuntu 服务器上的备份与恢复方案，适用于以下生产目录：

```bash
/home/liulonghai/lianruan-crm-deploy-v2.2.0
```

备份文件默认保存到：

```bash
/home/liulonghai/backup
```

本方案目标是先保证短期最稳的单机备份能力：每天凌晨 1 点自动生成完整备份包，数据库使用 SQLite 在线备份生成一致性快照，恢复脚本支持临时恢复演练和正式覆盖恢复。

## 二、方案边界

本方案是备份与恢复方案，不是热备、双活或高可用方案。

当前系统仍是单主服务架构，数据库为 SQLite 文件。备份可以降低误删、磁盘故障、程序升级失败带来的恢复风险，但不能做到故障后零丢数，也不能替代异地容灾。

异地备份已在脚本中预留配置位，当前默认不启用。

## 三、备份脚本

备份脚本路径：

```bash
/home/liulonghai/lianruan-crm-deploy-v2.2.0/scripts/backup_euler.sh
```

恢复脚本路径：

```bash
/home/liulonghai/lianruan-crm-deploy-v2.2.0/scripts/restore_euler.sh
```

推荐统一从项目启动脚本进入备份功能：

```bash
bash scripts/start.sh backup-install
bash scripts/start.sh backup-check
bash scripts/start.sh backup
bash scripts/start.sh backup-list
bash scripts/start.sh backup-restore-test
```

说明：

1. `bash scripts/start.sh install` 会在首次部署时自动尝试安装备份依赖，并安装每天凌晨 1 点的备份定时任务。
2. 如果备份初始化失败，业务服务仍会继续启动，避免因为系统源或 `crontab` 问题阻塞业务；修复后重新执行 `bash scripts/start.sh backup-install` 即可。
3. 项目目录整体丢失时，`scripts/start.sh` 也会随项目一起丢失，此时应使用 `/home/liulonghai/backup/rescue/restore_euler.sh` 做应急恢复。

## 四、备份内容

备份包包含以下内容：

| 类型 | 内容 | 说明 |
|---|---|---|
| 主业务数据库 | `backend/crm.db` | 使用 SQLite 在线备份生成一致性快照 |
| 审计数据库 | `backend/audit.db` | 使用 SQLite 在线备份生成一致性快照 |
| 后端项目文件 | `backend/` | 排除运行中的数据库原文件，替换为一致性快照 |
| 前端项目文件 | `frontend/` | 静态页面、脚本、样式 |
| 运维脚本 | `scripts/` | 启停、备份、恢复、测试脚本 |
| 项目文档 | `docs/` | 交付文档、运维文档、接口文档 |
| 上传目录 | `backend/uploads/` | 如有导入或附件临时数据会随项目目录备份 |
| 开放接口日志 | `backend/open-api-access.log` | 如果文件存在，会随项目目录备份 |
| 企业台账 | `backend/customer-ledger.csv` | 如果文件存在，会随项目目录备份 |
| 备份清单 | `backup_meta/manifest.txt` | 记录备份类型、时间、项目路径、保留策略 |
| 文件校验和 | `backup_meta/SHA256SUMS.txt` | 用于恢复前校验备份包内容 |

## 五、备份频率与保留策略

每天凌晨 1 点执行一次自动备份。

自动判断备份类型：

| 日期规则 | 备份类型 | 是否包含 `node_modules` | 默认保留 |
|---|---|---|---|
| 每月 1 日 | 月备份 | 包含 | 12 份 |
| 每周一 | 周备份 | 包含 | 12 份 |
| 其他日期 | 日备份 | 不包含 | 30 天 |
| 手动备份 | 手动备份 | 默认按命令参数 | 30 天 |

说明：每日备份不包含 `node_modules`，减少备份体积；每周和每月备份包含 `node_modules`，方便在依赖源不可用时做完整恢复。

## 六、标准目录结构

备份根目录不再直接堆放备份包，所有备份文件按类型和日期分层存放：

```text
/home/liulonghai/backup/
├── README.md                         # 备份目录说明
├── daily/                            # 每日备份
│   └── 2026/
│       └── 07/
│           ├── lianruan-crm-daily-20260721_010000.tar.gz
│           └── lianruan-crm-daily-20260721_010000.tar.gz.sha256
├── weekly/                           # 每周备份
│   └── 2026/
│       ├── lianruan-crm-weekly-20260727_010000.tar.gz
│       └── lianruan-crm-weekly-20260727_010000.tar.gz.sha256
├── monthly/                          # 每月备份
│   └── 2026/
│       ├── lianruan-crm-monthly-20260801_010000.tar.gz
│       └── lianruan-crm-monthly-20260801_010000.tar.gz.sha256
├── manual/                           # 手动备份
│   └── 2026/
│       └── 07/
├── latest/                           # 最新备份指针
│   ├── latest-backup.txt
│   ├── latest-daily.txt
│   ├── latest-weekly.txt
│   ├── latest-monthly.txt
│   └── latest-manual.txt
├── indexes/                          # 备份索引
│   └── backup-index.tsv
├── logs/                             # 定时任务日志
├── rescue/                           # 项目目录丢失时使用的应急恢复工具
│   ├── backup_euler.sh
│   ├── restore_euler.sh
│   └── 项目目录丢失应急恢复.md
├── restores/                         # 临时恢复演练目录
└── .system/                          # 脚本工作目录和锁文件
```

说明：

1. `daily/`、`weekly/`、`monthly/`、`manual/` 用于按备份类型快速定位备份包。
2. `latest/` 中保存最新备份包路径，恢复脚本执行 `latest` 时会优先读取这里。
3. `indexes/backup-index.tsv` 是备份索引表，可以直接查看备份时间、类型、大小和相对路径。
4. `rescue/` 中保存应急恢复脚本和说明，项目目录整体丢失时从这里恢复。
5. `.system/` 是脚本内部工作目录，不需要人工操作。

## 七、首次部署步骤

进入项目目录：

```bash
cd /home/liulonghai/lianruan-crm-deploy-v2.2.0
```

赋予脚本执行权限：

```bash
chmod +x scripts/start.sh scripts/backup_euler.sh scripts/restore_euler.sh
```

如果是首次部署并需要同时启动业务，执行：

```bash
bash scripts/start.sh install
```

该命令会依次完成：

1. 安装后端业务依赖。
2. 尝试安装备份依赖。
3. 尝试安装每天凌晨 1 点的自动备份任务。
4. 启动后端和前端服务。

如只安装备份功能，执行：

```bash
bash scripts/start.sh backup-install
```

说明：

1. 欧拉环境会优先使用 `dnf` 或 `yum` 安装 `sqlite`、`rsync`、`tar`、`coreutils`、`cronie`。
2. Ubuntu 环境会使用 `apt-get` 安装 `sqlite3`、`rsync`、`tar`、`coreutils`、`cron`。
3. 如果欧拉的 `update` 软件源返回 404，脚本会自动尝试使用 `--disablerepo=update` 重试。
4. 定时任务服务会自动识别：欧拉为 `crond`，Ubuntu 为 `cron`。

检查备份环境：

```bash
bash scripts/start.sh backup-check
```

查看已安装的备份定时任务：

```bash
bash scripts/start.sh backup-cron
```

## 八、手动备份命令

按当天规则执行备份：

```bash
bash scripts/start.sh backup
```

强制执行日备份，不包含 `node_modules`：

```bash
bash scripts/start.sh backup --type daily
```

强制执行周备份，包含 `node_modules`：

```bash
bash scripts/start.sh backup --type weekly
```

强制执行月备份，包含 `node_modules`：

```bash
bash scripts/start.sh backup --type monthly
```

执行手动备份并包含 `node_modules`：

```bash
bash scripts/start.sh backup --type manual --include-node-modules
```

查看备份列表：

```bash
bash scripts/start.sh backup-list
```

整理历史散落备份：

```bash
bash scripts/start.sh backup-organize
```

说明：`organize` 会把已经散落在 `/home/liulonghai/backup` 根目录下的旧备份包，按文件名中的备份类型和日期移动到标准目录中，并重建 `latest/` 和 `indexes/`。

## 十、恢复前校验

校验最新备份包：

```bash
bash scripts/start.sh backup-verify
```

校验指定备份包：

```bash
bash scripts/start.sh backup-verify /home/liulonghai/backup/daily/2026/07/lianruan-crm-daily-20260721_010000.tar.gz
```

校验内容包括：

1. 备份包可以正常解压。

3. `crm.db` 完整性检查返回 `ok`。
4. `audit.db` 完整性检查返回 `ok`。

## 十一、恢复演练

恢复演练不会覆盖正式项目目录，建议每周至少执行一次。

恢复最新备份到默认临时目录：

```bash
bash scripts/start.sh backup-restore-test
```

默认会恢复到 `/home/liulonghai/backup/restores/restore-test-年月日_时分秒/`。

恢复最新备份到指定目录：

```bash
bash scripts/start.sh backup-restore-test latest /home/liulonghai/restore-test
```

进入临时恢复目录检查：

```bash
cd /home/liulonghai/restore-test
bash scripts/start.sh start
```

检查内容建议包括：

1. 管理员账号可登录。
2. 客户、渠道商、商机、报价、订单数据可查询。
3. 审计日志可查询。
4. 前端页面可以正常访问。
5. 后端日志无数据库损坏报错。

演练完成后停止临时服务：

```bash
cd /home/liulonghai/restore-test
bash scripts/start.sh stop
```

## 十二、正式恢复

正式恢复会覆盖生产项目目录，执行前必须确认业务窗口和操作人。

使用最新备份正式恢复：

```bash
cd /home/liulonghai/lianruan-crm-deploy-v2.2.0
bash scripts/start.sh backup-restore-live
```

使用指定备份包正式恢复：

```bash
cd /home/liulonghai/lianruan-crm-deploy-v2.2.0
bash scripts/start.sh backup-restore-live /home/liulonghai/backup/daily/2026/07/lianruan-crm-daily-20260721_010000.tar.gz
```

正式恢复流程如下：

1. 解压并校验备份包。
2. 校验主业务库和审计库完整性。
3. 要求输入 `yes` 二次确认。
4. 自动执行一次恢复前手动备份。
5. 调用 `scripts/start.sh stop` 停止当前服务。
6. 用备份内容覆盖正式项目目录。
7. 再次校验恢复后的 `crm.db` 和 `audit.db`。
8. 调用 `scripts/start.sh start` 启动服务。

## 十三、项目目录整体丢失时恢复

如果整个项目目录丢失或严重损坏，例如：

```bash
/home/liulonghai/lianruan-crm-deploy-v2.2.0
```

仍然可以恢复，前提是备份目录仍然存在：

```bash
/home/liulonghai/backup
```

### 1. 检查备份目录

```bash
cd /home/liulonghai/backup
ls -l
ls -l latest rescue indexes
cat latest/latest-backup.txt
```

### 2. 安装依赖

```bash
bash /home/liulonghai/backup/rescue/backup_euler.sh install-deps
```

### 3. 校验最新备份

```bash
BACKUP_ROOT=/home/liulonghai/backup \
PROJECT_DIR=/home/liulonghai/lianruan-crm-deploy-v2.2.0 \
bash /home/liulonghai/backup/rescue/restore_euler.sh verify latest
```

### 4. 先做临时恢复演练

```bash
BACKUP_ROOT=/home/liulonghai/backup \
PROJECT_DIR=/home/liulonghai/lianruan-crm-deploy-v2.2.0 \
bash /home/liulonghai/backup/rescue/restore_euler.sh restore-temp latest /home/liulonghai/backup/restores/emergency-test
```

### 5. 正式重建项目目录

```bash
BACKUP_ROOT=/home/liulonghai/backup \
PROJECT_DIR=/home/liulonghai/lianruan-crm-deploy-v2.2.0 \
bash /home/liulonghai/backup/rescue/restore_euler.sh restore-live latest
```

说明：

1. 如果项目目录不存在，恢复脚本会按灾难恢复场景处理，跳过恢复前备份和停服，直接创建项目目录并恢复。
2. 如果恢复的是日备份，可能不包含 `node_modules`，恢复后需要在 `backend/` 下执行 `npm install`。
3. 如果 `/home/liulonghai/backup` 也丢失，本机无法恢复，必须依赖异地备份或其他服务器副本。

## 十四、异地备份预留配置

当前异地备份默认关闭：

```bash
REMOTE_BACKUP_ENABLED=0
```

后续如需要启用，可以设置异地目标：

```bash
REMOTE_BACKUP_ENABLED=1 \
REMOTE_BACKUP_TARGET=backup-user@backup-server:/data/lianruan-crm-backup \
bash scripts/start.sh backup
```

启用前必须先确认：

1. 服务器之间免密登录已配置。
2. 异地目录容量足够。
3. 异地备份服务器权限最小化。
4. 至少做一次异地备份恢复演练。

## 十五、常见问题

### 1. 提示缺少 `sqlite3`

优先执行自动依赖安装：

```bash
bash scripts/start.sh backup-install
```

### 2. 提示缺少 `rsync`

优先执行自动依赖安装：

```bash
bash scripts/start.sh backup-install
```

### 3. 欧拉安装依赖时报 `update` 源 404

如果看到类似错误：

```bash
Errors during downloading metadata for repository 'update'
Cannot download repomd.xml
```

优先执行脚本自动安装：

```bash
bash scripts/start.sh backup-install
```

脚本会自动尝试禁用失效的 `update` 源后重试。也可以手工执行：

```bash
sudo dnf --disablerepo=update install -y sqlite rsync tar coreutils cronie
```

如果仍失败，说明服务器软件源配置需要运维修复。建议检查：

```bash
ls -l /etc/yum.repos.d/
```

长期建议是修复或关闭失效的 openEuler `update` 软件源，不建议长期依赖不可用的软件源配置。

### 4. 定时任务没有执行

欧拉检查定时任务服务：

```bash
systemctl status crond
```

Ubuntu 检查定时任务服务：

```bash
systemctl status cron
```

欧拉启动定时任务服务：

```bash
sudo systemctl enable --now crond
```

Ubuntu 启动定时任务服务：

```bash
sudo systemctl enable --now cron
```

查看定时任务：

```bash
crontab -l
```

查看备份日志：

```bash
tail -100 /home/liulonghai/backup/logs/backup-cron.log
```

### 5. 备份失败提示已有任务运行

说明上一次备份还未结束，或异常退出留下锁目录。

先确认没有正在运行的备份进程：

```bash
ps -ef | grep backup_euler.sh | grep -v grep
```

如果确认没有备份进程，再删除锁目录：

```bash
rm -rf /home/liulonghai/backup/.system/backup.lock
```

### 6. 日备份恢复后缺少 `node_modules`

这是预期行为。日备份默认不包含 `node_modules`。

处理方式一：执行依赖安装：

```bash
cd /home/liulonghai/lianruan-crm-deploy-v2.2.0/backend
npm install
```

处理方式二：选择最近一次周备份或月备份恢复。

## 十六、运维检查清单

每天检查：

1. `/home/liulonghai/backup/daily/年/月/` 下是否生成新的日备份包。
2. `/home/liulonghai/backup/latest/latest-backup.txt` 是否指向最新备份包。
3. `/home/liulonghai/backup/indexes/backup-index.tsv` 是否有最新记录。
4. `/home/liulonghai/backup/logs/backup-cron.log` 是否有失败信息。
5. 备份目录磁盘空间是否充足。

每周检查：

1. 执行一次 `restore-temp` 恢复演练。
2. 确认恢复后的系统能启动。
3. 确认主业务库和审计库完整性检查通过。
4. 抽查客户、商机、报价、订单、审计日志。

每月检查：

1. 确认月备份包含 `node_modules`。
2. 确认历史备份按保留策略清理。
3. 评估是否需要启用异地备份。

## 十七、关键提醒

1. 不要只备份 `backend/data.json`，当前真实业务数据在 `backend/crm.db` 和 `backend/audit.db`。
2. 不建议在服务运行时直接复制 `.db`、`.db-wal`、`.db-shm` 作为唯一备份方式。
3. 正式恢复前必须先做恢复前备份。
4. 正式恢复必须安排业务窗口，避免用户正在写入数据。
5. 本机备份不能防服务器整机损坏，后续仍建议启用异地备份。
6. 项目目录整体丢失时，优先使用 `/home/liulonghai/backup/rescue/restore_euler.sh` 恢复。
