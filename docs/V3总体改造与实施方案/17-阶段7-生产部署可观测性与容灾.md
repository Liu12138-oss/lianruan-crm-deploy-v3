# 阶段 7：生产部署、可观测性与容灾

## 1. 阶段目标

把已经完成业务迁移的 V3 构建为可重复部署、可监控、可告警、可备份、可恢复和可回退的生产候选版本。首发按一台服务器容器化部署，同时验证应用无状态和未来多机扩展能力。

本阶段不接入 V2 最终生产数据，不正式对用户开放。

## 2. 前置条件

- 阶段 1 至阶段 6 全部通过验收。
- 新后端、新前端、任务进程和 PostgreSQL 数据迁移在预生产环境完整运行。
- 生产硬件、操作系统、域名、证书、异机备份、通知渠道和负责人已确认。
- 单机整机故障的可用性例外或备用服务器方案已书面确认。

## 3. 计划周期和分工

建议周期：4 至 6 周。

| 角色 | 责任 |
| --- | --- |
| 运维负责人 | 主机、容器、网络、证书、备份、监控、告警和发布脚本 |
| 后端负责人 | 健康检查、优雅停止、指标、日志、数据库参数和降级 |
| 前端负责人 | 生产构建、缓存、安全头、错误上报和版本展示 |
| 测试负责人 | 压力、长稳、故障、安全、恢复和发布验收 |
| 产品负责人 | 业务验收、停机提示、维护窗口和风险签字 |

备份进程可以使用受控临时容器或主机定时服务，但配置和版本必须进入交付清单。

## 5. 任务清单

### S7-01 固化生产镜像

执行内容：

1. 建立接口、任务和前端构建的多阶段镜像。
2. 运行镜像只保留运行依赖，使用非特权用户。
3. 固定基础镜像摘要和依赖锁，生成软件组成清单。
4. 镜像写入应用版本、提交编号、构建时间和契约版本。
5. 对镜像执行漏洞扫描、恶意文件扫描和密钥扫描。
6. 构建产物从预生产晋级，不在生产服务器执行 `npm install` 或编译。

验收：同一镜像在预生产和生产候选环境行为一致；高危漏洞有修复或书面例外。

### S7-02 建立单服务器 Compose 编排

执行内容：

1. 建立 `deploy/single-server`，固定所有镜像版本。
2. 区分入口网络、应用网络和数据网络。
3. 数据库和 Redis 不暴露宿主公网端口。
4. 设置健康检查、依赖顺序、重启策略、优雅停止和资源限制。
5. 持久卷使用明确宿主目录，避免匿名卷无法恢复。
6. 接口两个实例使用相同镜像和配置，仅实例编号不同。
7. 任务进程有独立连接和资源预算。

验收：重启全部容器、重启单个容器和重启服务器后服务按预期恢复，持久数据存在。

### S7-03 配置 Nginx 和 HTTPS

执行内容：

1. 443 提供统一入口，80 只跳转。
2. 静态资源和 `/api` 同源，后端实例使用内部地址。
3. 配置请求大小、上传超时、普通接口超时、限流和连接限制。
4. 接口转发携带请求编号和可信来源信息。
5. 配置安全响应头；入口文件短缓存，摘要静态资源长期缓存。
6. 健康接口只返回必要状态，依赖详情限制管理来源。
7. 证书续期流程和到期告警实际验证。

验收：外部端口扫描只看到批准端口；HTTP 强制跳转；安全头和证书链通过检查。

### S7-04 建立生产配置和密钥管理

执行内容：

1. 为数据库、Redis、会话、外部身份、开放接口和备份创建独立密钥。
2. 密钥文件权限限制到部署账号和运行容器。
3. 记录密钥所有者、创建、轮换、撤销和应急流程。
4. 环境示例文件不包含真实值，日志启动摘要只显示掩码。
5. 验证轮换会话密钥、开放接口密钥和数据库密码的影响及步骤。

验收：代码、镜像、前端构建、普通日志和备份报告不包含密钥明文。

### S7-05 调整 PostgreSQL 生产参数

执行内容：

1. 根据实际处理器、内存和磁盘设置内存、连接、日志、检查点和自动清理参数。
2. 使用 PgBouncer 控制应用总连接并保留运维连接。
3. 安装并启用经批准的统计扩展，如 `pg_stat_statements` 和 `pg_trgm`。
4. 设置慢查询、锁等待、临时文件和死锁日志。
5. 建立数据库账号最小权限：应用、迁移、备份、监控分别授权。
6. 压力和长稳测试后再定稿参数，不直接照搬通用模板。

验收：连接预算、慢查询、锁和自动清理指标可见；应用账号无法修改结构。

### S7-06 配置 Redis 生产参数

执行内容：

1. 开启 AOF 每秒刷盘和受控快照。
2. 设置认证、内部网络、最大内存和淘汰策略。
3. 队列和缓存使用明确前缀，避免缓存淘汰影响任务。
4. 建立慢命令、大键、热键、持久化失败和内存告警。
5. 验证重启恢复、AOF 重写和异常文件恢复流程。

验收：Redis 重启后会话按策略恢复或失效，任务可由 PostgreSQL补投，业务数据无损。

### S7-07 建立日志系统

执行内容：

1. 接口、任务、Nginx、PostgreSQL和 Redis 日志汇总到 Loki。
2. 应用日志使用结构化字段和统一请求编号。
3. 设置日志大小、保留期、压缩和磁盘上限。
4. 建立密码、令牌、密钥、Cookie、手机号和敏感字段脱敏测试。
5. 生产默认不输出调试级别和完整请求体。

验收：通过一个请求编号可以查到入口、接口、任务和审计链路；敏感扫描无泄露。

### S7-08 建立指标、看板和告警

执行内容：

1. 部署主机、容器、接口、Node.js、PostgreSQL、Redis、Nginx 和任务指标。
2. 建立总体、数据库、Redis、任务、登录安全和备份看板。
3. 告警分三级，包含中文影响、当前值、责任人和处理手册。
4. 配置独立于生产服务器的外部存活探测。
5. 逐条人为触发接口不可用、磁盘阈值、备份失败、队列积压和证书到期测试告警。

验收：每条一级和二级告警都至少实际触发一次并确认通知到达。

### S7-09 建立 PostgreSQL 备份和恢复

执行内容：

1. 使用 pgBackRest 配置持续归档、每日增量和每周全量。
2. 备份写入异机存储，传输和静态存储加密。
3. 监控最后成功备份、归档延迟、恢复点和存储容量。
4. 自动恢复到隔离数据库并运行数量、约束和抽样业务校验。
5. 记录恢复命令、凭据获取、负责人和预计时间。

验收：恢复点不超过 5 分钟；在目标 30 分钟内完成既定规模恢复，或对单机整机故障形成书面例外和备用机改进计划。

### S7-10 建立文件和配置备份

执行内容：

- 备份上传文件、未过期导出文件、生产配置模板、密钥恢复材料和部署清单。
- 密钥恢复材料独立加密并双人保管。
- 数据库备份和文件备份记录同一恢复演练批次。
- 禁止把本地日志目录整体当作长期备份。

验收：从备份恢复后，必要业务文件摘要一致，过期文件不要求恢复。

### S7-11 建立发布、回退和维护脚本

至少提供：

- 发布前检查。
- 数据库迁移预检和执行。
- 单实例滚动替换。
- 全系统状态检查。
- 旧镜像回退。
- 维护模式开启和关闭。
- PostgreSQL备份、恢复和校验。
- Redis 任务补投。
- 日志和诊断包采集。

脚本必须启用严格错误处理、输出中文步骤、拒绝空变量和错误环境，并默认不执行破坏性动作。

验收：未参与脚本编写的人员按手册在预生产完整执行一次。

### S7-12 建立预生产环境

执行内容：

1. 预生产的软件版本、容器拓扑、配置项和网络方式与生产一致。
2. 使用脱敏全量数据或接近规模的合成数据。
3. 外部依赖使用正式测试端点，不使用前端临时模拟。
4. 所有发布、迁移、回退、监控和恢复先在预生产执行。

验收：不存在“只能在生产验证”的基础部署步骤。

## 6. 完整测试计划

### 6.1 功能和权限回归

执行全部接口契约、浏览器流程、角色矩阵、金额、状态和开放接口回归。测试构建必须与生产候选镜像一致。

### 6.2 压力测试

按阶段 6 的基线、目标和峰值场景执行。额外验证两个接口实例流量分布、数据库连接预算、缓存失效、大导出和队列积压。

### 6.3 8 小时长稳测试

持续混合登录、查询、创建、状态更新、导入、导出和任务负载，观察：

- 接口错误率和延迟趋势。
- Node.js 内存和事件循环延迟。
- PostgreSQL连接、锁、慢查询、表膨胀和磁盘。
- Redis 内存、AOF、队列和大键。
- 文件和日志增长。

不得用中途重启掩盖内存泄漏。

### 6.4 故障演练

依次演练：

1. 停止一个接口实例。
2. 滚动替换两个接口实例。
3. 任务进程执行中停止。
4. Redis 重启和短时不可用。
5. PostgreSQL连接中断和数据库重启。
6. 外部身份和企业信息查询超时。
7. 磁盘达到告警阈值。
8. 备份目标短时不可用。
9. 整台预生产服务器重启。
10. 从异机备份恢复到备用环境。

每项记录用户影响、告警时间、发现时间、处理时间、数据结果和改进项。

### 6.5 安全验收

- 身份伪造、会话固定、会话撤销和暴力登录。
- 角色和数据范围越权。
- SQL 注入、脚本注入、任意文件路径和恶意上传。
- 导入导出和下载越权。
- 密钥、日志、错误、镜像和前端产物泄露。
- 安全响应头、HTTPS、端口和主机最小权限。
- 依赖和镜像高危漏洞。

严重和高风险问题必须修复后重新测试。

## 7. 单机可用性例外

如果首发仍只有一台物理服务器，项目负责人必须在上线批准中明确接受：

- 主板、处理器、内存、电源、系统盘、机房网络或操作系统整体故障会造成全站中断。
- 本机两个接口实例不能处理上述整机故障。
- 没有预装备用服务器时，30 分钟恢复目标可能无法达到。

最低补偿措施：企业级磁盘冗余、异机持续备份、外部存活监控、备用服务器恢复脚本、季度整机恢复演练。

## 8. 阶段验收门槛

- 生产候选镜像、Compose、配置、密钥和部署手册完整。
- 预生产完整发布和回退至少成功两次。
- 压力、峰值、8 小时长稳、故障、安全和恢复测试通过。
- PostgreSQL恢复点不超过 5 分钟，恢复报告可复核。
- 一级、二级告警实际触发并送达。
- 生产公网只开放批准端口，HTTPS 和安全头通过。
- 单机整机风险由负责人书面接受或已经准备备用服务器。

## 9. 回退

本阶段未接入 V2 生产数据。部署失败时保留诊断证据，回到上一个生产候选镜像和兼容数据库结构。不得删除失败环境的数据卷，直到确认无调查价值。数据库迁移遵循前向修复，不执行未经验证的破坏性回滚。

## 10. 阶段完成标志

建立 `v3-production-candidate` 标签和不可变镜像摘要，冻结生产候选版本。该版本只允许修复阻断上线的问题，任何新功能或非必要重构进入后续版本。
