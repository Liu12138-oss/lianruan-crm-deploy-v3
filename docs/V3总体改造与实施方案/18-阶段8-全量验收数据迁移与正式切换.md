# 阶段 8：全量验收、数据迁移与正式切换

## 1. 阶段目标

通过第二次、第三次全量迁移演练和正式 5 至 8 小时停机窗口，把 V2 最终数据完整迁移到 V3，完成业务验收、入口切换、受控开放和稳定期观察。V2 在切换后保持只读和可回退准备，不再接受新业务写入。

## 2. 启动条件

以下条件缺一不可：

- 阶段 0 至阶段 7 全部通过并有验收记录。
- 生产候选镜像和数据库迁移版本冻结。
- 第一轮全量迁移问题已解决。
- V2 生产数据质量阻断项已经清零或有书面隔离批准。
- 异机备份、备用恢复和外部监控可用。
- 正式停机窗口、业务通知、负责人和决策人已批准。
- 开放接口调用方知道停机和切换安排。
- 回退标准和 V3 开放后新增数据处理原则已签字。

## 3. 计划周期

建议阶段周期：3 至 4 周，其中包含两次正式规模演练、问题修正、最终迁移和至少两周重点稳定观察。正式停机窗口为其中一次受控操作。

## 4. 切换组织

| 角色 | 切换职责 |
| --- | --- |
| 总指挥 | 决定开始、继续、开放和回退 |
| 产品负责人 | 业务范围、数据抽样和用户验收 |
| 数据迁移负责人 | 快照、导出、装载、校验和迁移报告 |
| 后端负责人 | 接口、任务、数据库版本和故障定位 |
| 前端负责人 | 静态资源、入口、缓存和浏览器验证 |
| 运维负责人 | 维护模式、容器、网络、备份、监控和切换 |
| 测试负责人 | 自动回归、权限、金额、状态和业务冒烟 |
| V2 负责人 | V2 停写、快照和必要回退开放 |
| 业务代表 | 账号、渠道、报备、商机、报价和订单抽样 |
| 记录员 | 记录时间、命令、结果、异常和决策 |

关键角色必须有替补，正式窗口内所有人保持可联系。

## 5. 第二次全量迁移演练

### S8-01 使用最新快照执行全量演练

执行内容：

1. 使用比第一次更新的 V2 一致性快照。
2. 完整执行维护模式、快照、导出、临时装载、清洗、关系装载和校验。
3. 使用生产同规格或可换算环境测量耗时。
4. 执行全部自动回归和业务抽样。
5. 记录每个步骤时间预算和最长路径。

验收：迁移数据校验通过，完整流程不超过 8 小时；目标是在 6 小时内完成，为异常保留至少 2 小时。

### S8-02 消除演练问题

- 脚本问题通过版本化代码修复。
- 数据问题进入映射、补录或批准隔离流程。
- 性能问题通过批量、索引、连接和磁盘调整解决。
- 操作问题更新运行手册和责任分工。
- 禁止保留“正式迁移时手工处理”的未脚本化关键步骤。

## 6. 第三次全流程演练

### S8-10 完全模拟正式切换

第三次演练使用正式人员分工、正式命令、正式时间表、正式通知模板和生产候选镜像。演练至少覆盖一次回退决策和一次恢复到 V3 的前进修复。

验收：

- 5 至 8 小时窗口内完成。
- 每个命令有执行人和复核人。
- 不依赖编写脚本人员临时解释。
- 回退后 V2 能恢复测试访问，且源数据未被迁移脚本修改。
- 所有校验和告警按手册工作。

## 7. 正式切换前准备

### T-14 天

- 冻结 V3 生产候选版本和数据库结构。
- 公布停机窗口、影响范围和联系方式。
- 确认 V2、V3、域名、证书、备份和外部调用方清单。
- 清理第二次演练遗留问题。

### T-7 天

- 完成第三次全流程演练。
- 确认生产磁盘、异机备份容量和网络速度。
- 检查 V2 数据质量增量问题。
- 生成正式迁移包和摘要。
- 验证所有账号、密钥和应急访问。

### T-3 天

- 完成生产 V3 空库结构迁移和基础配置。
- 部署生产候选镜像但不开放用户入口。
- 验证外部身份、企业信息查询和开放接口网络。
- 完成 V2 可恢复备份。

### T-1 天

- 再次检查 V2 数据统计和磁盘。
- 禁止非必要 V2 配置和批量数据变更。
- 确认切换群组、电话、人员和替补。
- 确认维护页面和用户通知。
- 总指挥执行开始前检查并签字。

## 8. 5 至 8 小时正式迁移时间表

以下为 8 小时上限计划，第三次演练后可按实测缩短，但不得压缩校验和回退决策时间。

| 时间 | 目标 | 主要动作 | 继续门槛 |
| --- | --- | --- | --- |
| 第 0:00 至 0:30 | 停止业务写入 | 开启维护模式、停止 V2 接口写入、暂停开放接口和后台任务 | 验证无新增业务写入 |
| 第 0:30 至 1:10 | 保全 V2 | 停止必要进程、生成 SQLite 一致性快照、审计库快照、文件和配置备份 | 摘要、数量和异机复制成功 |
| 第 1:10 至 2:00 | 导出源数据 | 按实体流式导出，生成批次和统计 | 文件摘要和实体数量通过 |
| 第 2:00 至 3:00 | 装载临时层 | 批量导入 PostgreSQL临时迁移表 | 导入数量守恒、无损坏文件 |
| 第 3:00 至 4:20 | 转换正式表 | 按依赖顺序清洗、映射和装载 | 无阻断状态、角色、关联和金额错误 |
| 第 4:20 至 5:10 | 全量数据校验 | 数量、唯一、外键、状态、金额、权限和摘要 | 全部自动门槛通过 |
| 第 5:10 至 6:00 | 应用验证 | 启动接口、任务和前端，执行接口及浏览器冒烟 | 核心流程和外部依赖通过 |
| 第 6:00 至 6:40 | 业务抽样 | 业务代表核对账号、渠道和销售闭环样本 | 产品、测试和业务共同确认 |
| 第 6:40 至 7:10 | 受控开放 | 先开放内部管理员，再开放少量渠道账号 | 指标、日志和数据写入正常 |
| 第 7:10 至 7:40 | 全量切换 | 切换正式入口和开放接口，扩大用户范围 | 错误率、延迟和任务正常 |
| 第 7:40 至 8:00 | 最终决策 | 总结异常、确认继续或回退 | 总指挥签署结论 |

任何前置门槛未通过，不得以“先继续后修复”进入下一步。

## 9. 停写验证

维护页面显示不等于真正停写，必须同时执行：

- Nginx 拒绝 V2 写方法或把用户入口切到维护页。
- 停止 V2 后台任务和定时脚本。
- 暂停开放接口写入和已知外部调用。
- 记录停写时各实体数量和最后更新时间。
- 等待一个确认窗口后再次查询，确保没有新增或更新。
- 保留停写开始时间和验证 SQL 或脚本结果。

## 10. V2 一致性快照

- 推荐停止 V2 后端后使用 SQLite 官方备份方式生成 `crm.db` 和 `audit.db` 一致性快照。
- 不直接复制正在写入的单个数据库文件。
- 同时保存 WAL、配置、上传和必要业务文件，具体按备份脚本执行。
- 对所有快照和导出文件计算 SHA-256，并立即复制到异机存储。
- V2 源目录保持只读，不允许迁移脚本修改。

## 11. 自动校验门槛

### 11.1 必须为零

- 未解释的记录数量差异。
- 重复用户名、业务编号和原始编号。
- 孤儿外键和渠道环形关系。
- 未映射角色、状态和区域。
- 报价、订单金额重算差异。
- 重复报价转订单。
- 明文密码和开放接口密钥进入正式表。

### 11.2 必须守恒

每个实体满足：源记录数 = 成功记录数 + 经批准隔离记录数。失败记录未获批准时不得开放。

### 11.3 必须抽样

- 每类角色至少两个账号。
- 每个主要区域和渠道层级至少一个样本。
- 报备、商机、报价、订单各覆盖最新、最旧、高金额、异常状态和跨层级样本。
- 产品、价格和工作量使用阶段 0 固定样本重算。
- 开放接口使用实际测试客户端验证权限和返回。

## 12. 受控开放顺序

1. 运维和应急管理员只验证系统状态，不处理业务。
2. 内部系统管理员验证账号、权限、配置和审计。
3. 总部或区域业务代表验证核心记录和新建测试业务。
4. 选定少量渠道管理员和员工验证渠道端与移动端。
5. 开放全部内部用户。
6. 开放全部渠道用户和开放接口。

每一级至少观察 10 至 20 分钟，具体以第三次演练确定。发现越权、金额、重复写入或数据关联错误立即停止扩大范围。

## 13. 回退决策

### 13.1 开放用户前

出现以下任一情况立即回退到 V2：

- 自动数据校验未通过。
- 核心账号无法登录或权限范围错误。
- 报价、订单金额不一致。
- 报备到订单核心流程不可用。
- 数据库、备份或监控状态不可靠。
- 剩余时间不足以完成业务抽样和安全开放。

回退动作：停止 V3，保留迁移现场和日志，恢复 V2 进程和入口，验证 V2 数据仍为停写快照状态后开放。

### 13.2 V3 已受控开放后

立即冻结 V3 写入，导出从开放开始产生的所有业务和审计增量。总指挥根据增量规模决定：

- 修复后继续 V3；或
- 人工确认增量处理方案后回到 V2。

禁止直接丢弃 V3 新增数据。出现越权、金额错误或大面积重复写入时优先冻结写入和保全证据。

### 13.3 V3 全量开放后

只有重大故障委员会可以决定回退。优先采用前进修复或从 PostgreSQL备份恢复 V3。大范围运行后直接回 V2 通常会造成新数据丢失，因此不作为默认方案。

## 14. 上线后稳定期

### 首 2 小时

- 所有技术和业务负责人在线。
- 监控错误率、延迟、登录、数据库锁、队列、磁盘和外部依赖。
- 每 30 分钟记录一次核心实体数量和任务状态。

### 首 24 小时

- 冻结非阻断发布和配置变更。
- 每 2 小时检查业务量、错误和慢查询。
- 完成第一次生产增量备份和恢复点验证。
- 处理用户问题必须记录请求编号和业务编号。

### 首 7 天

- 每日业务数量和金额对账。
- 每日检查备份、归档、队列、磁盘和审计。
- 修复只允许阻断和高风险问题，使用正式发布流程。
- V2 保持只读和可恢复，不删除。

### 首 14 天

- 完成一次生产备份隔离恢复。
- 汇总性能、错误、容量、用户问题和迁移遗留。
- 产品、技术、测试和运维共同签署稳定期结论。

## 15. V2 后续处理

稳定期通过后：

1. 保留 V2 数据库、代码、配置和迁移快照的只读归档。
2. 关闭 V2 外部入口、定时任务和写入账号。
3. 根据合规和审计要求确定归档期限。
4. V2 正式下线和资源释放作为独立变更审批，不在切换当天删除。

## 16. 阶段验收门槛

- 正式迁移在批准的 5 至 8 小时窗口内完成。
- 全量自动校验和业务抽样通过。
- 所有当前功能、角色、数据范围、金额、状态和开放接口通过验收。
- 生产备份、监控、告警、队列和外部依赖正常。
- 上线 14 天内无数据丢失、严重越权、重复转单和金额错误。
- V2 已转为只读归档，V3 成为唯一写入系统。

## 17. 阶段完成标志

发布 `v3.0.0` 正式标签，归档生产镜像摘要、数据库版本、迁移批次、源文件摘要、校验报告、业务签字、上线记录和稳定期报告。
