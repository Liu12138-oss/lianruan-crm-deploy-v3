# 阶段 1：工程化骨架与研发流水线

## 1. 阶段目标

建立能够长期承载 V3 的 TypeScript 模块化单体工程、统一依赖管理、环境配置、构建、测试、接口契约和容器化本地开发骨架。阶段结束时，新工程可以独立启动并提供健康检查，但不迁移业务功能和生产数据。

## 2. 前置条件

- 阶段 0 已通过退出会议。
- V3 已有独立版本管理基线。
- Node.js 22 和容器运行环境在开发机及构建环境验证通过。
- PostgreSQL 和 Redis 本地开发容器可用。

## 3. 计划周期和分工

建议周期：2 周。

| 责任方向 | 人数建议 | 工作重点 |
| --- | ---: | --- |
| 架构与后端 | 2 | 工作区、接口骨架、配置、日志、契约和测试 |
| 前端 | 1 至 2 | Vue 工程、布局骨架、路由和接口客户端 |
| 测试 | 1 | 测试框架、构建门禁和基线接入 |
| 运维 | 1 | 容器、镜像、配置和构建产物 |

## 4. 任务清单

### S1-01 建立 npm 工作区

执行内容：

1. 根目录建立 npm 工作区，统一管理 `apps` 和 `packages`。
2. 固定 Node.js 22 长期支持版和 npm 主版本，提交锁文件。
3. 建立 `api`、`worker`、`web`、`contracts`、`shared` 和 `testing` 空间。
4. 配置共享 TypeScript 基线，启用严格类型检查。
5. 所有脚本使用统一中文说明，命令名称保持简洁稳定。

交付物：根工作区、统一依赖锁和类型配置。

验收：全新环境执行一次依赖安装后可以完成类型检查、测试和构建。

### S1-02 建立质量工具

执行内容：

1. 配置 ESLint、Prettier 和导入顺序规则，避免大范围自定义规则。
2. 建立 `检查`、`测试`、`构建`、`开发` 和 `生产启动` 脚本。
3. 配置提交前快速检查和构建环境完整检查。
4. 禁止检查工具自动修改旧版超长源码；旧目录只进行基线测试。
5. 设置单文件和函数复杂度告警，不因历史代码一次性阻断全部迁移。

验收：新工程故意引入类型错误、格式错误和失败测试时，流水线能够阻断。

### S1-03 建立环境配置系统

执行内容：

1. 使用 Zod 校验环境变量，启动时缺少必要配置立即失败并输出中文原因。
2. 分离本地、测试、预生产和生产配置；代码中不得出现生产地址和密钥。
3. 提供无密钥的示例配置文件和字段说明。
4. 配置数据库、Redis、会话、日志、上传、外部依赖、限流和健康检查参数。
5. 敏感值输出日志时统一掩码。

验收：缺失数据库连接、会话密钥或环境标识时生产进程不能带病启动。

### S1-04 建立接口应用骨架

执行内容：

1. Express 5 应用区分应用创建和端口监听，支持测试直接加载应用。
2. 建立请求编号、结构化日志、统一错误、404、请求体限制和优雅停止。
3. 建立 `/health/live`、`/health/ready` 和 `/health/dependencies`。
4. 就绪检查验证配置、PostgreSQL、Redis 和迁移版本，依赖故障使用明确状态。
5. 统一成功和错误响应结构。
6. 设置反向代理信任边界，只有来自可信 Nginx 的转发头可用于来源地址。

验收：应用可在两个不同端口同时启动；任一实例停止不影响另一个实例。

### S1-05 建立任务应用骨架

执行内容：

1. 建立独立任务进程，不与接口进程在同一个 Node.js 进程运行。
2. 建立 Redis 连接、队列注册、任务日志和优雅停止。
3. 先实现无业务副作用的健康任务，验证入队、领取、成功、失败和重试。
4. 任务载荷通过 Zod 校验，禁止把完整会话令牌放入任务。
5. 为后续 PostgreSQL任务事实和补投机制预留接口，本阶段不实现业务任务。

验收：任务进程重启后未完成的测试任务可以按配置重试，重复执行不会产生业务数据。

### S1-06 建立前端工程骨架

执行内容：

1. 建立 Vue 3、TypeScript、Vite、Vue Router、Pinia 和 Element Plus 工程。
2. 建立统一入口、管理端、渠道端和移动端四种布局骨架。
3. 使用路由懒加载和工作空间元数据，不复制多套根应用。
4. 建立中文错误页、无权限页、会话失效页和维护页。
5. 建立统一主题变量和基础组件封装，但不在本阶段重做视觉。
6. 构建产物使用相对或同源接口地址，生产地址由部署入口决定。

验收：四种布局可通过测试路由访问，构建产物不包含密钥和固定生产接口地址。

### S1-07 建立接口契约包

执行内容：

1. 使用 OpenAPI 3.1 描述健康检查、错误响应和后续接口公共结构。
2. 从契约生成前端请求类型和测试类型。
3. 规定契约变更检查，删除字段、改变类型和状态码视为破坏性变化。
4. 兼容接口基线暂时作为独立快照，不强行一次性改写为新契约。
5. 错误代码使用稳定代码和中文消息说明。

验收：修改契约后前端客户端可以重新生成；实现与契约不一致时测试失败。

### S1-08 建立测试骨架

执行内容：

1. 后端使用 Vitest 和 Supertest，建立单元测试和接口测试分层。
2. 数据库集成测试使用独立测试数据库，测试结束自动清理测试结构。
3. 前端建立组件测试和 Playwright 浏览器测试入口。
4. 性能测试建立 k6 目录和结果模板。
5. 旧版回归测试保持独立，避免新旧依赖互相污染。

验收：单元、接口、前端和浏览器测试各有一个可重复通过的样例。

### S1-09 建立本地开发编排

执行内容：

1. 扩展现有 `deploy/local-dev/docker-compose.yml`，固定 PostgreSQL 和 Redis 补丁版本。
2. 不在版本管理中保存真实密码，开发默认值只用于本机隔离环境。
3. 增加健康检查、持久卷和一键启动、停止、状态检查脚本。
4. 提供数据库初始化、清空测试数据和查看日志的中文文档。
5. 验证 Apple 芯片和生产目标处理器架构的镜像兼容性。

验收：新开发者按文档在 30 分钟内启动完整开发骨架。

### S1-10 建立构建和持续检查

执行内容：

1. 建立本地可执行的统一流水线脚本，暂不依赖具体代码托管平台。
2. 顺序执行依赖完整性、类型检查、格式检查、单元测试、接口测试、前端构建和镜像构建。
3. 生成版本、提交编号、构建时间和依赖清单。
4. 产物不可在生产服务器二次编译。
5. 构建失败时输出中文定位说明和原始日志路径。

验收：同一提交重复构建得到等价产物；构建版本可在健康接口和前端版本信息中查看。

### S1-11 处理旧代码边界

执行内容：

1. 旧 `backend` 和 `frontend` 保持可运行，作为迁移对照。
2. 建立 `legacy` 说明文件，明确旧代码只接受基线测试修复，不接受新架构和新功能。
3. 新工程不得直接导入旧 `server.js` 或浏览器全局对象。
4. 可以提取纯计算测试样本，但实际逻辑迁移必须进入目标模块并有测试。
5. 记录旧接口到新模块的迁移状态。

验收：新旧系统可分别启动，依赖和端口互不冲突。

## 5. 推荐根命令

命令的实际英文标识遵循工具生态，文档和错误说明使用中文：

| 命令 | 用途 |
| --- | --- |
| `npm run dev` | 启动新接口、任务和前端开发环境 |
| `npm run check` | 执行类型、格式和静态检查 |
| `npm test` | 执行单元和接口测试 |
| `npm run test:e2e` | 执行浏览器回归 |
| `npm run build` | 构建全部生产产物 |
| `npm run verify` | 执行提交前完整验证 |

## 6. 阶段测试

- 从无缓存环境完整安装、检查、测试和构建。
- 两个接口实例同时启动并通过 Nginx 测试代理。
- PostgreSQL 或 Redis 停止时就绪检查正确失败，存活检查仍能区分进程状态。
- 任务进程收到停止信号后不再领取任务。
- 前端四种布局在桌面和移动视口无空白、重叠和构建错误。
- 构建产物扫描不含开发密码、生产地址、令牌和数据库连接串。

## 7. 阶段验收门槛

- 根目录一条命令可以完成完整验证。
- 新工程所有质量检查通过。
- 新工程没有业务功能和生产数据依赖。
- 旧代码没有被大范围格式化或改变行为。
- 本地开发文档由未参与编写者实际走通。
- 接口和任务进程支持优雅启动、健康检查和停止。

## 8. 回退

本阶段不替换现有业务入口。若新工程骨架失败，可删除或回退新工作区提交，旧系统仍独立运行。不得为了让新工程通过而修改旧生产依赖或数据库文件。

## 9. 阶段完成标志

建立 `v3-engineering-foundation` 基线标签，记录依赖版本、构建镜像摘要和验证报告。只有该基线通过后，阶段 2 才能开始编写正式数据库迁移。
