# 阶段 2：PostgreSQL 数据底座

## 1. 阶段目标

建立 V3 关系型数据库结构、版本化迁移、数据访问基础、V2 导出与清洗工具、迁移校验体系。阶段结束时，V2 快照可以完整迁移到 PostgreSQL，并形成可重复报告；新业务模块尚未正式接管生产流量。

## 2. 前置条件

- 阶段 0 的数据字典、状态映射和质量报告完成。
- 阶段 1 的接口应用、任务应用和测试数据库可用。
- 关键未知角色、状态、区域和渠道关系已有处理结论。
- 数据负责人和业务负责人明确异常数据签字流程。

## 3. 计划周期和分工

建议周期：4 至 6 周。

| 方向 | 人数建议 | 责任 |
| --- | ---: | --- |
| 数据架构和后端 | 2 至 3 | 关系模型、迁移、查询和约束 |
| 测试 | 1 至 2 | 数据校验、并发、性能和迁移测试 |
| 产品及业务 | 1 | 映射规则和异常数据决策 |
| 运维 | 1 | PostgreSQL 参数、备份和迁移运行环境 |

## 4. 任务清单

### S2-01 输出逻辑和物理数据模型

执行内容：

1. 按认证、组织、渠道、报备、商机、报价、订单、产品、工作量、通知、审批、集成、任务和审计划分关系表。
2. 为每个表说明业务含义、主键、业务编号、V2 原始编号、外键、唯一约束、检查约束、索引和生命周期。
3. 明确当前值表和历史事件表，禁止把多个业务对象压缩成一个万能状态字段。
4. 对扩展字段逐个判断是否使用独立列、子表或 `jsonb`。
5. 本轮不创建公海池等未开发功能表。

交付物：

- `docs/database/V3逻辑数据模型.md`
- `docs/database/V3物理表结构.xlsx`
- `docs/database/V3实体关系图.md`

验收：每个 V2 实体字段都有目标字段、弃用原因或隔离策略。

### S2-02 建立数据库迁移框架

执行内容：

1. 选择并固定迁移执行方式，迁移文件按时间和任务编号命名。
2. 建立迁移状态表、执行锁、当前版本检查和校验摘要。
3. 迁移脚本区分结构迁移、数据回填和索引创建。
4. 大表索引和回填具备分批或并发安全策略，不长时间阻断业务。
5. 生产应用账号不具备结构修改权限，迁移使用独立账号。

验收：空数据库可以从零迁移到最新版本；重复执行不重复修改；版本不一致时应用就绪检查失败。

### S2-03 建立核心表和约束

执行顺序：

1. 账号、外部身份、角色、权限和组织。
2. 渠道主档、关系、成员和画像。
3. 产品目录、价格和工作量配置。
4. 报备、商机、跟进、报价、明细和订单。
5. 通知、审批、开放接口和审计。
6. 任务、文件、幂等记录和事件发件箱。

每组表建立后立即编写约束测试，不等待全部表完成。

验收：孤儿外键、重复业务编号、非法状态、负金额和重复转单均被数据库拒绝。

### S2-04 建立 Kysely 数据访问基础

执行内容：

1. 建立数据库连接、事务、分页、游标、锁和错误映射公共能力。
2. 数据库错误转换为稳定错误代码和中文说明，不向上泄露 SQL。
3. 建立只读查询和写事务入口，禁止业务模块自行创建连接池。
4. 建立测试事务或独立测试数据库清理机制。
5. 为慢查询记录请求编号、模块和查询名称，不记录敏感参数。

验收：连接池总数受控；接口实例和任务进程可以共享数据库但使用独立连接池配置。

### S2-05 建立服务端分页和查询规范

执行内容：

1. 为渠道、报备、商机、报价、订单、用户和审计定义允许筛选和排序字段。
2. 普通查询支持限制页大小；高增长表建立游标分页。
3. 为每类角色的数据范围组合设计索引。
4. 建立规范化公司名、用户名和编号检索列。
5. 使用查询计划测试目标规模数据，记录实际索引命中。

验收：百万级测试数据下核心列表没有无界返回；关键查询计划符合预期。

### S2-06 建立 SQLite 一致性导出工具

执行内容：

1. 使用 SQLite 官方一致性备份方式生成源快照，包含 WAL 数据。
2. 只读打开快照，按实体流式导出，避免一次性加载全部数据。
3. 每个实体输出记录数、文件大小和 SHA-256 摘要。
4. 审计库单独导出并保持时间字段和原始编号。
5. 导出工具禁止修改源库，缺少文件或校验失败立即停止。

交付物：

- `scripts/migration/export-v2/`
- `docs/migration/V2导出操作手册.md`

验收：对同一快照重复导出，记录数和内容摘要一致。

### S2-07 建立临时迁移表和导入工具

执行内容：

1. 临时迁移表保存批次号、实体名、原始编号、原始 JSON、摘要、处理状态和错误原因。
2. 导入使用批量写入，不逐行发起独立网络往返。
3. 同一批次和源记录唯一，重复导入不重复。
4. 支持检查点、失败继续和指定实体重跑。
5. 导入结束生成数量和错误报告。

验收：中途终止后可以继续；重复执行结果一致。

### S2-08 建立字段清洗和映射

执行内容：

1. 将阶段 0 冻结的状态、角色、区域、渠道层级和空值规则写成版本化映射。
2. 账号迁移时直接把明文密码转换为 `scrypt` 散列，不在中间文件输出明文。
3. 金额和比例按业务样本转换并重算。
4. 时间按明确源时区转换；无效时间进入错误清单。
5. 未知值不猜测，标记阻断或隔离并等待业务确认。

验收：所有映射有测试样例，修改映射版本后能够说明影响记录数量。

### S2-09 建立关联迁移顺序

迁移顺序：

1. 字典和组织。
2. 用户、角色、权限和外部身份。
3. 渠道主档、渠道关系、成员和档案。
4. 产品、价格和工作量。
5. 报备和审批。
6. 商机和跟进。
7. 报价、明细和快照。
8. 订单、明细和状态历史。
9. 通知、开放接口和审计。

每个步骤完成后运行外键和业务校验。下游不得在上游存在未处理阻断错误时继续正式装载。

### S2-10 建立迁移校验工具

执行内容：

1. 校验实体数量守恒和失败分类。
2. 校验业务编号、原始编号、用户名和关键唯一字段。
3. 校验外键、渠道环形关系、状态和角色合法性。
4. 重算报价、订单金额和关键工作量样本。
5. 比较有效账号、渠道范围、报备和订单权限样本。
6. 输出机器可读结果和中文验收报告。

验收：人为制造重复、孤儿、非法状态和金额差异时校验能准确失败。

### S2-11 建立百万级测试数据

执行内容：

1. 生成不含真实个人信息的用户、渠道、报备、商机、报价、订单和审计测试数据。
2. 数据分布包含热门区域、长尾渠道、不同状态、时间跨度和少量异常边界。
3. 生成器支持固定随机种子和指定规模。
4. 目标至少覆盖 200 万客户预留查询形态、500 万报备和 1 亿审计分区的缩小验证或分区容量推算。
5. 测试数据不得进入生产备份或演练迁移包。

验收：同一随机种子生成的数据统计一致，关联完整。

### S2-12 完成第一次全量迁移演练

执行内容：

1. 使用最新 V2 脱敏快照完整执行导出、导入、清洗、装载和校验。
2. 记录每步耗时、峰值内存、磁盘、失败记录和人工决策时间。
3. 所有手工修复转化为映射、脚本或正式问题清单，禁止只在数据库中直接修改。
4. 输出第一版迁移运行手册。

验收：除已批准隔离数据外，数量、关联、金额、状态和权限校验通过。

## 5. 数据库测试要求

- 所有唯一约束、外键、检查约束和乐观锁有自动测试。
- 两个并发请求创建同一转单结果时只成功一个。
- 并发更新同一记录时后提交者收到 409 冲突，不覆盖前者。
- 分页在新增记录同时发生时不重复、不漏掉已稳定范围内记录。
- PostgreSQL 重启后已提交数据存在，未提交事务不产生半记录。
- 迁移脚本中断、重跑和版本变化行为可预测。

## 6. 性能门槛

- 批量迁移期间内存有上限，不随总记录数线性增长。
- 目标数据规模下核心查询第 95 百分位满足阶段 7 前置目标。
- 不存在单请求全表读取或同步全库写入。
- 数据库连接池不超过预算，压力下无连接耗尽和长时间锁等待。
- 审计分区创建、查询和归档策略通过测试。

## 7. 阶段验收门槛

- 空库迁移、升级迁移和测试回退流程完整。
- V2 全量迁移可以重复执行并生成一致报告。
- 正式关系表不保存本地密码明文和开放接口密钥明文。
- 所有当前实体都有目标表和迁移策略。
- 关键并发一致性由数据库约束验证。
- 第一轮全量演练完成，阻断问题全部有责任人和解决期限。

## 8. 回退

本阶段不接管现有业务流量。迁移失败时删除本次目标测试数据库并从空库重建，不修改 V2 源快照。已经发布到共享测试环境的结构只通过新迁移修正，不手工篡改迁移历史。

## 9. 阶段完成标志

建立 `v3-postgresql-foundation` 基线标签，冻结第一版物理模型、迁移版本、字段映射和全量演练报告。阶段 3 和阶段 4 只能基于该版本开发。
