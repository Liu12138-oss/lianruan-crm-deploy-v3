# V3 项目任务总表与排期建议

## 1. 排期结论

当前系统约 4.7 万行核心前后端脚本、约 248 个后端路由，并包含账号、渠道、报备、商机、报价、订单、产品、移动端和开放接口。要在保持现有功能的同时完成关系型数据、权限、高可用和生产迁移，不能按普通小版本估算。

推荐使用 7 至 9 人核心团队，在 24 至 32 个自然周内完成。人员不足时应顺延周期，不应删减数据迁移、权限、测试和容灾阶段。

## 2. 推荐团队

| 角色 | 建议人数 | 核心责任 |
| --- | ---: | --- |
| 产品总负责人 | 1 | 范围、业务规则、决策和最终验收 |
| 架构兼技术负责人 | 1 | 架构、模块、数据、接口和技术质量 |
| 后端工程师 | 2 至 3 | 数据、权限、领域模块、任务和开放接口 |
| 前端工程师 | 2 | 管理、渠道、移动和工程化迁移 |
| 测试工程师 | 1 至 2 | 契约、权限、浏览器、数据、性能和故障 |
| 运维工程师 | 1，可阶段投入 | 容器、生产、监控、备份、恢复和发布 |
| 业务代表 | 2 至 3，兼职 | 角色、金额、状态、抽样和迁移确认 |

如果只有一名全栈开发独立执行，建议按 12 至 18 个月规划，并把测试和运维复核安排给独立人员。单人编写、单人测试、单人上线不满足高风险生产系统的复核要求。

## 4. 推荐并行计划

```text
第 1-2 周：阶段 0
第 3-4 周：阶段 1
第 5-10 周：阶段 2
第 9-13 周：阶段 3，与阶段 2 后半部分有限并行
第 14-25 周：阶段 4
第 17-28 周：阶段 5，按稳定接口分批并行
第 26-29 周：阶段 6
第 28-32 周：阶段 7，环境准备可提前
第 33-36 周：阶段 8
```

这是保守的 36 周参考。团队成熟、自动测试基础完整且外部决策及时，可以压缩到 24 至 32 周；不得通过跳过阶段来压缩。

## 5. 关键路径

关键路径为：现状冻结 → 数据模型 → 认证权限 → 报备到订单后端 → 对应前端 → 任务化 → 性能容灾 → 全量迁移。

以下任务不能并行绕过：

- 未冻结状态和金额规则前，不迁移报价订单。
- 未完成 PostgreSQL核心表前，不实现正式领域写入。
- 未完成服务端身份和范围前，不开放新业务接口。
- 未稳定接口契约前，不批量迁移对应页面。
- 未完成三次全量演练前，不正式切换。

## 7. 任务状态规则

每个任务使用以下状态：

- 待确认：业务或环境条件未明确。
- 待开始：前置条件已满足。
- 开发中：已有负责人和目标完成日期。
- 待复核：代码和自测完成，等待独立评审。
- 待验收：已部署测试环境，等待阶段证据。
- 已完成：验收标准和证据齐全。
- 已阻断：有明确阻断原因、责任人和下一检查日期。

不得用“基本完成”“差不多”和“后续优化”代替状态。

## 8. 每个任务的完成定义

一个任务只有同时满足以下条件才能完成：

- 需求和边界与任务编号一致。
- 代码、数据库迁移和配置已评审。
- 单元、接口、权限或浏览器测试按风险完成。
- 中文错误、日志和审计符合规范。
- 接口契约、数据字典和运行文档同步更新。
- 性能和安全影响已评估。
- 回退或前进修复方案已验证。
- 验收证据存入阶段目录。

## 9. 分支和发布建议

- 主分支始终保持可构建、可测试。
- 每个任务使用独立短分支和任务编号。
- 大模块按可独立验收批次合并，不保持数月大分支。
- 每阶段建立基线标签，生产候选后只接受阻断修复。
- 数据库迁移一经进入共享环境不得修改历史文件，只能新增修正迁移。
- 生产修复必须先回合主线，避免生产出现孤立代码。

## 10. 质量指标

| 指标 | 门槛 |
| --- | --- |
| 接口迁移覆盖 | 纳入范围路由 100% 有结论 |
| 页面迁移覆盖 | 纳入范围页面 100% 有结论 |
| 权限矩阵 | 核心资源允许和拒绝用例 100% 通过 |
| 状态机 | 核心合法与非法迁移 100% 覆盖 |
| 关键金额 | 固定样本逐分一致 |
| 数据迁移 | 数量守恒、孤儿为零、未知映射为零或批准隔离 |
| 严重缺陷 | 上线前为零 |
| 高风险安全问题 | 上线前为零 |
| 性能 | 达到阶段 6 和阶段 7 目标 |
| 备份恢复 | 恢复点和恢复演练通过 |

## 11. 风险储备

排期至少保留 20% 风险储备，重点用于：

- 历史角色、区域和渠道关系不一致。
- 报价和订单价格历史语义难以还原。
- 开放接口存在未登记调用方。
- 生产欧拉系统的容器镜像或原生依赖兼容问题。
- V2 数据在开发期间继续增长并出现新脏数据。
- 单机硬件不能达到目标压力或恢复时间。
- 外部身份测试环境不稳定。

风险储备用于已知项目风险，不用于插入新功能。

## 12. 第一周立即启动清单

项目批准后第一周只做阶段 0：

1. 任命产品、架构、后端、前端、测试、运维和业务代表。
2. 初始化 V3 Git 仓库和基线标签，排除数据库、日志、备份和密钥。
3. 冻结本轮功能范围和不做清单。
4. 自动提取约 248 个路由和页面接口调用。
5. 生成 V2 只读一致性快照和首版数据字典。
6. 建立角色权限和状态机工作表。
7. 核对生产服务器、异机备份和备用恢复条件。
8. 建立待确认业务决策清单和每项最晚确认日期。

第一周不得开始重写报备、报价、订单或前端页面。

## 14. 项目周报要求

周报只报告：本周完成任务及证据、下周任务、阻断、风险变化、范围变化、质量指标和需负责人决策事项。禁止只用代码行数和页面数量表达进度。

## 15. 项目最终交付包

- 全部源码、锁文件、数据库迁移和自动测试。
- 前端、接口和任务不可变镜像及摘要。
- OpenAPI 契约和开放接口兼容报告。
- 数据字典、关系模型、迁移脚本和三次演练报告。
- 部署、发布、回退、备份、恢复、告警和故障手册。
- 功能、权限、性能、安全、长稳和业务验收报告。
- V2 最终快照摘要、迁移批次和稳定期报告。
- 未完成的新功能需求和后续技术债清单。
