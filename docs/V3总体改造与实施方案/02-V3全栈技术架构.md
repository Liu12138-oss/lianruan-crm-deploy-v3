# V3 全栈技术架构

## 1. 技术选型原则

技术选型服务于可维护、可测试、可部署和可恢复，不以追求组件数量为目标。V3 保留 Node.js 和 Vue 技术方向，减少业务重写风险；使用 TypeScript、关系型数据库和工程化构建解决现有结构问题。

## 2. 固定技术栈

| 层级 | 技术选择 | 使用边界 |
| --- | --- | --- |
| 运行时 | Node.js 22 长期支持版 | 接口和任务进程统一版本 |
| 后端框架 | Express 5 + TypeScript | 模块化单体，不引入微服务框架 |
| 参数校验 | Zod | 请求、响应、环境变量和任务载荷统一校验 |
| 接口规范 | OpenAPI 3.1 | 生成接口文档、类型和契约测试 |
| 数据访问 | Kysely + `pg` 连接池 | 保留 SQL 可控性，禁止在控制器中直接执行 SQL |
| 数据库 | PostgreSQL 16 | 唯一业务事实来源 |
| 缓存和会话 | Redis 7 + ioredis | 缓存、会话、限流和短期协调 |
| 任务队列 | BullMQ | 导入、导出、通知和可重试后台任务 |
| 日志 | Pino 结构化日志 | 输出中文消息和稳定字段，不记录敏感明文 |
| 前端 | Vue 3 + TypeScript + Vite | 统一工程、按工作空间和路由分包 |
| 前端组件 | Element Plus | 延续现有交互习惯，建立统一封装 |
| 前端状态 | Pinia | 只保存会话、权限和跨页面必要状态 |
| 前端路由 | Vue Router | 工作空间、页面权限和懒加载 |
| 单元与接口测试 | Vitest + Supertest | 后端和前端统一测试入口 |
| 浏览器回归 | Playwright | 覆盖管理端、渠道端和移动端核心流程 |
| 性能测试 | k6 | 固定场景、固定数据规模和固定报告 |
| 容器 | Docker + Docker Compose | 首发单服务器编排 |
| 入口 | Nginx | HTTPS、静态资源、反向代理和应用负载均衡 |
| 指标和告警 | Prometheus + Grafana + Alertmanager | 服务、数据库、Redis、主机和业务指标 |
| 日志汇总 | Loki + Promtail | 单机首发的集中日志检索 |
| 数据备份 | pgBackRest | PostgreSQL 全量、增量和持续归档 |

如果某个依赖在生产欧拉系统或离线环境无法稳定安装，必须先在与生产同架构的环境验证，再决定是否替换。不得在正式部署时临时更换数据库驱动、密码算法或构建工具。

## 3. 暂不引入的组件

| 组件 | 暂不引入原因 | 重新评估条件 |
| --- | --- | --- |
| 微服务 | 当前团队和业务边界不足以抵消分布式复杂度 | 单模块独立扩容、独立发布需求持续出现 |
| Kubernetes | 单机首发无收益，增加运维负担 | 生产稳定运行在三台以上应用节点且有专职平台运维 |
| Kafka | 当前任务规模可由 Redis 队列和数据库事件发件箱覆盖 | 事件吞吐或跨系统订阅超过现有方案能力 |
| Elasticsearch | PostgreSQL 索引和全文检索足以覆盖当前功能 | 百万级复杂模糊检索实测无法达标 |
| 分布式事务 | 当前模块共享 PostgreSQL | 真正拆分数据库后再设计补偿机制 |
| 通用工作流引擎 | 当前审批流程固定 | 产品确认出现多套可配置复杂流程 |

## 5. 后端内部结构

每个业务模块只保留必要的三层：

```text
模块路由层：解析请求、调用校验、返回协议
    |
模块服务层：权限后的业务规则、事务和状态变化
    |
模块数据层：查询、写入、锁和数据库映射
```

禁止为每个简单操作机械增加命令层、领域对象层和适配层。只有跨模块事务、复杂状态机或外部集成需要额外策略对象。

## 6. 请求处理链

所有受保护请求按固定顺序处理：

1. 生成或接收请求编号。
2. 校验来源、请求体大小和内容类型。
3. 认证会话或开放接口令牌。
4. 检查账号状态和会话撤销状态。
5. 检查功能权限。
6. 计算并应用组织、区域、渠道或本人数据范围。
7. 使用 Zod 校验允许字段，拒绝未知敏感字段。
8. 检查业务状态、版本号和幂等键。
9. 在数据库事务中执行写入和事件发件箱记录。
10. 写入审计结果并返回统一响应。

中间件只处理通用上下文，具体数据范围和业务状态由模块策略执行。禁止把所有权限写成一个不断增长的全局条件函数。

## 7. 接口规范

### 7.1 路径和版本

- 新内部接口使用 `/api/v3` 前缀。
- 当前页面依赖的 `/api` 路径由兼容路由转换。
- 已发布开放接口 `/api/open/v1` 在完成调用方确认前保持契约稳定。
- 健康检查使用 `/health/live`、`/health/ready` 和 `/health/dependencies`。

### 7.2 正常响应

```json
{
  "success": true,
  "data": {},
  "requestId": "请求编号"
}
```

### 7.3 错误响应

```json
{
  "success": false,
  "code": "REGISTRATION_STATUS_CONFLICT",
  "message": "当前报备状态不允许执行该操作",
  "requestId": "请求编号",
  "details": []
}
```

错误代码稳定供程序判断，中文消息供用户和运维理解。生产环境不返回堆栈、SQL、内部路径、密钥或第三方原始敏感响应。

### 7.4 列表协议

- 普通列表支持 `page`、`pageSize`，单页上限 100。
- 深分页和大表使用游标，游标包含稳定排序键和主键。
- 排序字段和筛选字段使用允许清单，不拼接任意客户端字段。
- 响应返回总数的接口必须评估计数成本；超大表可返回是否还有下一页。

### 7.5 幂等和并发

- 创建订单、报价转单、导入执行、任务创建等接口要求幂等键。
- 更新核心记录携带 `version`，数据库按版本条件更新。
- 并发冲突返回 409 和中文原因，不静默覆盖。
- 唯一业务事实由数据库唯一约束兜底，不能只在应用层先查询再写入。

## 8. 认证和会话结构

### 8.1 浏览器会话

- 登录成功后生成高强度随机会话令牌。
- 浏览器只保存安全 Cookie；服务端 Redis 保存会话，PostgreSQL保存会话摘要和审计元数据。
- 会话包含用户编号、授权版本、登录来源、设备摘要、创建和过期时间。
- 账号停用、密码修改、角色变化时提升授权版本或撤销会话。
- 会话默认闲置 30 分钟、最长 8 小时，具体数值在阶段 3 由产品和安全确认。

### 8.2 本地密码

- 使用 Node.js 内置 `scrypt`、独立随机盐和常量时间比较。
- 数据库存储算法版本、参数、盐和散列，不存储可逆密码。
- V2 明文密码只允许存在于受控迁移进程内存中，转换后立即丢弃。
- 应急管理员首次部署生成一次性密码，首次使用强制修改。

### 8.3 开放接口

- 客户端密钥只在创建或重置时显示一次。
- 数据库保存密钥摘要、权限、来源地址、状态和过期时间。
- 访问令牌短期有效，可撤销、可限流、可审计。

## 9. 前端架构

V3 使用一个 Vue 工程承载统一入口、管理工作空间、渠道工作空间和移动工作空间，通过布局和路由分包隔离，而不是继续维护多个超长脚本。

```text
web/src/modules/
├── portal/
├── admin/
├── partner/
├── mobile/
├── account/
├── registration/
├── opportunity/
├── quotation/
├── order/
├── catalog/
└── system/
```

前端规则：

- 路由按工作空间和领域懒加载。
- 页面不得直接拼接接口地址，统一通过生成的契约客户端。
- Pinia 不保存大列表和完整业务数据库，只保存会话和少量跨页状态。
- 权限指令只控制显示，服务端仍执行最终鉴权。
- 所有列表使用服务端分页、筛选和排序。
- 表单提交防重复，冲突状态给出中文提示和刷新选项。
- 金额显示和提交使用字符串或定点处理，不使用二进制浮点运算决定价格。
- 移动端和桌面端共享契约与业务枚举，但分别使用适配布局。
- 旧页面按页面清单逐一替换，不在同一批次重做交互和业务规则。

## 10. PostgreSQL 使用结构

- 使用 Kysely 统一构造查询，复杂索引、分区和批处理允许使用受审查的参数化 SQL。
- 接口实例各自使用有限连接池，所有实例和任务进程的连接总数不得超过数据库预算。
- 事务只包围必要数据库操作，不在事务内等待第三方接口或执行大文件处理。
- 状态变化、业务写入和事件发件箱在同一事务提交。
- 所有外键、唯一约束、检查约束和关键索引进入版本化迁移。
- 生产禁止自动同步表结构，应用启动不得自行修改数据库。

## 11. Redis 使用结构

建议键前缀：

```text
crm:v3:session:{摘要}
crm:v3:rate:{维度}:{标识}
crm:v3:cache:{模块}:{版本}:{键}
crm:v3:lock:{业务}:{键}
crm:v3:bull:{队列}
```

Redis 只用于以下场景：

- 可撤销会话和短期授权缓存。
- 登录、开放接口、导出等限流计数。
- 字典、产品树、权限版本等可重建缓存。
- BullMQ 任务调度和重试。
- 极短时间的协调锁；最终一致性仍由 PostgreSQL 约束保障。

不得把订单状态、报价金额、报备审批结论等唯一业务事实只写入 Redis。

## 12. 任务进程

接口进程只负责创建任务并快速返回任务编号。任务进程负责导入、导出、通知、统计预计算和过期文件清理。

每个任务必须具备：任务类型、创建人、数据范围快照、状态、进度、幂等键、重试次数、错误代码、中文错误原因、创建和完成时间。任务重试不能重复创建业务记录。

PostgreSQL中的任务记录和事件发件箱是恢复依据。Redis 队列丢失后，补偿程序可以重投未完成任务。

## 13. 可观测性

### 13.1 日志字段

至少包含时间、级别、服务、版本、环境、请求编号、用户编号摘要、模块、动作、耗时、结果和错误代码。手机号、密码、令牌、密钥、完整联系人和原始导入内容必须脱敏或排除。

### 13.2 指标

- 请求量、错误率和延迟分位数。
- Node.js 事件循环延迟、内存和进程重启次数。
- PostgreSQL 连接、慢查询、锁等待、复制延迟和磁盘增长。
- Redis 内存、命中率、拒绝连接、持久化和队列积压。
- 任务成功率、重试率、等待时长和失败类型。
- 登录失败、越权拒绝、导出量和高风险操作量。

### 13.3 告警

告警必须包含中文名称、影响、当前值、处理手册链接和责任人。仅有图表没有告警不算完成。

## 14. 测试结构

| 测试层 | 重点 |
| --- | --- |
| 单元测试 | 状态机、价格、工作量、数据范围和字段映射 |
| 数据库集成测试 | 事务、约束、锁、分页、索引和迁移 |
| 接口契约测试 | 当前 248 个路由和新 `/api/v3` 协议 |
| 权限矩阵测试 | 每个角色对列表、详情、写入、导出和下载的范围 |
| 浏览器测试 | 登录、报备、商机、报价、订单、审核和管理配置 |
| 迁移测试 | 数量、关联、金额、状态、账号和抽样业务一致性 |
| 性能测试 | 基线、峰值、长稳、慢查询和任务积压 |
| 故障测试 | 接口实例、Redis、PostgreSQL、磁盘和外部依赖异常 |

## 15. 构建和交付

- 根目录使用 npm 工作区统一锁定依赖。
- 每次构建输出不可变版本号、提交编号和构建时间。
- 同一构建产物从测试环境晋级生产，不在生产服务器重新安装或编译。
- 容器镜像使用固定摘要或明确版本，禁止长期使用 `latest`。
- 生产镜像使用非特权用户、只读根文件系统和明确可写卷。
- 数据库迁移作为独立发布步骤，执行前自动检查备份和当前版本。
- 前端静态资源使用内容摘要缓存，入口文件不做长期缓存。

## 16. 架构验收要点

- 新增一个模块不需要修改全局巨型路由文件。
- 接口实例可以启动两个并由 Nginx 分流，会话和权限保持一致。
- 任意实例重启不会丢失业务数据和任务事实。
- PostgreSQL 断开时就绪检查失败并停止接收流量，不回退到内存写入。
- Redis 断开时核心业务数据仍安全，系统按降级策略限制登录和任务功能。
- 前端构建不包含生产密钥和固定后端地址。
- 旧接口兼容与新领域服务分离，能够统计剩余旧调用量。
