# 阶段 6：Redis、任务化与性能治理

## 1. 阶段目标

在不新增业务能力的前提下，把现有会话、限流、导入、导出、到期通知生成、开放接口统计和可重试后台处理纳入 Redis 与 BullMQ；对核心查询、缓存、数据库连接和前端加载进行系统性能治理。

本阶段的重点是“请求快速返回、后台可靠执行、失败可追踪、重复不产生副作用”，不是把所有业务都异步化或缓存化。

## 2. 前置条件

- 阶段 3 共享会话和限流基础可用。
- 阶段 4 相关业务模块已迁移到 PostgreSQL。
- 阶段 5 已有任务进度和下载所需前端公共组件。
- 阶段 2 的任务事实、事件发件箱、幂等和文件表可用。

## 3. 计划周期和分工

建议周期：3 至 4 周。

| 方向 | 责任 |
| --- | --- |
| 后端 | 队列、任务事实、补投、缓存和接口改造 |
| 前端 | 任务进度、失败明细、下载和重试交互 |
| 测试 | 重复、失败、重启、积压、性能和恢复测试 |
| 运维 | Redis 持久化、内存、告警和容量参数 |

## 4. 任务队列设计

建议队列按资源和风险分离：

| 队列 | 当前用途 | 初始并发 |
| --- | --- | ---: |
| `import` | 导入预检和正式执行 | 1 至 2 |
| `export` | 大列表导出和文件生成 | 2 |
| `notification` | 现有通知生成和后续投递 | 5 |
| `integration` | 外部接口补偿和统计 | 5 |
| `maintenance` | 文件清理、发件箱补投和受控维护 | 1 |

并发是初始值，必须根据单机处理器、数据库连接和外部限流调整。

## 5. 公共任务

### S6-01 完成任务事实模型

执行内容：

- 任务先写 PostgreSQL，再提交 Redis 队列。
- 保存任务类型、创建人、数据范围快照、参数摘要、状态、进度、重试、错误和结果文件。
- 参数中的敏感信息单独加密或不持久化，日志只保存摘要。
- 状态至少包含待排队、运行中、成功、失败、取消和等待人工处理。
- 任务状态更新使用版本号，避免多个执行者覆盖。

验收：Redis 全部清空后，可以从 PostgreSQL找出未完成任务并按策略补投。

### S6-02 建立统一任务处理器

执行内容：

- 处理器启动前校验任务状态、创建人账号状态和载荷版本。
- 每个任务有幂等键和执行检查点。
- 短暂故障自动重试，业务校验失败不盲目重试。
- 错误分类为可重试、不可重试和需人工处理，并提供中文说明。
- 任务结束释放临时资源并记录指标。

验收：同一任务被重复投递时不会重复写业务数据或生成多份有效结果。

### S6-03 建立事件发件箱发布器

执行内容：

- 分批锁定待发布事件，多个任务进程不会重复占有同一批。
- 发布成功和失败有状态、次数和下次时间。
- 超过重试上限进入人工处理列表并告警。
- 消费者按事件编号幂等。
- 发件箱清理只处理超过保留期的已完成事件。

验收：接口提交后立即停止任务进程，恢复后事件仍能发布。

### S6-04 建立队列监控和管理操作

执行内容：

- 监控等待、运行、延迟、完成、失败、重试和停滞任务。
- 管理操作只允许查看、重试可重试任务、取消未执行任务。
- 不提供任意修改任务载荷和跳过权限的管理入口。
- 所有人工重试、取消和清理进入审计。

验收：失败任务可以定位到业务编号、请求编号、错误代码和中文原因。

## 6. 导入任务化

### S6-10 改造导入预检

执行内容：

- 上传后保存文件摘要、大小、创建人和数据范围。
- 预检在任务进程流式读取，限制文件大小、行数、列数和解压大小。
- 使用与正式执行完全相同的字段和业务校验。
- 输出成功、警告、失败数量及行级中文原因。
- 预检结果绑定文件摘要和规则版本，文件变化后不能直接执行旧预检。

### S6-11 改造导入执行

执行内容：

- 只有预检通过且用户仍有权限时允许执行。
- 分批事务写入，批次大小通过测试确定。
- 每行使用业务唯一键和任务幂等键防重。
- 部分失败策略按导入类型明确：全批回滚或允许成功行，不能临时决定。
- 执行结束输出结果和失败文件，下载重新鉴权。

验收：超时重试、任务进程重启和重复点击不会重复导入。

## 7. 导出任务化

### S6-20 改造大数据导出

执行内容：

- 创建任务时保存经过服务端确认的数据范围和筛选条件。
- 任务执行时重新检查账号状态，不扩大创建时范围。
- 使用游标分批读取和流式写文件，不一次加载全部结果。
- 设置单次最大行数、并发导出数和文件保留期。
- 文件保存摘要，下载检查权限、任务所有者和过期状态。

验收：百万行受控测试导出内存稳定，不阻塞普通查询；越权用户无法下载已知文件编号。

## 8. 通知和到期检查任务化

### S6-30 分离到期通知生成

执行内容：

- 移除登录或查询通知时扫描未来到期数据的副作用。
- 定时任务按时间槽扫描，使用业务对象、提醒类型和日期唯一约束防重。
- 生成通知后通过事件发件箱和通知队列处理。
- 登录和通知列表只查询既有通知，不触发全量生成。
- 本轮只覆盖当前已有提醒，不增加企业微信和新提醒规则。

验收：同一时间槽重复执行、任务重启和多执行者不会生成重复通知。

## 9. 缓存治理

### S6-40 建立缓存清单

只允许缓存经过批准的可重建数据：

- 权限和授权版本的短期结果。
- 地区字典和稳定元数据。
- 已发布产品树和工作量规则版本。
- 短期经营统计结果。

每个缓存登记数据源、键、生命周期、最大大小、失效事件、回源风险和责任人。没有清单的缓存不得进入生产。

### S6-41 实现缓存失效

执行内容：

- 缓存键包含结构或数据版本，避免批量扫描删除。
- 配置发布、权限变化和产品变化后更新版本或精准删除。
- 使用随机过期抖动，避免同一时刻集中失效。
- 热点回源使用短时间请求合并，不使用长时间分布式锁。
- Redis 不可用时限速回源并告警。

验收：修改权限或价格后，旧缓存不会继续授权或计算旧结果。

### S6-42 防止大键和热键

执行内容：

- 单个缓存值设置大小上限，不缓存整张业务表。
- 禁止使用无界集合保存全部在线用户或业务编号。
- 定期扫描大键、热键和无过期键。
- 队列键与缓存淘汰策略隔离。

验收：Redis 监控中没有未登记的大键和长期增长无界键。

## 10. 查询和接口性能治理

### S6-50 核心查询逐项优化

针对用户、渠道、报备、商机、报价、订单、产品树、审批、审计和开放接口：

- 记录查询名称、数据范围、筛选、排序和预期索引。
- 使用真实数据分布分析执行计划。
- 消除循环查询、重复统计和不必要大字段返回。
- 计数昂贵时评估延迟计数或是否还有下一页，不伪造总数。
- 更新统计信息并验证索引选择稳定。

### S6-51 限制请求和数据库资源

执行内容：

- 为接口设置请求体、响应行数、查询超时和事务超时。
- 数据库连接池设置获取超时和泄漏监控。
- 大任务使用独立并发和连接预算，不能占满接口连接。
- 外部接口使用独立连接和并发限制。
- 超出限制返回中文可操作提示，不无限等待。

### S6-52 建立热点统计预计算

只对阶段 7 实测证明昂贵且高频的当前看板统计建立预计算。预计算结果保存统计口径、时间范围、数据范围、生成时间和版本。不得提前为未上线指标建立复杂数据仓库。

## 11. 前端性能治理

- 路由和大型组件懒加载。
- 同条件重复请求合并，离开页面取消无用请求。
- 列表只保留当前页和必要缓存，不累计全部翻页数据。
- 图表和下拉候选使用服务端聚合和搜索。
- 静态资源压缩、长期缓存和入口文件短缓存。
- 记录真实首屏、交互和接口耗时，不能只看构建大小。

## 12. 性能测试场景

| 场景 | 目标 |
| --- | --- |
| 基线 | 50 并发持续 15 分钟，无错误和资源异常 |
| 目标 | 500 活跃并发，持续请求量 300 次每秒，持续 30 分钟 |
| 峰值 | 600 次每秒持续 10 分钟，错误率低于 0.1% |
| 长稳 | 典型混合负载持续 8 小时，无持续内存增长和任务积压 |
| 导出并行 | 普通查询负载下同时执行受控大导出，页面目标不严重退化 |
| 队列积压 | 人为积压后恢复消费者，能够稳定清空且不压垮数据库 |
| 缓存失效 | Redis 清空后逐步恢复，无数据库雪崩 |

实际结果必须记录服务器配置、数据规模、数据分布、脚本版本和原始指标。

## 13. 阶段验收门槛

- 导入、导出、通知扫描和长任务已从接口请求中分离。
- 任务有 PostgreSQL事实、Redis 队列、幂等、重试、补投、告警和审计。
- Redis 清空不会丢失业务唯一数据。
- 登录不再触发到期提醒全量扫描。
- 核心查询具备索引和执行计划证据。
- 目标、峰值和 8 小时长稳测试达到设定标准。
- 缓存清单、失效策略和降级演练通过。

## 14. 回退

缓存可以通过开关停用并回源数据库。任务化接口上线前保留受控兼容路径，但不得在生产长期保留无边界同步大任务。任务处理器问题时停止对应队列，不影响已提交业务事实；修复后从 PostgreSQL补投。已经生成的结果文件和任务记录保留审计，不自动删除。

## 15. 阶段完成标志

建立 `v3-async-performance-complete` 基线标签，附带队列清单、缓存清单、性能报告、长稳报告和 Redis 故障恢复报告。
