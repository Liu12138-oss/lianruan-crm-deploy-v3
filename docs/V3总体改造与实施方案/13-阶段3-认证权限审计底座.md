# 阶段 3：认证、权限与审计底座

## 1. 阶段目标

建立所有后续业务模块共用的可信身份、可撤销会话、功能权限、数据范围、字段保护、幂等入口和操作审计。阶段结束后，任何新迁移接口都不得再信任前端传入的操作人、角色、区域或渠道决定授权。

## 2. 前置条件

- 阶段 0 角色权限矩阵和数据范围来源已冻结。
- 阶段 2 的账号、外部身份、角色、权限、组织、会话和审计表可用。
- 统一身份认证和真实客户关系管理系统测试环境或可验证模拟服务可用。
- 产品负责人确认会话时间、应急管理员和账号状态策略。

## 3. 计划周期和分工

建议周期：3 至 4 周。

| 方向 | 责任 |
| --- | --- |
| 后端 | 登录适配、会话、权限策略、数据范围、审计和兼容中间件 |
| 前端 | 登录、工作空间、会话续期、退出和无权限处理 |
| 测试 | 权限矩阵、会话撤销、越权和外部身份故障测试 |
| 运维安全 | 密钥、来源限制、应急账号和审计告警 |

## 4. 身份来源优先级

1. 统一身份认证登录用于正式组织账号。
2. 真实客户关系管理系统登录作为已确认的业务身份来源和兼容入口。
3. 本地应急管理员只用于外部身份系统故障和紧急运维。
4. 测试模拟登录仅存在于开发和测试构建，不进入生产镜像。

多个来源映射到同一个 `iam_users` 用户，业务权限只来自 V3 角色和数据范围，不直接信任外部系统返回的前端角色字符串。

## 5. 任务清单

### S3-01 建立身份领域服务

执行内容：

1. 实现用户查询、账号状态、外部身份映射和授权版本。
2. 统一正常、停用、待审核、拒绝、锁定等状态语义。
3. 登录前后都检查账号状态；状态变化记录操作人和原因。
4. 禁止通过用户名模糊匹配或姓名匹配自动绑定外部身份。
5. 外部主体找不到映射时返回中文说明并审计，不自动创建高权限账号。

验收：同一外部主体只能映射一个有效本地用户；冲突映射被拒绝。

### S3-02 实现本地密码安全存储

执行内容：

1. 使用 Node.js 内置 `scrypt`，为每个密码生成独立随机盐。
2. 保存算法版本和参数，为未来逐步升级预留重新散列能力。
3. 使用常量时间比较，登录失败不区分账号不存在和密码错误。
4. 登录失败计数进入 Redis 限流和安全审计。
5. V2 密码迁移只在受控内存中转换，不落中间明文文件。
6. 密码修改和管理员重置后撤销现有会话。

验收：数据库、日志、审计和接口响应均找不到密码明文。

### S3-03 实现统一身份认证适配器

执行内容：

1. 封装统一身份认证授权、回调、状态校验和用户信息获取。
2. 校验状态参数、防重放参数、回调地址、签名和证书。
3. 设置短超时和有限重试，失败不进入本地匿名会话。
4. 外部令牌只在服务端受控使用，不传递到业务前端。
5. 建立外部身份系统不可用时的中文提示和已有会话策略。

验收：伪造回调、重复回调、错误状态参数和无映射用户均被拒绝。

### S3-04 实现真实客户关系管理系统登录适配器

执行内容：

1. 将现有真实登录逻辑从巨型服务文件迁入独立适配器。
2. 规范超时、错误代码、映射和审计。
3. 生产关闭模拟接口，模拟配置不能被环境变量误开启。
4. 外部登录成功但本地映射缺失时不自动授权。
5. 逐步统计该登录来源的实际使用量，为未来收敛提供依据。

验收：适配器故障不会让请求回退到前端自报身份。

### S3-05 实现 Redis 共享会话

执行内容：

1. 登录成功生成高强度随机令牌，浏览器使用安全 Cookie。
2. Redis 保存会话内容，PostgreSQL保存令牌摘要、设备和撤销元数据。
3. 会话包含用户编号、授权版本、登录来源、创建、最后活动和过期时间。
4. 两个接口实例共享会话，任一实例创建的会话可在另一实例验证。
5. 退出、密码修改、账号停用、权限变化和应急操作可以撤销会话。
6. Cookie 设置 `HttpOnly`、`Secure` 和合适的 `SameSite`。

验收：接口实例交替处理请求时用户状态一致；已撤销会话立即失效。

### S3-06 建立功能权限模型

执行内容：

1. 权限代码使用“模块.资源.动作”，与阶段 0 矩阵映射。
2. 角色和权限进入 PostgreSQL，发布变更提升授权版本。
3. 控制器通过声明或明确策略要求权限，拒绝散落角色字符串判断。
4. 超级管理员权限也通过明确授权，不使用隐藏的全局绕过。
5. 页面权限信息由服务端会话接口返回，但仅用于界面展示。

验收：移除角色权限后旧会话不能继续执行该动作。

### S3-07 建立数据范围策略

执行内容：

1. 支持全部、指定区域、指定渠道、渠道树和本人相关等当前范围。
2. 数据范围从组织绑定和渠道成员关系计算，不读取请求中的区域和角色。
3. 查询策略返回可组合的数据库条件，不能读取全部数据后过滤。
4. 详情、更新、删除、审批、导出和下载复用同一范围策略。
5. 对无组织绑定、断裂渠道关系和多个冲突范围保护性拒绝并告警。

验收：已知其他区域记录编号也无法通过详情接口读取或修改。

### S3-08 建立字段允许清单和服务端事实

执行内容：

1. 每个写接口使用 Zod 严格模式，未知字段默认拒绝。
2. 创建人、更新人、审批人、角色、区域、渠道归属、状态和可信金额由服务端写入。
3. 兼容接口接收历史操作者字段时只用于审计对比或直接忽略，绝不用于授权。
4. 对敏感字段越权提交返回稳定错误代码并审计。
5. 不同角色的响应字段按服务端策略脱敏。

验收：篡改 `operatorRole`、`operatorId`、`region` 和 `partnerId` 不会扩大权限。

### S3-09 建立统一审计

执行内容：

1. 统一审计记录请求编号、服务端操作者、模块、动作、目标、结果、来源地址和必要前后值。
2. 定义登录、账号、权限、渠道、审批、价格、导入、导出、密钥和恢复等高风险动作。
3. 敏感字段统一掩码；禁止写入密码、令牌、密钥和完整 Cookie。
4. 普通失败审计可异步可靠写入；高风险动作审计不可用时按策略阻断。
5. 审计查询本身受权限和数据脱敏约束，并记录导出行为。

验收：同一个操作可以通过请求编号关联应用日志和审计记录。

### S3-10 建立限流和安全锁定

执行内容：

1. 登录按来源地址、用户名摘要和设备维度限流。
2. 开放接口按客户端和来源地址限流。
3. 密码重置、导出、导入执行和密钥重置设置更严格限流。
4. 锁定和解锁策略有明确时间、通知和审计，不永久误锁正常账号。
5. Redis 不可用时使用保护性策略，不能完全取消限流。

验收：暴力尝试被阻断，正常用户的错误次数和恢复流程符合产品确认。

### S3-11 建立应急管理员机制

执行内容：

1. 应急管理员使用独立本地账号，不复用普通超级管理员。
2. 初始密码一次性生成，双人保管，首次使用强制修改。
3. 默认限制来源地址和使用时段；每次启用需要原因和批准记录。
4. 登录立即触发最高级告警，所有操作进入高风险审计。
5. 外部身份系统恢复后立即停用并复核操作记录。

验收：未启用或来源不符时无法登录；使用后能生成完整审计报告。

### S3-12 建立旧接口认证兼容层

执行内容：

1. 为旧 `/api` 接口建立统一认证中间件，不逐个依赖前端参数。
2. 兼容层把旧请求转换为新服务输入，操作者从会话注入。
3. 统计仍传递历史操作者字段的页面和调用方。
4. 在测试环境记录警告，生产日志按采样记录，避免日志洪水。
5. 未迁移的高风险旧接口在兼容层先加认证和范围保护。

验收：不携带有效会话的旧受保护接口请求被拒绝；兼容页面仍可正常使用。

### S3-13 改造前端登录和工作空间

执行内容：

1. 新前端只通过会话接口获取当前用户、角色、权限和工作空间。
2. 不从本地存储中的用户对象决定身份。
3. 实现登录、统一身份认证跳转、退出、会话过期和无权限页面。
4. 处理接口实例切换、会话撤销和外部身份系统故障。
5. 移动端和桌面端复用会话协议。

验收：修改浏览器本地存储不能改变服务端身份和可访问数据。

## 6. 权限测试矩阵

每个核心资源至少覆盖：

| 场景 | 期望 |
| --- | --- |
| 无会话访问 | 401 |
| 会话已过期或撤销 | 401 |
| 有身份无功能权限 | 403 |
| 有功能权限但跨区域 | 404 或 403，策略统一 |
| 有功能和数据权限但状态非法 | 409 |
| 篡改操作者、角色、区域 | 不影响授权并记录风险 |
| 停用账号使用旧会话 | 立即拒绝 |
| 权限变化后使用旧会话 | 按授权版本立即拒绝或刷新 |
| 导出跨范围数据 | 拒绝，且不可通过任务绕过 |

## 7. 故障测试

- Redis 中断：已有核心业务数据不丢失，登录和敏感操作按保护性策略响应。
- PostgreSQL 中断：就绪检查失败，不回退到内存账号或权限。
- 统一身份认证超时：请求在规定时间内失败，接口线程不长期占用。
- 两个接口实例交替请求：会话、权限和撤销一致。
- 审计写入异常：高风险动作按确定策略阻断，普通动作进入可靠补偿。

## 8. 阶段验收门槛

- 本地密码和开放接口密钥不再明文存储。
- 所有新接口身份只来自服务端会话或开放接口令牌。
- 旧高风险接口已经接入兼容认证保护。
- 权限矩阵允许和拒绝用例全部通过，无跨区域、跨渠道和跨用户越权。
- 两个接口实例共享会话并完成撤销演练。
- 应急管理员流程、告警和审计经过实际演练。
- 安全测试未发现可利用的身份伪造和数据范围绕过。

## 9. 回退

阶段 3 在测试环境逐步启用。认证表和会话表属于扩展结构，代码回退不删除数据。若新会话机制发生阻断问题，可在未对生产开放前回到旧测试入口；生产一旦开始使用新密码散列，不得回退到明文密码验证。

## 10. 阶段完成标志

建立 `v3-identity-security-foundation` 基线标签，冻结认证协议、权限代码、数据范围策略、会话配置和审计字段。阶段 4 的任何业务模块都必须依赖该底座。
