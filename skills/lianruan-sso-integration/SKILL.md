# 联软双单点登录对接

## 适用范围

当目标系统需要接入以下任一能力时使用本技能：

- IAM/EMM H5 单点登录：浏览器或 EMM 客户端取得 `sso_token`，服务端换取身份。
- UniSDP 接口单点登录：前端提交 `sso_token`，服务端校验后建立会话。
- UniSDP 门户单点登录：门户直接访问 `/app/sso.htm`，服务端完成登录并落到业务页面。
- 需要复用现有的“手机号走渠道、用户名走管理端”身份分流和双会话落点。

不适用于普通 OAuth2/OIDC 授权码接入，也不适用于没有真实票据、只能做页面假跳转的演示实现。

## 先读手册

- 实施、配置、身份映射、会话、验收和排障：读 [references/sso-integration-manual.md](references/sso-integration-manual.md)。
- 需要核对请求体、响应字段、错误码或测试样例：读 [references/api-reference.md](references/api-reference.md)。

## 实施原则

1. **先确认协议再写代码。** 先取得目标环境的校验地址、ISAID、成功响应样例、失败响应样例和账号映射规则；没有真实样例时，不得声称对接完成。
2. **服务端校验票据。** 浏览器传来的 `entry`、`redirect`、角色、手机号和用户名都不可信；身份必须由服务端调用身份提供方后得到。
3. **不复制本项目敏感值。** 手册中的地址、ISAID、Cookie 名和内部路径只是协议说明；目标系统必须使用自己的配置，不得把真实密钥写入技能、日志或前端包。
4. **入口由身份形态决定。** 规范化手机号命中渠道账号后进入渠道端；用户名命中管理角色后进入管理端。请求方传入的入口只用于选择校验标识，不决定最终落点。
5. **同时建立两层会话。** 需要 HttpOnly Cookie 承载服务端会话，并按目标系统现状建立业务页面会话；两层会话必须由同一份服务端身份签发。
6. **失败必须可回退。** 单点失败返回账号密码登录页，并清理单点相关 URL 参数和失效 Cookie；不能把用户困在中转页。
7. **敏感信息不落日志。** 只记录 `requestId`、票据指纹、长度、阶段、错误码和脱敏账号，不记录完整票据、Cookie、密码或 ISAID 明文。

## 推荐实施顺序

1. 按手册“对接前信息清单”确认目标系统的身份提供方、账号字段、角色模型、会话方式和页面落点。
2. 先实现服务端适配器：配置读取、超时、提供方请求、响应解析、错误映射和身份匹配。
3. 再实现服务端登录接口：校验票据、签发 Cookie、返回业务页面会话；门户模式额外实现完成页。
4. 然后实现前端入口识别、凭证读取、中转页、URL 清理和安全跳转。
5. 最后按手册的测试矩阵做单元测试、假提供方测试和真实票据回归；真实票据未完成时只能标记“代码完成，联调未完成”。

## 最小接口契约

建议保持以下职责边界，具体路径可按目标系统调整，但不要合并“校验票据”和“信任前端身份”：

- `GET /api/auth/sso/iam/config`：返回 IAM 是否启用、可用入口、入口对应的请求标识和超时时间。
- `POST /api/auth/sso/iam/login`：接收 IAM/EMM 票据，服务端校验后建立会话。
- `POST /api/auth/sso/unisdp/login`：接收 UniSDP 票据，服务端校验后建立会话。
- `GET|POST /app/sso.htm`：接收 UniSDP 门户票据，完成服务端登录并返回页面会话完成页。

响应中至少包含用户摘要、业务页面会话、入口类型和匹配方式；不要把提供方原始响应原样透传给浏览器。

## 完成判定

只有以下条件全部满足，才能说“对接完成”：

- 成功票据能建立 Cookie 会话和页面会话，刷新后仍能恢复。
- 过期、无效、缺失票据分别返回稳定错误，并回到账号密码登录页。
- 渠道手机号和管理员用户名分别落到正确页面；手机号重复时拒绝登录，不静默选一个账号。
- 前端入口不会把 UniSDP 票据误送 IAM，也不会把 IAM 标记误送 UniSDP。
- 单点票据不出现在日志、历史记录、页面 DOM 或后续 API 中。
- 真实提供方票据、失败票据和重复回调各完成一次端到端验证；无法取得真实票据时明确记录为阻塞项。

## 目标系统信息不足时

如果目标系统使用不同的身份提供方字段、不同的会话模型或不同的角色体系，先列出手册中的“未知信息”，向用户确认后再编码。不要用本项目的字段名、角色码或页面路径直接覆盖目标系统。
