# KB说明

## 基本信息

- KB 编号：`KB-20260731-003`
- KB 名称：渠道商员工与企业管理员创建修复强制生效补丁
- 目标版本：`3.0.0-stage9.22.20260731-kb002`
- 最低版本：`3.0.0-stage9.20.20260729`
- 包类型：热修复
- 影响服务：`api-1`、`api-2`、`nginx`

## 问题背景

管理端渠道商详情中添加员工后，后端已存在渠道员工保存接口，但渠道商详情查询未从成员关系表聚合返回员工数组，页面刷新后看不到新员工。

企业管理员页面原先直接创建用户账号，没有绑定到渠道商成员关系，因此右侧“现有企业管理员”无法从渠道商员工列表中发现该账号。

同时，前端 `role` 字段在不同场景下既表示账号角色，又表示员工职位，编辑保存时存在把企业管理员账号角色覆盖成普通员工的风险。

上一版升级后，`10.20.3.10` 的 `/health/live` 仍返回 `3.0.0-stage9.22.20260730`，前端 `admin-app.js` 仍包含旧判断，说明服务没有实际切换到修复镜像。本补丁在保留业务修复镜像的基础上，强化升级脚本，使升级必须切到目标容器和目标构建号，否则直接失败并输出日志。

## 修复内容

1. 渠道商查询返回时，从 `channel.partner_members`、`iam.users` 聚合 `staff` 数组。
2. 员工保存接口区分 `accountRole` 与 `staffRole`，编辑时保留原渠道成员账号角色。
3. 管理端创建企业管理员改为调用 `/partners/:id/staff`，确保账号与渠道企业建立成员关系。
4. 管理端添加员工成功后刷新当前渠道商详情和列表缓存，并给出成功提示。
5. `inactive` 状态映射为数据库允许的 `disabled`，避免禁用操作被误写回启用。
6. 升级脚本同步 `config/v3.env` 构建号，强制重建 `api-1`、`api-2`、`nginx`，并校验容器镜像、健康接口版本、前端静态资源和渠道商 `staff` 字段。

## 验证方式

自动验证：

```bash
bash scripts/verify.sh /opt/lianruan-crm-v3
```

接口验证：

```bash
curl -sS http://127.0.0.1/health/live
curl -sS 'http://127.0.0.1/api/v2/partners?pageSize=1'
curl -sS http://127.0.0.1/admin-app.js | grep "accountRole === 'partner_admin'"
```

成功标准：

1. `/health/live` 返回版本 `3.0.0-stage9.22.20260731-kb002`。
2. 渠道商接口返回对象中包含 `staff` 字段。
3. 前端资源包含 `accountRole` 企业管理员判断。

人工验证：

1. 管理端进入“渠道商管理”，打开任一渠道商详情。
2. 添加员工，保存后确认员工出现在销售团队中。
3. 进入“企业管理员”，选择渠道企业创建企业管理员。
4. 确认右侧“现有企业管理员”出现新账号。
5. 使用新企业管理员账号从渠道伙伴入口登录，确认可进入渠道端。

## 回退方式

升级脚本会输出回退命令，格式如下：

```bash
sudo bash scripts/rollback.sh /opt/lianruan-crm-v3 /opt/lianruan-crm-v3/releases/3.0.0-stage9.22.20260731-kb002-pre-时间戳
```

回退只恢复应用配置和镜像标签，不自动恢复数据库。由于本 KB 不包含数据库结构迁移，通常不需要数据库回退。
