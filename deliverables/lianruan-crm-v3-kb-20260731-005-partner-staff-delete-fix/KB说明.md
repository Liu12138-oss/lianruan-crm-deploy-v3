# KB说明

## 基本信息

- KB 编号：`KB-20260731-005`
- KB 名称：渠道商员工删除刷新残留修复补丁
- 目标版本：`3.0.0-stage9.22.20260731-kb005`
- 最低版本：`3.0.0-stage9.20.20260729`
- 包类型：热修复
- 影响服务：`api-1`、`api-2`、`nginx`

## 问题背景

管理端渠道商详情中删除已创建用户后，刷新页面仍能看到该用户，只是卡片变为灰色。截图中的“王波”就是这种表现。

根因是删除接口原先复用了“禁用员工”的状态更新逻辑，只把账号状态写成禁用，没有删除 `channel.partner_members` 中的渠道商成员关系。渠道商详情刷新时仍会从成员关系表聚合 `staff` 数组，因此禁用账号继续以灰色卡片出现。

## 修复内容

1. `DELETE /api/v2/partners/:partnerId/staff/:staffId` 改为删除渠道商成员关系，不再只做禁用。
2. 删除成员关系后，如果该账号不再属于任何渠道商，则禁用账号并写入删除来源；如果仍属于其他渠道商，则只记录删除信息，不影响其他渠道商业务。
3. 保留“禁用/启用员工”接口语义，禁用后仍允许灰色显示；只有删除后刷新不再返回该员工。
4. 前端删除成功后，按 `id`、`userId`、`uuid`、`username` 多标识同步移除详情和列表缓存，避免接口返回标识不同导致卡片残留。
5. 本包保留前序渠道商员工创建、企业管理员创建、企业管理员列表显示修复，确保现场直接升级到本版本即可覆盖相关渠道商问题。
6. 升级脚本同步 `config/v3.env` 构建号，强制重建 `api-1`、`api-2`、`nginx`，并校验容器镜像、健康接口版本、前端静态资源和渠道商 `staff` 字段。
7. 升级前备份由本包直接执行 `pg_dump` 并使用 `zip` 打包业务目录，不调用服务器已有 `backup.sh`。

## 验证方式

自动验证：

```bash
bash scripts/verify.sh /opt/lianruan-crm-v3
```

接口验证：

```bash
curl -sS http://127.0.0.1/health/live
curl -sS 'http://127.0.0.1/api/v2/partners?pageSize=1'
curl -sS http://127.0.0.1/admin-app.js | grep "removePartnerStaffFromList"
```

成功标准：

1. `/health/live` 返回版本 `3.0.0-stage9.22.20260731-kb005`。
2. 渠道商接口返回对象中包含 `staff` 字段。
3. 前端资源包含 `removePartnerStaffFromList` 删除缓存同步逻辑。
4. 前端资源保留 `accountRole` 企业管理员判断。

人工验证：

1. 管理端进入“渠道商管理”，打开出现问题的渠道商详情。
2. 对销售团队中已存在的员工执行“删除”。
3. 删除后卡片立即消失。
4. 刷新页面或重新打开渠道商详情，已删除员工不再出现。
5. 对另一个员工执行“禁用”，刷新后该员工仍可作为灰色卡片出现。
6. 添加员工、创建企业管理员、查看现有企业管理员仍正常。
