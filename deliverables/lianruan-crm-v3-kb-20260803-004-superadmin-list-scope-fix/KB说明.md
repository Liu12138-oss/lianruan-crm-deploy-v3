# KB-20260803-004 修复说明

## 问题范围

超管登录 V3 管理端后，区域管理员、超管、企业管理员、渠道商、订单、报价等列表为空。

## 根因说明

旧静态管理端会在列表请求中携带 `operatorId`。KB003 后端已收紧渠道数据范围，但部分列表仍把 `operatorId` 当成负责人筛选条件，导致超管全量权限被自己的账号再次过滤，最终页面显示为空。

## 修复内容

1. 服务端列表查询改为优先使用可信会话和角色计算数据范围。
2. `operatorId` 仅作为旧页面操作者兼容参数，不再作为超管、管理员、企业管理员的列表范围条件。
3. 渠道商、账号列表补齐服务端数据范围，避免修复超管全量可见时误放开渠道账号。
4. 报备、商机、报价、订单沿用同一套范围规则，超管可看全量，区域管理员按区域，企业管理员按绑定渠道，渠道员工按本人。
5. 修复问题文档已补充渠道数据范围回归规则，后续涉及列表范围必须覆盖渠道商、账号、报价、订单。

## 数据库变更

无。

## 验证结论

本地已通过：

1. API 渠道数据范围回归测试。
2. Web 单元测试。
3. 项目静态门禁。

## 回退说明

升级脚本会自动生成应用配置快照和数据备份。本次不变更数据库，回退脚本只恢复应用配置和镜像引用。
