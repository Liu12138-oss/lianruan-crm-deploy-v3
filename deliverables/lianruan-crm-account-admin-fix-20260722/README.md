# 账号管理员精确操作修复包

本包用于修复渠道商员工、企业管理员等历史账号在编辑、启停、重置密码或删除时，因“渠道商员工记录编号”和“登录账号编号”不一致而出现无响应、接口 `404` 或提示账号不存在的问题。

本包只替换以下三个文件：

| 目标文件 | 用途 |
| --- | --- |
| `backend/server.js` | 按渠道商和员工记录精确定位账号，并兼容历史孤儿员工记录 |
| `frontend/admin-app.js` | 所有相关操作改为调用精确员工接口，并对路径参数进行编码 |
| `frontend/admin.html` | 更新前端脚本缓存版本 |

不包含数据库、依赖、配置、上传文件、日志或原有启停脚本。

## 数据保护承诺

- 升级前自动在 `/home/liulonghai/tmp/lianruan-crm-account-admin-fix-backups/` 创建时间戳备份目录。
- 自动备份三份旧代码文件，并对 `backend/crm.db`、`backend/audit.db` 创建 SQLite 一致性快照和校验清单。
- 升级、自动回退和一键还原均不会执行数据库导入、删除、覆盖、恢复或迁移。
- 一键还原默认只还原三个代码文件，绝不还原数据库快照，避免覆盖升级后新增的真实业务数据。
- 若三份生产代码的校验和不是本包对应的升级前基线，脚本会在停服前中止，防止覆盖其他已发布改动。
- 脚本会先确认 3000、8080 端口进程及进程编号文件均属于目标项目；发现端口被其他服务占用时会中止，不会误杀其他业务进程。

## 生产执行

请使用运行现有服务的同一账号执行。建议安排在低峰期，升级期间会有短暂服务中断。

```bash
# 进入已解压的升级包目录
cd /home/liulonghai/tmp/lianruan-crm-account-admin-fix-20260722

# 只读预检；失败时不停止服务、不替换文件、不操作数据库
bash check.sh

# 一键升级：自动备份、停服、替换三个文件、启服、健康检查、失败自动回退
bash upgrade.sh
```

默认目录如下，无需传参：

```text
项目目录：/home/liulonghai/lianruan-crm-deploy-v2.2.0
备份目录：/home/liulonghai/tmp/lianruan-crm-account-admin-fix-backups
后端端口：3000
前端端口：8080
```

升级成功后，浏览器请使用强制刷新重新加载管理后台页面。

## 一键还原

若需要撤回本次代码修复，在同一升级包目录执行：

```bash
cd /home/liulonghai/tmp/lianruan-crm-account-admin-fix-20260722
bash restore.sh
```

脚本默认选择最近一次成功升级备份；也可以传入指定备份目录：

```bash
bash restore.sh /home/liulonghai/tmp/lianruan-crm-account-admin-fix-backups/upgrade-时间戳
```

还原前仍会自动备份当前三个代码文件和两份数据库快照。数据库快照仅供人工灾难处置参考，不会被该脚本自动恢复。

## 升级后核验

1. 访问管理后台，确认页面正常打开。
2. 在“企业管理员”中，对历史管理员执行编辑、启用或停用、重置密码、删除等操作，确认有明确成功或失败提示。
3. 在“渠道商管理”的员工列表中，对同一类历史员工执行上述操作，确认不再出现“没有该账号”。
4. 对“左梅君”这类历史孤儿员工记录，确认删除动作能够正常提交并给出结果。删除本身会改变业务数据，必须由具备业务权限的人员在界面确认后手动执行；升级脚本不会代为删除任何生产账号。
5. 如需核对备份，可查看 `/home/liulonghai/tmp/lianruan-crm-account-admin-fix-backups/` 中本次时间戳目录的 `metadata/备份文件校验和.txt`、`database/crm.db` 与 `database/audit.db`。

## 不应使用的旧脚本

不要使用项目中旧的全量升级或全量恢复脚本来回退本补丁。它们可能覆盖无关文件或数据库。日常撤回本修复只使用本包的 `restore.sh`。
